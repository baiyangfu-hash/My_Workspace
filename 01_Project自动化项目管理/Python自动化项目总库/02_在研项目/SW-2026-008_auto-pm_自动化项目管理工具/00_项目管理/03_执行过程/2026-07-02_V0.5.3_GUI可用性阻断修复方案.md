# V0.5.3 GUI 可用性阻断修复方案

## 0. 触发背景

电气部门 GUI 试用反馈两个阻断性问题，用户判定"对于电气部门来说现在只是一个看板，无法正常工作使用"：

1. **PLC 总库显示 6，在研显示 1，其他都是 0** — 大量项目被忽略
2. **GUI 未找到新建项目的窗口** — 核心功能入口不可见

## 1. 诊断结论（已运行时验证）

### Bug 1：项目扫描计数丢失

**诊断脚本**：`_diag_scan.py`（已写入项目根目录）
**实际结果**：扫描到 13 个项目

| 分布维度 | 数据 |
|---------|------|
| 按 stack | plc=6, **unknown=6**, python=1 |
| 按 phase | **空=11**, developing=2 |

**根因链**：

1. **`stack='unknown'` 项目丢失（6 个）**：
   - SW-2026-001/004/005/006/007 + SYS-2026-001 全是 Python 项目
   - 这些项目 PM_SESSION 无 frontmatter `stack:` 字段，仅靠目录名/路径推断
   - `ProjectScanner` 未做"路径在 `01_Project自动化项目管理/Python自动化项目总库/` 下 → stack=python"的兜底推断
   - `NavigationTree._STACK_DEFS`（`nav_tree.py:36-39`）只有 plc/python 两类，无 unknown 容器

2. **`phase=''` 项目丢失（11 个）**：
   - `ProjectScanner._read_phase_from_pm_session` 仅在 PM_SESSION 有 frontmatter `phase:` 字段时返回
   - 回退策略 `_derive_phase_from_pm_session_content` 仅匹配 §2 current_focus / §8 current_state 关键词（archived/production/commissioning/developing），未匹配到则返回空
   - 11 个项目 PM_SESSION 既无 frontmatter phase 又无关键词匹配
   - `NavigationTree._PHASE_DEFS`（`nav_tree.py:42-47`）只有 developing/commissioning/production/archived 4 类，无"未分类"节点

**用户实际看到**：PLC 总库 6（含 DJ-2026-000/005/097/098 + SysLib + DJ-2026-100）+ 在研 1（DJ-2026-100 phase=developing），其他阶段全 0。SW-2026-008 是 python stack 不在 PLC 总库显示。

### Bug 2：新建项目窗口不可见

**根因链**：

1. "新建"按钮存在（`main_window.py:224-237`），但 `QToolButton` + `InstantPopup` + `ToolButtonTextOnly` 三件套下**不显示下拉箭头**
2. 按钮夹在搜索框/业务线下拉 + 导入项目/同步缓存/刷新列表之间，**无视觉突出**
3. 项目列表页（首屏）**无独立"新建项目"主操作位**，用户必须在工具栏菜单中二次选择
4. 电气工程师点击"新建"按钮后菜单弹出但用户**不知道在等什么**（无视觉反馈）

## 2. 修复方案

### Fix 1：导航树新增"未分类"兜底节点（最小改动）

**修改文件**：`auto_pm/ui/navigation/nav_tree.py`

- `_STACK_DEFS` 增加 `("unknown", "未分类", "📂")` 第三类（兜底）
- `_PHASE_DEFS` 不变（已分类的 4 阶段保留），但 `ProjectListView` 的 phase_cn 映射已含 `"": "未设置"`
- NavigationTree 渲染时，stack=unknown 的项目归入"未分类"节点；phase 为空的项目在对应 stack 节点下增加"未分类阶段"子节点

**预期效果**：6 个 unknown stack Python 项目归入"未分类"节点；11 个 phase 空项目归入"未分类阶段"节点（按 stack 分组）

### Fix 2：ProjectScanner 路径兜底推断 stack=python

**修改文件**：`auto_pm/core/project_scanner.py`

- 新增 `_infer_stack_from_path(project_path)` 方法：
  - 路径包含 `01_Project自动化项目管理\Python自动化项目总库\` → `stack="python"`
  - 路径包含 `0100_PLC自动化\` → `stack="plc"`
  - 其他 → `stack="unknown"`
- 在 `_enrich_from_pm_session` / `_enrich_from_copier` 后置调用兜底
- 6 个 SW-2026-* Python 项目从 `stack=unknown` 修正为 `stack=python`

**预期效果**：6 个 Python 项目归入"Python 总库"节点；导航树不再有"未分类"节点（除了 SYS-2026-001 实际跨域）

### Fix 3：ProjectScanner phase 兜底为 "developing"

**修改文件**：`auto_pm/core/project_scanner.py`

- `_read_phase_from_pm_session` 关键词匹配失败时，回退为 `"developing"`（默认在研）
- 理由：项目存在于工作空间 → 默认在研；只有显式标记 archived 的项目才归档
- 11 个 phase 空项目修正为 `phase=developing`

**预期效果**：11 个空 phase 项目归入"在研项目"节点；导航树不再有"未分类阶段"节点

### Fix 4：新建项目入口可视化强化

**修改文件**：`auto_pm/ui/main_window.py` + `auto_pm/ui/project_list/list_view.py` + `auto_pm/ui/styles.py`

**方案 A（推荐）**：
1. 工具栏"新建"按钮改为 `QToolButton` + `ToolButtonStyle.ToolButtonTextBesideIcon` + 添加 ➕ 图标 + tooltip "新建项目（点击选择类型）"
2. 项目列表页首屏空状态（项目数为 0 时）增加大按钮"➕ 新建第一个项目"
3. 项目列表页右上角增加"➕ 新建"主操作按钮（与 ViewControls 同行）
4. `styles.py` 新增 `QToolButton` 样式：背景色突出 + hover 反馈

**方案 B（备选）**：保留 InstantPopup 模式，仅在按钮右侧增加 `▼` 下拉箭头字符

**预期效果**：用户在首屏可见至少 2 处"新建项目"入口（工具栏 + 项目列表页主操作位），点击后直接弹出类型选择菜单
