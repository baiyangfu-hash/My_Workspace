## 2. 本轮目标

让 `plc check <Python 项目 ID>` 返回 `not_applicable=True` 的 CheckResult（不跑检查、不 FAIL、输出友好提示），并让 DashboardService 在 stack 判定之外增加 `not_applicable` 防御性检查；扩展 DashboardSummaryDTO 与 UI 透明展示"PLC 检查不适用项目数"，使用户能直观看到 Python 项目被正确识别。同时通过 CHG-075 dogfooding 闭环验证变更管理流程对"模型扩展 + 服务防御 + DTO 扩展 + UI 展示 + 多测试点"中等规模变更的支撑能力。

## 4. 执行策略

### 4.1 决策

- **分层防御**：CLI 层（友好提示）+ Checker 层（治本，not_applicable 标记）+ DashboardService 层（防御性条件）+ DTO/UI 层（透明展示）。任一层独立生效，组合后形成多层保护
- **检测规则复用**：PlcChecker 开头检测沿用 `_is_project_dir` 的 pyproject.toml 排除规则思路（无 .plc.json + 有 pyproject.toml → Python 项目）
- **CheckResult 字段最小扩展**：只加 `not_applicable: bool` + `not_applicable_reason: str`，不加复杂的状态枚举（保持向后兼容）
- **DTO + UI 同步扩展**：让用户在驾驶舱首页直接看到"PLC 检查不适用: N"标签，避免误以为 Python 项目被遗漏
- **risk_hints 区分**：原有"PLC 检查失败项目"提示保留（仅真失败）；新增"PLC 检查不适用项目"提示（仅 Python 项目）
- **dogfooding 先行**：CHG-075 在实施前创建并流转到 `approved`，实施完成后流转到 `closed`

### 4.2 数据流

```
plc check <Python 项目 ID>
    ↓
cmd_check → PlcService.check(proj.path) → PlcChecker.check_project
    ↓
[新增] 开头检测：if 无 .plc.json and 有 pyproject.toml:
    return CheckResult(not_applicable=True, reason="Python 项目，PLC 检查不适用")
    ↓
[否则] 跑原有 5 项检查

DashboardService.get_summary(projects)
    ↓
For project in projects:
    if project.stack != "plc": continue        # 既有 stack 判定
    result = plc_service.check(project.path)
    if result.not_applicable:                   # 新增防御性
        not_applicable_ids.append(project.project_id)
    elif result.fail_count > 0:
        failed_project_ids.append(project.project_id)
    ↓
DashboardSummaryDTO(
    failed_check_project_count=len(failed_project_ids),
    failed_check_project_ids=failed_project_ids,
    not_applicable_project_count=len(not_applicable_ids),    # 新增
    not_applicable_project_ids=not_applicable_ids,            # 新增
)

list_view.set_summary(summary)
    ↓
_check_label.setText(f"检查失败项目: {failed_count}")
[新增] _not_applicable_label.setText(f"检查不适用: {not_applicable_count}")
```

### 4.3 检测规则

| 项目特征 | stack | 检测路径 | 结果 |
|---|---|---|---|
| 有 .plc.json | plc | 跑 5 项检查 | 正常通过/失败 |
| 无 .plc.json + 有 pyproject.toml | python/unknown | 直接返回 not_applicable=True | 不适用，不跑检查 |
| 无 .plc.json + 无 pyproject.toml | unknown | 跑 5 项检查（保持原行为） | 按检查结果 |

**注意**：检测规则与 `PlcChecker._is_project_dir`（[plc/checker.py:466-497](../../auto_pm/plc/checker.py)）的 pyproject.toml 排除规则一致，避免行为分歧。

## 6. 风险与依赖

- **stack 误判根因未修**：本轮通过 `not_applicable` 防御性兜底；若 Python 项目 stack 被误判为 plc（_enrich_from_plc_json），DashboardService 会调用 check，但因 PlcChecker 返回 not_applicable=True，不会加入 failed_project_ids。根因修复（_enrich_from_plc_json 改为不强改 stack）留给后续迭代
- **既有 _is_project_dir 复用风险**：PlcChecker.check_project 开头检测逻辑需与 _is_project_dir 保持一致；若两者规则分歧会导致 --all 模式与单项目模式行为不一致
- **DTO 扩展向后兼容**：DashboardSummaryDTO 新增字段必须有默认值（`Field(0)` / `Field(default_factory=list)`），避免破坏既有反序列化
- **UI 测试**：本轮涉及 UI 改动，需要 offscreen 模式测试；既有 79 个 UI 测试无回归
- **dogfooding 风险**：第8次闭环，规模中等（模型扩展 + 服务 + DTO + UI + 多测试点），但流程已稳定7次，风险可控
- **依赖**：本轮依赖 CheckResult 模型的稳定性；依赖 write_file 原子写入能力（V0.3.8 TD-T11 已修复）
