## 4. 变更原因

**变更背景**:
V0.9.1 闭环后（CHG-100 第 31 次 dogfooding），用户决策启动 V0.9.2 治理收口迭代，目标是"拆薄 QmlBridge + 收口 README/qml_main_window.py/pyproject.toml 文档时效性 + 修复 VarTableEditorView.qml L259 + 定位 pytest 污染 + 纳入 Claude P2-P4 共 8 项长期建议"。迭代计划文档 `00_项目管理/03_执行过程/2026-07-08_V0.9.2_治理收口迭代计划.md` 定义 6 Phase 任务分解，用户指令"Phase 3-6 全部连续推进"。

**变更必要性**:
1. **PM_SESSION 真源失真**（Phase 1）：§2/§8 声明 mypy 8 errors + ruff 2 errors + QmlBridge 未拆分，实测 mypy 0 + ruff 0 + QmlBridge 已拆分为 5 个域 bridge
2. **Claude P2-P4 项待核查**（Phase 2）：Claude v3 诊断报告 P2-P4 共 8 项长期建议需逐条核查真实性
3. **文档时效性偏差**（Phase 3）：README.md 仍描述 QWidget/QWizard/QMainWindow 时代 + qml_main_window.py docstring 保留 --qml 历史说明 + pyproject.toml 疑似保留 pywebview 依赖
4. **测试污染问题**（Phase 4）：全量 pytest 卡在 96% + 7 个 CLI JSON 测试失败（json.loads 报 Extra data）+ VarTableEditorView.qml L259 onFocusLost 属性问题
5. **质量加固评估**（Phase 5）：Ruff 扩展规则集 + AutoPmConfig 配置类评估
6. **dogfooding 闭环**（Phase 6）：V0.9.2 迭代需走 CHG-*.md 变更单流程闭环

**参考依据**:
- `00_项目管理/03_执行过程/2026-07-08_V0.9.2_治理收口迭代计划.md`（迭代计划真源）
