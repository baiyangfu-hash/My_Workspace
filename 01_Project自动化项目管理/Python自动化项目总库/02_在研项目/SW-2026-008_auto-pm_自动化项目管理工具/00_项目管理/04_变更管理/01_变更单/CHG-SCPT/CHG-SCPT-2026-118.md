## 6. 变更影响分析

### 6.1 项目约束影响（PMBOK五大约束）

| 约束维度 | 影响程度 | 影响描述 | 应对措施 |
|---------|:--------:|----------|----------|
| **范围(Scope)** | ☑低 | 纯增量新增 GUI 入口，不改后端对账逻辑 | 复用 CHG-108 的 `LedgerReconciler`，仅在其上叠加 Facade/Bridge/QML 三层 |
| **进度(Schedule)** | ☑无 | 当日完成，无延期 | - |
| **成本(Cost)** | ☑无 | 纯代码变更，无外部成本 | - |
| **质量(Quality)** | ☑低 | 新增 8 个单元测试覆盖 Facade/Bridge 全部路径 | ruff 0 错误 + mypy 0 错误 + 33 个修改测试通过 + 309 个回归通过 |
| **风险(Risk)** | ☑低 | `LedgerReconciler.auto_fix()` 会写入磁盘，但仅在用户显式点击"自动修复"时触发；对账模式只读 | 对话框默认按钮为"仅对账"（auto_fix=False），"自动修复"按钮次显著；reconciled 信号触发 `loadChanges()` 刷新列表 |

**风险等级**（PMBOK风险评估）：☑低

**缓解措施**（风险应对策略）：
1. 对账模式（auto_fix=False）只读不写，用户可先预览差异
2. 自动修复后立即刷新变更列表，确保 UI 与磁盘一致
3. Facade/Bridge 全部路径有单元测试覆盖（成功/auto_fix/降级/异常 4 个场景 × 2 层 = 8 个测试）
4. 复用 CHG-108 已稳定后端，避免重复实现

## 12. 附录

### 12.1 填写指南

#### 如何选择技术领域?
- 主要改哪个专业的交付物,就选哪个领域
- 如果同时涉及多个专业,选**最主要**的那个作为主领域,其他在§6.2中标注

#### 如何判断影响范围?
- **LOCAL**: 改一个变量/一行代码/一个接线端子
- **MODULE**: 改一个FB/一条输送线/一台设备
- **SYSTEM**: 改全局变量/联锁逻辑/通讯接口
- **CROSS**: 改了电气,PLC和HMI都要跟着改
- **SAFE**: 动了急停回路/安全继电器/SIL相关
