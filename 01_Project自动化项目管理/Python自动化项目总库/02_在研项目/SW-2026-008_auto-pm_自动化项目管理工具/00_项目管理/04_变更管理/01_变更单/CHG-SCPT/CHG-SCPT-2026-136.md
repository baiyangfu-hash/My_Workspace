## 4. 变更原因

**变更背景**：
CHG-133闭环后发现§10.1/§11声称'25+11=36 passed'但实际tests/modbus/test_modbus_service.py仅25个测试函数，11个新功能码（FC02/07/20/22/23/24/43读+FC21/22写）的测试用例从未实际添加，属于失真声明

**变更必要性**：
补齐缺失的11个功能码测试用例，确保测试覆盖与变更单声明一致，消除质量盲区，modbus测试25→36 passed

**参考依据**：
- CHG-SCPT-2026-133 §10.1/§11（失真声明：声称 25+11=36 passed，实际仅 25 个测试）
- pymodbus v3.14.0 API 文档（功能码规范）
- modbus_service.py ModbusService.read_registers/write_register 方法签名

## 11. 版本详细变更说明

<a name="v100"></a>
### V1.0.0 版本详细变更
1. **新增 TestReadNewFunctionCodes 类**（8 个测试函数）：
   - `test_read_discrete_inputs_fc02`：验证 FC02 离散输入读取，返回 is_coil=True，物理地址以 "1" 开头
   - `test_read_discrete_inputs_fc02_physical_range`：验证 FC02 物理地址映射范围（10001-19999）
   - `test_read_exception_status_fc07`：验证 FC07 异常状态读取，返回 8 位异常状态字节
   - `test_read_file_record_fc20`：验证 FC20 文件记录读取，返回 10 条记录
   - `test_read_mask_write_fc22`：验证 FC22 掩码写寄存器读取，and_mask=0x00FF 低位掩码
   - `test_read_write_multiple_fc23`：验证 FC23 读写多寄存器，读 4 个+写 2 个
   - `test_read_write_multiple_fc23_float_decode`：验证 FC23 浮点解码（CDAB 字节序）
   - `test_read_fifo_queue_fc24`：验证 FC24 FIFO 队列读取，dec=3（FIFO 计数为 3）
   - `test_read_device_identification_fc43`：验证 FC43 设备识别读取，返回 3 个 ID 对象
2. **新增 TestWriteNewFunctionCodes 类**（3 个测试函数）：
   - `test_write_file_record_fc21`：验证 FC21 文件记录写入，message 含 "FC21"
   - `test_write_mask_write_register_fc22`：验证 FC22 掩码写寄存器，message 含 "FC22"
3. **修正 3 处断言错误**：
   - FC21 测试：`assert "21" in result.tx_hex` → `assert "FC21" in result.message`（FC21 的 FC 字节为 0x15≠"21"）
   - FC22 写测试：`assert "22" in result.tx_hex` → `assert "FC22" in result.message`（FC22 的 FC 字节为 0x16≠"22"）
   - FC24 测试：`assert "FIFO" in ...` 标签断言 → `assert reg.dec == 3`（FIFO 计数为 3）
4. **测试覆盖完整性**：modbus 测试从 25 个函数增至 36 个函数，覆盖全部 11 读+6 写功能码，消除 CHG-133 的失真声明

## 12. 附录

### 12.1 填写指南

#### 如何选择技术领域?
- 主要改哪个专业的交付物,就选哪个领域
- 如果同时涉及多个专业,选**最主要**的那个作为主领域,其他在§6.2中标注

#### 如何判断影响范围?
- **LOCAL**: 改一个变量/一行代码/一个接线端子
- **MODULE**: 改一个FB/一条输送线/一台设备
- **SYSTEM**: 改全局变量/联锁逻辑/通讯接口
- **CROSS**: 改了电气,PLC和HMI都要跟着改
- **SAFE**: 动了急停回路/安全继电器/SIL相关
