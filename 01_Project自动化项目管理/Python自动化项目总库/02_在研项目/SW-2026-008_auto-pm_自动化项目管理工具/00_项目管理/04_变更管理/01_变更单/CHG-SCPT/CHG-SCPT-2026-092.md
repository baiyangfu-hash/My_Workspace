## 4. 变更原因

**变更背景**：
V0.8.0 Phase 2（CHG-091）已完成 4 个 QML 页面（SpecCenter/Report/Template/Settings）+ main.qml 7 页全部为真实页面，QML UI 具备与 QWidget 旧版等价的能力。但 `auto-pm gui` 仍默认启动 QWidget，需手动加 `--qml` 才能用 QML。

同时，旧 QWidget 全局页代码（`auto_pm/ui/global_pages/report_page.py` 等 4 页 + 6 个 spec_center_tabs）已被 QML 完整替代，可激进清理。

**变更必要性**：

1. **CLI 默认入口切换**：让 QML UI 成为默认入口，用户无需手动加 `--qml` 标志
2. **A 类激进清理**：删除已被 QML 完整替代的旧 QWidget 全局页代码，降低维护成本
3. **旧测试迁移**：删除对应已废弃 QWidget 页面的单元测试

**约束**：

- main_window.py 仍被 17 个 tests/gui/ + tests/ui/ 测试依赖，本期不删除 main_window.py 本身
- 保留 QWidget 作为 `--qwidget` 标志的后备入口（向后兼容）
- tests/gui/ 全功能测试本期保留，待 V0.9 QML UI 经过实战验证后再迁移

## 5. 变更内容

### 5.1 Phase 3：CLI 默认入口切换（`auto_pm/cli/gui.py`）

**变更**：

- 翻转默认：`auto-pm gui` → 启动 QML（之前默认 QWidget，需 `--qml`）
- 新增 `--qwidget` 标志：启动旧版 QWidget UI（向后兼容，标记为 deprecated）
- 弃用 `--qml` 标志（默认行为即 QML，标志保留但变为 no-op，输出 deprecation 警告）
- 更新 help 文本

**核心代码**：

```python
@click.command()
@click.option("--debug", is_flag=True, help="调试模式")
@click.option(
    "--qwidget",
    is_flag=True,
    help="启动旧版 QWidget GUI（deprecated，V0.9 移除）",
)
@click.option(
    "--qml",
    is_flag=True,
    help="(deprecated) QML 现为默认入口，本标志将被移除",
)
@click.pass_context
def gui_command(ctx, debug, qwidget, qml):
    if qml:
        console.print("[yellow]--qml 已弃用：QML 现为默认入口，本标志将在 V0.9 移除[/yellow]")
    if qwidget:
        console.print("[cyan]启动 QWidget GUI (legacy): {workspace}[/cyan]")
        _run_pyside_gui(workspace, debug)
    else:
        console.print(f"[cyan]启动 QML GUI (V0.8.0): {workspace}[/cyan]")
        _run_qml_gui(workspace, debug)
```

## 6. 影响分析

### 6.1 正面影响

- **正面**：CLI 默认入口切换为 QML，用户无需手动加 `--qml`
- **正面**：删除 10 个旧 QWidget 全局页文件 + 4 个对应测试，减少 ~2500 行死代码
- **正面**：降低维护成本，避免 QWidget/QML 双份代码长期分叉
- **正面**：为 V0.9 完整移除 QWidget UI 铺路

### 6.2 风险影响

- **风险 1**：main_window.py 仍 import 已删除的 global_pages，导致 QWidget 启动失败
- **缓解**：修改 main_window.py 的 import 块，将已删除的页面改为 placeholder QWidget（显示 "已迁移到 QML，请使用 `auto-pm gui`"），QWidget 仍可启动
- **风险 2**：tests/gui/test_10~13 端到端测试可能因 main_window.py placeholder 而失败
- **缓解**：本期接受这 4 个测试可能失败（标记 xfail），V0.9 完整移除 main_window.py 时一并删除
- **风险 3**：CLI 默认行为变化，已有脚本/CI 调用 `auto-pm gui`（无 --qml）的将启动 QML
- **缓解**：QML 已通过 200/200 测试，功能等价；脚本可加 `--qwidget` 恢复旧行为

### 6.3 缓解措施

1. 修改 main_window.py 的 import 块，对已删除页面用 try/except + placeholder QWidget
2. tests/gui/test_10~13 加 pytest.mark.xfail(reason="main_window.py 已迁移到 QML，本期保留 main_window.py 框架但页面为 placeholder")
3. 完整回归 tests/qml/（200 测试）+ tests/cli/ + tests/core/
