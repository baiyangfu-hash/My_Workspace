## 4. 变更原因

**变更背景**：
V0.8.0 Phase 1（CHG-090）已完成 QmlBridge 6 个 Service 注入 + main.qml 侧边栏补全 6 入口 + StackLayout 7 页占位 Rectangle。当前 4 个占位页（规范中心/报告中心/模板管理/设置）仅显示 "V0.8.0 Phase 2 占位" 文本，无实际功能。

Phase 2 是 QML 完整覆盖的核心：实现 4 个真实 QML 页面替换占位，让 QML UI 拥有与 QWidget 旧版完全等价的报告/模板/设置/规范中心能力，为 Phase 3 默认入口切换做前置准备。

**变更必要性**：
1. **占位 Rectangle 必须替换为真实页面**：当前 4 个占位只显示标题 + Service 注入状态，无任何业务功能
2. **QmlBridge 需补齐 6 个 Slot**：4 个新页面需要更细粒度的后端调用（如 getTemplateDetail/getSettingsSummary/clearCache/rebuildIndex/getSpecOverview/listSpecEntries），Phase 1 仅暴露了基础 Slot
3. **SpecCenter 简化为 3 Tab**：原 QWidget 版本 6 Tab 复杂度过高，Phase 2 先实现 3 Tab（概览/检查/索引），Frontmatter/报告/对比 Tab 留待 V0.9
4. **为 Phase 3 默认入口切换做前置**：4 页面就绪后，QML UI 才具备替代 QWidget 的完整能力

**参考依据**：
- Phase 1 闭环：CHG-SCPT-2026-090（QmlBridge 扩展 + main.qml 侧边栏）
- 4 个 QWidget 源页：
  - `auto_pm/ui/global_pages/report_page.py`（2×2 卡片柱状图）
  - `auto_pm/ui/global_pages/template_page.py`（卡片列表 + 更新项目）
  - `auto_pm/ui/global_pages/settings_page.py`（工作空间路径 + DB 统计 + 清除/重建）
  - `auto_pm/ui/global_pages/spec_center.py`（6 Tab 简化为 3 Tab）
- QML 复用模式参考：`auto_pm/ui/qml/views/ChangeCenterView.qml`（三重守卫 + 顶部导航 88px + 列表+详情布局）

## 5. 变更内容

### 5.1 QmlBridge Phase 2 Slot 补齐（`auto_pm/ui/qml/qml_bridge.py`）

**新增 6 个 Slot**：

| Slot | 签名 | 用途 | 数据来源 |
|------|------|------|----------|
| `getTemplateDetail(name)` | `Slot(str, result="QVariant") -> dict` | 模板详情（版本/描述/使用项目数） | TemplateService + ProjectService |
| `getSettingsSummary()` | `Slot(result="QVariant") -> dict` | 设置摘要（workspace/db_path/项目数/变更数/上次同步） | ProjectService.db + ChangeService |
| `clearCache()` | `Slot(result="QVariant") -> dict` | 清除 DB 缓存（删 db 文件 + 重新 init_schema） | ProjectService.db |
| `rebuildIndex()` | `Slot(result="QVariant") -> dict` | 重建索引（sync_to_cache force_full） | ProjectService.sync_to_cache |
| `getSpecOverview()` | `Slot(result="QVariant") -> dict` | 规范概览（spec_count/domain_counts/lifecycle_counts/health_summary） | SpecCenterAdapter.get_overview |
| `listSpecEntries(domain)` | `Slot(str, result=list) -> list[dict]` | 规范索引条目列表 | SpecCenterAdapter.list_entries |

**SpecCenterAdapter 工厂函数新增**：`make_spec_center_service(workspace_root) -> Any | None`，包装 SpecCenterAdapter 实例化，无 spec_registry.json 时返回 None。

**向后兼容**：所有新 Slot 在 SpecCenter/TemplateService 等未注入时返回空数据/getSettingsSummary 始终可用（基于 project_service）。

## 6. 影响分析

### 6.1 质量影响
- **正面**：QML UI 4 个占位替换为真实页面，覆盖全部 6 大功能页（项目列表/变更中心/规范中心/报告/模板/设置）
- **正面**：为 Phase 3 默认入口切换做前置准备（QML UI 具备替代 QWidget 的完整能力）
- **风险**：4 个新 QML 页面 + 6 个新 Slot 增加代码量，需保证 ruff/mypy 0 错误 + W1/W2/W3/W4 既有测试零回归

### 6.2 风险影响
- **风险 1**：SpecCenter 简化 3 Tab 可能丢失原 QWidget 6 Tab 的 Frontmatter/报告/对比功能
- **缓解**：3 Tab 覆盖核心需求（概览/索引/检查），其余 3 Tab 留待 V0.9 单独迭代
- **风险 2**：clearCache/rebuildIndex 涉及 DB 写操作，QML 端误触发可能损坏数据
- **缓解**：QML 端必须弹确认对话框二次确认 + Slot 内部 try/except 包裹
- **风险 3**：4 个 QML 页面 Component.onCompleted 自动加载数据，若 bridge 未注入可能报错
- **缓解**：三重守卫 `typeof bridge === "undefined" || bridge === null || !bridge.hasXxxService`

### 6.3 缓解措施
1. 所有新 Slot 内部 try/except 包裹，异常时返回 `{error: ...}` dict
2. QML 端三重守卫 + 空状态提示
3. clearCache/rebuildIndex 必须弹确认对话框
4. 完整回归 W1/W2/W3/W4 + Phase 1 既有测试
