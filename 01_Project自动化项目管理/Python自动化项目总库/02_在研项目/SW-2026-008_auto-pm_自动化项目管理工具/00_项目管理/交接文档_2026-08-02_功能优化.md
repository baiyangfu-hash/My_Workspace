### P2-5: `change transition` CHG 章节完整性校验

**用法**: 流转到 `closed` 时自动校验：
```powershell
auto-pm -w "<工作空间根>" change transition CHG-xxx --to closed
```

**门禁**: 13 个必需章节非空才能流转到 `closed`：

> §5 变更前后 / §6.1 五大约束影响 / §6.2 跨领域影响 / §6.3 变更传播链 / §7 实施计划 / §8.1 审批流程 / §8.2 审批结论 / §9 变更实施记录 / §10.1 验证项清单 / §10.2 跨领域联动验证 / §10.3 验证结论 / §11 版本详细变更说明 / §12 附录

**流程**: `completed → closed` 为新增的有效状态流转（`STATUS_FLOW` 中原已定义，本次补充门禁）。

**错误提示示例**:
```
变更单 CHG-xxx 章节不完整，缺失 3 个必需章节: §11 版本详细变更说明, §12 附录, §7 实施计划；
请补全所有章节后再流转到 closed
```

### P2-7: `spec check --verbose` 详细 diff 输出

**用法**:
```powershell
# 普通模式（原有）
auto-pm -w "<工作空间根>" spec check

# verbose 模式：按 check_id 分组，显示详细 diff
auto-pm -w "<工作空间根>" spec check --verbose
auto-pm -w "<工作空间根>" spec check -v -c SHC-002

# JSON 模式 + verbose（增加 summary 统计）
auto-pm -w "<工作空间根>" spec check --verbose --format json
```

**差异**: verbose 模式下：
- 按 `check_id` 分组，每个 SHC 检查项独立显示
- 每个结果显示序号、详细信息分行缩进（`│` 前缀）
- JSON 输出增加 `summary` 字段（total/error/warning/info 统计）

### P3-8: `ai_context.json` 自动生成

**触发时机**: 运行 `project show` 或 `plc check <项目ID>` 后自动生成。

**生成路径**: `<工作空间根>/.auto-pm/ai_context.json`

**生成内容示例**:
```json
{
  "generated_at": "2026-08-02T...",
  "source": "auto-pm CLI",
  "workspace_root": "C:\\Users\\fubai\\Desktop\\My_Workspace",
  "active_project": {
    "id": "DJ-2026-005",
    "name": "DJ-2026-005",
    "stack": "plc",
    "phase": "developing"
  },
  "active_change": null,
  "active_page": "workspace"
}
```

**用途**: 驾驶舱（cockpit）和 AI 技能（pm-workflow）启动时读取此文件恢复上下文，跳过冗余的项目识别步骤。

**容错**: 写入失败时静默降级（仅 `logging.warning`），不影响主流程。
