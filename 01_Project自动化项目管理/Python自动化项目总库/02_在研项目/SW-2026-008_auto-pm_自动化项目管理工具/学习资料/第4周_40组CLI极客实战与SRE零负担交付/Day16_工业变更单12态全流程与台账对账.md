# Day 16：工业变更单 12 态全流程与台账对账

> 🎯 **今日目标**：掌握工程变更单（CHG Ticket）的标准 12 状态机流转，熟练使用 `auto-pm change` 与 `auto-pm ledger reconcile` 实现变更全生命周期闭环与台账 0 差异对账。  
> ⏱️ **预计耗时**：50 分钟  
> 🛠️ **前置准备**：查看 `04_监控/01_变更管理/` 与 PM-042/PM-043 规范。

## 💡 一、工控视角看变更管理：严禁“现场私改程序不留底”

每一个在车间一线摸爬滚打过的工程师，都经历过这种噩梦：
- 某天设备突然报警停机，查了一整天，发现三个月前同事去现场调试时，顺手在 PLC 里把某个安全连锁给屏蔽了，**既没在图纸上改，也没在台账里记！**
- 工业工程的铁律是：**任何代码、配置、点位的修改，都必须开具正式变更单（CHG），登记台账，验收归档！**

`auto-pm` 实现了汽车制造级的 **12 态严密变更状态机**：

```text
草稿 (draft) ──> 已提交 (submitted) ──> 审核中 (under_review) ──> 已批准 (approved)
                                                                        │
                                                                        ▼
待验收 (pending_acceptance) <── 实施中 (implementing) <─────────────────┘
         │
         ▼
验收中 (accepting) ──> 已完成 (completed) ──> 已关闭 (closed) ──> [台账闭环归档]
```

---

## ⚙️ 二、台账对账引擎（Ledger Reconcile）

- **自动入账**：当执行 `auto-pm change create` 时，系统自动在 `01_版本变更台账.md` 顶部插入新流水号记录；
- **生产对账**：运行 `auto-pm ledger reconcile <PID>`，系统会无死角比对硬盘上所有 `CHG-*.md` 文件与台账表格：
  - 是否有单据存在但台账漏记（台账缺失）？
  - 是否有台账记录了但文件丢了（孤儿记录）？
  - 是否单据章节内状态与台账不一致（状态不一致）？
- **零容忍**：必须达成 `0 缺失、0 孤儿、0 不一致`，方允许项目结项！

## 🧪 三、5 分钟动手实操实验

### 步骤 1：查看变更单状态流转帮助
```powershell

python -m auto_pm -w "c:\Users\fubai\Documents\My_Workspace" change transition --help
```
*预期输出*：列出 `--to` 目标状态与审批人、验证结论等参数。

### 步骤 2：对当前项目执行台账一致性生产对账
```powershell
python -m auto_pm -w "c:\Users\fubai\Documents\My_Workspace" ledger reconcile SW-2026-008
```
*预期输出*：输出台账对账报告，断言 `台账缺失: 0 条, 台账多余(孤儿): 0 条, 状态不一致: 0 条 -> 对账无差异`。

## 🛡️ 四、改崩恢复法与今日自测打卡

### 🚑 状态机流转阻断排查
若流转到 `completed` 失败：
核对 `--verification-conclusion` 中是否包含“通过”字样；
若流转到 `closed` 失败：
核对变更单 Markdown 是否遗漏了 `### 6.3 变更传播链` 等强制章节。
