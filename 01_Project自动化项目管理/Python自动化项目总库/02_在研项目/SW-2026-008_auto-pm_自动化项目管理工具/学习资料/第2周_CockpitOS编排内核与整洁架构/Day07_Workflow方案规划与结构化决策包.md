## 💡 一、工控视角看决策包：PLC“参数锁定与互锁确认单”

在自动化调试中，如果要对一条运转中的产线做重大变更（例如把气缸下压延时从 2s 改为 0.5s，或者调整机器人抓取点位），电气工程师绝不能“拍脑袋直接改参数下载”！
必须有一张**《工艺参数调整与互锁确认单》**：
- 记录变更前参数与变更后参数；
- 列明涉及哪些气缸与伺服轴（白名单）；
- 必须经过工艺主管与电气主管签字（Sign-off）；
- 现场只允许改动这张单子上列明的点位，多动一个轴就算违规操作！

`auto-pm` 的 **结构化决策包（Decision Package, DEC-*.json）** 就是这张数字化的互锁确认单！

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ 📋 结构化决策包 (DEC-YYYYMMDD-XXXXXXXX)                                      │
├─────────────────────────────────────────────────────────────────────────────┤
│ • 决策目标 (Goal)：变更的业务诉求与范围                                      │
│ • 依据规范 (Baseline Specs)：强制绑定的法典 (如 LSP-905, STD-840)           │
│ • 白名单文件 (Touched Files)：被严格限制的修改路径清单                      │
│ • 审批指纹 (Approver & Hash)：架构师签名与全生命周期锁死凭据                │
└─────────────────────────────────────────────────────────────────────────────┘
```

## ⚙️ 二、WorkflowOrchestrator.plan 规划流水线

在 Cockpit OS 中，任何任务在开工编码之前，必须先经过规划流水线（Plan Pipeline）：

```text
[用户原始需求] ──> [项目合法性校验] ──> [草稿单复用/新建] ──> [规范自动绑定] ──> [锁死决策包 DEC]
```

- **防越界硬把关（Scope Gating）**：决策包一旦生成，其 `touched_files` 白名单就会成为物理捕兽夹。后续执行阶段，任何子代理或工具如果试图改动白名单以外的文件，门禁直接熔断打回！

## 🛡️ 四、改崩恢复法与今日自测打卡

### 🚑 决策包范围越界报错处理
若执行阶段报错 `Scope Gating: file outside whitelist`：
说明实际修改超出了报批范围。必须重新走决策变更流程，扩充决策包白名单并重新审批，严禁私自绕过。
