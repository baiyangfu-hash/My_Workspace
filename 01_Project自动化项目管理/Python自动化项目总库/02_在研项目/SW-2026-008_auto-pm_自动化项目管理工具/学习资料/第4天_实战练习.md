### 3.1 找到类定义

### 3.2 加一个信号

在类的信号定义区域（搜索 `Signal`），加一个新信号：

```python
# 在已有信号下面加
refreshCompleted = Signal(str)   # 刷新完成信号，带消息
```

### 3.3 加一个 Slot 方法

在类的方法区域找一个合适位置，加：

```python
@Slot()
def refreshProjects(self):
    """刷新项目列表（QML 调用）"""
    try:
        # 调用 Facade 获取最新项目列表
        result = self._facade.list_project_cards(self._workspace_root)
        
        if result.success:
            # 更新内部数据
            self._projects = result.data or []
            # 发射信号通知 QML
            self.projectsChanged.emit()
            self.refreshCompleted.emit(f"已刷新 {len(self._projects)} 个项目")
        else:
            self.refreshCompleted.emit(f"刷新失败：{result.message}")
    except Exception as e:
        self.refreshCompleted.emit(f"刷新出错：{e}")
```

## 第 6 步：理解你做了什么

回顾整个链路：

```
1. 用户点击 QML 按钮
   → onClicked: { bridge.refreshProjects() }
   
2. Bridge 收到调用
   → @Slot def refreshProjects(self):
   
3. Bridge 调用 Facade
   → self._facade.list_project_cards(workspace_root)
   
4. Facade 调用 Service
   → self._project_service.list_projects(workspace_root)
   
5. Service 返回数据
   ← QueryResult(success=True, data=[项目列表])
   
6. Bridge 发射信号
   → self.projectsChanged.emit()
   → self.refreshCompleted.emit("已刷新 N 个项目")
   
7. QML 收到信号
   → onRefreshCompleted(message) { statusLabel.text = message }
   → onProjectsChanged() { 重新加载列表 }
   
8. 画面更新
   ← 用户看到刷新后的列表和状态文字
```

**这就是 auto-pm 的完整数据流。你以后改任何功能，都是这个模式。**

## 常见问题

### Q: 改完 QML 后 GUI 没变化？
A: 关掉 GUI 重新运行。QML 不会热更新。

### Q: 点击按钮报 `bridge is not defined`？
A: 检查 `qml_main_window.py` 里 Bridge 是否正确注入了 context property。

### Q: `@Slot` 报错？
A: 检查参数类型声明。`@Slot()` 无参数，`@Slot(str)` 一个字符串。

### Q: 信号没反应？
A: 检查 QML 的 `Connections` 里方法名：
- Signal 名 `refreshCompleted` → QML 方法 `onRefreshCompleted`
- 首字母必须大写

### Q: 测试挂了？
A: 先看你改了哪些文件，检查有没有语法错误：
```powershell
python -c "from auto_pm.ui.qml.bridges.workbench_bridge import WorkbenchBridge; print('OK')"
```
