# Day 01：Git 入门与工控概念类比

> 🎯 **今日目标**：理解 Git 的核心心智模型，掌握日常查看修改与打备份快照的必备命令。
> ⏱️ **预计耗时**：45 分钟
> 🛠️ **前置准备**：打开 PowerShell 并进入工作空间根目录。

---

## 💡 一、工控视角看 Git：告别“散装压缩包备份”

在过去做 PLC 项目时，你可能经常这样备份程序：
* `DJ-2026-005_20260801_初版.zip`
* `DJ-2026-005_20260810_现场改完.zip`
* `DJ-2026-005_20260815_最终版_不要动.zip`
* `DJ-2026-005_20260818_真最终版_带伺服.zip`

这种方式极易产生三大痛点：**占硬盘、不知道两次压缩包具体改了哪一行、多人修改无法合并**。

Git 就是软件世界的**“专业 PLC 程序版本管理机”**，它的核心概念与工控完全对应：

```
PLC 工控概念                    Git 版本控制概念
──────────────────              ─────────────────────────
PLC 在线监视/未下载的编辑内存    Working Tree (工作区)
博途/AutoShop 中的“程序比对”     git diff (代码差异比对)
博途中的“全项目一致性编译保存”    git add . (暂存准备)
带时间戳与修改说明的“黄金快照”    git commit -m "说明" (提交快照)
版本历史台账记录                git log --oneline (提交日志)
```

## 🛠️ 二、日常维护 4 步走标准工作流

每天开始和结束维护驾驶舱时，只需牢记这 4 步：

```
① 查看改动状态          ② 比对改动细节          ③ 暂存与打快照          ④ 查看历史台账
┌───────────────┐     ┌───────────────┐     ┌───────────────┐     ┌───────────────┐
│  git status   │ ──> │   git diff    │ ──> │ git commit -m │ ──> │  git log -n 5 │
└───────────────┘     └───────────────┘     └───────────────┘     └───────────────┘
```

### 1. `git status` —— 一眼看清当前“修改清单”
就像 PLC 的未保存修改提示灯，它会告诉你哪些文件被修改了、哪些是新增的。

### 2. `git diff` —— 精确对比“改了哪一行”
按行高亮显示：
* `- 红字`：被删掉的旧代码
* `+ 绿字`：新添加的代码
* 按 `q` 键退出比对视图。

### 3. `git add .` 与 `git commit -m "说明"` —— 拍一张立等可取的“黄金快照”
* `git add .`：把当前工作区的所有修改放进暂存盘。
* `git commit -m "feat(modbus): 修改浮点解码显示精度为4位"`：正式固化为一个带编号的快照。

### 4. `git log --oneline -n 5` —— 查看最近 5 次版本快照

## 🧪 三、5 分钟动手实战实验

我们来实际演练一次“修改文案 $\rightarrow$ 比对 $\rightarrow$ 提交快照”的全过程：

### 步骤 1：查看当前状态
```powershell
git status
```
*预期输出*：显示当前分支名称，确认工作区状态。

### 步骤 2：查看最近的提交记录
```powershell
git log --oneline -n 3
```
*预期输出*：输出类似 `a1b2c3d feat: xxx` 的简短提交历史。

### 步骤 3：查看具体某次提交的改动
```powershell
git show --stat HEAD
```
*预期输出*：展示最新一次提交涉及修改的文件列表。

## 🛡️ 四、防呆贴士与安全准则

> [!TIP]
> 1. **每次 commit 必须写清人话**：严禁写 `111`、`fix`、`改了` 这种无意义说明。标准格式建议为：`类型(模块): 说明`（例如 `fix(ui): 修复表格列宽`、`feat(plc): 增加SCL定时器检查`）。
> 2. **小步快跑，频繁提交**：每完成一个独立小改动就 commit 一次，不要攒了一周才提一次，否则一旦出 Bug 很难精确定位。

---

## 📝 今日打卡小结

1. Git 的 `commit` 就相当于 PLC 程序的**黄金备份快照**。
2. 动代码前后，第一件事永远是敲 `git status`。
3. 比对修改细节使用 `git diff`。
