## 💡 一、工控视角看代码门禁：PLC 编译器的“汽车级严苛把关”

在编写 PLC 代码时，博途或汇川编译器只会检查最基础的语法错（如拼错变量名、分号漏写），但它**绝不会提示逻辑与架构缺陷**：
- CASE 语句漏写 `ELSE` 分支（一旦状态异常立刻死锁停机）；
- 定时器没有三段式复位保护；
- 变量命名随意（`a1`, `temp2` 满天飞，后人接手如看天书）；
- 缺少首出报警诊断，设备停机找不到第一故障源。

`auto-pm plc check` 就是专为工业自动化打造的**“汽车制造级 SCL Linter 体检机”**！
它基于严苛的德国汽车工业标准与 LSP-905~908 规范，在代码刷入 PLC 之前进行地毯式扫描。

```text
│ • 状态机规范：STD-830 OMAC 状态机，CASE 语句严禁漏写 ELSE                   │

```

## ⚙️ 二、机器无情判卷与真退出码（Zero-Burden Law）

在 Release 1.2.4 中，系统彻底消除了历史上的“假绿”技术债：
- 只要扫描出任何一项未达标（FAIL），命令退出码**坚决返回 Exit 1**；
- 只有 100% 全绿无违规，才返回 **Exit 0**；
- 主控 PM 与 CI 门禁严禁人工肉眼审查，完全采信底层物理 Exit Code，机器说不过就必须重写！

## 🧪 三、5 分钟动手实操实验

```powershell

```

### 步骤 2：对特定在研项目运行门禁
