# Day 04：项目全生命周期与 Copier 标准立项

> 🎯 **今日目标**：掌握工业项目的全生命周期管理（立项/推进/归档），熟练使用 Copier 脚手架模板瞬间建立标准工业项目工程。  
> ⏱️ **预计耗时**：50 分钟  
> 🛠️ **前置准备**：理解工作空间项目编号规范（如 `DJ-YYYY-XXX`、`SW-YYYY-XXX`）。

---

## 💡 一、工控视角看标准立项：拒绝“拷贝旧工程另存为”

每一个电气工程师在接新项目时，最习惯的动作往往是：
- 找到去年的旧项目 `DJ-2025-008_三工位装配机`；
- 复制整个文件夹，改名为 `DJ-2026-003_五工位打螺丝机`；
- 进去删掉不需要的程序块，保留部分轴配置和报警列表。

**这种“祖传代码另存为”是工控现场 80% 隐蔽 Bug 的根源**：残留了旧项目的绝对路径、冲突的站号与 IP、没有清理干净的死变量、混乱的说明书。

`auto-pm` 采用 **Copier 模板脚手架（Template Scaffolding）**：
- 就像博途的标准库模板（Project Template）；
- 每次立项输入项目编号、工站数量、PLC 型号（西门子/汇川/欧姆龙），系统在 1 秒内精准注入具备完整目录结构、标准命名与门禁骨架的纯净工程！

## ⚙️ 二、项目全生命周期流转模型

```text
┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
│  01_启动  │ ──> │  02_规划  │ ──> │  03_执行  │ ──> │ 04_监控  │ ──> │  05_收尾  │
│ CHARTER  │     │ PRD/INT  │     │ SCL/HW   │     │ CHG/LOG  │     │ SUM/DEL  │
└──────────┘     └──────────┘     └──────────┘     └──────────┘     └──────────┘
```

每个通过 `auto-pm` 管理的工业项目，根目录下均配备唯一的单一事实真源：`PM_SESSION_<PID>.md`。它忠实记录了：
- 项目元数据（技术栈、责任人、当前版本）；
- 阶段门禁状态（启动、规划、执行、监控、收尾）；
- 变更单历史与关联交付物索引。

## 🧪 三、5 分钟动手实操实验

### 步骤 1：列出当前系统所有受控项目
```powershell
$env:PYTHONPATH = "00_Infrastructure/auto_pm"
python -m auto_pm -w "c:\Users\fubai\Documents\My_Workspace" project list
```
*预期输出*：表格化列出 DJ-2026-000、DJ-2026-005、SW-2026-008 等全部项目及其生命周期阶段。

### 步骤 2：查看特定项目的详细健康状态
```powershell
python -m auto_pm -w "c:\Users\fubai\Documents\My_Workspace" project show SW-2026-008
```
*预期输出*：展示项目的基本信息、路径分布、当前活动变更单与各阶段文档覆盖情况。

## 🛡️ 四、改崩恢复法与今日自测打卡

### 🚑 立项错误回滚
若测试创建项目填错了参数，可直接运行带安全二次确认的删除指令：
```powershell
python -m auto_pm -w "c:\Users\fubai\Documents\My_Workspace" project delete <PID> --confirm
```
