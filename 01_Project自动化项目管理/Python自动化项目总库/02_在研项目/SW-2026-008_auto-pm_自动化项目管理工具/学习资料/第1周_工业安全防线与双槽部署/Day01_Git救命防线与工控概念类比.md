# Day 01：Git 救命防线与工控概念类比

> 🎯 **今日目标**：建立 Git 版本控制的工控心智模型，掌握随时“查看现场差异”与“出厂快照回滚”的救命命令。  
> ⏱️ **预计耗时**：45 分钟  
> 🛠️ **前置准备**：PowerShell 进入工作空间根目录，确认 git 处于可用状态。

---

## 💡 一、工控视角看 Git：告别“散装备份压缩包”

在传统非标电气工程中，大家最熟悉的备份方式是打带日期的压缩包：
- `DJ-2026-005_20260801_初版.zip`
- `DJ-2026-005_20260810_现场改完伺服参数.zip`
- `DJ-2026-005_20260815_最终版_不要动.zip`
- `DJ-2026-005_20260818_真最终版_带气缸报警.zip`

这种做法有三大致命硬伤：**占用磁盘巨大、无法对比两次修改具体动了哪一行、多个人修改时代码无法合并**。

Git 就是软件工程世界的**“专业 PLC 程序版本记录与快照管理机”**：

```text
PLC 工控实体概念                     Git 版本控制核心概念
──────────────────────────          ─────────────────────────────────
PLC 在线监视 / 内存中未下载的改动      Working Tree (工作区，未暂存)
博途 / AutoShop 中的“与项目比对”       git diff (精准行级差异对比)
将改动编译校验并装入“待下发缓冲区”     git add . (暂存区 Staging Area)
写入 PLC ROM 并打上版本号的固件快照   git commit -m "变更说明" (提交快照)
设备历史维修台账记录簿                git log --oneline (版本演进日志)
出厂设置一键恢复开关闭合              git restore / git reset (撤销与回滚)
```

## ⚙️ 二、日常维护 4 步走标准工作流

无论你是准备修改一行 Python 配置文件，还是准备调整一个 SCL 模板，请牢记每日维护的黄金四步：

```text
① 查看现场状态          ② 比对改动细节          ③ 固化安全快照          ④ 查看历史台账
┌───────────────┐     ┌───────────────┐     ┌───────────────┐     ┌───────────────┐
│  git status   │ ──> │   git diff    │ ──> │ git commit -m │ ──> │  git log -n 5 │
└───────────────┘     └───────────────┘     └───────────────┘     └───────────────┘
```

1. **`git status`**：就像 PLC 编程软件界面右下角的黄色“未保存更改”感叹号，告诉你哪些文件被动过了；
2. **`git diff`**：就像“在线比对器”，绿色表示新增代码，红色表示删除代码；
3. **`git add .` + `git commit -m "描述"`**：就像往 PLC 刷入固件，打上一个永不丢失的时间戳与 SHA 哈希指纹；
4. **`git log --oneline -n 5`**：按时间倒序展示最近 5 次提交，清晰明了。

## 🧪 三、5 分钟动手实操实验

### 步骤 1：查看当前工作空间干净状态
```powershell
git status
```
*预期输出*：显示当前分支（如 `main` 或当前 HEAD），列出受控变更，没有意料之外的未受控文件。

### 步骤 2：查看最近 3 次带哈希的提交快照
```powershell
git log --oneline -n 3
```
*预期输出*：每行一个短哈希与清晰的提交摘要，例如 `1.2.4-6699a5b` 相关的治理提交。

## 🛡️ 四、改崩恢复法与今日自测打卡

### 🚑 改崩救命三板斧
1. **只是改了代码但还没提交（想要放弃本次全部修改，恢复出厂）**：
   ```powershell
   git restore .
   ```
2. **不小心把临时文件放进了暂存区（想移出来）**：
   ```powershell
   git restore --staged .
   ```
