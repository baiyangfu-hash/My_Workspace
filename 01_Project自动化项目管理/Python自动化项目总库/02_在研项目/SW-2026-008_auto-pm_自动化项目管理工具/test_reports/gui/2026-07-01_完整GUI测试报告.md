## 二、操作步骤（关键路径）

### 场景 3：新建 PLC 项目
1. 工具栏「新建」→「PLC 项目」
2. QTimer.singleShot 注册回调
3. 填写：项目编号 DJ-2026-099 / 名称 GUI测试临时项目 / 技术栈 plc / 业务线 DJ
4. 点击 OK → QMessageBox 提示成功
5. 实际创建项目目录：`02_在研项目/DJ-2026-099_GUI测试临时项目/`
6. **发现 Bug**：`.copier-answers.yml` 中 `equipment_type/plc_vendor/plc_model` 为 null，导致 ProjectInfo Pydantic 校验失败
7. 测试策略绕过：`_fix_copier_answers()` 补全字段，让后续测试继续

### 场景 5：创建变更单
1. 变更 Tab → 创建变更单按钮
2. QWizard 向导第 1 页：填项目/领域 PLC/性质 DEF/范围 LOCAL/申请人/背景
3. next() → 描述页：填必要性
4. next() → 确认页
5. next() → 触发 validatePage → _on_create
6. 实际创建：CHG-PLC-2026-001，文件保存到 `04_变更管理/01_变更单/CHG-PLC/`

### 场景 6：变更审批流转（7 次）
1. 6.1 草稿→已提交：GUI 对话框（单目标直接弹），填审批人+意见，点 OK
2. 6.2-6.7：多目标流转会弹 QMenu 菜单，自动化复杂，降级用 ChangeService.transition_status() API
3. 完整流转链：草稿→已提交→审核中→已批准→实施中→待验收→验收中→已完成
4. 每次流转后刷新 ChangeTab UI，截图验证状态徽标更新

## 五、Bug 清单

### Bug #1: TD-G01 - 新建项目后 .copier-answers.yml 字段为 null

| 属性 | 值 |
|------|-----|
| **Bug ID** | TD-G01 |
| **严重程度** | 高（major） |
| **影响范围** | 所有通过 GUI 新建项目的场景 |
| **截图** | 03_new_project_form_mobile.png, 03_project_created_mobile.png |
| **根因** | [new_project_dialog.py:317-324](../../auto_pm/ui/dialogs/new_project_dialog.py#L317) `equipment_type/plc_vendor/plc_model` 仅在 `if value` 时写入 data，未填时 copier 模板渲染为 null。但 [ProjectInfo 模型](../../auto_pm/core/project_scanner.py#L229) 要求 str，导致 `read_copier_answers` 校验失败 |
| **复现步骤** | 1. 工具栏新建 PLC 项目<br>2. 填编号+名称，不选设备类型/PLC 供应商/型号<br>3. 提交创建<br>4. 刷新项目列表 → 新项目不显示<br>5. 查看日志：Pydantic ValidationError: equipment_type Input should be a valid string, input_value=None |
| **建议修复** | 方案 A：`new_project_dialog.py` 提交时为空字段填默认空字符串 `data[key] = value or ""`<br>方案 B：`ProjectInfo` 模型将 `equipment_type/plc_vendor/plc_model` 改为 `str = ""` 默认值<br>方案 C：`read_copier_answers` 用 `answers.get(key, "") or ""` 二次保底 |
| **优先级** | P0（影响核心功能：新建项目后无法识别） |

## 六、视觉问题清单

### 程序化几何检查发现（12 个，全部 major）

#### V-01/02/03: 工作区概览 Tab 内容溢出（out_of_bounds）

| 属性 | 值 |
|------|-----|
| **问题类型** | 控件超出父控件边界 |
| **位置** | MainWindow > QSplitter > QStackedWidget > ProjectWorkspaceView > QTabWidget |
| **截图** | 04_workspace_overview_{desktop,tablet,mobile}.png |
| **视口** | desktop: 控件(1098,1245)超出父(1098,676)，溢出569px<br>tablet: 控件(694,1261)超出父(694,676)，溢出585px<br>mobile: 控件(694,1261)超出父(694,608)，溢出653px |
| **严重程度** | 高 |
| **影响范围** | 概览 Tab 底部内容（最近活动等）被裁剪不可见，无滚动条 |
| **根因** | [overview_tab.py](../../auto_pm/ui/workspace/overview_tab.py) 概览页主容器未包裹 QScrollArea，或 setWidgetResizable(True) 未生效，内容强制撑高父 QTabWidget |
| **建议修复** | 概览页主内容容器包裹 `QScrollArea` + `setWidgetResizable(True)`；移动端考虑信息网格单列堆叠 |
| **优先级** | P1 |

#### V-04~V-12: 变量表 Tab Splitter 子控件零宽度（zero_size）

| 属性 | 值 |
|------|-----|
| **问题类型** | 可见控件尺寸为 0 |
| **位置** | MainWindow > QSplitter > QStackedWidget > ProjectWorkspaceView > QTabWidget |
| **截图** | 09_vartable_tab_{desktop,tablet,mobile}.png |
| **视口** | desktop: 0x541, 0x541, 0x24（3个）<br>tablet: 0x541, 0x541, 0x24（3个）<br>mobile: 0x473, 0x473, 0x24（3个） |
| **严重程度** | 高 |
| **影响范围** | 变量表 Tab 整个内容区不可见（宽度为0），用户看到空白 |
| **根因** | [vartable_tab.py](../../auto_pm/ui/vartable/vartable_tab.py) QSplitter 左右子页（文件列表 + 编辑器）宽度为 0，Tab 首次显示时 splitter 未完成布局分配 |
| **建议修复** | ① Tab `showEvent` 中调用 `splitter.adjustSize()`<br>② 为 splitter 子控件设 `setMinimumWidth(200)`<br>③ 确保 splitter 在 Tab 可见时调用 `refresh()` |
| **优先级** | P1 |

### 无法程序化检测的视觉项（需人工复核）

以下维度因程序化检查限制无法覆盖，建议人工目视复核关键截图：
- 文字重叠/溢出/截断（尤其移动端长路径文本、状态徽标）
- 按钮/输入框错位（QWizard 向导页、流转对话框）
- 弹窗是否超出屏幕
- 表格列宽异常
- 图标缺失（emoji 图标在某些字体下可能不渲染）
- 颜色对比度（状态徽标颜色）
- 响应式布局问题（卡片→列表切换、导航树折叠）

## 八、测试结论

### 总体评价

auto-pm V0.5.0 GUI 核心功能完整可用，13 个电气工程师使用场景全部跑通，关键业务流程（新建项目、创建变更单、7 次状态流转、PLC 检查）均实际执行成功。

### 主要风险

1. **P0 Bug TD-G01**：新建项目后项目"消失"（无法被扫描识别），严重影响电气工程师首次使用体验
2. **P1 视觉问题**：概览页内容溢出 + 变量表 Tab 空白，影响工作区核心页面可用性

### 建议下一步

1. 立即修复 TD-G01（P0），恢复新建项目功能
2. 修复概览页滚动 + 变量表 Splitter（P1）
3. 修复后重新运行 `scripts/gui_plc_full_test.py` 回归验证
4. 升级 `tests/gui/` 下业务流程类 pytest 为"实际提交"测试（处理二级 QMessageBox）
5. 人工目视复核关键截图，补充程序化检查无法覆盖的视觉维度
