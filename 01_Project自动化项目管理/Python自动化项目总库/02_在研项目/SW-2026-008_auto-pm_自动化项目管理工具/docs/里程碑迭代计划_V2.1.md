# 里程碑迭代计划 V2.1

> 项目：SW-2026-008 auto-pm 自动化项目管理工具
> 版本：V2.1 计划
> 创建日期：2026-06-22
> 基线：V2.0.1-A/C 已完成（778 测试通过）
> 关联文档：[PM_SESSION_SW-2026-008.md](../PM_SESSION_SW-2026-008.md)、[CHANGELOG.md](../CHANGELOG.md)

## 0. 背景与目标

### 0.1 背景

V2.0.1-A/C 完成后，项目存在三类问题：

1. **文档与代码不一致**：6 项严重不一致（版本号、CLI 参数、UI 组件等）
2. **架构技术债**：2 个上帝类（ProjectService 570 行、ChangeService 890 行）、UI 跨层访问 DB/plc
3. **能力缺口**：8 项 P1 缺口（SubstanceChecker、python 命令、CLI 参数补全等）

### 0.2 目标

通过 4 个里程碑、27 个迭代，实现：

- 文档与代码 100% 一致
- 架构分层清晰，无上帝类，无跨层调用
- INT 声明的接口 100% 实现
- 测试覆盖率 >=85%
- PRD 路线图 V2.1~V2.3 交付

### 0.3 路线图

```
M1 稳基座（文档/版本对齐）     ->  M2 补能力（CLI/Service 缺口）
        |                                |
M3 重架构（拆上帝类+接口抽象）  ->  M4 扩功能（V2.1~V2.3 路线图）
```

### 8.3 技术决策记录

| 决策 | 选项 | 最终选择 | 原因 |
|------|------|----------|------|
| 上帝类拆分模式 | 继承 vs 组合 | 组合模式 + 向后兼容委托方法 | 保持 API 兼容性，渐进式迁移 |
| 接口抽象方式 | ABC vs Protocol | Python Protocol | 结构性子类型，无需显式继承 |
| 路径常量管理 | 分散 vs 统一 | `core/paths.py` + `core/constants.py` | 单一真源，消除硬编码 |
| 验收流程状态机 | 新状态 vs 复用 | 新增 pending_acceptance/accepting | 符合业务需求，门禁清晰 |
| offscreen 模式测试 | isVisible vs isHidden | isHidden() | offscreen 下 isVisible() 始终返回 False |
