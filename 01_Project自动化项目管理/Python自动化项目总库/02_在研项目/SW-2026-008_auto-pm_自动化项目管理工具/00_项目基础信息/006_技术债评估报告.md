### TD-T08: 测试执行耗时过长 🟢 ✅

- **位置**: 全量测试套件
- **现象**: 1163 个测试耗时 388.84 秒（6.4 分钟，--no-cov 模式）
- **根因**: GUI 测试 + 集成测试未并行化；--cov 模式进一步劣化（37 倍差距）
- **影响范围**: 开发反馈循环慢
- **潜在风险**: 开发者倾向跳过测试
- **严重程度**: 🟢 低
- **修复成本**: 🟡 中（需引入 pytest-xdist 并行化）
- **修复方案**: 引入 pytest-xdist，按模块并行执行
- **修复实施**: T87 完成（2026-06-27）—— 实测 pytest-xdist 在当前测试套件规模下**反优化**：
  - 串行 `tests/change/` 158 测试：39.62s
  - 并行 `-n 2`：492.75s（**慢 12 倍**）
  - 根因：Windows worker 进程启动开销 + PySide6 在每个 worker 重复 import + 测试套件规模不足以摊销 worker 启动成本
  - 结论：xdist 不适合当前项目（1163 测试规模太小），保留安装供未来测试规模增长后重新评估
- **替代加速方案**（已落地）：
  1. `pyproject.toml` dev 依赖新增 `pytest-xdist>=3,<4`（保留工具链）
  2. `tests/conftest.py` `pytest_collection_modifyitems` 改用固定 seed `random.Random(20260627)`（确保未来 xdist 收集一致性）
  3. `007_发布门禁规范_REL.md` G3 门禁已明确使用 `pytest --no-cov --timeout=60`（日常开发加速 37 倍）
  4. `Taskfile.yml` 已提供 `task test-fast`（--no-cov）和 `task test`（带 cov）双模式
- **验证**: tests/change/ 串行 158 passed in 39.62s；xdist -n 2 158 passed in 492.75s（反优化证据）；conftest.py 固定 seed 后 xdist 收集一致性修复
- **状态**: ✅ 已偿还（2026-06-27，V0.3.8 T87；xdist 验证不适用，采用 --no-cov 加速方案）

## 12. 长期治理建议（V0.5.0+ 路线图）

> 本章节为 V0.5.0 收口时沉淀的长期技术债预防与治理路线图，作为后续版本（V0.5.x 稳定期 + V0.6.0+ 长期路线）技术债治理的参考基线。所有建议均基于 V0.4.0~V0.5.0 共 32 项技术债的治理经验提炼。

### 12.1 技术债预防机制（防止技术债再产生）

#### 12.1.1 测试代码类型标注规范（防 TD-C10 复发）

- **问题背景**：TD-C10 治理耗时 8-16h，根因是历史测试文件类型标注长期缺失，累积到 381 errors 才统一治理
- **长期策略**：
  1. **新增测试文件类型标注强制**：`tests/` 下所有新增 `.py` 文件必须有函数签名类型标注（`def test_xxx(tmp_path: Path) -> None:`）
  2. **CI 门禁**：`mypy tests/` 纳入发布门禁（007_REL G3 期望 6 skipped 已对齐），任何新增测试文件若引入 mypy error 阻断发布
  3. **关键技术沉淀**（TD-C10 治理时发现的 5 项关键技术，后续可直接复用）：
     - `bool(obj)` 包装打破 mypy 属性 narrowing（替代 `if obj.property:` 直接判断）
     - `str` 变量打破 Literal 收窄（将 Literal 类型赋值给 str 变量后传递）
     - Generator 返回类型显式标注（`Iterator[None]` / `Generator[None, None, None]`）
     - `Callable[[Any], None]` 逆变（fixture 参数类型用 `Callable[[Any], None]` 而非 `Callable[..., None]`）
     - PySide6 枚举完整路径（`Qt.ItemDataRole.UserRole` 而非 `Qt.UserRole`）

#### 12.1.2 docstring 规范化持续维护（防 TD-C08 复发）

- **问题背景**：8 个生产文件 docstring 引用规范编号时缺文件名完整引用
- **长期策略**：
  1. **首次引用完整格式**：首次引用规范编号时使用 `LSP-907 907_项目配置规范_LSP` 完整格式
  2. **后续引用可简写**：同一文件内后续引用可简写为 `LSP-907`
  3. **区分"docstring 引用"与"数据字面量"**：`spec_id` 配置列表（如 `["LSP-905","LSP-907"]`）是数据字面量，不修改
  4. **规范文件名映射**：LSP-903→`903_定时器使用规范_LSP` / LSP-904→`904_SCL注释规范_LSP` / LSP-905→`905_SCL编程规范_LSP` / LSP-906→`906_错误预防规则_LSP` / LSP-907→`907_项目配置规范_LSP`
