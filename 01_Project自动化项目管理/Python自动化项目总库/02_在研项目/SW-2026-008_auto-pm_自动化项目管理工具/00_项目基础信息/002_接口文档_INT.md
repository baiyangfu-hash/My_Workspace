## 3. 接口概述

### 3.1 文档目的

本文档定义 auto-pm V2.0 项目的两类接口：
- **Part A: CLI 命令接口** - 用户通过终端调用的 Click 命令（含技能调用入口）
- **Part B: Service 层 Python API** - 业务逻辑层方法，供 CLI 和 PySide6 UI 调用

> **V2.0 变更**: 移除 Part C（pywebview JS Bridge API），改为 PySide6 直接调用 Service 层 API（见 Part B）。PySide6 UI 通过 Signal/Slot 与 Service 通信，无需 JS Bridge 中间层。

### 3.2 术语定义

| 术语 | 说明 |
|------|------|
| workspace | 工作空间根目录，包含多个项目 |
| project_id | 项目编号，格式如 `SW-2026-008`、`DJ-2026-010` |
| change_number | 变更单编号，格式如 `CHG-PLC-2026-001` |
| stack | 技术栈，值为 `plc` 或 `python` |
| business_line | 业务线，值为 `SW`/`DJ`/`ZD`/`XT`/`WX`（V2.0 新增） |
| role | 用户角色，值为 `pm`/`plc`/`python`/`spec`（V2.0 新增） |
| ApiResponse | 统一返回格式 `{success, data, error, message, timestamp}`（仅 CLI JSON 输出和内部 DTO 使用） |

#### CLI-01: auto-pm project list（V2.0 增强，V2.0.1 核对修正）

**功能**: 列出工作空间内所有项目，支持业务线/技术栈筛选

> **V2.0.1 核对修正**: INT V2.0.0 原声明的 `--phase`/`--search`/`--json` 参数**实际未实现**；输出列也不含"业务线"和"阶段"列。

**语法**:
```bash
auto-pm -w "<ws>" project list [--business-line <SW|DJ|ZD|XT|WX>] [--stack <plc|python|unknown>]
```

**参数**（实际实现）:

| 参数名 | 类型 | 必填 | 默认值 | 描述 |
|--------|------|------|--------|------|
| --business-line, -bl | Choice[SW,DJ,ZD,XT,WX] | 否 | None | 按业务线筛选（CLI 层内存过滤，按 `project_id.split("-")[0]` 匹配） |
| --stack | Choice[plc,python,unknown] | 否 | None | 按技术栈筛选（CLI 层内存过滤） |

> **未实现参数**: INT V2.0.0 原声明的 `--phase`/`--search`/`--json` 在实际 CLI 中不存在。

**输出格式**: Rich 表格，列：项目ID / 名称 / 技术栈 / 版本 / 来源 / 路径

**退出码**:
- 0: 成功（含无项目情况）

#### CLI-02: auto-pm project create（V2.0.1 核对修正，V2.0.2 新增 --mode）

**功能**: 创建新项目（调用 Copier 模板生成骨架）

> **V2.0.1 核对修正**: INT V2.0.0 原声明的 `--business-line` 参数**实际未实现**；项目创建路径为 `<workspace_root>/<project_id>_<project_name>`（非 `02_在研项目/` 子目录）。

> **V2.0.2 新增**: 新增 `--mode` 选项，仅 `--stack=plc` 时有效，用于选择 PLC 项目模式（shared-library/test-suite/standard-project），默认 `standard-project`。模板名通过 `auto_pm.core.constants.get_template_name(stack, mode)` 统一解析。

**语法**:
```bash

```

**参数**（实际实现）:

| 参数名 | 类型 | 必填 | 默认值 | 描述 |
|--------|------|------|--------|------|
| --stack | Choice[plc,python] | 是 | - | 技术栈 |
| --id | String | 是 | - | 项目编号（如 DJ-2026-010） |
| --name | String | 是 | - | 项目名称 |
| --desc | String | 否 | "" | 项目描述 |
| --mode | Choice[shared-library,test-suite,standard-project] | 否 | standard-project | PLC 项目模式（仅 `--stack=plc` 时有效，V2.0.2 新增） |
| --dry-run | Flag | 否 | False | 仅预览，不实际创建 |

> **未实现参数**: INT V2.0.0 原声明的 `--business-line` 在实际 CLI 中不存在。

**退出码**:
- 0: 成功
- 1: 目标路径已存在 / 模板不存在 / 创建失败

#### SVC-21: PlcService（V2.0.2 新增）

**文件**: `auto_pm/plc/service.py`

**职责**: PLC 项目统一服务入口，封装 PlcChecker/PlcRepairer/SubstanceChecker。CLI/UI 层通过本服务操作 PLC 项目，遵循分层架构，不直接访问底层检查器/修复器。

```python
class PlcService:
    def __init__(self, workspace_root: str) -> None: ...
    def check(self, project_path: str, fix: bool = False) -> CheckResult: ...
    def repair(self, project_path: str, dry_run: bool = False, rename_confirm: bool = False) -> RepairResult: ...
    def standardize(self, project_path: str, dry_run: bool = False) -> StandardizeResult: ...
    def check_substance(self, project_path: str) -> CheckResult: ...
    def check_workspace(self) -> list[CheckResult]: ...
```

**方法清单**:

| 方法 | 功能 | 委托对象 |
|------|------|---------|
| `check(project_path, fix=False)` | 检查 PLC 项目规范性；`fix=True` 时检查后自动修复非破坏性问题并重新检查 | PlcChecker + PlcRepairer |
| `repair(project_path, dry_run, rename_confirm)` | 修复 PLC 项目规范问题 | PlcRepairer |
| `standardize(project_path, dry_run)` | 标准化 PLC 项目文档命名 | PlcRepairer |
| `check_substance(project_path)` | 文档实质化检查（V2.0.1-B）：检查 PRD/DSN/INT/TEC 文档字数、章节数、占位符 | SubstanceChecker |
| `check_workspace()` | 检查工作空间内所有 PLC 项目 | PlcChecker |

**调用关系**: CLI 层（`cli/plc/__init__.py`、`cli/project.py::cmd_retrofit`）和 UI 层通过 `PlcService` 操作 PLC 项目，不再直接实例化 `PlcChecker`/`PlcRepairer`/`SubstanceChecker`。

**示例**:
```python
from auto_pm.plc.service import PlcService

svc = PlcService("/workspace")

# 常规检查
result = svc.check("/workspace/DJ-2026-010_边框缓存机")

# 检查并自动修复
result = svc.check("/workspace/DJ-2026-010_边框缓存机", fix=True)

# 文档实质化检查
substance_result = svc.check_substance("/workspace/DJ-2026-010_边框缓存机")

# 修复项目结构
repair_result = svc.repair("/workspace/DJ-2026-010_边框缓存机", dry_run=False)
```

## 7. 接口安全

### CLI 接口安全
- 破坏性操作需显式确认（如 `project delete --confirm`、`plc repair --rename`）
- 路径安全校验（path_resolver 防止目录遍历攻击）
- 项目路径必须在 workspace_root 下
- `project import` 校验 PATH 必须为有效目录

### Service 接口安全
- 所有 Service 方法不暴露内部异常堆栈给 CLI/UI 层
- 破坏性操作（delete/repair --rename）需显式标志
- 路径校验防止目录遍历攻击
- 禁止在代码中硬编码密钥/Token/密码

### PySide6 UI 接口安全（V2.0 新增）
- UI 层直接调用 Service，无 JS Bridge 中间层（消除 pywebview 的 XSS 风险）
- 破坏性操作弹窗二次确认
- 角色切换不影响数据安全（仅控制 Tab 可见性，不控制数据访问权限）

### PySide6 UI 调用 Service 示例（V2.0 新增）

```python
# ui/project_list/list_view.py
from PySide6.QtCore import Slot
from auto_pm.core.project_service import ProjectService

class ProjectListView(QWidget):
    def __init__(self, workspace_root: str) -> None:
        super().__init__()
        self.service = ProjectService(workspace_root)
        self._setup_ui()
        self._load_projects()

    def _load_projects(self) -> None:
        """加载项目列表（优先从缓存）"""
        try:
            projects = self.service.list_projects_cached()
            self.model.set_projects(projects)
        except RuntimeError:
            # 缓存未就绪，回退到文件系统扫描
            projects = self.service.list_projects()
            self.model.set_projects(projects)

    @Slot(dict)
    def on_filter_applied(self, filters: dict) -> None:
        """筛选条件变更时刷新列表（实际使用 list_projects_filtered）"""
        try:
            results = self.service.list_projects_filtered(
                stack=filters.get("stack"),
                business_line=filters.get("business_line"),
                phase=filters.get("phase"),
            )
            self.model.set_projects(results)
        except RuntimeError:
            # 缓存未就绪，回退到全量扫描 + 内存过滤
            projects = self.service.list_projects()
            if filters.get("stack"):
                projects = [p for p in projects if p.stack == filters["stack"]]
            if filters.get("business_line"):
                projects = [p for p in projects if p.business_line == filters["business_line"]]
            self.model.set_projects(projects)
```

## 14. 注意事项

### 使用注意
- `-w` 必须放在子命令之前
- 破坏性操作（delete/repair --rename/import --force）需显式确认
- GUI 依赖 PySide6，未安装时 CLI 其他功能不受影响
- `project import` 路径必须为有效目录，相对路径相对于当前工作目录解析

### 故障处理
- 项目扫描失败: 检查 workspace_root 路径权限
- Copier 模板缺失: 检查 templates/ 目录
- DB 锁定: SQLite WAL 模式支持并发读，写操作串行
- PySide6 启动失败: 检查 PySide6 是否安装、显卡驱动是否兼容
- 项目导入失败: 检查路径有效性、.copier-answers.yml 是否可补全

### 安全注意
- 禁止在代码中硬编码密钥/Token/密码
- 路径校验防止目录遍历攻击
- 删除操作不可恢复，需谨慎
- `project import` 不允许导入工作空间外的项目（路径安全校验）

## 15. 最佳实践

### 参数验证
- CLI 层使用 Click 的 type=click.Choice 做枚举校验
- Service 层使用 Pydantic v2 模型做类型验证
- 规范校验使用 validate_* 函数
- business_line 必须在 SW/DJ/ZD/XT/WX 列表内

### 错误处理
- Service 层抛出具体异常，CLI 层捕获并转换为用户友好消息
- PySide6 UI 层捕获异常并弹窗提示，不崩溃
- 日志记录所有错误（log.error）

### 性能优化
- GUI 优先从 DB 缓存读取，避免频繁扫描文件系统
- 增量扫描使用 file_mtime 判据
- 延迟导入避免启动时加载所有依赖
- `search_projects` 优先走缓存（use_cache=True）

### PySide6 UI 最佳实践（V2.0 新增）
- View 不直接持有其他 View 引用，通过 Signal/Slot 通信
- Service 调用放在 Slot 内，避免阻塞 UI 线程
- 长时间操作（如全量扫描）使用 QThread 避免 UI 卡顿
- 角色-Tab 映射通过 ROLE_TAB_MAP 常量配置，不硬编码在 View 内
