## 1. Executive Summary

### 1.1 Problem Statement

**现状**: 工作空间内存在 5 个功能重叠/互补的工具，UI 技术栈混乱、功能重复、死代码与空壳并存，单一工具无法覆盖多角色工作流：

| 工具 | 编号 | 核心功能 | 实际 UI 技术栈 | 关键问题 |
|------|------|---------|----------------|---------|
| PLC变量表解析工具 | SW-2026-001 | 多格式变量表解析 | tkinter | `src/variable/` 死代码、`src/converter/` 空壳（convert() 直接 return） |
| Python项目管理工具 | SW-2026-004 | 项目模板、变更管理、数据库、CI/CD | PyQt5（非 PRD 声明的 PySide6） | UserStore 硬编码、API 路由无 auth_required、影响分析未持久化 |
| PLC项目管理工具 | SW-2026-005 | PLC项目初始化、LSP-907检查、变更管理、看板 | pywebview + HTML/JS | 扫描深度不一致（depth=1 vs 4）、变更单编辑缺失 |
| 规范管理工具 | SW-2026-006 | 规范健康检查、索引、Frontmatter | GUI 完全未实现（V0.2.0，非 PRD 声明的 V1.1.0） | `--config`/`--quiet` 选项未实现、SHC-002 级别与 PRD 不符 |
| auto-pm | SW-2026-008 | 项目CRUD、变更管理、PLC检查 | pywebview + 单页 HTML/JS | 4 个阻断性 Bug、GUI 仅项目列表+详情+几个弹窗 |

**根因诊断**:

1. **008 自身基础不牢**: 4 个阻断性 Bug 必须先修复（详见 §1.4）
2. **UI 技术栈混乱**: 5 个工具的 GUI 层均不可直接复用（tkinter/PyQt5/pywebview/未实现），无法承载八大模块
3. **功能重复**: 变更管理（004/005/008）、变量表解析（001/004 插件）、规范检查（005 LSP-907/006 通用）、项目管理（004/005/007）四类重复
4. **死代码/空壳**: 001 的 `variable/`、`converter/`，004 的硬编码 UserStore，006 的未实现 CLI 选项
5. **多角色适配不足**: 使用者兼任项目经理/PLC工程师/Python工程师/规范编辑多角色，当前 UI 无角色区分，功能堆叠混乱

### 1.2 Core Strategy

**一个工具: auto-pm 统一工作台全量吸收 5 个源工具**

**四个核心能力**:

| 优先级 | 能力 | 核心价值 | 技术方案 |
|--------|------|----------|----------|
| **P0** | **PySide6 项目中心式 UI** | 原生桌面、多角色适配、复杂表格/树形/拖拽 | PySide6 QMainWindow + StackedWidget + 项目工作区 Tab |
| **P0** | **项目CRUD + 总库管理** | 对齐004：导入/分类/搜索/多业务线 SW/DJ/ZD/XT/WX | Click CLI + ProjectService + SQLite 缓存 |
| **P0** | **Bug 修复前置** | 4 个阻断性 Bug 必须先修复 | 修正路径假设、扫描路径、枚举对齐、模板推断 |
| **P1** | **多版本渐进式交付** | V2.0~V2.5 六个版本独立交付验证 | 文档先行、增量开发、Bug 优先 |

**设计理念**: 工具承载标准化逻辑（Copier 模板+结构检查+变更管理+规范中心+变量表），AI 技能只做决策判断；以 PySide6 原生桌面 + 项目中心式 UI 重构，多版本渐进式交付，文档先行。

### 3.2 UI 技术栈决策（pywebview → PySide6）

#### 决策依据

经源码核查，5 个源工具的 GUI 层均不可直接复用，统一以 PySide6 原生桌面重写：

| 工具 | PRD 声明 | 实际源码 | 复用决策 |
|------|----------|----------|----------|
| SW-2026-001 | （未明确） | **tkinter** | 弃用 tkinter，逻辑层复用，UI 重写为 PySide6 |
| SW-2026-004 | PySide6 | **PyQt5**（实际源码） | 弃用 PyQt5，逻辑层复用，UI 重写为 PySide6 |
| SW-2026-005 | （未明确） | **pywebview + HTML** | 弃用 pywebview，UI 重写为 PySide6 |
| SW-2026-006 | V0.3.0 规划 GUI | **GUI 完全未实现**（当前 V0.2.0） | 从零构建 PySide6 GUI |
| SW-2026-008 | pywebview | **pywebview + 单页 HTML/JS** | 弃用，重写为 PySide6 |

#### 选择 PySide6 的理由

1. **原生桌面体验**: 复杂表格（QTableView）、树形（QTreeView）、多窗口（QDialog）、拖拽（Drag&Drop）支持完善
2. **LGPL 授权**: 商业友好，比 PyQt5 的 GPL/商业双授权更宽松
3. **Qt 生态成熟**: 文档丰富、社区活跃、工具链完善（Qt Designer）
4. **承载八大模块**: pywebview + HTML/JS 无法承载总库/模板/监控/变更/插件/规范/报告/设置八大模块的复杂交互
5. **多角色适配**: 通过 QMainWindow + StackedWidget + Tab 容器实现角色-Tab 映射

#### 弃用 5 个源工具 GUI 层

- SW-2026-001 tkinter GUI 层 → 弃用，V2.3 重写为 PySide6 变量表 Tab
- SW-2026-004 PyQt5 GUI 层 → 弃用，V2.0~V2.4 重写为 PySide6 各模块
- SW-2026-005 pywebview GUI 层 → 弃用，V2.0 重写为 PySide6 项目工作区
- SW-2026-006 GUI 完全未实现 → V2.2 从零构建 PySide6 规范中心页
- SW-2026-008 pywebview GUI 层 → 弃用，V2.0 重写为 PySide6 主框架

### 3.6 数据真源策略

三源并存，各有职责（V2.0 不变）：

| 真源 | 职责 | 写入方 | 读取方 |
|------|------|--------|--------|
| `.copier-answers.yml` | 项目元数据真源（project_id/name/stack/version/description/phase/business_line） | Copier（创建时）、auto-pm edit（更新时） | auto-pm project list/show、技能 |
| `PM_SESSION_*.md` | 项目管理真源（定位/焦点/状态/日志/交付物） | pm-workflow 技能、auto-pm init | pm-workflow/plc-electrical-engineer/fullstack-engineer 技能 |
| `.auto-pm/index.db` | 索引缓存（加速查询，可随时重建） | auto-pm sync | auto-pm GUI、auto-pm project list --cached |

**同步规则**:
1. 文件系统为权威源，DB 为缓存
2. `auto-pm sync` 从文件系统重建 DB
3. `auto-pm project edit` 同时写入 `.copier-answers.yml` 和 DB
4. `auto-pm project create` 通过 Copier 写入 `.copier-answers.yml` + PM_SESSION，然后 sync 到 DB
5. `auto-pm project import` 由 CLI 层直接处理导入逻辑（复制/移动 + retrofit 补全），扫描项目元数据写入 `.copier-answers.yml`，然后 sync 到 DB（无需独立 Service 方法）
