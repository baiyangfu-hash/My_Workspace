## 4. 变更原因

**变更背景**：
CHG-104 文档同步过程发现 `change transition/show/edit` 跨项目单号过滤缺陷（TD-A04）。`ChangeFileLocator.find_change_file(change_number)` 递归遍历工作空间返回第一个匹配文件（`file_locator.py:297 if result: return result`），不按 project_id 过滤。当不同项目有相同变更单号时（如 DJ-2026-005 和 SW-2026-008 都有 CHG-DOCU-2026-001），会返回错误项目的文件，导致状态流转/查看/编辑操作作用到错误项目上。

影响传播链 11 处调用点（诊断脚本 `scripts/diag_change_cross_project_bug.py` 4 用例验证根因）：
- 核心层：`file_locator.py` `find_change_file` L199 + `_recursive_find_change_file` L246
- Service 层：`change_service.py` 4 方法（`get_change_request` L336 / `transition_status` L433 / `update_change_request` L688 / `delete_change_request` L749）
- Facade 层：`change_facade.py` 3 方法（`get_change_detail` L84 / `transition_change` L115+L123 / `get_change_validation_summary` L168）
- CLI 层：`change.py` 3 命令（`cmd_show` L360 / `cmd_transition` L487 / `cmd_edit` L577）
- Command 层：`change_commands.py` `TransitionChangeCommand`（无 project_id 字段）

**变更必要性**：
1. 跨项目单号冲突会导致变更状态流转作用到错误项目，影响变更管理可信度；2. 当前仅靠删除冲突文件规避（已删除 DJ-2026-005 的 CHG-DOCU-2026-001.md），非根本修复；3. 后续 CHG-106 工作台 KPI 会创建新变更单，若与其他项目单号冲突会无法 dogfooding 闭环

**参考依据**：
- TD-A04 技术债登记：`00_项目基础信息/006_技术债评估报告.md` §4 架构债 TD-A04
- 诊断脚本：`scripts/diag_change_cross_project_bug.py`（4 用例验证根因）
- PM_SESSION §9 done_when：CHG-105 前置条件 CHG-104 闭环已满足

## 12. 附录

### 12.1 填写指南

#### 如何选择技术领域?
- 主要改哪个专业的交付物,就选哪个领域
- 如果同时涉及多个专业,选**最主要**的那个作为主领域,其他在§6.2中标注

#### 如何判断影响范围?
- **LOCAL**: 改一个变量/一行代码/一个接线端子
- **MODULE**: 改一个FB/一条输送线/一台设备
- **SYSTEM**: 改全局变量/联锁逻辑/通讯接口
- **CROSS**: 改了电气,PLC和HMI都要跟着改
- **SAFE**: 动了急停回路/安全继电器/SIL相关
