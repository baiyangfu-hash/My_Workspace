## 6. 变更影响分析

### 6.1 项目约束影响（PMBOK五大约束）

| 约束维度 | 影响程度 | 影响描述 | 应对措施 |
|---------|:--------:|----------|----------|
| **范围(Scope)** | ☑低 | 纯增量新增 GUI 入口，不改后端报告生成逻辑 | 复用后端 ReportService，仅在其上叠加 Facade/Bridge/QML 三层 |
| **进度(Schedule)** | ☑无 | 当日完成，无延期 | - |
| **成本(Cost)** | ☑无 | 纯代码变更，无外部成本 | - |
| **质量(Quality)** | ☑低 | 新增 7 个单元测试覆盖 Facade/Bridge 全部路径 | ruff 0 错误 + mypy 0 错误 + 31 个修改测试通过 + 315 个回归通过 |
| **风险(Risk)** | ☑低 | `ReportService.generate()` 会写入磁盘生成报告文件，覆盖现有报告；但用户可通过格式选择控制范围 | 对话框有"⚠️ 此操作将覆盖现有报告文件"提示；生成成功后展示输出路径+文件大小+内容预览 |

**风险等级**（PMBOK风险评估）：☑低

**缓解措施**（风险应对策略）：
1. 格式选择 ComboBox 默认"Markdown"，用户可选 JSON 格式
2. 对话框有醒目的覆盖警告提示
3. Facade/Bridge 全部路径有单元测试覆盖（成功/格式透传/无服务/异常/文件大小 5 个场景 × 2 层 = 7 个测试 + 2 个降级断言）
4. 复用后端已稳定 ReportService，避免重复实现
5. 工厂函数 `make_spec_report_service` 处理 FileNotFoundError，无注册表时返回 None，Facade 降级返回 "No report_service"
6. 字段命名用 `spec_report_service` 避免与 DeliveryFacade 的 `report_service` 冲突

### 12.1 填写指南

#### 如何选择技术领域?
- 主要改哪个专业的交付物,就选哪个领域
- 如果同时涉及多个专业,选**最主要**的那个作为主领域,其他在§6.2中标注

#### 如何判断影响范围?
- **LOCAL**: 改一个变量/一行代码/一个接线端子
- **MODULE**: 改一个FB/一条输送线/一台设备
- **SYSTEM**: 改全局变量/联锁逻辑/通讯接口
- **CROSS**: 改了电气,PLC和HMI都要跟着改
- **SAFE**: 动了急停回路/安全继电器/SIL相关
