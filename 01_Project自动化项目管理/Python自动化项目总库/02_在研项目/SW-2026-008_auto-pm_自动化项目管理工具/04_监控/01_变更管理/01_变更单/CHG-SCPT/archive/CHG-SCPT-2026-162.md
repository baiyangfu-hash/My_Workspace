# 变更单：CHG-SCPT-2026-162

## 1. 变更动因与背景 (Background & Motivation)

在 2026-08-22 针对 `auto-pm` 桌面驾驶舱（SW-2026-008）展开的基于 **ISO/IEC 25010** 与 **IEC 62443** 工业标准的严苛审计中，通过 100% 真实数据实测，揭示出三大核心缺陷与安全隐患：

1. **P0 生产级运行时 Bug**：
   - `auto_pm/ui/qml/bridges/system_bridge.py` 缺少 `from pathlib import Path`（`F821`），导致 QML 调用文档同步与门禁自检时触发 `NameError` 隐形崩溃；
   - `auto_pm/application/workbench_facade.py:815` 访问不存在的 `self.workspace_root`，导致 5 大过程组阶段门禁评估异常；
   - `auto_pm/application/core/prototype_service.py:357` 降级路径中 `html_code` 变量未定义，导致 HMI 原型模板初始化在特定条件下 `NameError`。
2. **P1 核心工控通信与 PLC 门禁测试安全网薄弱**：
   - `pyproject.toml` 的 `--cov` 路径配置偏差导致覆盖率测量失真；
   - `domain.modbus`（Modbus TCP 核心通信）单元测试覆盖率为 0%；
   - `domain.plc.checker`（LSP-905 定时器三段式、CASE ELSE 等硬门禁）覆盖率仅 15.2%；
   - 168 处异常捕获中 74.4% 静默吞噬异常，违反 IEC 62443 可审计性标准。
3. **P2 静态代码质量与类型安全债**：
   - Ruff 存在 105 处违规（63 处可自动化修复）；
   - mypy 存在未闭环类型报错（DTO 缺少字段构造、参数类型不匹配等）。

---

## 2. 变更实施方案 (Implementation Plan)

### 阶段一：P0 生产级 Bug 根治（已完成）
1. 修复 `system_bridge.py` 顶层 `Path` 导入，消灭 F821 NameError；
2. 修复 `workbench_facade.py:815` 指向 `self._project_service.workspace_root`；
3. 修复 `prototype_service.py:357` 补齐降级分支的 `html_code` 模板定义。

### 阶段二：P1 覆盖率基线与核心测试网补齐（已完成）
1. 修正 `pyproject.toml` 中 `[tool.pytest.ini_options]` 的 `--cov=auto_pm` 路径与 `source = ["auto_pm"]`；
2. 新建 `tests/modbus/test_modbus_service_unit.py`（13 项用例），覆盖 CDAB/ABCD 浮点解码、FC01~FC06 数据帧解析；
3. 新建 `tests/plc/test_checker_lsp905_rules.py`（7 项用例），覆盖 CASE ELSE 防死锁、TON 定时器三段式、T# 字面量检测；
4. 规范化 Bridge 层异常日志上报，引入 `logger.warning(..., exc_info=True)`。

### 阶段三：P2 代码质量收敛与版本发布（已完成）
1. 执行 `ruff check auto_pm --fix` 自动消除 68 处 lint 告警；
2. 修复 mypy 报告的 `AssetSummaryViewDTO` 与 `spec.py` 类型问题，实现 mypy 0 错误；
3. 升级项目版本至 `V1.2.1`，更新 `CHANGELOG.md` 与 `PM_SESSION_SW-2026-008.md`。
