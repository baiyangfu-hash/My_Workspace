# 变更单：CHG-SCPT-2026-161

## 1. 变更动因与背景

在 DJ-2026-009 长边框自动码垛机的接管与逆向过程中，暴露了三大系统级架构缺陷：
1. **模板业务污染严重**：`templates/plc-standard-project` 与 `templates/industrial_hmi` 中硬编码了 DJ-005 的“打胶机送料/机器人交互”，导致所有新生成的 PLC 项目与 HMI 原型出现荒唐的死业务残留；
2. **缺乏工业级逆向摄取流水线**：面对 3,000+ 异构变量表（AutoShop CSV/XML），过去由大模型在 Prompt 里逐行拼凑，导致上下文瞬间被海量表格淹没（Lost in the Middle），甚至出现假模块刷门禁的形式主义；
3. **PM 技能与 PLC 技能分工混乱**：PM 技能大包大揽代写 SCL 代码，导致 PLC 工程师技能机制性放空，缺乏清晰的交接卡点。

---

## 2. 变更方案与核心实施

### 2.1 驾驶舱后端逆向引擎正式化 (PlcIngestService)
- 新增 `auto_pm/application/plc/ingest_service.py`，原生提供 Python 毫秒级 ETL 逆向流水线；
- 批量抽取 3,000+ 工业变量，自动分类为 Alarm（800+）、Servo（500+）、IO（90+），并生成标准 Markdown/CSV 资产（`io_points.csv`, `communications.yml`, `VAR.md`, `015_IO.md`, `016_PLC.md`, `018_FLOW.md`）；
- CLI 挂载顶级命令：`auto-pm plc ingest --src <源路径> --pid <ID>`。

### 2.2 HMI 原型拓扑自适应标准落地 (STD-909 §3.3)
- 在 `PrototypeService.init` 与 CLI 中新增 `--topology [infeed|outfeed|both]` 选项；
- 自动根据设备在产线中的拓扑位置裁剪 HTML 与 JS 导航（首端单机=outfeed，末端单机=infeed，中间单机=both），彻底杜绝假交互画面。

### 2.3 模板底盘彻底净化与去污
- 彻底清理 `templates/plc-standard-project` 与 `auto_pm/templates/industrial_hmi` 中的所有写死业务，重塑为高通用性纯净底座。

### 2.4 PM ── PLC 双技能协同契约标准化
- 重构 `.trae/skills/pm-workflow/SKILL.md`（极轻量需求与拓扑判定门面，强制通过 Handoff 派发工单）；
- 重构 `.trae/skills/plc-electrical-engineer/SKILL.md`（确立为异构摄取、SCL 算法建模与电气文档编制的核心主力）。
