### [M7-001] `retrofit` 未递归查找嵌套 .plc.json，导致 stack/name 识别错误

- **发现场景**：Phase 1 · 接管执行
- **分类**：FUN（功能缺陷）
- **严重度**：P1 🟠
- **复现步骤**：
  1. 执行 `auto-pm project import <PLC项目路径> --business-line DJ`
  2. 项目 `.plc.json` 位于 `02_PLC程序/PLC_ST/.plc.json`（非项目根目录）
  3. 查看生成的 `.copier-answers.yml` 和 `project show` 输出
- **预期行为**：`stack: plc`、名称和描述从 `.plc.json` 读取
- **实际行为**：`stack: python`（unknown fallback）、名称为目录名
- **根因**：`retrofit_project_by_path` 调用 `_read_plc_json`（仅查根目录），未调用具备递归能力的 `_find_plc_json_recursive`
- **处理状态**：✅ Fixed
- **修复说明**：在 `project_service.py` 的 `retrofit_project_by_path` 方法中，当根目录 `_read_plc_json` 返回 `None` 时，追加调用 `self._scanner._find_plc_json_recursive(project_path)` 递归查找，修复后正确识别 `stack=plc`、`version=V7.1.1`、`description=边框缓存机 PLC 控制系统`
- **关联 CHG**：待开（Full Track）

### [M7-002] SysLib 库路径在 copy 模式导入后失效

- **发现场景**：S4 · PLC 规范全量检查（`auto-pm plc check DJ-2026-005`）
- **分类**：COMPAT（兼容问题）
- **严重度**：P2 🟡
- **复现步骤**：
  1. 执行 `auto-pm project import <路径> --business-line DJ`（默认 copy 模式）
  2. 执行 `auto-pm plc check DJ-2026-005`
  3. 查看 `.plc.json` libraries 检查项
- **预期行为**：WARN 或 PASS，并有清晰的修复建议
- **实际行为**：WARN `库路径不存在: C:\...\01_SharedLibraries\SysLib`（相对路径 `../../../01_SharedLibraries/SysLib` 在 copy 后目录层级变化导致失效）
- **根因**：copy 模式改变了项目的目录层级，但 `.plc.json` 内的相对 library 路径未做适配
- **处理状态**：Open
- **建议方案**：import 时检测 libraries 相对路径，若目标位置不可达，在输出中给出路径重映射建议；或在 `plc check` WARN 中增加具体修复指引

### [M7-003] 存量 PLC 项目 PRD 目录结构与 LSP-907 标准不兼容

- **发现场景**：S4 · PLC 规范全量检查（`auto-pm plc check DJ-2026-005`）
- **分类**：COMPAT（兼容问题）
- **严重度**：P2 🟡
- **复现步骤**：
  1. 执行 `auto-pm plc check DJ-2026-005`
  2. 查看 PRD 目录检查项
- **预期行为**：识别并接受现有目录结构（或提供迁移路径）
- **实际行为**：多项 WARN，显示项目使用历史路径（`00_项目管理/`、`01_需求与设计/`、`02_PLC程序/PLC_ST/PRD/`），与 LSP-907 规定的根 `PRD/` 目录不一致
- **背景说明**：DJ-2026-005 是典型的存量历史项目，文档目录是按照老规范（或项目发展过程中自然形成）的结构，不是 auto-pm 模板生成的。这是工具与真实存量项目之间结构性兼容差距的第一次真实呈现。
- **处理状态**：Open
- **建议方案**：在 `plc check` 中区分"新建项目缺失"（ERROR）和"存量项目历史路径"（INFO/WARN），降低噪音；并提供可选的 `--migrate` 迁移命令

### [M7-004] SHC-014 门禁与存量 PM_SESSION §4 格式不兼容，阻断 CHG 状态机闭环

- **发现场景**：S8 · 状态推进全流程（`accepting → completed`）
- **分类**：COMPAT（兼容问题）
- **严重度**：P2 🟡
- **复现步骤**：
  1. 在 DJ-2026-005 创建 CHG 单并推进至 `accepting`
  2. 执行 `auto-pm change transition CHG-PLC-2026-001 --to completed`
- **预期行为**：验证结论写入后流转成功
- **实际行为**：`SHC-014` 门禁拦截，报错 `PM_SESSION §4 缺少必需文档索引: int, req, tec`
- **根因**：存量 PM_SESSION 使用自然语言结构（`- req-analysis:`、`- req-spec:` 等语义丰富的别名），SHC-014 的 `_DOC_ENTRY_RE` 正则要求精确匹配 `req`、`int`、`dsn`、`tec` 四个关键词（`^- (req|int|dsn|tec)\s*:`），格式不兼容。
- **处理状态**：✅ Fixed（方案 C：import / retrofit 阶段自动生成 SHC-014 兼容索引）
- **修复说明**：在 `project_service.py` 中实现了 `_scan_doc_index_candidates` 与 `_append_shc014_index_to_pm_session`。存量 PLC 项目导入/补全时自动按 `_REQ` / `_INT` / `_TEC` / `_DSN` 命名规则识别文档并追加标准索引条目，完美通过 SHC-014 门禁。
- **关联 CHG**：CHG-SCPT-2026-148 (closed)
