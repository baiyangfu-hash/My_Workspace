# UI 架构原型说明

## 1. 原型用途

`Html原型预览/archive/012_UI架构原型_V7.html` 不是运行时前端，而是这次架构重设计的讨论载体。

它的作用是：

1. 用页面语言讲清楚架构
2. 让电气工程师能从界面层面理解新的模块边界
3. 为后续 QML 页面调整和潜在 Web 试点提供视觉真源

## 2. 原型表达了什么

## 2.1 左侧导航

左侧导航按工作域组织：

- 驾驶舱
- 项目工作台
- 变更中心
- 规范中心
- 报告与发布
- 系统设置

这样做的原因是：用户的工作动作是按业务域发生的，不是按技术模块发生的。

## 2.2 中间主体区

主体区分 4 类信息：

1. 架构结论
2. 驾驶舱 KPI
3. 核心页面结构
4. 接口层和数据流

它故意没有做很多视觉细节，因为当前目标不是 UI 美化，而是把结构说明白。

## 3. 和 PLC/HMI 的类比

原型中的数据流示意，实际上对应以下关系：

| 软件层 | PLC 类比 |
|------|---------|
| QML / HTML 页面 | HMI 画面 |
| Bridge / Facade | 变量接口层 / 命令接口层 |
| Service | PLC 程序逻辑 |
| DB / 文件系统 | 工程数据与历史记录 |

这也是本次重设计最重要的认知转化：

> UI 不直接“懂”业务内部，它只通过约定好的接口驱动系统。

## 4. 页面状态说明

后续所有页面建议统一覆盖以下状态：

1. `loading`
2. `success`
3. `empty`
4. `warning`
5. `error`

其中：

- `warning` 对工业工具很重要，因为很多场景不是“失败”，而是“可继续但需关注”
- `empty` 不能简单当错误处理，否则新项目初始体验会很差

## 5. 原型与实现的关系

本原型只定义三件事：

1. 页面信息结构
2. 模块边界
3. 数据流方向

它不定义：

1. 最终 QML 代码长什么样
2. 是否立即改成 Web
3. 视觉风格细节

## 6. 后续如何使用这个原型

### 阶段 1

用于确认：

- 工作域是否合理
- 信息密度是否合适
- 架构分层是否容易理解

### 阶段 2

用于指导：

- QML 页面重新接线
- Bridge/Fascade 命名
- DTO 设计口径

### 阶段 3

如果未来做 Web 试点，可作为：

- 首版页面骨架参考
- 信息架构参考
- DTO 对齐参考

## 7. 结论

这个原型最重要的价值不是“像网页”，而是：

> **用你容易理解的界面语言，把架构分层和接口思想固定下来。**
