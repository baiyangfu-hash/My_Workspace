# 里程碑与实施计划

## 1. 计划定位

本计划面向“架构收口 + 运行时解耦 + 真实试用验证”，周期按 **30 周** 设计。

30 周不是为了把时间拉长，而是为了给这个项目留出三类必要空间：

1. 架构整理时间
2. 稳定性回归时间
3. 真实试用和反馈吸收时间

## 2. 总体原则

1. **先接口，后界面替换**
2. **先试用证据，后重大技术切换**
3. **能复用就不重写**
4. **里程碑必须有可验证输出物**

## 3.2 HTML 原型 V7 落地四阶段（2026-07-09 起）

> 本章节为 V3.1.0 新增（CHG-SCPT-2026-104 T2），记录 HTML 原型 V7 交互界面的四阶段落地规划与实施进度。本规划独立于 M0-M9 里程碑主线，作为 V1.0.0 发布前的视觉系统升级专项。

### 规划背景

V0.9.0 完成 QWidget → QML 迁移后，QML 成为唯一 UI 入口。但现有 QML 页面仍沿用旧视觉风格，与 HTML 原型 V7（`02_设计/Html原型预览/archive/012_UI架构原型_V7.html`）的设计语言不一致。为在 V1.0.0 发布前完成视觉系统升级，规划四阶段 CHG 专项迭代，每阶段独立 dogfooding 闭环。全部四阶段已于 2026-07-09 完成。

### 四阶段规划

| 阶段 | 变更单 | 范围 | 状态 | 闭环证据 |
|------|--------|------|------|----------|
| 第 1 阶段 | CHG-SCPT-2026-102 | 视觉系统升级（Theme.qml 暗色玻璃设计）+ 导航框架重构（main.qml 三轨导航） | ✅ 已闭环 closed（2026-07-09） | 第 33 次 dogfooding 闭环，三轨门禁全绿 |

### 关键决策

1. **CHG-104 文档同步插入**：CHG-2 闭环后核查发现 006/005 文档基线严重滞后（006 停留在 V0.6.0，005 缺失 HTML 原型 V7 规划），用户决策"单独走 CHG-DOC"先对齐文档基线，再继续 CHG-3
2. **TD-A04 登记而非立即修复**：CHG-104 文档同步过程发现 `change transition/show/edit` 跨项目单号过滤缺陷，用户决策"先登记为技术债，继续之前的变更"，留 CHG-105 专门迭代修复。理由：① CHG-104 范围是文档同步，混入代码修复违反原子性；② TD-A04 修复涉及 11 处调用点 + 测试，需独立 dogfooding 闭环
3. **CHG-105 优先于 CHG-3**：TD-A04 修复优先于第 3 阶段，避免跨项目单号冲突阻碍 CHG-3 的 dogfooding 流程（CHG-3 会创建新变更单，若与其他项目单号冲突会无法流转状态）
4. **版本号策略**：V0.9.3 是视觉系统版本号（CHG-102/103），CHG-107 已升级 pyproject.toml 至 V1.0.0（2026-07-09 发布）

### 验证策略

- 每阶段独立 dogfooding 闭环（CHG-*.md 走完整 9 步状态流转 draft→closed）
- 三轨门禁：ruff 0 errors + mypy 0 errors + tests/qml 全通过 + PM_SESSION size 合规
- 保留约束验证：每阶段保留关键 token 名称/函数签名/属性不变，确保 qml 测试零破坏
