# auto-pm GUI 使用说明书（电气工程师视角）

> **版本**: V1.0（2026-07-01）
> **适用对象**: PLC/电气工程师，使用 auto-pm 管理 PLC 自动化项目
> **基于**: GUI 原型设计 V2.1 + V0.5.0 实际实现
> **用途**: 作为 GUI 自动化测试的场景基线，同时供电气工程师作为操作手册

---

## 一、概述

auto-pm 是面向 PLC 自动化项目的管理工具，集项目立项、变更管理、规范检查、文档管理、变量表管理于一体。本说明书以电气工程师的日常使用场景为主线，描述完整操作流程。

**设计原则**（摘自 GUI 原型设计 §一）：无角色区分，使用者一人兼顾项目经理/PLC 开发，所有功能全部可见，无需角色切换。

## 二、电气工程师日常使用流程（13 个场景）

### 场景 1：启动应用

**操作**：双击 auto-pm 桌面图标或运行 `python -m auto_pm`

**预期界面**：
- 顶部菜单栏：视图 | 工具 | 帮助
- 左侧侧边栏（220px）：PLC 总库 / Python 总库 / 全部项目 / 变更中心 / 规范中心 / 报告中心 / 系统设置
- 顶部工具栏：搜索框 | 业务线筛选 | 新建下拉 | 导入 | 同步 | 刷新
- 中央内容区：项目分组视图（默认按"总库+业务线"分组）
- 底部状态栏：项目数 | 变更数 | DB 状态 | 工作空间路径 | 扫描时间

**验证点**：
- 窗口标题显示 "auto-pm"
- 侧边栏树形结构完整
- 状态栏显示正确的工作空间路径
- 项目列表有数据（非空状态）

### 场景 2：查找项目

**操作步骤**：
1. 侧边栏点击「PLC 总库」→ 展示 PLC 总库下所有项目
2. 侧边栏点击「在研项目」子节点 → 筛选 developing 阶段项目
3. 工具栏搜索框输入 "DJ-2026" → 实时筛选
4. 工具栏业务线下拉切换 → "单机设备 (DJ)" / "软件开发 (SW)" / "全部业务线"
5. 视图控制区切换"卡片视图"/"列表视图"
6. 分组模式下拉切换：总库+业务线 / 总库+阶段 / 业务线 / 阶段

**预期界面**：
- 卡片视图：每个项目显示编号、名称、技术栈徽标、阶段、版本、变更数
- 列表视图：表格显示编号/业务线/名称/技术栈/阶段/版本/变更数/修改时间
- 搜索实时生效，清空搜索框恢复全量
- 业务线筛选立即生效
- 分组标题显示项目计数

**验证点**：
- 搜索框输入立即筛选
- 业务线切换立即生效
- 卡片/列表视图切换无数据丢失
- 分组模式切换正确重排
- 空结果有友好提示

### 场景 3：新建 PLC 项目

**操作步骤**：
1. 工具栏点击「新建」下拉 → 选择「PLC 项目」
2. 弹出「新建项目」对话框
3. 填写表单：
   - 项目编号：`DJ-2026-099`（格式：DJ-YYYY-XXX）
   - 项目名称：`测试输送线项目`
   - 技术栈：自动锁定为 PLC（不可改）
   - 业务线：单机设备 (DJ)
   - 模式：标准机型
   - 勾选/取消"Dry Run 预览"
4. 点击「确定」

**预期界面**：
- 对话框模态显示，遮罩主窗口
- 编号输入实时校验（非法格式红色提示）
- 确定后弹出 QMessageBox 提示"项目创建成功"
- 主窗口项目列表自动刷新，新项目出现在列表中
- 新项目目录在工作空间 `0100_PLC自动化/DJ-2026-099_测试输送线项目/` 创建

**验证点**：
- 编号格式校验生效
- 重复编号提示"已存在"
- 创建成功后列表刷新
- 项目目录实际创建（含 .plc.json、PM_SESSION_*.md、基础目录结构）

### 场景 5：创建变更单

**操作步骤**：
1. 点击「变更」Tab
2. 点击「+ 创建变更单」按钮
3. 弹出「创建变更单」对话框（QWizard 向导）
4. 填写表单：

   - 领域：PLC（下拉选择）
   - 性质：DEF 缺陷 / ENH 增强 / NEW 新增（下拉选择）

   - 变更背景：`修复输送线启停逻辑缺陷`
5. 点击「下一步」→ 确认页
6. 点击「完成」

**预期界面**：
- 变更 Tab 空状态时显示"暂无变更单，点击创建"
- 对话框为向导式（多页）
- 表单字段完整
- 提交后 QMessageBox 提示"变更单创建成功"
- 变更列表出现新卡片（状态：草稿）

**验证点**：
- 空状态提示正确
- 向导页切换正常
- 表单校验生效（必填项）
- 创建成功后列表刷新
- 变更单编号格式：CHG-{项目ID}-{序号}

### 场景 6：变更审批流转

**操作步骤**：
1. 在变更 Tab 找到状态为"草稿"的变更单卡片
2. 点击卡片上的「流转」按钮
3. 弹出「状态流转」对话框
4. 填写：
   - 审批人：`auto_test`
   - 流转意见：`提交审核`
5. 点击「确定」
6. 重复步骤 2-5，依次流转：草稿 → 已提交 → 审核中 → 已批准 → 实施中 → 待验收 → 验收中 → 已完成

**预期界面**：
- 每次流转后卡片状态徽标更新
- 流转对话框显示当前状态 → 目标状态
- 已完成状态需要填写验收记录
- 流转历史可在卡片展开查看

**验证点**：
- 状态流转顺序正确（不能跳级）
- 每次流转后状态徽标更新
- 流转意见记录到变更单
- 已完成状态需验收记录

## 四、自动化测试要点

### 4.1 模态对话框处理

所有 `dialog.exec()` 调用会阻塞主线程，自动化测试必须使用 `QTimer.singleShot` 模式：

```python
def _fill_and_submit():
    dlg = find_dialog(app, "新建项目")
    dlg._id_edit.setText("DJ-2026-099")
    dlg._button_box.button(QDialogButtonBox.Ok).click()
    # 预注册二级 QMessageBox 处理
    QTimer.singleShot(200, lambda: dismiss_message_boxes(app))

QTimer.singleShot(100, _fill_and_submit)
window._on_new_project("plc")  # exec() 阻塞，回调在事件循环中执行
```

### 4.2 三视口测试

每个关键页面在三种视口下截图：
- 桌面：1920×1080
- 平板：768×1024
- 手机：375×812

### 4.3 视觉检查项

- 文字重叠/溢出/截断
- 按钮/输入框错位
- 弹窗超出屏幕
- 表格列宽异常
- 图标缺失
- 颜色对比度过低（WCAG AA < 4.5:1）
- 响应式布局异常
- 滚动区域不合理
- 点击后状态无变化
