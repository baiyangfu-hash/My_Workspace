## 四、测试方法说明

- **真实 widget 操作**：所有测试通过 MainWindow 实例化真实组件链路（MainWindow → ReportPage / TemplatePage / SettingsPage / SpecCenterView），点击/输入通过 `_on_item_clicked()`、`click()` 等真实操作触发，未使用 mock 替换组件行为。
- **数据注入**：通过 `_create_sample_projects()` 辅助函数在临时工作空间创建 5 个真实项目目录（含 `.copier-answers.yml`，覆盖多技术栈/阶段/业务线），通过 `ProjectService.sync_to_cache(force_full=True)` 全量扫描同步到 DB 缓存；通过 `_inject_sample_changes()` 向 DB 注入 2 条变更记录。
- **真实服务调用**：ReportPage 内部使用真实的 `ReportService`（非 mock），通过 `get_project_overview()` / `get_change_overview()` 真实查询 DB 聚合统计；SettingsPage 的"清除缓存"/"重建索引"按钮真实操作 SQLite DB 文件。
- **离屏渲染**：`QT_QPA_PLATFORM=offscreen` 模式运行，无需真实显示设备。
- **QStackedWidget 页面切换验证**：通过 `main_window._nav_tree._on_item_clicked(_function_nodes[xxx], 0)` 真实触发导航树点击信号，验证 `main_window._stack.currentIndex()` 切换到对应索引（4/5/6/7）。
- **完整流程验证**：`test_full_flow_settings_rebuild` 真实执行"清除缓存 → 重建索引 → 数据恢复"全链路，验证清除后 DB 归零、重建后项目数恢复为 5。
- **QMessageBox 模态对话框处理**：完整流程测试中通过 monkey-patch `QMessageBox.question` / `QMessageBox.information` / `QMessageBox.warning` 静态方法（保存原始方法并在 finally 中恢复），避免模态对话框在 offscreen 模式下阻塞。
- **Windows 文件锁定处理**：清除缓存前调用 `gc.collect()` 强制垃圾回收，关闭未显式关闭的 SQLite 连接，避免 Windows 文件锁定（WinError 32）导致 DB 文件无法删除。

## 五、发现的问题

本次测试未发现新问题。所有交互测试均通过，ReportPage / TemplatePage / SettingsPage / SpecCenterView 功能符合预期。

### 5.1 已知行为说明（非 bug）

- **QMessageBox 静态方法阻塞**：`QMessageBox.question` / `QMessageBox.information` / `QMessageBox.warning` 是模态对话框静态方法，在 offscreen 模式下会阻塞测试执行。完整流程测试中通过 monkey-patch 替换为非阻塞版本（返回 `Yes` 或 `None`），并在 finally 中恢复原始方法。这是测试环境适配，不影响生产代码行为。
- **SQLite 连接未显式关闭**：`DatabaseManager.get_connection()` 每次创建新连接，`with` 语句只提交事务不关闭连接，在 Windows 上可能导致 DB 文件被锁定无法删除。测试中通过 `gc.collect()` 强制垃圾回收关闭未显式关闭的连接。这是 `DatabaseManager` 的已知设计行为，建议后续迭代优化为显式关闭连接（使用 `contextlib.closing` 或在 `get_connection` 中返回可关闭的上下文管理器）。
- **重建索引仅恢复项目数**：`test_full_flow_settings_rebuild` 验证重建索引后项目数恢复为 5，但未验证变更记录是否恢复（变更记录是通过 `_inject_sample_changes()` 直接注入 DB 的，重建索引只扫描项目目录不会恢复变更记录）。这是设计行为，重建索引只恢复项目数据，不恢复变更记录。
