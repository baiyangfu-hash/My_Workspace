## 四、测试方法说明

- **真实 widget 操作**：所有测试通过 MainWindow 实例化真实组件链路（MainWindow → WorkspaceView → CheckTab / DocTab），点击/输入通过 `click()`、`setText()` 等真实操作触发，未使用 mock 替换组件行为。
- **数据注入**：通过 `_create_mixed_project()` / `_create_doc_project()` / `_create_standardize_project()` / `_create_empty_project()` 辅助函数在临时工作空间创建真实项目目录（含 `.plc.json`、`PM_SESSION_*.md`、`PRD/` 文档、`.copier-answers.yml` 等），通过 `main_window._workspace_view.load_project(proj)` 加载到工作区。
- **真实检查器/修复器**：CheckTab 内部使用真实的 `PlcChecker` 和 `PlcRepairer`（非 mock），执行检查/修复时真实读写文件系统。
- **离屏渲染**：`QT_QPA_PLATFORM=offscreen` 模式运行，无需真实显示设备。
- **双击打开验证**：`test_doc_tab_double_click` 通过 `_on_document_double_clicked()` 触发打开，使用 `patch` 拦截 `QDesktopServices.openUrl` 系统调用（非 widget 行为 mock），验证传入路径正确。
- **完整流程验证**：`test_full_flow_check_repair` 真实执行"检查 → 修复 → 重新检查"全链路，验证修复后 fail 项归零、pass 项增加、warn 项保留（rename_confirm=False）。

## 五、发现的问题

本次测试未发现新问题。所有交互测试均通过，CheckTab 和 DocTab 功能符合预期。

### 5.1 已知行为说明（非 bug）

- **warn 项修复需确认**：`PlcRepairer.repair_project(rename_confirm=False)` 不会修复 warn 项（命名不匹配），需用户确认重命名。这是设计行为，`test_full_flow_check_repair` 中验证了 warn 项在修复后仍保留（1 warn）。
- **自动修复为预览模式**：CheckTab 的"自动修复"按钮执行 `dry_run=True` 预览，不实际修改文件系统。实际修复通过点击单项"修复"按钮触发（`dry_run=False`）。
