## 3. 新发现缺陷清单

### 3.1 严重缺陷（P0）

#### Bug-6：`project edit --phase` 写入非法枚举值导致项目列表崩溃

- **严重度**：P0（阻断性）
- **复现命令**：`auto-pm -w <ws> project edit <ID> --phase "调试中"`
- **现象**：
  1. `project edit --phase "调试中"` 写入中文值"调试中"到 `.copier-answers.yml`
  2. 后续所有读取命令（`project list`/`project show`/`plc check`/`plc repair`/`plc standardize`）崩溃
  3. 报错：`pydantic_core._pydantic_core.ValidationError: 1 validation error for Project / phase / Input should be 'developing', 'commissioning', 'production', 'archived' or ''`
- **根因**：
  1. CLI `project edit` 命令不校验 `--phase` 值是否为合法枚举值
  2. `_read_copier_answers` 读取到非法 phase 值时直接抛出 ValidationError，无异常处理
- **影响**：单个项目写入非法 phase 值后，整个工作空间扫描失败，所有 CLI 命令不可用
- **修复建议**：
  1. CLI `project edit` 命令应校验 `--phase` 值，仅接受 `developing/commissioning/production/archived/` 或支持中文映射
  2. `_read_copier_answers` 应捕获 ValidationError，返回 None 或使用默认值，避免单个项目崩溃影响整体
- **测试计划用例**：CLI-PROJ-021（`project edit <ID> --phase 调试中`）— 测试计划假设 phase 接受中文，实际实现是英文枚举

### 3.2 中等缺陷（P1）

#### Bug-7：`_read_copier_answers` 缺少异常处理

- **严重度**：P1
- **现象**：读取到任何非法元数据（如 phase 非法、JSON 损坏等）时，整个 `list_projects` 崩溃
- **根因**：`_read_copier_answers` 中 `ProjectInfo(...)` 构造未用 try-except 包裹
- **影响**：单个项目的非法元数据会导致整个工作空间扫描失败
- **修复建议**：捕获 ValidationError，记录警告，返回 None 跳过该项目

### 3.3 轻微缺陷（P2）

#### UI-002 部分修复：工作空间默认值

- **严重度**：P2
- **现象**：`MainWindow.__init__` 中 `workspace_root or os.getcwd()` 使用当前目录作为默认值
- **影响**：从项目目录启动 GUI 时，工作空间指向项目自身，扫描结果异常
- **修复建议**：默认值应指向工作空间根目录（如 `c:\Users\fubai\Desktop\My_Workspace`），或启动时提示用户选择

#### UI-004 部分修复：状态栏扫描时间 + 工作空间路径

- **严重度**：P2
- **现象**：
  1. 状态栏扫描时间只显示"—"，同步后未更新为实际时间
  2. 状态栏未显示当前工作空间路径
- **修复建议**：
  1. `_on_sync` 完成后更新 `_status_scan` 为相对时间（如"3 秒前"）
  2. 状态栏增加工作空间路径标签
