## 二、P0 严重问题（3 项，阻断使用）

### N1 [P0] `--version` 命令崩溃

**涉及文件：** `auto_pm/__main__.py`、`auto_pm/cli/__init__.py`

**问题：** `python -m auto_pm --version` 抛出 `RuntimeError: 'auto_pm' is not installed. Try passing 'package_name' instead.`

**根因：** `click.version_option()` 在 `python -m` 非安装模式下无法解析 package_name。

**修复方案：**
- 方案 A（推荐）：在 `__main__.py` 中显式传入 `package_name="auto_pm"`
- 方案 B：在 `cli/__init__.py` 中将 `@click.version_option()` 改为 `@click.version_option(version="1.0.0", package_name="auto_pm")`

**验证：** `python -m auto_pm --version` 输出 `auto-pm, version 1.0.0`

---

### N2 [P0] 全局中文乱码（GBK 编码问题）

**涉及文件：** `auto_pm/cli/__init__.py`（CLI 入口）、`auto_pm/utils/`（rich 输出工具）

**问题：** 所有 CLI 命令在 Windows PowerShell 中输出中文乱码，rich 表格/文本中的中文全部不可读。

**根因：** rich 库输出使用 UTF-8，但 Windows PowerShell 默认 GBK 编码。

**修复方案：**
- 方案 A（推荐）：在 CLI 入口处 `sys.stdout.reconfigure(encoding='utf-8')`（Python 3.7+）
- 方案 B：按项目已有的 `_supports_unicode_output()` 模式，不支持 unicode 时用 ASCII 替代
- 注意：方案 A 只需一行代码，且不影响非 Windows 平台

**验证：** 在 Windows PowerShell 中运行 `python -m auto_pm -w ... project list`，中文正常显示

---

### N3 [P0] `python check` 所有检查项状态为 "?"

**涉及文件：** `auto_pm/cli/python/__init__.py`、`auto_pm/core/python_service.py`

**问题：** `python check SW-2026-008` 输出 13 个检查项，状态全部为 "?"（未填充），没有任何 PASS/WARN/FAIL。

**根因：** Python 规范检查服务未正确返回检查结果，或 CLI 渲染层未正确映射状态。需进一步诊断。

**修复方案：**
1. 先用诊断脚本确认 `PythonService.check_project()` 返回的 CheckResult 对象状态是否正确
2. 若 Service 层正确，检查 CLI 渲染层状态映射
3. 若 Service 层不正确，修复检查逻辑

**验证：** `python -m auto_pm -w ... python check SW-2026-008` 输出有 PASS/WARN/FAIL 状态
