### 3.2 问题分级

#### 🔴 严重问题（阻断使用）

**P0-1: `--version` 命令崩溃**
- 命令: `python -m auto_pm --version`
- 错误: `RuntimeError: 'auto_pm' is not installed. Try passing 'package_name' instead.`
- 根因: `click.version_option()` 在非安装模式下无法解析 package_name
- 影响: 用户无法获取版本信息，CI/CD 版本检查失效
- 修复: 在 `__main__.py` 中显式传入 `package_name="auto_pm"` 或改用手动版本输出

**P0-2: 全局中文乱码（GBK 编码问题）**
- 影响范围: 所有 CLI 命令输出（project/change/plc/spec/ledger/template/python）
- 表现: 所有中文在 PowerShell 中显示为乱码（如"项目列表"→"Ŀб"）
- 根因: rich 库输出使用 UTF-8，但 Windows PowerShell 默认 GBK 编码
- 影响: 中文用户无法正常阅读 CLI 输出，**工具对中国用户不可用**
- 修复: 在 CLI 入口处设置 `sys.stdout.reconfigure(encoding='utf-8')` 或使用 `_supports_unicode_output()` 判断 + ASCII fallback

**P0-3: `python check` 所有检查项状态为 "?"**
- 命令: `python -m auto_pm -w ... python check SW-2026-008`
- 表现: 13 个检查项状态全部显示为 "?"（未填充），没有任何 PASS/WARN/FAIL
- 根因: Python 规范检查服务未正确返回检查结果，或 CLI 渲染层未正确映射状态
- 影响: Python 项目规范检查功能完全不可用

#### 🟡 中等问题（影响体验）

**P1-1: SW-2026-008 项目重复警告污染输出**
- 每次 CLI 命令都输出 "项目重复（按 project_id=SW-2026-008）: 保留 copier@... 跳过 copier@..."
- 根因: 工作空间存在两个 `SW-2026-008_auto-pm_自动化项目管理工具` 目录（`01_Project自动化项目管理/...` 和 `02_在研项目/...`）
- 影响: 非致命但严重污染输出，干扰用户阅读

**P1-2: `pm-session check` 无法找到 PM_SESSION 文件**
- 命令: `python -m auto_pm -w ... pm-session check`
- 错误: "在 C:\Users\fubai\Desktop\My_Workspace 未找到 PM_SESSION_*.md 文件"
- 根因: pm-session check 在 workspace root 查找，但 PM_SESSION 文件在项目子目录中
- 影响: PM_SESSION 检查功能不可用

**P1-3: `spec check` 422 个 WARN 噪音**
- 大量 WARN 来自 archive 文件（`PM_SESSION_SW-2026-008_archive_V0.6.0.md`）中引用的过时文件路径
- 包括 `auto_pm/ui/main_window.py`、`auto_pm/ui/styles.py` 等已删除文件
- 影响: 真正需要关注的规范问题被淹没在噪音中

**P1-4: `change show` 只接受单参数 CHANGE_NUMBER**
- 与 `change list PROJECT_ID` 接口不一致
- `change show` 无法区分不同项目的同名变更单号
- 影响: 跨项目场景下变更单查询可能串台

**P1-5: `doc refresh` 对 Python 项目不适用**
- 输出 "仅 PLC 项目支持 doc refresh"
- 影响: Python 项目无法使用文档刷新功能，但 CLI 接受 SW-2026-008（Python 项目）为参数

#### 🟢 轻微问题

**P2-1: `change list` 和 `plc check` 的 PROJECT_ID 是位置参数而非 `--pid`**
- `change list` 使用 `PROJECT_ID` 位置参数，`change show/transition/edit` 使用 `--pid` 选项
- 接口风格不一致但已确认：`change show/transition/edit` 的 `--pid` 在 CHG-SCPT-2026-105 中已修复，`change list` 保持位置参数是合理的（列表/筛选模式下项目ID是主要操作对象）
- 影响: 无阻断，但用户需记忆两种风格

**P2-2: `vartable detect` 命令不存在**
- 实际子命令是 `detect-format`，审查报告原文误写为 `detect`
- 影响: 审查报告自身文档错误，代码和 CLI 正确
