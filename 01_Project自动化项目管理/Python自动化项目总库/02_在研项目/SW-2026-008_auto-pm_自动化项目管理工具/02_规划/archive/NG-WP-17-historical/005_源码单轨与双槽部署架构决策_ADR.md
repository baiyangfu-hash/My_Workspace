# ADR-SW008-001：源码单轨、稳定运行双槽

> 状态：**APPROVED ARCHITECTURE BASELINE / IMPLEMENTATION NOT AUTHORIZED**
> 项目：SW-2026-008
> 治理项目：SYS-2026-001_WorkspaceGovernance
> 日期：2026-09-04
> 决策权：User；Codex 独立审查；执行团队无批准、提交、发布或切流权
> 核心原则：**源码单轨、运行双槽、文档归母体、状态归工作空间**

## 1. 批准的目标架构

User 已批准本 ADR 所述的目标架构。本次批准仅用于固化架构决策、差异回收方案、发布/回退 WBS 和验收标准，**不授权** WBS-3 或后续实施，不授权文件移动、覆盖、删除、入口切换、Git 提交、Tag、部署或回退。

WBS-2 Bootstrap R0 的批准不向 WBS-3 或 CHG-177 继承。后续每个 WBS 必须使用新决策编号、精确文件白名单和 User 明文批准；不得覆写或扩大 `DEC-20260904-3362BFFF` 的语义。

`SW-2026-008_auto-pm_自动化项目管理工具` 是 auto-pm 的唯一研发母体。它拥有 `auto_pm/`、`tests/`、`templates/`、`pyproject.toml`、`CHANGELOG` 以及 PM_SESSION、CHG、设计、测试、验收和发布记录。

`00_Infrastructure/auto_pm` 只是本机稳定部署容器，不是日常研发源目录。只有经正式 deploy 流程批准的制品可以写入其中；研发、修复、测试和设计变更必须先发生在母体。

`My_Workspace/.auto-pm` 是运行状态区，保存数据库、handoff、decision、报告、缓存和运行日志；它既不是研发源码，也不是稳定部署程序，不得将运行状态回写到源码目录。

`00_Obsidian_Base全局规范文件仓库` 保持为规范真源，驾驶舱和母体只读；`.trae/skills` 保持为技能路由与执行 SOP 真源；跨项目架构治理在 `SYS-2026-001_WorkspaceGovernance` 落账。

旧文档中“基础设施位为源码真源、母体冻结或可作为运行回退来源”的描述已经被否决，仅保留为历史成因，不得作为任何实施依据。

## 2. 不可违反的隔离规则

- 禁止 Junction、软链接、硬链接、双向同步和复制后反向写回。
- 禁止 editable install、`.pth` 或其他方式将母体挂接到稳定运行环境。
- 禁止根入口或 Launcher 静默回退到母体。
- 候选版本不得自审、自批、自发；执行团队不得替 User 签发批准或发布证据。
- 稳定容器的任何写入必须经过已批准的 deploy 流程；失败候选仅可标记 `rejected` 或 `quarantined`，不得自动删除。

## 3. 稳定容器契约

容器根为 `00_Infrastructure/auto_pm/`，其受控结构为：

```text
00_Infrastructure/auto_pm/
  launcher/
  releases/<release-id>/
  active_release.json
  previous_release.json
  deployment_manifest.json
  .lock
```

每个指针 JSON 只记录经过验证的 `release_id`。读取端必须验证：release id 合法、解析路径位于 `releases/` 内、目标目录存在且具备完整 manifest。指针文件损坏、路径越界、目标缺失或 manifest 不匹配均视为无效。

Launcher 只可加载 active 指针指向的稳定槽。active 无效时，可以在记录明确告警的前提下加载 previous 指向的已批准稳定槽；不得加载研发母体。active 与 previous 均无效时必须 Fail-Closed 并返回非零退出码。

写入端必须在同卷同目录创建临时指针文件，刷盘后通过 `os.replace` 原子替换，并持有 `.lock` 排他锁。性能数值仅在实测后才能成为 SLO；本 ADR 不宣称任何毫秒级指标已经实现。

## 4. 三重门禁与发布时序

1. 锁定候选 Commit SHA；候选不得包含未跟踪或未提交内容。
2. 由母体构建候选制品与不可变 SHA-256 manifest。
3. Gate 1：母体工作树洁净、测试、Ruff、Mypy 和发布前检查全部通过。
4. Gate 2：在非活动槽以隔离进程验证候选制品；宿主发现 editable 或 `.pth` 污染时立即停止。
5. 生成发布申请和完整证据包，物理停机。
6. User 在控制台作出明文批准。
7. 仅在该批准之后，才允许对锁定 Commit 签发正式 Tag、部署非活动槽、原子更新 active/previous 指针并完成切流验证。
8. 切流后由 Codex 独立复核证据，User 最终验收；保留 active 和 previous，其他候选不自动清理。

手动 rollback 同样属于生产变更：必须有 User 明文授权、验证稳定运行解释器、获取排他锁并记录审计证据。它不得通过母体回退实现。

## 6. Dogfood 与发布隔离

- 稳定驾驶舱管理 SW-2026-008 候选版本。
- 候选版本不得审批自己、部署自己或签发自己的通过结论。
- 候选开发使用独立 Git worktree 或明确隔离目录。
- 只有稳定驾驶舱可消费最终执行回执并触发部署；User 是最终发布批准人。

## 7. 当前适用性

本 ADR 的目标架构已批准，但当前物理状态尚未合规：`00_Infrastructure/auto_pm` 仍是当前 import 来源，工作空间 `.venv` 仍含 `_editable_impl_auto_pm.pth`，根入口与双槽结构尚未转换，并存在 26 个未独立验证的 staged 候选。

因此当前工程门禁仍为 **NO-GO**。差异回收、环境解耦、启动器改造、部署、切流和清理均需要后续独立批准。
