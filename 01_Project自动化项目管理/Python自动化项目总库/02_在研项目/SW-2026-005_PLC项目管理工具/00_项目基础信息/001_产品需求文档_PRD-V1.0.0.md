## 2. 产品概览

### 2.1 产品简介

**SW-2026-005 PLC项目管理工具** 是一款面向IEC 61131-3标准的PLC自动化项目集成化管理桌面应用。本产品旨在解决PLC开发过程中的项目管理分散、代码规范检查困难、文档生成繁琐、诊断分析不足等痛点，提供一站式项目管理解决方案。

**核心价值主张**:
- 🎯 **全生命周期管理**: 从项目创建到交付的完整流程覆盖
- 🔍 **智能规范检查**: 六维自动化代码质量检测
- 📄 **标准化文档生成**: 10种模板一键生成工程文档
- 📊 **深度诊断分析**: 七维度项目健康度评估
- 🔄 **变更管理Sync**: 版本一致性检查、CHG/IFC文档自动生成

### 2.2 产品目标

#### 业务目标
- 提升PLC项目开发效率 **30%+**
- 降低代码规范问题率 **50%+**
- 缩短文档编写时间 **60%+**
- 实现项目管理标准化、规范化

#### 技术目标
- 构建高内聚低耦合的分层架构
- 实现可扩展的插件化检查器体系
- 支持多品牌PLC（Siemens/Beckhoff/Omron/Mitsubishi/Codesys）
- 提供响应速度 < 3秒的用户体验

#### 用户目标
- **项目经理**: 快速创建标准化项目结构，实时监控项目健康度
- **PLC工程师**: 高效编辑ST代码，自动检查命名/语法规范，一键生成变更文档
- **文档工程师**: 一键生成标准文档模板(含CHG变更记录/IFC接口文档)
- **质量工程师**: 执行规范检查和诊断分析，输出项目健康度报告

### 2.3 术语定义

| 术语 | 定义 |
|------|------|
| **PLC (Programmable Logic Controller)** | 可编程逻辑控制器，工业自动化核心设备 |
| **IEC 61131-3** | 国际电工委员会制定的PLC编程语言标准 |
| **SCL (Structured Control Language)** | 结构化控制文本语言，类似Pascal的高级PLC语言 |
| **FB (Function Block)** | 功能块，IEC 61131-3中的可复用程序组织单元 |
| **FC (Function)** | 函数，IEC 61131-3中的无状态程序单元 |
| **POU (Program Organization Unit)** | 程序组织单元，包含Program/FB/FC |
| **GVL (Global Variable List)** | 全局变量列表 |
| **HMI (Human Machine Interface)** | 人机界面，用于监控和操作PLC系统 |
| **LSP (Language Server Protocol)** | 语言服务器协议，提供代码智能提示 |
| **SCLTest** | 基于SCL语言的单元测试框架 |

### 3.2 核心流程设计

#### 流程1: 新建项目向导

```
用户点击[新建项目]
    ↓
NewProjectDialog.show()
    ├── Step 1: 选择业务线 (包装/物流/组装/其他)
    ├── Step 2: 填写项目信息 (名称/负责人/描述)
    ├── Step 3: 选择技术选型 (PLC品牌/HMI品牌)
    ├── Step 4: 选择项目规模 (M001完整版 / S001精简版)
    └── Step 5: 确认存储路径
        ↓
ProjectService.create_new_project(project_info)
    ├── 验证必填字段
    ├── 构建项目根目录 {parent}/{id}_{name}
    ├── 加载并应用模板JSON
    ├── 创建12个标准目录 + .gitkeep
    ├── 生成8个占位文件 (README/PRD/VAR_LIST等)
    ├── 写入 .plc_project.json 元数据
    └── 缓存Project对象 → 返回成功
        ↓
EventBus.project_created.emit(path)
    → Dashboard刷新统计
    → ProjectTree刷新节点
    → StatusBar显示成功消息
```

#### 流程2: 规范检查执行

```
用户在SpecCheckPanel选择检查规则 → 点击[开始检查]
    ↓
SpecCheckerService.run_checks(project_path, selected_rule_ids)
    ↓
RuleRegistry.get_checkers(rule_ids)  # 获取检查器实例列表
    ↓
并发扫描 (max_workers=4):
    for each checker:
        ├── FileScanner.scan()  # glob("**/*.st", "**/*.TcPOU")
        │   └── 排除: _test/example/.bak/.tmp
        └── for each file:
            ├── 读取文件内容 (限制1MB)
            └── checker.check(context)
                └── return List[CheckResult]
                    ├── rule_id: "NAMING_001"
                    ├── file: "Main.st"
                    ├── line: 42
                    ├── message: "变量名不符合匈牙利命名法"
                    ├── severity: Severity.MEDIUM
                    └── suggestion: "建议改为 'motor_Start_Cmd'"
    ↓
聚合结果 → CheckReport
    ├── summary: {total: 150, passed: 120, failed: 20, warning: 10}
    └── details: List[CheckResult]
        ↓
UI更新:
    ├── 结果列表展示 (✅通过 / ❌失败 / ⚠️警告)
    ├── 统计图表 (通过率环形图)
    └── 导出报告 (HTML/JSON)
```

#### 流程3: 七维度诊断分析

```
用户在DiagnosticPanel点击[开始诊断]
    ↓
DiagnosticService.run_diagnosis(project_path)
    ↓
按权重顺序执行三阶段诊断:

Phase 1: 规范检查 (基础分40%)
    ├── 调用 SpecCheckerService.run_checks()
    └── 计算合规得分 (0-100)

Phase 2: LSP兼容性诊断 (专项15%)
    ├── LSPCompatibilityChecker.scan_plc_output_dir()
    ├── detect_stub_misuse()  # 检测builtin stub误用
    ├── analyze_call_chain()  # 分析OB→FB调用链完整性
    └── check_missing_impl()  # 检查缺失的FB/FC实现

Phase 3: 健康度分析 (综合45%)
    ├── structure_score: 目录/文件齐全性 (15%)
    ├── naming_score: 命名规范符合率 (15%)
    ├── doc_coverage: 必需文档存在情况 (15%)
    ├── code_quality: 语法/注释综合评分 (20%, 权重最高)
    ├── config_compliance: .plc_project.json正确性 (10%)
    ├── test_coverage: 测试用例匹配度 (10%)
    └── library_status: 库引用状态 (15%)

    ↓
加权计算 overall_score = Σ(dimension_score × weight)
    ↓
生成 DiagnosticReport
    ├── overall_score: 85.5
    ├── dimension_scores: {structure: 90, naming: 80, ...}
    ├── issues: List[DiagnosticIssue]
    │   ├── dimension: "naming"
    │   ├── severity: Severity.HIGH
    │   ├── rule_id: "NAMING_001"
    │   ├── message: "30%变量名不规范"
    │   └── suggestion: "批量重命名为匈牙利命名法"
    └── suggestions: List[str]  # 改进建议 (score<80时生成)
        ↓
UI展示:
    ├── 总分仪表盘 (0-100刻度)
    ├── 雷达图 (七维度可视化)
    ├── 问题列表 (按严重程度排序)
    └── [一键修复] 按钮 (针对可自动修复的问题)
```

## 4. 非功能需求

### 4.1 性能需求

| 指标 | 要求 | 测试方法 |
|------|------|----------|
| 应用启动时间 | ≤ 3秒 (冷启动) | 计时从main.py到MainWindow.show() |
| 项目扫描速度 | ≤ 5秒 (1000文件内) | 使用timeit测量FileScanner耗时 |
| 检查响应时间 | 单文件 ≤ 100ms | 对每个checker进行性能基准测试 |
| 内存占用 | 运行时 ≤ 200MB | 使用memory_profiler监控 |
| UI帧率 | ≥ 30fps (动画流畅) | PyQt5性能分析工具 |

### 4.2 安全需求

- **本地存储安全**: settings.json 敏感信息（最近项目路径）不包含密码
- **文件读写权限**: 仅访问用户指定的项目目录，不越权读取
- **输入校验**: 所有用户输入经过validators.py白名单过滤
- **异常处理**: 全局try-catch机制，避免崩溃导致数据丢失

### 4.3 兼容性需求

| 环境 | 最低要求 | 推荐配置 |
|------|----------|----------|
| 操作系统 | Windows 10 (1809+) | Windows 11 |
| Python版本 | 3.9+ | 3.11+ |
| 屏幕分辨率 | 1280×720 | 1920×1080或更高 |
| 字体支持 | Consolas (等宽字体) | 安装Source Code Pro |

### 4.4 可扩展性需求

- **检查器扩展**: 新增Checker只需继承BaseChecker并注册到RuleRegistry（零修改现有代码）
- **文档模板扩展**: 在`src/templates/documents/`添加.md文件并在config.py注册即可
- **项目模板扩展**: 在`src/templates/project_structures/`添加.json文件
- **品牌支持扩展**: 在config.py的PLC_CONFIG.supported_brands添加新品牌枚举

## 5. 数据需求

### 5.1 核心数据模型

#### Project (项目实体)
```python
@dataclass
class Project:
    name: str                           # 项目名称
    code: str                           # 项目编号 (如 "DJ-2026-005")
    path: str                           # 项目根目录(绝对路径)

    description: str                     # 项目描述
    plc_brand: Optional[PLCBrand]        # PLC品牌
    hmi_brand: Optional[HMIBrand]        # HMI品牌
    created_at: datetime                 # 创建时间
    updated_at: datetime                 # 最后更新时间
```

#### Document (文档实例)
```python
@dataclass
class Document:
    doc_type: str                        # 文档类型 (REQ/DES/IFC/UM/...)
    doc_number: str                      # 文档编号 (如 "REQ-DJ-2026-005-V1.0.0")
    version: str                          # 版本号
    author: str                           # 作者
    content: str                          # 文档内容(Markdown格式)
    path: str                             # 文件保存路径
    created_at: datetime                   # 创建时间
```

#### DiagnosticReport (诊断报告)
```python
@dataclass
class DiagnosticReport:
    overall_score: float                 # 总分 (0-100)
    dimension_scores: Dict[str, float]   # 各维度得分
    issues: List[DiagnosticIssue]         # 问题列表
    project_path: str                    # 被诊断项目路径
    checked_at: datetime                  # 诊断时间
```

### 5.2 数据存储方案

| 数据类型 | 存储位置 | 格式 | 说明 |

### 5.3 数据安全措施

- **自动备份**: 关闭项目前自动保存settings.json
- **版本兼容**: 配置文件格式变更时提供迁移脚本
- **损坏恢复**: settings.json损坏时使用默认配置启动
- **敏感信息**: 不存储密码/token等敏感数据
