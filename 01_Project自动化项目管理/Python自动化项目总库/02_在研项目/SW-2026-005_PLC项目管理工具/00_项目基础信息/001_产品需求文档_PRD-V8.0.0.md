# 产品需求文档（PRD）- V8.0.0 需求重置版

## 1. Executive Summary

### 1.1 Problem Statement

**现状**: 项目历经V1→V9共9轮迭代，代码膨胀至100+文件，核心功能不可靠，用户反馈"功能都没有了，总览的数据都是假的"。

**根因诊断**:

1. **数据来源错误**: 总览数据来自文件系统扫描(.plc_project.json)，而非项目文档——用户更新了文档，总览不会变
2. **功能膨胀**: 从2个核心需求膨胀到12个模块，大部分从未真正可用
3. **架构腐化**: APIGateway每次请求新建Service实例、IPC链路断裂、Mock/真实模式切换崩溃

### 1.2 V8.0.0 核心策略

**一个原则: 数据来自文档，文档更新则总览自动更新**

**只做2个功能**:

| 优先级 | 功能 | 核心价值 | 数据来源 |
|--------|------|----------|----------|
| **P0** | **项目总览** | 一眼看到所有PLC项目的业务描述、技术环境、核心功能、开发状态 | 项目立项表 `*_PROJ-*.md` |
| **P0** | **变更管理** | 创建/查看/流转变更单，遵循PM-042正式流程 | `04_变更管理/` 文件夹 |

### 1.3 Success Criteria

| 维度 | 指标 | 目标值 |
|------|------|--------|
| **数据真实性** | 总览数据100%来自项目文档，0个硬编码/假数据 | 100% |
| **数据时效性** | 文档修改后，刷新总览即可看到最新数据 | ≤1次刷新 |
| **功能性** | 变更单创建→审批→执行→关闭全流程可用 | 100%路径覆盖 |
| **易用性** | 新用户5分钟内完成第一个变更单创建 | ≤5分钟 |
| **规范性** | 变更单数据结构100%符合CHG-040模板 | 100%字段覆盖率 |

#### US-04: 变更单列表与状态流转（P0）

**作为** PLC工程师/项目经理，**我希望** 能查看所有变更单并跟踪其从创建到归档的完整生命周期。

**数据来源**: `00_项目管理/04_变更管理/01_变更单/` 目录下所有 `CHG-*.md` 文件

**变更单状态流转**:

```
draft → submitted → under_review → approved → implementing → completed → closed
                ↘ rejected        ↘ rejected
                                                      → archived
```

| 状态 | 中文名 | 说明 |
|------|--------|------|
| draft | 草稿 | 刚创建，尚未提交 |
| submitted | 已提交 | 提交审批 |
| under_review | 审批中 | 正在审批 |
| approved | 已批准 | 审批通过，可执行 |
| rejected | 已拒绝 | 审批不通过，可修改后重新提交 |
| implementing | 实施中 | 正在执行变更 |
| completed | 已完成 | 变更执行完毕 |
| closed | 已关闭 | 变更关闭 |
| archived | 已归档 | 归档保存 |

**Acceptance Criteria**:

| 编号 | 验收标准 | 优先级 |
|------|----------|--------|
| AC-04.1 | 变更单列表显示当前项目所有变更单 | Must |
| AC-04.2 | 列表支持按状态/领域/性质筛选 | Should |
| AC-04.3 | 点击变更单可查看完整内容 | Must |
| AC-04.4 | 支持状态流转操作（提交/审批/执行/关闭） | Must |
| AC-04.5 | 状态流转时更新变更单文件中的状态字段 | Must |
| AC-04.6 | rejected状态可修改后重新提交 | Should |

4. 缓存解析结果，检测文件mtime变化时自动刷新

## 4. Technical Specifications

### 4.1 目标架构

```
前端层 (PyWebView HTML/JS)
    │
    ├── 工作空间总览页: 项目卡片网格 + 统计栏
    ├── 项目详情页: 六块信息卡 + 变更台账
    ├── 变更管理页: 变更单列表 + 创建向导 + 状态流转
    │
    ↓ IPC (pywebview.api)
    │
WebViewBridge层
    │
    ↓
Service层 (2个核心Service)
    ├── ProjectOverviewService: 解析立项表，提取项目信息
    ├── ChangeManagementService: 变更单CRUD + 状态流转 + 台帐更新
    │
    ↓
文件系统 (Markdown文档)
```

### 4.2 核心Service定义

#### ProjectOverviewService

| 方法 | 输入 | 输出 | 说明 |
|------|------|------|------|
| get_workspace_projects | workspace_path | list[ProjectInfo] | 扫描工作空间下所有项目，解析立项表 |
| get_project_detail | project_path | ProjectDetail | 解析单个项目立项表完整内容 |
| get_project_changes | project_path | list[ChangeSummary] | 扫描变更管理文件夹，返回变更单摘要 |

#### ChangeManagementService

| 方法 | 输入 | 输出 | 说明 |
|------|------|------|------|
| create_change_request | project_path, fields | ChangeRequest | 创建变更单，保存MD文件 |
| list_change_requests | project_path, filters | list[ChangeSummary] | 列出变更单，支持筛选 |
| get_change_request | change_file_path | ChangeRequest | 读取变更单完整内容 |
| transition_status | change_file_path, new_status | ChangeRequest | 状态流转，更新MD文件 |
| update_ledger | project_path, change_info | void | 更新版本变更台帐 |

### 4.3 数据提取策略

**立项表解析**:
- 使用Markdown表格解析器提取结构化数据
- 按章节标题(§3/§4/§5/§6/§7)定位数据块
- 按字段名匹配表格行
- 容错: 字段缺失时返回默认值，不报错

**变更单解析**:
- 扫描 `04_变更管理/01_变更单/` 下所有 `CHG-*.md` 文件
- 解析Markdown表格提取字段值
- 从文件路径提取domain分类

**缓存策略**:
- 基于文件mtime的缓存: 文件未修改则使用缓存
- 手动刷新: 强制清除缓存重新解析
- 不使用TTL过期，只依赖mtime

### 4.4 工作空间约定

| 配置项 | 值 | 说明 |
|--------|-----|------|
| 工作空间根目录 | `0100_PLC自动化/` | 固定，相对于工作空间根 |
| 项目标识 | 目录名 | 如 DJ-2026-005 |
| 立项表路径模式 | `00_项目管理/01_立项与需求/*_PROJ-*.md` | 每个项目一个 |
| 变更单路径模式 | `00_项目管理/04_变更管理/01_变更单/CHG-*/CHG-*.md` | 按domain分目录 |
