# SW-2026-005 项目文档体系整改 Spec

## Why

当前项目文档存在以下问题，严重影响后续开发者快速上手和迭代效率：

1. **文档缺失严重**：仅有1个用户手册和若干模块README，缺少项目级核心文档
2. **文档结构混乱**：文档散落在不同目录，未按规范仓库V3.0结构组织
3. **内容过时或不完整**：用户手册停留在V1.0.0初始版本，未反映当前功能状态
4. **无架构设计文档**：新开发者无法理解系统整体设计和模块关系
5. **无开发指南**：环境搭建、代码规范、调试方法等关键信息缺失

## What Changes

- Affected code: 无代码修改，纯文档新增/重写

## ADDED Requirements

### REQ-DOC-001: 项目入口文档 (README.md)

**优先级**: P0 (必须)

系统 SHALL 提供 `README.md` 作为项目入口文档，包含：

#### 场景: 开发者首次克隆项目后
- **WHEN** 开发者打开项目根目录
- **THEN** 能在30秒内了解：
  - 项目名称、版本、一句话描述
  - 技术栈清单（Python版本/依赖/GUI框架）
  - 快速启动步骤（3步以内）
  - 项目结构概览图（ASCII或链接）
  - 核心功能列表
  - 开发者快速导航索引

### REQ-DOC-002: 用户操作手册 V2.0 (user_manual.md)

**优先级**: P0 (必须)

系统 SHALL 提供完整的用户操作手册，包含：

#### 场景: 用户需要学习如何使用工具
- **WHEN** 用户打开用户手册
- **THEN** 能找到：
  - 完整功能模块说明（与当前代码一致）
  - 每个功能的操作步骤截图/文字说明
  - 常见问题解答（FAQ）
  - 快捷键完整列表
  - 故障排除指南

**具体要求**:
- 更新至V2.0.0，反映已实现的所有功能
- 覆盖：仪表盘、项目管理、文档管理、ST编辑器、HMI映射、规范检查、诊断面板、测试运行器
- 移除"开发中"标注（对已完成功能）

### REQ-DOC-003: 架构设计文档 (ARCH-V1.0.0)

**优先级**: P0 (必须)

系统 SHALL 提供架构设计文档，包含：

#### 场景: 新开发者需要理解系统设计
- **WHEN** 开发者阅读架构文档
- **THEN** 能理解：
  - 系统整体架构图（分层/MVC/事件驱动）
  - 核心模块职责划分（core/ui/services/models/parsers/checkers/diagnostics/utils）
  - 模块间依赖关系图
  - 关键设计决策（为什么这样设计）
  - 数据流图（用户操作→UI→Service→Model）
  - 扩展点说明（如何添加新功能）

### REQ-DOC-004: 详细设计文档 (DES-V1.0.0)

**优先级**: P1 (重要)

系统 SHALL 提供详细设计文档，包含：

#### 场景: 开发者需要修改特定模块
- **WHEN** 开发者查看详细设计
- **THEN** 能找到：
  - 每个核心类的职责和接口定义
  - 关键算法/流程的伪代码或流程图
  - 数据模型定义（Project/Document/Template/Variable等）
  - 配置项说明（settings.json结构）
  - 事件总线机制说明

### REQ-DOC-005: API接口文档 (INT-V1.0.0)

**优先级**: P1 (重要)

系统 SHALL 提供核心API接口文档，包含：

#### 场景: 开发者需要调用服务层API
- **WHEN** 开发者查阅API文档
- **THEN** 能看到：
  - 公开类和方法签名
  - 参数类型和返回值
  - 使用示例代码
  - 异常情况处理说明

**覆盖范围**:
- SettingsManager: 配置存取API
- ProjectService: 项目CRUD API
- TemplateService: 模板管理API
- DiagnosticService: 诊断执行API
- DocumentService: 文档生成API

#### 场景: 开发者需要在代码中定位功能
- **WHEN** 开发者查看代码结构文档
- **THEN** 能快速定位：
  - 目录结构与模块映射关系

  - 文件命名约定

### REQ-DOC-007: 开发环境搭建指南 (DEV-V1.0.0)

系统 SHALL 提供环境搭建指南，包含：

## 文档质量标准

所有新建文档须满足：

1. **格式规范**: 遵循 `004_通用项目文档版本管理与变更核心规范`
2. **命名规范**: `{编号}_{文档名称}_{前缀码}-V{版本}.md`
3. **版本号**: 初始版本均为 V1.0.0（除user_manual为V2.0.0）
4. **语言**: 中文为主，代码/术语保持英文
5. **链接**: 使用Obsidian `[[]]` 双向链接语法
6. **时效性**: 反映截至 2026-05-08 的最新代码状态
