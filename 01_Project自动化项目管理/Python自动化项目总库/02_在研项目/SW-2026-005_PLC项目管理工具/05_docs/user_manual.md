# PLC项目管理工具 用户操作手册

> **版本**: V2.0.0 | **适用**: SW-2026-005 V1.1.0+ | **更新**: 2026-05-08

---

## 1. 产品概述

### 1.1 产品定位

PLC项目管理工具是一款**面向IEC 61131-3标准的桌面集成化管理工具**，为PLC自动化项目提供从创建到交付的全生命周期管理能力。

### 1.2 核心价值

| 痛点 | 解决方案 |
|------|----------|
| 项目结构不统一 | M001/S001标准模板一键生成 |
| SCL代码规范性差 | 六维自动检查 + 实时反馈 |
| 文档编写耗时 | 10种标准模板自动填充 |
| 项目健康度不可见 | 七维度深度诊断评分 |
| HMI变量管理混乱 | 映射表可视化编辑 |

### 1.3 技术栈

- **运行环境**: Windows 10/11, Python 3.9+
- **GUI框架**: PyQt5 (Material Design风格)
- **代码编辑**: QScintilla (SCL语法高亮，可选)

## 3. 功能详解

### 3.1 仪表盘 (Dashboard)

**位置**: 启动后默认显示的首页标签页

**功能说明**:
- **项目统计卡片**: 显示当前打开项目的FB数量、变量数、文档数、测试用例数
- **健康度环形图**: 综合评分(0-100)，颜色编码(绿>80 / 黄60-80 / 红<60)
- **最近项目列表**: 快速访问最近打开的10个项目
- **快捷操作按钮**: 一键新建项目、打开项目、生成文档、运行检查

**操作流程**:
1. 启动应用后自动展示仪表盘
2. 点击"最近项目"中的条目快速打开
3. 或点击"新建项目"按钮开始创建

---

### 3.2 项目管理

#### 3.2.1 新建项目

**入口**: 菜单栏 → 文件 → 新建项目 / 工具栏[新建]按钮 / 仪表盘快捷操作

**操作步骤**:

```
1. 点击 [新建项目]，弹出 NewProjectDialog 对话框

2. 填写基本信息:
   - 项目名称: 如 "DJ-2026-006_贴标机"
   - 业务线: 选择 (包装/物流/组装/其他)
   - 项目经理: 输入负责人姓名
   - 项目描述: 可选填写

3. 选择模板:
   - M001: 中大型单机设备 (PLC+HMI) — 推荐
   - S001: 小型单机设备 (PLC+HMI)

4. 配置硬件品牌:
   - PLC品牌: Siemens/Mitsubishi/OMRON/其他
   - HMI品牌: Siemens Pro/Mitsubishi/其他

5. 选择存储路径 (默认: ./Projects/)
   
6. 点击 [确认创建]
```

**预期结果**:
- 在指定路径生成完整的项目目录结构
- 自动创建标准子目录 (Programs/Blocks/HMI/Documents/Tests 等)
- 项目信息写入 settings.json 的 recent_projects 列表
- 项目树刷新显示新项目

#### 3.2.2 打开项目

**入口**: 菜单栏 → 文件 → 打开项目 / 工具栏[打开] / 仪表盘最近列表

**支持格式**:
- 已有的标准结构项目目录
- 含 `.plc.json` 配置文件的 TIA Portal 项目

#### 3.2.3 项目树浏览

**位置**: 左侧 Dock 区域的 ProjectTree 组件

**功能**:
- 树形展示项目完整目录结构
- 双击文件在对应编辑器中打开
- 右键菜单: 新建文件/文件夹、删除、重命名
- 支持拖拽移动文件

### 3.4 ST代码编辑器

**位置**: 中央标签页 → ST编辑器 标签

**功能特性**:

| 特性 | 说明 |
|------|------|
| **SCL语法高亮** | 关键字(FB/IF/CASE等)着色显示 (需QScintilla) |
| **代码片段库** | 内置7种常用ST片段，一键插入 |
| **自动缩进** | IF/CASE/FOR块自动缩进对齐 |
| **行号显示** | 左侧行号栏便于定位 |

#### 3.4.1 使用代码片段

**可用片段**:

| 片段名 | 触发场景 | 内容示例 |
|--------|----------|----------|
| fb.snippet | 创建功能块 | `FUNCTION_BLOCK FB_xxx` 结构 |
| case.snippet | CASE分支判断 | `CASE xxx OF` 多路选择 |
| for.snippet | FOR循环计数 | `FOR #i := x TO y DO` 循环 |
| if.snippet | 条件分支 | `IF xxx THEN ... END_IF;` |
| move.snippet | 赋值操作 | `#variable := value;` |
| ton.snippet | 定时器调用 | `TON_Inst(IN:=, PT:=);` |

**插入方式**:
1. 光标定位到插入位置
2. 使用菜单或快捷键呼出片段面板
3. 双击目标片段名称
4. 片段内容插入到光标位置

### 3.5 HMI变量映射

**位置**: 右侧 Dock → HMI映射标签页

**功能**:
- 建立 PLC变量与 HMI 屏幕元素的对应关系
- 表格化编辑映射关系
- 支持 Excel 导入/导出 IO 分配表

**操作流程**:

```
1. 打开项目后切换到 HMI映射标签

2. 点击 [导入IO表] 从Excel加载信号定义

3. 在表格中编辑:
   - 变量地址 (如 %I0.0.1, %QW10)
   - 变量名称 (如 DI_Start_Sensor)
   - HMI标签 (如 "启动传感器")
   - 数据类型 (BOOL/INT/WORD/DWORD)

4. 点击 [保存映射] 持久化到项目配置

5. 点击 [导出] 生成标准IO分配表文档
```

### 3.6 规范检查面板

**位置**: 右侧 Dock → 规范检查标签页

**检查维度一览**:

| 维度 | 检查器类 | 检查内容 | 严重级别 |
|------|----------|----------|----------|
| **命名规范** | NamingChecker | FB/变量命名前缀、大小写、长度 | 🔴 高 |
| **语法规则** | SyntaxChecker | SCL关键字用法、语句结构 | 🔴 高 |
| **注释规范** | CommentChecker | 中文标点禁令、嵌套注释检测 | 🟡 中 |
| **配置合规** | ConfigChecker | .plc.json格式验证 | 🟡 中 |
| **定时器使用** | TimerChecker | FB_TON参数类型(DINT非TIME) | 🟠 低 |
| **变量规范** | VariableChecker | I/O地址范围、命名一致性 | 🟡 中 |

**执行检查**:

```
1. 打开项目并确保已加载SCL源文件

2. 切换到规范检查面板

3. 选择检查范围:
   - 全部检查 (6个维度全选)
   - 自定义勾选需要的维度

4. 点击 [开始检查]

5. 等待检查完成，查看结果列表:
   - ✅ 通过项: 绿色标记
   - ❌ 问题项: 红色标记 + 问题描述 + 修复建议
   - ⚠️ 警告项: 黄色标记

6. 点击问题行查看详情和修复步骤
```

**结果导出**: 支持将检查报告导出为 Markdown 文档

### 3.7 诊断面板

**位置**: 右侧 Dock → 诊断分析标签页

**七维度诊断体系**:

| 维度 | 指标 | 权重 |
|------|------|------|
| **结构完整性** | 目录/文件是否齐全 | 15% |
| **命名规范率** | 符合命名规范的占比 | 15% |
| **文档覆盖率** | 必需文档的存在情况 | 15% |
| **代码质量分** | 语法/注释/复杂度综合 | 20% |
| **配置合规性** | .plc.json正确性 | 10% |
| **LSP兼容性** | 与Siemens LSP的兼容程度 | 15% |
| **测试覆盖度** | 测试用例与功能的匹配 | 10% |

**执行诊断**:

```
1. 打开目标项目

2. 切换到诊断面板

3. 点击 [开始深度诊断] 按钮

4. 系统依次执行各维度检查 (约5-10秒)

5. 查看:
   - 总体健康度分数 (0-100)
   - 各维度得分雷达图
   - 问题清单 (按严重度排序)
   - 一键修复建议

6. 对可修复的问题点击 [立即修复]
```

**LSP兼容性检查**:
- 检测 `.plc.json` 中 `libraries` 字段格式
- 验证相对路径引用的正确性
- 检测与 Siemens LSP 插件的兼容性风险点

### 3.8 测试运行器

**位置**: 右侧 Dock → 测试运行标签页

**功能**:
- 解析 SCLTest 格式的测试用例文件
- 展示测试用例列表 (用例ID/名称/优先级/状态)
- 执行单个或批量测试用例
- 查看测试结果 (通过/失败/错误日志)

**使用流程**:

```
1. 在项目中准备 SCLTest 测试文件 (.sttest)

2. 切换到测试运行器面板

3. 点击 [加载测试用例] 扫描项目中的测试文件

4. 在列表中选择要执行的用例:
   - 单击选中一个
   - Ctrl+A 全选

5. 点击 [运行测试]

6. 查看结果:
   - 🟢 PASS: 测试通过
   - 🔴 FAIL: 测试失败 (附错误信息)
   - ⚪ ERROR: 执行异常
```

## 5. 常见问题 (FAQ)

### Q1: 程序无法启动，提示模块找不到

**原因**: Python路径未正确设置或依赖未安装完全。

**解决方法**:
```bash
# 1. 确认在正确的目录下执行
cd SW-2026-005_PLC项目管理工具/03_主程序/01_主程序核心代码

# 2. 重新安装依赖
pip install -r requirements.txt --force-reinstall

# 3. 如果仍报错，检查Python版本 >= 3.9
python --version
```

### Q2: 打开项目后项目树为空

**原因**: 项目目录不符合标准结构，或路径中包含特殊字符。

**解决方法**:
- 确认项目是通过工具"新建"生成的标准结构
- 检查项目路径不含中文空格或特殊符号
- 尝试使用"打开项目"对话框重新选择项目根目录

### Q3: 规范检查无结果或全部通过但明显有问题

**原因**: 未加载SCL源文件，或检查器的扫描范围未包含目标文件。

**解决方法**:
1. 确保项目中存在 `.scl` 或 `.st` 源文件
2. 在项目树中选中要检查的文件/目录
3. 在检查面板中确认扫描范围设置正确
4. 点击"重新扫描"强制刷新文件列表

### Q4: 诊断报告显示健康度为0或N/A

**原因**: 项目信息不完整，或关键配置文件缺失。

**解决方法**:
1. 确认项目根目录下有有效的项目配置
2. 至少包含一个 Programs 目录和一个 Blocks 目录
3. 检查 settings.json 中 current_project 字段已正确设置
4. 尝试关闭项目后重新打开

### Q5: ST编辑器没有语法高亮

**原因**: QScintilla 未安装或未正确配置。

**解决方法**:
```bash
# 安装 QScintilla
pip install QScintilla>=2.13.0

# 重启应用
python main.py
```

如果安装后仍未生效，检查 PyQt5 和 QScintilla 版本兼容性：
```bash
pip show PyQt5 QScintilla
# 确保 PyQt5 >= 5.15 且 QScintilla >= 2.13
```

### Q6: 生成的文档中文乱码

**原因**: 系统编码非UTF-8，或编辑器未以UTF-8模式打开。

**解决方法**:
- 本工具生成的所有文档均为 UTF-8 编码
- 使用 VSCode / Obsidian / Typora 等支持UTF-8的编辑器打开
- 如需转为GBK编码，可在编辑器中另存为时选择编码

### Q7: HMI映射导入Excel失败

**原因**: Excel文件格式不支持（仅支持.xlsx），或列头不匹配。

**解决方法**:
- 确保文件是 `.xlsx` 格式（非旧版 `.xls`）
- Excel应包含以下列头: 地址/变量名/HMI标签/数据类型/备注
- 模板可从工具内导出空白模板参照格式

## 6. 故障排除

### 6.1 日志查看

应用运行日志位于控制台输出，可通过以下方式查看详细错误：

```bash
# 启动时开启调试模式（在main.py中修改）
# 将 debug=False 改为 debug=True
python main.py
```

日志级别:
- `INFO`: 正常操作记录
- `WARNING`: 可恢复的问题
- `ERROR`: 操作失败
- `DEBUG`: 详细调试信息（需开启debug模式）

### 6.2 常见错误码

| 错误现象 | 可能原因 | 处理方式 |
|----------|----------|----------|
| `ModuleNotFoundError: No module named 'PyQt5'` | 依赖未安装 | `pip install PyQt5` |
| `Settings file not found` | 首次运行正常 | 自动创建默认配置 |
| `Project path does not exist` | 项目被移动或删除 | 重新打开或从最近列表移除 |
| `Template not found: M001` | 模板文件缺失 | 检查 src/templates/project_structures/ 目录 |

### 6.3 重置应用状态

如遇到异常状态，可删除配置重置：

```bash
# 删除用户配置（会清除最近项目列表和偏好设置）
del data\settings.json

# 重新启动应用
python main.py
```

> **注意**: 此操作不会影响项目数据，仅重置应用级配置。

## 附录B: 规则检查项一览

### NamingChecker (命名规范)

| 规则ID | 规则描述 | 示例 |
|--------|----------|------|
| NAM-001 | FB名称必须以 `FB_` 前缀开头 | ✅ `FB_Conveyor_Motor` / ❌ `ConveyorMotor` |
| NAM-002 | 变量命名采用帕斯卡或下划线分隔 | ✅ `Start_Sensor` / ❌ `startsensor` |
| NAM-003 | 名称长度不超过32字符 | ✅ 合规 / ❌ 超长截断 |
| NAM-004 | 禁止使用保留字作为名称 | ❌ `FOR` / `CASE` / `END_VAR` |

### SyntaxChecker (语法规则)

| 规则ID | 规则描述 |
|--------|----------|
| SYN-001 | 每条语句必须以分号结尾 |
| SYN-002 | IF必须配对END_IF |
| SYN-003 | CASE必须配对END_CASE |
| SYN-004 | FOR循环必须有TO/DOWNTO和DO |
