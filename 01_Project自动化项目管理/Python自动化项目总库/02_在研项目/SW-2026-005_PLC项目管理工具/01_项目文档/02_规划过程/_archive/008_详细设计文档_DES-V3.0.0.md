# 详细设计文档 DES-V3.0.0

> **项目**: SW-2026-005 PLC项目管理工具
> **版本**: V3.0.0
> **日期**: 2026-06-01
> **状态**: 当前主线详细设计
> **适用范围**: PLC工作空间支持 + PyWebView双模式UI

---

## 1. 设计目标

本设计文档聚焦解决以下问题：
- 让工具能识别并打开 `PLC Workspace`，而不是只支持单项目
- 让工作空间下的 DJ 项目、共享库、普通 `.plc.json` 项目都能被聚合加载
- 在不破坏当前单项目能力的前提下，建立后续跨项目治理基础
- 新增 PyWebView 模式，通过 IPCBridge 实现 Python 后端与 Web 前端的通信桥接
- 支持双模式入口（PyWebView / PyQt），通过环境变量切换

## 3. 工作空间识别设计 ✅已实现

### 3.1 识别优先级 ✅已实现

`ArtifactRegistryService.detect_project_type(project_path)` 已实现以下5级优先级（位于 `src/services/artifact_registry_service.py`）：

1. 根目录存在 `workspace.json` -> `PLC_WORKSPACE` ✅已实现
2. 满足 DJ 三标记 -> `DJ_SINGLE_MACHINE` ✅已实现
3. 根目录存在 `.plc.json` 且包含共享库典型分类子目录 -> `PLC_LIBRARY` ✅已实现
4. 根目录下存在 2 个及以上可识别子项目 -> `PLC_WORKSPACE` ✅已实现
5. 其他情况 -> `GENERIC` ✅已实现

### 3.2 共享库典型判定 ✅已实现

`_is_plc_library(root)` 方法已实现，使用 `PLC_LIBRARY_CATEGORY_DIRS` 常量进行判定：

- 检查 `.plc.json` 是否存在
- 遍历子目录，与 `PLC_LIBRARY_CATEGORY_DIRS` 集合取交集
- 交集非空即判定为共享库

`PLC_LIBRARY_CATEGORY_DIRS` 包含：`actuator/timer/counter/edge/convert/analog/motion/communication/safety`

### 3.3 子项目计数 ✅已实现

`_count_identifiable_subprojects(root)` 方法已实现，统计以下三类可识别子项目：

- DJ 单机项目（三标记匹配，通过 `_is_dj_project()`）
- 共享库（`.plc.json` + 分类目录，通过 `_is_plc_library()`）
- 含配置文件的普通项目（`project.json/.plc_project.json/.plc.json`，通过 `_has_project_config()`）

### 3.4 忽略规则 ✅已实现

扫描工作空间根目录时使用 `WORKSPACE_IGNORED_DIRS` 常量，忽略：

- `.trae` / `.git` / `__pycache__` / `_archive` / `node_modules` / `.venvs` / `.plc-out`

### 3.5 子项目扫描与分类 ✅已实现

新增 `scan_workspace_subprojects()` 和 `_classify_subproject()` 方法：

- 遍历工作空间根目录一层子目录
- 对每个子目录分类为 `dj_single_machine` / `plc_library` / `generic` 或忽略
- 返回 `List[Dict]`，每项包含 `path` / `name` / `type`

## 4. 工作空间加载设计 ✅已实现

### 4.1 新增接口 ✅已实现

`ProjectService.load_workspace_from_path(workspace_path)` 已实现（位于 `src/services/project_service.py`）。

输入：
- `workspace_path: str`

输出：
- `Tuple[Optional[List[Project]], Optional[str]]`

职责：
- 校验目录存在且为 `PLC_WORKSPACE` 类型
- 调用 `ArtifactRegistryService.scan_workspace_subprojects()` 获取子项目列表
- 遍历子项目，通过 `_load_subproject()` 逐个加载
- 无可管理子项目时返回错误提示

### 4.2 加载规则 ✅已实现

`_load_subproject(sub_path, sub_type)` 方法已实现，按子项目类型分派加载：

- **DJ 项目** ✅已实现：调用 `import_dj_project()`，失败时走 `_create_fallback_project()`
- **共享库** ✅已实现：优先尝试 `load_project_from_path()`；若无标准元数据，则调用 `_create_library_project()` 构造降级 `Project`
- **普通 `.plc.json` 项目** ✅已实现：走 `load_project_from_path()`，失败时走 `_create_fallback_project()`

所有成功加载的子项目均标记 `project.extra["_workspace_child"] = True`。

### 4.3 共享库降级 Project 设计 ✅已实现

`_create_library_project(lib_path)` 方法已实现，当共享库没有 `project.json` / `.plc_project.json` 时构造轻量 `Project`：

- `name = 目录名`
- `code = 目录名`
- `description = "PLC共享库: {name}"`
- `business_line = BusinessLine.LIBRARY`（使用 `LIB` 枚举值）
- `project_type = ProjectType.PLC_LIBRARY`
- `path = 目录路径`
- `status = ProjectStatus.ACTIVE`
- `workflow_stage = WorkflowStage.DEVELOPMENT`
- `extra["_workspace_child"] = True`

### 4.4 通用降级 Project 设计 ✅已实现

`_create_fallback_project(sub_path, sub_type)` 方法已实现，为加载失败的子项目构造降级 `Project`：

- `description = "工作空间子项目({sub_type}): {name}"`
- `business_line = BusinessLine.DEVICE`
- `project_type` 根据传入 `sub_type` 动态匹配，无法匹配时回退 `GENERIC`
- `workflow_stage = WorkflowStage.INITIATION`
- `extra["_workspace_child"] = True`

## 5. 打开流程设计 ✅已实现

### 5.1 `ProjectController.on_project_opened()` ✅已实现

打开逻辑已新增工作空间分支（位于 `src/ui/controllers/project_controller.py`）：

- 先校验目录存在 ✅已实现
- 判断根目录是否有单项目配置文件 ✅已实现
- 若无配置文件，则通过 `detect_project_type()` 识别 ✅已实现
- 若识别为 `PLC_WORKSPACE`，则转入 `_open_as_workspace()` ✅已实现
- 若识别为 `DJ_SINGLE_MACHINE`，仍走当前单项目逻辑 ✅已实现
- 其他情况保留错误提示 ✅已实现

**PyWebView 模式补充**：在 PyWebView 模式下，前端通过 `window.pywebview.api.open_project(path)` 调用 `IPCBridge.open_project()`，由 `_safe_call` 包装后委托给 `ProjectController.on_project_opened()` 执行相同逻辑，结果通过 JSON 返回前端。

### 5.2 `_open_as_workspace()` ✅已实现

已实现（位于 `src/ui/controllers/project_controller.py`）：

- 调用 `ProjectService.load_workspace_from_path()` ✅已实现
- 若无任何子项目，弹出"打开工作空间失败"提示 ✅已实现
- 若有结果，则调用 `project_tree_widget.load_workspace()` 批量加载到项目树 ✅已实现
- 状态栏显示子项目数量 ✅已实现

**PyWebView 模式补充**：在 PyWebView 模式下，`IPCBridge.open_project()` 内部调用 `_open_as_workspace()` 后，通过 `_emit("project_opened", data)` 主动推送事件到前端，前端 `__ipc_recv` 回调接收后更新项目列表视图。

## 16. IPCBridge 详细设计

### 16.1 IPCBridge 类设计

**位置**: `src/ui/webview_window.py`

**职责**: Python 后端 ↔ JavaScript 前端的通信桥接层

**设计模式**: Facade 模式 + 异常包装模式

- Facade 模式：IPCBridge 作为统一入口，将后端 Service 层的多个服务调用封装为前端可直接调用的 API 方法，隐藏内部服务编排细节
- 异常包装模式：通过 `_safe_call` 统一包装所有公开 API 方法，保证前端调用不会因 Python 异常而崩溃

**生命周期**: 由 `create_window()` 工厂函数创建，随 webview 窗口销毁

**核心依赖**:

| 依赖 | 用途 |
|---|---|
| `ProjectService` | 项目/工作空间加载与管理 |
| `CompanionService` | 伴生跳转与能力边界判定 |
| `LibraryService` | 共享库扫描与治理 |
| `WorkspaceService` | 工作空间治理与聚合报告 |
| `ConfigLoader` | 配置加载 |

### 16.2 `_safe_call` 异常包装模式

```python
def _safe_call(self, name: str, fn, *args, **kwargs):
    # 1. 记录调用日志
    # 2. 执行fn(*args, **kwargs)
    # 3. 成功: 记录结果日志，返回result
    # 4. 异常: 记录错误日志+traceback，返回 {"success": False, "error": str(e)}
```

**设计要点**:

- 所有公开 API 方法都通过 `_safe_call` 包装
- 保证前端调用不会因 Python 异常而崩溃
- 统一的错误返回格式 `{"success": False, "error": "错误描述"}`
- 成功时直接返回 Service 层的结果（Service 层方法已有各自的返回格式）
- 日志记录包含方法名、参数摘要、执行结果/异常信息，便于调试

**异常包装示例**:

```python
def open_project(self, path: str):
    return self._safe_call("open_project", self._open_project, path)

def _open_project(self, path: str):
    # 实际业务逻辑，调用 ProjectController / ProjectService
    ...
```

### 16.3 `_emit` 事件推送机制

```python
def _emit(self, event: str, data=None):
    payload = json.dumps({"event": event, "data": data}, ensure_ascii=False)
    self._window.evaluate_js(f"window.__ipc_recv({payload})")
```

**设计要点**:

- 后端主动推送事件到前端，实现双向通信
- 前端通过 `window.__ipc_recv` 回调接收事件
- payload 使用 `json.dumps(ensure_ascii=False)` 保证中文正确传输
- 通过 `evaluate_js` 注入 JS 调用，实现 Python → JS 的数据传递

**支持的事件**:

| 事件名 | 触发时机 | data 内容 |
|---|---|---|
| `project_created` | 新建项目完成 | `{name, path, code}` |
| `project_opened` | 打开项目/工作空间完成 | `{name, path, type, subproject_count?}` |
| `project_closed` | 关闭项目完成 | `{name, path}` |
| `document_created` | 新建文档完成 | `{name, path, project}` |
| `setting_changed` | 设置项变更 | `{key, value}` |
| `settings_reset` | 设置重置为默认值 | `{}` |

### 16.5 前端调用链设计

**请求-响应模式（前端 → 后端）**:

```
前端JS → window.pywebview.api.xxx(args)
  → IPCBridge.xxx(args)
  → _safe_call("xxx", self._xxx, args)
  → Service层调用
  → 返回JSON结果
```

**事件推送模式（后端 → 前端）**:

```
后端推送 → _emit("event_name", data)
  → window.evaluate_js("window.__ipc_recv({event, data})")
  → 前端JS __ipc_recv回调
  → 更新state → 重新渲染视图
```

**完整调用链示例（打开项目）**:

```
1. 前端: window.pywebview.api.open_project("/path/to/workspace")
2. IPCBridge.open_project("/path/to/workspace")
3. _safe_call("open_project", self._open_project, "/path/to/workspace")
4. self._open_project → ProjectController.on_project_opened()
5. ProjectController → ProjectService.load_workspace_from_path()
6. 返回结果到前端
7. _emit("project_opened", {name, path, type, subproject_count})
8. 前端 __ipc_recv → 更新项目列表视图
```

**错误处理链**:

```
前端调用 → IPCBridge → _safe_call → Service层异常
  → _safe_call 捕获异常 → 返回 {"success": False, "error": "错误描述"}
  → 前端根据 success 字段显示错误提示
```

### 16.6 `create_window()` 工厂函数

```python
def create_window(html_path=None, title="", width=1280, height=800):
    bridge = IPCBridge()
    url = f"file:///{html_path.replace(os.sep, '/')}"
    window = webview.create_window(
        title=title, url=url, js_api=bridge,
        width=width, height=height,
        min_size=(960, 600), text_select=True
    )
    bridge.set_window(window)
    return window
```

**设计要点**:

- 工厂函数封装窗口创建和桥接器绑定的完整流程
- `html_path` 转为 `file:///` URL 格式，兼容 Windows 路径分隔符
- `js_api=bridge` 将 IPCBridge 实例暴露为 `window.pywebview.api`
- `min_size=(960, 600)` 保证最小可用视口
- `text_select=True` 允许前端文本选择（复制等操作）
- `bridge.set_window(window)` 在窗口创建后绑定窗口引用，供 `_emit` 使用

**窗口创建时序**:

```
1. create_window() 调用
2. 创建 IPCBridge 实例（此时 _window = None）
3. webview.create_window() 创建窗口并绑定 js_api
4. bridge.set_window(window) 绑定窗口引用
5. 返回 window 对象
6. webview.start() 启动事件循环后，前端可开始调用 API
```

## 17. 双模式入口设计

### 17.1 `main.py` 入口逻辑

```python
USE_WEBVIEW = os.environ.get("PLC_GUI_MODE", "webview") == "webview"

def main():
    if USE_WEBVIEW:
        try:
            run_webview()
        except ImportError:
            run_pyqt()  # 自动回退
    else:
        run_pyqt()
```

**模式切换**:

| 环境变量 | 值 | 行为 |
|---|---|---|
| `PLC_GUI_MODE` | `"webview"`（默认） | 启动 PyWebView 模式 |
| `PLC_GUI_MODE` | `"pyqt"` | 启动 PyQt 模式 |
| 未设置 | — | 默认 PyWebView 模式 |

**回退机制**: 当 `PLC_GUI_MODE="webview"` 但 `pywebview` 未安装时，`ImportError` 被捕获并自动回退到 PyQt 模式，保证工具始终可用。

**切换示例**:

```powershell
# 默认 PyWebView 模式
python main.py

# 强制 PyQt 模式
$env:PLC_GUI_MODE = "pyqt"
python main.py
```

### 17.2 `run_webview()` 启动流程

```
1. ConfigLoader.load()                    # 加载应用配置
2. 获取 app_name 和 version               # 从配置中读取
3. 确定 html_path                         # BASE_DIR/ui_prototype/index.html
4. create_window(html_path, title)        # 创建窗口并绑定 IPCBridge
5. webview.start(debug=True)              # 启动 webview 事件循环
```

**详细说明**:

- `ConfigLoader.load()`: 加载 `config.yaml` 或默认配置，初始化日志、路径等
- `html_path`: 指向前端原型文件 `ui_prototype/index.html`，使用 `file:///` 协议加载
- `create_window()`: 调用第16章定义的工厂函数，完成窗口创建和 IPCBridge 绑定
- `webview.start(debug=True)`: 启动 webview 事件循环，`debug=True` 开启开发者工具（生产环境应关闭）

**启动时序图**:

```
main()
  └→ run_webview()
       ├→ ConfigLoader.load()
       ├→ app_name = config["app_name"]
       ├→ version = config["version"]
       ├→ html_path = BASE_DIR / "ui_prototype" / "index.html"
       ├→ create_window(html_path, f"{app_name} v{version}")
       │    ├→ IPCBridge()
       │    ├→ webview.create_window(url, js_api=bridge, ...)
       │    └→ bridge.set_window(window)
       └→ webview.start(debug=True)
            └→ 前端 index.html 加载完成
            └→ window.pywebview.api 可用
            └→ 前端可开始调用 IPCBridge API
```

### 17.3 `run_pyqt()` 启动流程

```
1. Qt高DPI属性设置                       # AA_EnableHighDpiScaling, AA_UseHighDpiPixmaps
2. QApplication创建                      # QApplication(sys.argv)
3. 字体解析和设置                         # 从配置中读取字体族/字号
4. MainWindow().show()                   # 创建并显示主窗口
5. app.exec_()                           # 启动 Qt 事件循环
```

**详细说明**:

- **高DPI属性**: 在 `QApplication` 创建前设置 `AA_EnableHighDpiScaling` 和 `AA_UseHighDpiPixmaps`，保证在高分辨率显示器上界面不模糊
- **QApplication创建**: 传入 `sys.argv`，支持 Qt 命令行参数
- **字体设置**: 从 `ConfigLoader` 加载的配置中读取字体族和字号，通过 `QFont` 设置为应用默认字体
- **MainWindow**: PyQt 模式的主窗口，包含项目树、编辑器、状态栏等完整 UI 组件
- **事件循环**: `app.exec_()` 启动 Qt 事件循环，阻塞直到窗口关闭

**启动时序图**:

```
main()
  └→ run_pyqt()
       ├→ QApplication.setAttribute(AA_EnableHighDpiScaling)
       ├→ QApplication.setAttribute(AA_UseHighDpiPixmaps)
       ├→ app = QApplication(sys.argv)
       ├→ font = QFont(config["font_family"], config["font_size"])
       ├→ app.setFont(font)
       ├→ window = MainWindow()
       ├→ window.show()
       └→ app.exec_()
```
