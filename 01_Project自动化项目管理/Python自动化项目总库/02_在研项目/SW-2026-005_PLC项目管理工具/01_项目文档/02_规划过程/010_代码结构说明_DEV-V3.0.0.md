## 4. PyWebView架构关键文件

V4.0架构采用 PyWebView + HTML前端 替代 PyQt5 作为主UI方案，PyQt5保留为回退模式。

### 4.1 main.py — 双模式入口

| 特性 | 说明 |
|---|---|
| 环境变量 | `PLC_GUI_MODE=webview`(默认) / `PLC_GUI_MODE=pyqt` |
| PyWebView路径 | `run_webview()` → 加载 `ui_prototype/index.html` |
| PyQt5回退 | `run_pyqt()` → 启动 `MainWindow` |
| 自动回退 | PyWebView不可用时自动降级到PyQt5 |
| 依赖注入 | `lib/` 目录在启动时注入 `sys.path` |

```python
USE_WEBVIEW = os.environ.get("PLC_GUI_MODE", "webview") == "webview"

def main():
    if USE_WEBVIEW:
        try:
            run_webview()
        except ImportError:
            run_pyqt()  # 自动回退
    else:
        run_pyqt()
```

### 4.2 lib/ — PyWebView运行时依赖

| 包 | 版本 | 用途 |
|---|---|---|
| `bottle` | 0.13.4 | PyWebView内置HTTP服务器 |
| `cffi` | 2.0.0 | C FFI接口（pythonnet依赖） |
| `clr_loader` | 0.3.1 | .NET CLR加载器 |
| `pythonnet` | 3.1.0 | Python-.NET互操作 |
| `pycparser` | 3.0 | C语言解析器（cffi依赖） |
| `proxy_tools` | 0.1.0 | 代理工具（pythonnet依赖） |

**为什么存在此目录**：PyWebView打包（PyInstaller/Nuitka）时需要将 `bottle`/`pythonnet` 等依赖打包到可执行文件中。将这些依赖放在 `lib/` 目录下，通过 `sys.path.insert(0, LIB_DIR)` 在运行时注入，确保打包后的可执行文件能正确找到依赖。

## 6. 代码扩展原则

- 工作空间识别逻辑优先放在 `services/`
- UI 控制器只保留事件编排与用户反馈
- 复用现有 `Project` 模型，避免复制出一套新的平行结构
- PyWebView模式下业务逻辑通过 `IPCBridge` 暴露，前端只做展示和交互
- 任何结构性变更都要同步更新 `006~011` 主线文档
