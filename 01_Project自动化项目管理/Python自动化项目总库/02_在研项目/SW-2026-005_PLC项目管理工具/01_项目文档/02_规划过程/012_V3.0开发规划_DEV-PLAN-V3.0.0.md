## 1. V3.0+ 总体目标

在 SW-2026-005 中集成 SCL 语言服务器，替代 Go 版 Dynamic Siemens Language Support 插件，实现：
- SCL/ST 代码的完整语法解析（词法分析 + 递归下降 → AST）
- 实时类型检查与语义诊断
- LSP 服务器（代码补全/悬停/跳转/引用/Inlay Hints）
- .plc.json 项目作用域管理与库引用解析
- .s7dcl/.s7res 文件解析与 FBD 预览
- 可选的 C# TIA Portal Openness 网关

### 1.1 验收标准

| # | 验收项 | 量化指标 |
|---|--------|----------|
| A1 | SCL 语法覆盖率 | ≥90% 常用 SCL 语法结构可正确解析为 AST |
| A2 | 类型检查准确性 | 5类诊断（类型错误/未声明变量/重复声明/类型不兼容/参数不匹配）误报率 <5% |
| A3 | LSP 响应性能 | 补全/悬停/跳转响应 <100ms（10K 行 SCL 项目） |
| A4 | VS Code 集成 | 可通过 LSP 连接，获得完整智能编辑体验 |
| A5 | 现有功能无回归 | V2.x 全部测试用例 PASS |

## 2. Epic 分解

### Epic 5: SCL 解析器基础（V3.0，P0）

**目标**: 实现 SCL 源码 → 完整 AST 的解析能力

#### Story 5.1: 定义 Token 类型体系

**产出**: `src/scl/tokens.py`
- TokenType 枚举（关键字/标识符/字面量/运算符/标点/注释/EOF）
- Token dataclass（type + lexeme + literal + line + column）
- SCL 关键字映射表（FUNCTION_BLOCK / ORGANIZATION_BLOCK / DATA_BLOCK / VAR_* / IF / CASE / FOR / WHILE / METHOD 等）

#### Story 5.2: 实现词法分析器

**产出**: `src/scl/lexer.py`
- SclLexer 类，逐字符扫描生成 Token 流
- 支持：关键字/标识符/字符串字面量/数字字面量/运算符/行注释/块注释
- 错误恢复：遇到非法字符时记录错误并继续扫描
- 行号/列号追踪

#### Story 5.3: 定义 AST 节点

**产出**: `src/scl/ast_nodes.py`
- ProgramNode（顶层节点，包含多个 Block）
- FunctionBlockNode / OrgBlockNode / DataBlockNode / FunctionNode
- VarSectionNode（VAR_INPUT / VAR_OUTPUT / VAR / VAR_TEMP / VAR_IN_OUT 等）
- VarDeclNode（名称/类型/初始值/注释）
- StatementNode 体系：AssignmentNode / IfNode / CaseNode / ForNode / WhileNode / FBCallNode / ReturnNode
- ExpressionNode 体系：BinaryExpr / UnaryExpr / LiteralExpr / IdentifierExpr / ArrayAccessExpr / FieldAccessExpr

#### Story 5.4: 实现递归下降语法分析器

**产出**: `src/scl/parser.py`
- SclParser 类，基于 Token 流构建 AST
- 优先级：声明 > 语句 > 表达式
- 错误恢复：同步点（END_IF / END_FOR / END_VAR 等）跳过错误区域
- 支持的语法结构覆盖 90%+ 常用 SCL

#### Story 5.5: 实现 AST 访问者模式

**产出**: `src/scl/visitor.py`
- ASTVisitor 基类（通用遍历）
- ASTTransformer 基类（修改 AST）
- 用于类型检查器/代码格式化/诊断生成等下游消费者

#### Story 5.6: 迁移现有 STParser 测试

**产出**: `tests/test_scl_lexer.py` + `tests/test_scl_parser.py`
- 将现有 test_st_parser.py 的测试用例迁移到新解析器
- 新增边界条件测试（嵌套 IF/CASE、中文标识符、长行等）
- 确保新解析器覆盖旧正则版全部场景

---

### Epic 6: 类型检查与诊断（V3.0，P0）

**目标**: 实现实时类型检查和语义诊断

#### Story 6.1: 定义 SCL 类型系统

**产出**: `src/checker/type_system.py`
- SclType 体系：BoolType / IntType / DIntType / RealType / TimeType / StringType / ArrayType / StructType / FBType / VoidType
- 类型兼容性矩阵（哪些类型可隐式/显式转换）
- 类型推导规则

#### Story 6.2: 实现作用域管理

**产出**: `src/checker/scope.py`
- Scope 类（变量名→类型映射，父作用域引用）
- 作用域层次：全局 → POU → VAR 区域 → 语句块
- 符号查找：当前作用域 → 父作用域 → 全局

#### Story 6.3: 实现类型检查器

**产出**: `src/checker/type_checker.py`
- TypeChecker 类（继承 ASTVisitor）
- 赋值类型兼容性检查
- FB 调用参数匹配检查
- 未声明变量检测
- 重复声明检测
- 返回类型一致性检查

#### Story 6.4: 实现语义分析器

**产出**: `src/checker/semantic_analyzer.py`
- SemanticAnalyzer 类（继承 ASTVisitor）
- 不可达代码检测
- 未使用变量检测
- 死代码检测（恒真/恒假条件）

#### Story 6.5: 定义诊断消息体系

**产出**: `src/checker/diagnostics.py`
- SclDiagnostic dataclass（code / severity / message / range / suggestion）
- 诊断代码体系：TC-001~099（类型检查）/ SA-001~099（语义分析）
- 严重程度映射：Error / Warning / Information / Hint

#### Story 6.6: 集成到现有 DiagnosticService

**产出**: 修改 `src/services/diagnostic_service.py`
- 新增第四阶段：SCL 类型检查诊断
- 现有三阶段权重调整：规范检查(35%) + LSP兼容性(10%) + 健康度(35%) + SCL类型检查(20%)
- TypeChecker 诊断结果推送到 DiagnosticPanel

### Epic 7: LSP 服务器（V3.1，P0）

**目标**: VS Code 可通过 LSP 连接 Python 语言服务器

#### Story 7.1: 搭建 pygls 服务器骨架

**产出**: `src/language_server/server.py`
- SclLanguageServer 类（继承 pygls LanguageServer）
- 服务器启动/停止/配置

#### Story 7.2: 实现文档同步

**产出**: `src/language_server/features/document_sync.py`
- textDocument/didOpen：解析文档，构建符号表
- textDocument/didChange：增量更新
- textDocument/didClose：清理资源

#### Story 7.3: 实现诊断推送

**产出**: `src/language_server/features/diagnostics.py`
- textDocument/publishDiagnostics：推送 TypeChecker 诊断到编辑器

#### Story 7.4: 实现代码补全

**产出**: `src/language_server/features/completion.py`
- textDocument/completion：基于当前作用域返回补全列表
- 补全项：变量名/FB名/关键字/数据类型/代码片段

#### Story 7.5: 实现悬停提示

**产出**: `src/language_server/features/hover.py`
- textDocument/hover：变量类型/FB定义位置/注释

#### Story 7.6: 实现跳转定义

**产出**: `src/language_server/features/definition.py`
- textDocument/definition：跨文件符号解析

#### Story 7.7: 实现查找引用

**产出**: `src/language_server/features/references.py`
- textDocument/references：全工作区符号搜索

#### Story 7.8: 实现 Inlay Hints

**产出**: `src/language_server/features/inlay_hints.py`
- textDocument/inlayHint：.s7dcl 引用提示 + .s7res 标题

#### Story 7.9: VS Code 扩展适配

**产出**: `client/` 目录
- VS Code 扩展 package.json
- LSP 客户端配置
- 文件关联（.scl / .st / .s7res / .s7dcl / .db / .udt）

### Epic 8: 项目作用域与文件格式（V3.2，P1）

## 4. 风险与依赖

| 风险 | 影响 | 概率 | 应对 |
|------|------|------|------|
| SCL 语法解析器覆盖度不足 | 高 | 中 | 渐进式覆盖，优先保证常用语法；参考 Go 插件 parser 模块 |
| LSP 协议兼容性 | 高 | 低 | pygls 已被多个生产级项目验证 |
| 大型项目解析性能 | 中 | 中 | 增量解析 + 符号索引持久化 + 多线程 |
| .s7dcl/.s7res 格式逆向 | 中 | 中 | 通过样本文件反推；FBD 预览可简化为接口列表 |
| pygls 框架稳定性 | 低 | 低 | 活跃维护，社区验证 |
| 与现有模块集成冲突 | 中 | 低 | 语言服务层独立于现有模块，通过接口集成 |
