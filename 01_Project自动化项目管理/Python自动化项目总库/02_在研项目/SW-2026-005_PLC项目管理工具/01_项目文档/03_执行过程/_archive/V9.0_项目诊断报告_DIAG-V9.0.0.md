## 2. 核心问题清单 (P1-P6)

### P1 [致命] APIGateway 每次请求新建 Service 实例

- **问题**: `APIGateway._dispatch()` 中 `if isinstance(service, type): instance = service()` 每次IPC调用都创建新的Service实例
- **影响**: ProjectService._projects 缓存字典在请求间丢失，Dashboard每次刷新都全量扫描文件系统
- **根因**: APIGateway.__init__ 中注册的是类而非实例 `self._services = {"project": ProjectService, ...}`
- **修复方向**: 改为注册单例实例，或在APIGateway中维护实例缓存

### P2 [致命] 变更管理 V2 IPC 调用链路断裂

- **问题**: 前端 change-wizard.js 调用 `IPC.call('create_change_request_v2', ...)` 时，IPC层将方法名转换为 `change_create_change_request_v2`，但 WebViewBridge 暴露的方法名是 `create_change_request_v2`
- **影响**: 变更管理核心功能（创建变更单V2）不可用
- **根因**: IPC.call 的域名前缀拼接逻辑与 WebViewBridge 方法命名不一致
- **修复方向**: 统一命名规范，或在WebViewBridge中添加别名方法

### P3 [严重] get_templates 方法缺失

- **问题**: 前端 `ipcGetTemplates()` 调用 `_pyapi('get_templates')`，但 WebViewBridge 没有暴露 `get_templates` 方法
- **影响**: 文档生成功能不可用
- **修复方向**: 在WebViewBridge中添加 get_templates 方法，路由到 DocumentService

### P4 [严重] Mock 数据格式与真实 Service 返回格式不一致

- **问题**: MockDataProvider 返回扁平字典，真实 Service 返回嵌套的 dataclass.to_dict() 结构
- **影响**: 开发时Mock可用，切到真实模式就崩溃
- **修复方向**: MockDataProvider 返回与真实 Service 相同的嵌套结构

### P5 [严重] 文档与实际严重不符

- **问题**: PRD/立项表声称15个模块"已完成"，实际仅6个核心模块完全可用
- **影响**: 误导开发决策，浪费排查时间
- **修复方向**: 基于代码实际状态重写文档

### P6 [中等] 无 UI 原型文档

- **问题**: 所有UI设计都是文字描述，无法直观看到交互效果
- **影响**: 开发反复返工
- **修复方向**: 输出可交互的HTML UI原型

## 5. Service 实例化策略问题分析

当前 APIGateway._dispatch() 实现：

```python
def _dispatch(self, domain, method, *args, **kwargs):
    service = self._services.get(domain)
    if service is None:
        raise ValueError(f"Unknown domain: {domain}")
    if isinstance(service, type):
        instance = service()  # 每次调用都创建新实例！
    else:
        instance = service
    method_func = getattr(instance, method, None)
    ...
```

问题：

1. `self._services` 注册的是类（如 `ProjectService`），不是实例
2. 每次 `_dispatch` 都 `service()` 创建新实例
3. `ProjectService._projects` 缓存字典在新实例中为空
4. 导致每次 Dashboard 刷新都全量扫描文件系统
