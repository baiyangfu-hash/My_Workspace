## 🐛 Bug修复详情

### [BUG-001] 🔴 关键：BaseModel DateTime类型兼容性修复

**问题等级**: 🔴 Critical (影响所有模板更新操作)

**问题描述**：
用户反馈V2.4.2交付物使用**单机设备(PLC+HMI)**模板创建项目时，目录结构仍然是旧版（00/07/10/20/30/40/90跳跃编号），而不是预期的**00~07连续编号**。

**根因分析**：

```
数据流追踪:
template_service.py:58 → TemplateDAO.update(id, existing_tmpl.to_dict())
    ↓
base.py:66-74 to_dict() → updated_at (datetime) 变成 "2026-04-12T14:19:52" (ISO string)
    ↓
base.py:76-79 update_from_dict() → setattr(template, 'updated_at', "string")
    ↓
SQLAlchemy → 尝试写入string到DateTime列 → 💥 TypeError!
    ↓
except吞掉异常 → 模板从未被更新 → 用户看到旧结构！
```

**错误日志**：
```
TypeError: SQLite DateTime type only accepts Python datetime and date objects as input.
[parameters: {'version': 'V2.0.0', 'updated_at': '2026-04-12T14:19:52.354692', ...}]
```

**影响范围**：
- ❌ 所有内置模板无法通过 `initialize_builtin_templates()` 更新
- ❌ 新建项目使用旧版目录结构
- ❌ 模板编辑后保存可能失败

**修复方案**：

修改文件：`src/models/base.py` — `update_from_dict()` 方法

```python
def update_from_dict(self, data: dict):
    from datetime import datetime as dt

    for key, value in data.items():
        if hasattr(self, key) and key not in ["id", "created_at", "updated_at"]:
            column = self.__table__.columns.get(key)
            if column is not None and isinstance(column.type, DateTime) and isinstance(value, str):
                try:
                    value = dt.fromisoformat(value)
                except (ValueError, TypeError):
                    continue
            setattr(self, key, value)
```

**修复要点**：
1. ✅ 排除 `updated_at` 字段（由数据库自动管理）
2. ✅ 智能检测DateTime字段+字符串值，自动解析回datetime对象
3. ✅ 使用 `column is not None` 避免SQLAlchemy布尔判断错误

### 从 V2.4.2 升级（重要！）

⚠️ **本次升级强烈建议全新安装**，原因如下：

1. **数据库需要重置**
   - V2.4.2的数据库中模板数据为旧版
   - V2.4.3会自动在首次启动时更新所有内置模板到最新版本
