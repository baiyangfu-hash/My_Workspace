## 当前已知问题清单

### ⚠️ P2-001: 文档自动填充功能尚未实现

**问题描述**:
当前版本生成项目文档时，所有文档均为空白模板，需要用户手动填充内容。

**期望行为**:
基于项目基本信息（项目编号、名称、业务类型等）和已有源文件（PLC程序、HMI画面等），自动生成文档初稿，减少手工工作量。

**当前影响**:
- 用户需要逐一手动填写每个文档
- 效率较低，容易遗漏
- 不同项目间文档质量不一致

**临时解决方案**:
1. 使用 AI 辅助工具（如本会话）批量生成文档内容
2. 建立文档模板库，复制粘贴常用内容
3. 制定文档填写 Checklist，确保完整性

**计划修复版本**: V2.6.0+

**优先级**: 低（增强功能，不影响核心流程）

---

### ⏳ P3-001: 多语言支持不完善

**问题描述**:
当前工具界面和生成的文档均为中文，不支持英文或其他语言。

**当前影响**:
- 国际化项目需手动翻译文档
- 与国外客户协作时不便
- 不符合部分企业的国际化要求

**临时解决方案**:
1. 手动翻译关键文档
2. 使用翻译工具辅助
3. 在项目命名时统一使用英文标识

**计划修复版本**: V2.7.0+（需评估需求优先级）

**优先级**: 低（取决于用户群体）

---

### ⏳ P3-002: 批量项目修复缺少GUI入口

**问题描述**:
历史项目修复脚本 (`fix_project_complete.ps1`) 需要在命令行中手动运行，对不熟悉 PowerShell 的用户不够友好。

**当前影响**:
- 用户可能不知道如何使用修复脚本
- 需要记住命令行参数
- 无法在工具界面内一键触发

**临时解决方案**:
1. 参考本文档附录的使用说明
2. 请技术人员协助运行
3. 在工具的"帮助"菜单中添加说明链接

**计划修复版本**: V2.5.0（可选增强）

**优先级**: 低（用户体验优化）

---

### ℹ️ INFO-001: 性能优化空间

**观察现象**:
当项目数量较多（>100个）或单个项目文件较多（>500个文件）时，项目列表加载速度略有下降。

**原因分析**:
- 文件系统递归扫描耗时
- 数据库查询未充分优化
- UI 渲染未使用虚拟滚动

**当前影响**:
- 轻微的响应延迟（通常 < 2秒）
- 不影响正常使用

**优化方向**:
1. 添加文件系统缓存机制
2. 优化数据库索引
3. 列表控件使用懒加载

**计划修复版本**: V2.5.0+（持续优化）

**优先级**: 低（性能可接受）

## 使用建议与最佳实践

### 对于新用户

1. **首次使用前**：阅读 [用户操作手册](../01_项目文档/03_执行过程/01_用户操作手册_MAN-V1.0.0.md)
2. **创建第一个项目**：选择合适的模板（推荐 TPL-SINGLE-PLC-001 用于单机设备）
3. **验证创建结果**：检查是否有 `{project_code}` 残留（V2.4.1 应该没有）
4. **补全文档**：按优先级填写核心文档（立项表 → IO分配表 → 需求分析）

### 对于升级用户

1. **备份数据**：升级前务必备份 `config/` 和 `projects/` 目录
2. **运行修复脚本**：对已有项目执行 `fix_project_complete.ps1`
3. **验证功能**：创建测试项目确认 Bug 已修复
4. **反馈问题**：如遇异常，参考本文档的临时解决方案

### 对于开发者

1. **阅读源码**: 修改集中在 `project_service.py` 和 `constants.py`
2. **理解架构**: 模板系统采用 JSON 定义 + Python 动态生成
3. **扩展模板**: 参照现有模板结构添加自定义模板
4. **贡献代码**: 遵循项目编码规范（210_Python编程规范）

## 附录：修复脚本使用说明

### fix_project_names.ps1（基础版）

**用途**: 仅修复文件名中的 `{project_code}` 占位符

**用法**:
```powershell
.\fix_project_names.ps1 -ProjectPath "D:\Projects\你的项目"
```

**参数**:
- `-ProjectPath`: 必填，项目根目录路径
- `-ProjectCode`: 可选，默认自动从路径提取

**输出**: 控制台显示重命名的文件列表

---

### fix_project_complete.ps1（增强版）

**用途**: 完整的项目后处理工具集

**用法**:
```powershell
.\fix_project_complete.ps1 -ProjectPath "D:\Projects\你的项目" -CompleteChangeManagement:$true
```

**参数**:
- `-ProjectPath`: 必填，项目根目录路径
- `-ProjectCode`: 可选，项目编码
- `-ProjectName`: 可选，项目名称（用于文档填充）
- `-CompleteChangeManagement`: 可选，是否补全变更管理目录（默认 true）
- `-GenerateReport`: 可选，是否生成修复报告（默认 true）

**输出**:
1. 控制台显示处理进度
2. 生成 `_fix_report_时间戳.md` 详细报告

**适用场景**:
- 从 V2.4.0 或更早版本升级的用户
- 发现项目中有残留占位符的用户
- 需要补全变更管理目录的用户
