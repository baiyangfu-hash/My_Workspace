## 🔧 修复内容详情

### [FIX-001] 🔴 严重：模板文件路径占位符未被替换

**问题描述**：
使用内置模板创建新项目时，14个文档文件名包含未替换的 `{project_code}` 占位符字符串。

**影响范围**：
- 所有新建项目（使用 TPL-SINGLE-PLC-001 / TPL-FULLLINE-AUTO-001 / TPL-SINGLE-ROBOT-001 模板）
- 影响文件数量：14个 .md 文件

**问题现象**：
```
❌ 错误：{project_code}_项目立项表.md
✅ 正确：DJ-2026-001_项目立项表.md
```

**根本原因**：
[`project_service.py`](../03_主程序/01_主程序核心代码/src/services/project_service.py) 中的 `create_project()` 和 `change_template()` 方法在生成文件路径时，直接使用了模板定义中的原始路径字符串（包含 `{project_code}` 占位符），未执行变量替换操作。

**修复方案**：
1. 新增 [`_resolve_template_path()`](../03_主程序/01_主程序核心代码/src/services/project_service.py#L27-L47) 静态方法，用于解析并替换路径中的所有占位符
2. 修改 `create_project()` 方法（第256行）调用新函数
3. 修改 `change_template()` 方法（第734行）调用新函数

**验证方法**：
```python
# 创建测试项目后执行
import glob
result = glob.glob("**/*{project_code}*", recursive=True)
assert len(result) == 0, "发现未替换的占位符"
```

**影响评估**：
- ✅ 仅影响新建项目（已有项目不受影响）
- ✅ 向后兼容，不破坏任何现有功能
- ⚠️ 已有项目需使用附带的 `fix_project_complete.ps1` 脚本手动修复

- 新建项目的变更管理目录完整性

## 🚀 安装与升级

### 全新安装

1. 解压 `Python自动化项目管理系统_V2.4.1_20260415.zip` 到任意目录
2. 双击 `Python项目管理工具.exe` 启动
3. 首次启动时配置项目存储路径

### 从 V2.4.0 升级

**推荐升级步骤**：

1. **备份现有数据**（重要！）
   ```
   复制以下目录到安全位置：
   - config/          # 配置文件
   - projects/        # 项目数据
   - data/project_manager.db  # 数据库
   ```

2. **解压新版本**
   - 将 V2.4.1 包解压到新目录（或覆盖旧版本）

3. **恢复配置和数据**
   - 将备份的 `config/` 和 `projects/` 复制回新版本目录

4. **修复已有项目**（可选但推荐）
   ```powershell
   cd 工具目录
   .\fix_project_complete.ps1 -ProjectPath "D:\Projects\你的项目名"
   ```

5. **启动验证**
   - 启动工具，确认版本显示为 V2.4.1
   - 创建一个测试项目验证 Bug 是否已修复

### 升级注意事项

⚠️ **重要提示**：
- 本版本为补丁修复版，核心功能无变化
- 配置文件格式完全兼容，无需手动修改
- 数据库结构无变化，可直接复用
