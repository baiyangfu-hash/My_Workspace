## 3. 系统概述

SW-2026-004 Python项目管理工具是一个功能全面的Python项目管理系统，旨在提供总库管理、项目管理、变更管理、插件系统等核心功能。系统采用分层架构设计，结合PyQt5 GUI界面和Flask API接口，为用户提供直观的操作体验。

## 4. 系统安装

### 4.1 系统要求

- **操作系统**：Windows 10/11
- **Python版本**：Python 3.8+
- **内存**：至少4GB
- **硬盘空间**：至少100MB

### 4.2 安装步骤

#### 4.2.1 安装包安装

1. 下载系统安装包 `Python项目管理工具.exe`
2. 双击运行安装包
3. 按照安装向导的提示完成安装
4. 安装完成后，在桌面会生成快捷方式

#### 4.2.2 源码安装

1. 克隆项目源码到本地
2. 安装依赖包：`pip install -r requirements.txt`
3. 运行主程序：`python main.py`

## 3. 系统登录

1. 双击桌面快捷方式或运行主程序
2. 系统启动后，会显示登录界面
3. 输入用户名和密码（默认用户名：admin，密码：admin）
4. 点击"登录"按钮进入系统主界面

## 4. 主界面介绍

系统主界面主要包含以下部分：

- **菜单栏**：位于顶部，包含文件、编辑、视图、工具、帮助等菜单
- **工具栏**：位于菜单栏下方，包含常用功能的快捷按钮
- **左侧导航栏**：包含总库管理、项目管理、变更管理、插件管理等功能模块
- **主工作区**：显示当前功能模块的详细内容
- **状态栏**：位于底部，显示系统状态和操作提示

## 6. 项目管理

### 6.1 项目列表

1. 在左侧导航栏点击"项目管理" -> "项目列表"

6. 选择项目后点击"查看详情"按钮查看项目详细信息

### 6.2 项目模板

1. 在左侧导航栏点击"项目管理" -> "项目模板"
2. 主工作区会显示项目模板列表
3. 点击"创建模板"按钮创建新项目模板
4. 选择模板后点击"编辑模板"按钮修改模板信息
5. 选择模板后点击"删除模板"按钮删除模板
6. 选择模板后点击"使用模板"按钮基于模板创建项目

**当前模板列表**：
- **整线项目模板**：适用于整线集成项目，包含所有内容
- **单机设备-机器人版**：适用于机器人单机设备项目，包含eplan、机械、通讯设计
- **单机设备-PLC-HMI版**：适用于PLC-HMI单机设备项目，包含eplan、机械、通讯设计
- **系统升级模板**：适用于系统升级项目
- **上位机项目模板**：适用于上位机软件项目，只有软件python

### 6.3 模板变更

1. 在左侧导航栏点击"项目管理" -> "项目列表"
2. 在项目列表中找到需要变更模板的项目
3. 右键点击项目行，在弹出的菜单中选择"变更模板"
4. 在弹出的对话框中，从下拉列表中选择新的模板
5. 点击"确定"按钮执行模板变更
6. 系统会根据新模板更新项目的目录结构和文件
7. 变更完成后，系统会显示成功提示

**注意**：模板变更会根据新模板的定义更新项目结构，可能会添加新的目录和文件，但不会删除现有的文件。

## 11. 交付物打包与发布

本工具提供全自动化的交付物打包脚本 `package.py`，用于将开发版本的代码编译为可分发的安装包。

### 11.1 打包脚本概述

`package.py` 是一个一键式自动化打包脚本，位于源码目录 `03_主程序/01_主程序核心代码/package.py`，能够自动完成从代码到 ZIP 归档的全部流程。

**自动化流程（10步）**：
1. 读取版本号并校验三处一致性
2. 同步数据库文件并清理绝对路径
3. 验证数据库完整性
4. PyInstaller 编译生成 EXE
5. 整理交付物目录结构
6. 同步项目文档到交付物
7. 创建 ZIP 归档
8. 自动更新打包版本记录

### 11.2 使用方法

#### 前置条件
- Python 3.8+ 环境
- 已安装 PyInstaller：`pip install pyinstaller`
- 源码目录结构完整

#### 基本命令

在 `03_主程序/01_主程序核心代码/` 目录下执行：

```bash
# 完整打包（推荐先试运行）
python package.py --dry-run

# 正式打包
python package.py

# 清理后重新打包（删除 build/dist 目录）
python package.py --clean

# 指定版本号（覆盖 version.py 的值）
python package.py --version 2.6.0

# 组合使用
python package.py --clean --version 2.6.0 --dry-run
```

#### 参数说明

| 参数 | 说明 | 示例 |
|------|------|------|
| （无参数） | 完整打包 | `python package.py` |
| `--version X.Y.Z` | 指定版本号 | `--version 2.6.0` |
| `--dry-run` | 试运行模式（只打印不执行） | `--dry-run` |
| `--clean` | 清理旧构建产物后重新打包 | `--clean` |
| `--help` | 显示帮助信息 | `--help` |

### 11.3 打包输出物

打包成功后，以下文件会自动生成或更新：

```
06_交付物/
├── 01_可执行文件/          ← 可运行目录
│   ├── Python项目管理工具.exe    (~58 MB)
│   ├── config/                  (4个JSON配置)
│   │   ├── app_config.json       (含版本号)
│   │   ├── api_config.json
│   │   ├── database_config.json
│   │   └── spec_version_config.json
│   ├── data/
│   │   └── project_manager.db     (已清理绝对路径)
│   └── Projects/.gitkeep         (预置项目目录)
├── 02_发布说明/            ← 版本文档
│   └── V{x.y.z}_更新说明.md
├── 03_项目文档/            ← 项目过程文档（自动同步）
│   └── ... (25个.md文件)

```

### 11.4 打包脚本内置的质量保障

`package.py` 在每个阶段都有自动校验机制，防止历史问题重现：

| 校验项 | 防止的问题 |
|--------|-----------|
| 三处版本号一致性校验 | 标题栏显示错误版本号 |
| 数据库同步+清理 | 分类项目数显示为0、root_path含旧绝对路径 |
| 数据完整性验证 | 交付物DB缺少必要数据 |
| EXE大小检查 (>50MB) | 打包不完整 |
| dry-run模式 | 提前发现配置问题 |

### 11.5 发布流程建议

1. **修改代码/修复Bug** → 更新 `version.py` 版本号
2. **本地测试** → 运行 `python main.py` 验证功能正常
3. **试运行打包** → 执行 `python package.py --dry-run` 确认无报错
4. **正式打包** → 执行 `python package.py`
5. **验证交付物** → 解压ZIP到测试目录，运行EXE确认功能
6. **归档发布** → 将ZIP上传至分发位置

### 11.6 常见打包问题

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 版本校验失败 | version.py 与 app_config.json 版本不一致 | 统一三处版本号后再打包 |
| PyInstaller 报错 | 缺少依赖或 hidden import | 检查 spec 文件的 hiddenimports 配置 |
| DB验证失败 | 源码DB缺少分类或项目数据 | 先在开发环境运行一次程序初始化DB |
| ZIP过大 | data/ 目录包含测试报告等临时文件 | 清理 data/reports/ 和 data/test_reports/ 后重打 |

## 12. 常见问题与解决方案

### 12.1 登录失败

- **问题**：输入用户名和密码后登录失败
- **解决方案**：检查用户名和密码是否正确，默认用户名：admin，密码：admin

### 12.2 插件安装失败

- **问题**：安装插件时失败
- **解决方案**：检查插件文件是否完整，是否符合系统要求

### 12.3 数据库连接失败

- **问题**：系统无法连接数据库
- **解决方案**：检查数据库连接参数是否正确，数据库服务是否运行

### 12.4 系统运行缓慢

- **问题**：系统运行缓慢
- **解决方案**：检查系统资源使用情况，关闭不必要的程序
