# 文档与代码同步更新机制

## 1. 概述

本文档描述了Python项目管理工具的文档与代码同步更新机制，旨在确保文档与代码保持一致，提高文档的准确性和时效性。

## 2. 同步机制设计

### 2.1 版本控制集成

- **统一版本控制**：使用Git对代码和文档进行统一版本控制
- **分支策略**：文档与代码使用相同的分支策略，确保版本对应
- **提交规范**：提交代码时，同时更新相关文档，并在提交信息中说明文档变更

### 2.2 文档生成自动化

- **API文档自动生成**：从Flask路由和函数注释自动生成API文档
- **代码结构文档**：从模块结构和类定义自动生成代码结构文档
- **示例代码验证**：自动验证文档中的示例代码是否可执行

### 2.3 变更检测与提醒

- **Git钩子**：使用pre-commit钩子检测代码变更，提醒更新相关文档
- **CI/CD集成**：在CI/CD流程中添加文档检查步骤，确保文档与代码同步
- **变更追踪**：使用变更日志记录代码和文档的变更历史

### 2.4 文档与代码关联

- **代码中的文档引用**：在代码中添加文档引用注释，指向相关文档章节
- **文档中的代码引用**：在文档中使用代码块和文件路径引用，便于定位代码
- **交叉引用**：建立文档与代码之间的交叉引用，便于互相导航

## 3. 实施步骤

### 3.1 版本控制配置

1. **初始化Git仓库**：确保代码和文档在同一Git仓库中
2. **配置.gitignore**：合理配置.gitignore文件，避免提交不必要的文件
3. **设置分支策略**：制定统一的分支策略，如main、develop、feature等

### 3.2 文档生成工具配置

1. **安装文档生成工具**：如Sphinx、mkdocs等
2. **配置文档生成规则**：根据项目结构配置文档生成规则
3. **集成到构建流程**：将文档生成集成到项目构建流程中

### 3.3 Git钩子设置

1. **创建pre-commit钩子**：检测代码变更，提醒更新相关文档
2. **创建post-commit钩子**：自动生成API文档等
3. **测试钩子功能**：确保钩子正常工作

### 3.4 CI/CD配置

1. **添加文档检查步骤**：在CI/CD流程中添加文档检查
2. **配置文档部署**：自动部署更新后的文档
3. **设置通知机制**：当文档与代码不同步时发送通知

## 4. 最佳实践

### 4.1 文档编写规范

- **使用一致的文档格式**：统一使用Markdown格式
- **保持文档结构清晰**：使用层级结构，便于导航
- **添加详细的示例**：在文档中添加详细的代码示例和使用场景
- **定期更新文档**：确保文档与代码保持同步

### 4.2 代码注释规范

- **函数注释**：使用文档字符串，说明函数功能、参数、返回值
- **模块注释**：说明模块功能、依赖关系
- **关键代码注释**：对复杂逻辑添加详细注释
- **文档引用**：在代码中添加文档引用，指向相关文档

### 4.3 变更管理

- **变更日志**：维护详细的变更日志，记录代码和文档的变更
- **版本标签**：使用版本标签标记重要的版本变更
- **文档审查**：在代码审查过程中同时审查相关文档

### 4.4 自动化测试

- **示例代码测试**：自动测试文档中的示例代码
- **文档链接测试**：测试文档中的链接是否有效
- **文档完整性测试**：检查文档是否完整，是否有缺失内容

## 5. 交付物打包自动化（package.py）

自 V2.5.9 起，本项目引入了全自动化的交付物打包脚本 `package.py`，实现了从源码到可分发 ZIP 的一键式自动化流程。

### 5.1 脚本定位

- **文件位置**: `03_主程序/01_主程序核心代码/package.py`
- **执行位置**: 必须在 `03_主程序/01_主程序核心代码/` 目录下执行
- **依赖**: Python 3.8+, PyInstaller, SQLite3（标准库）

### 5.2 完整工作流

```
┌─────────────────────────────────────────────────────────────┐
│                    package.py 全流程                          │
├─────────────────────────────────────────────────────────────┤
│ Phase 1: 准备与校验                                           │
│   Step 1  读取 version.py → 解析 VERSION                      │
│   Step 2  三处版本一致性校验 (version.py + app_config.json×2) │
│                                                              │
│ Phase 2: 数据库预处理                                          │
│   Step 3  复制源码 DB → 交付物/data/ (两处备份)                │
│   Step 4  SQL清理 root_path 含盘符记录                         │
│   Step 5  验证 categories≥5, projects≥1                       │
│                                                              │
│ Phase 3: PyInstaller 打包                                      │
│   Step 6  执行 pyinstaller --noconfirm .spec                   │
│   Step 7  验证 EXE > 50MB                                     │
│                                                              │
│ Phase 4: 交付物组装                                             │
│   Step 8  整理 01_可执行文件/ (EXE + config×4 + data + Projects)│
│   Step 9  同步 01_项目文档/ → 03_项目文档/ (25个md文件)        │
│                                                              │
│ Phase 5: 归档与记录                                            │
│   Step 10 创建 ZIP (整个 06_交付物/ 目录)                     │
│   Step 11 自动追加记录到 打包版本记录.md                        │
└─────────────────────────────────────────────────────────────┘
```

### 5.3 命令参考

| 场景 | 命令 | 说明 |
|------|------|------|
| **首次使用/日常打包** | `python package.py --dry-run` | ★ 推荐：先试运行确认无误 |
| **正式打包** | `python package.py` | 完整10步自动化 |
| **指定版本号** | `python package.py --version 2.6.0` | 覆盖 version.py |
| **完全重建** | `python package.py --clean` | 删除 build/dist 后重打 |
| **查看帮助** | `python package.py --help` | 显示所有参数 |

### 5.4 关键防护机制

package.py 内置了多层质量保障，防止历史交付物缺陷重现：

| 阶段 | 防护措施 | 解决的历史问题 |
|------|---------|--------------|
| Phase 1 | 三处版本号强制校验 | V2.5.7~V2.5.9 标题栏版本号错误 |
| Phase 2 | DB同步+root_path清理+完整性验证 | 分类项目数为0、D盘路径残留 |
| Phase 3 | EXE大小检查(>50MB)+超时保护 | 打包不完整 |
| Phase 4 | config×4强制同步 | 配置文件版本不一致 |
| Phase 5 | ZIP包含完整交付物目录 | 用户需下载多个文件 |

### 5.5 与本同步机制的关系

package.py 是本同步机制在**发布环节**的具体实现：

| 同步层面 | 工具/方法 | 触发时机 |
|---------|----------|---------|
| 代码→文档 | 开发者手动维护 + Git提交规范 | 每次代码变更时 |
| 文档→交付物 | package.py Phase 6 (sync_project_docs) | 每次打包时自动 |
| 代码→EXE | package.py Phase 3 (PyInstaller) | 每次打包时自动 |
| 数据→交付物 | package.py Phase 2 (DB同步+清理) | 每次打包时自动 |
| 版本→记录 | package.py Phase 5 (版本记录更新) | 每次打包时自动 |

### 5.6 维护指南

当需要发布新版本时的完整 checklist：

- [ ] 1. 更新 `src/core/version.py` 的 VERSION
- [ ] 2. 更新 `config/app_config.json` 的 version 字段（源码）
- [ ] 3. 本地运行 `python main.py` 验证功能
- [ ] 4. 执行 `python package.py --dry-run` 试运行
- [ ] 5. 确认所有 Phase 输出 [OK]
- [ ] 6. 执行 `python package.py` 正式打包
- [ ] 7. 解压 ZIP 到独立测试目录
- [ ] 8. 运行 EXE 验证：标题栏版本号、新建项目路径、总库管理、分类管理
- [ ] 9. 确认通过后将 ZIP 归档至正式分发位置
