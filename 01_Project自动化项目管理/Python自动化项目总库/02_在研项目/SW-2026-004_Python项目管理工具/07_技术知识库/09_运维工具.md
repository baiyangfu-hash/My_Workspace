# 运维工具说明

**文档版本**: V1.0.0
**编制日期**: 2026-04-17
**适用版本**: V2.5.5+

---

## 概述

本目录下的 Python 脚本用于诊断和修复 Python项目管理工具 的常见运行时问题。所有脚本均位于主程序目录下（`03_主程序/01_主程序核心代码/`）。

## 使用前提

- Python 3.8+ 已安装
- 当前工作目录为主程序目录
- 数据库文件 (`data/project_manager.db`) 存在且可访问

---

## 1. diagnose_library.py - 总库诊断脚本

**用途**: 检查总库管理模块的数据完整性

**何时使用**:
- 总库管理显示 0 个项目
- 项目管理与总库数据不一致
- 需要了解数据库当前状态

**运行方式**:
```bash
cd "03_主程序/01_主程序核心代码"
python diagnose_library.py
```

**输出内容**:
- libraries 表: 总库列表及状态
- projects 表: 所有项目列表
- library_projects 表: 关联记录（**关键！**）
- categories 表: 分类列表
- 诊断结论和建议

**示例输出关键项**:
```
【检查 3】library_projects 表（关联表）⭐ 最关键
关联记录数量: 3  ← 应该 > 0
```

**注意事项**:
- 只读操作，不会修改任何数据
- 可重复运行无副作用

---

## 2. repair_library_projects.py - 数据修复脚本

**用途**: 将已有的项目重新关联到默认总库

**何时使用**:
- `diagnose_library.py` 发现 library_projects 表为空
- 总库显示 0 个项目但项目管理有数据
- 数据迁移后关联关系丢失

**运行方式**:
```bash
cd "03_主程序/01_主程序核心代码"
python repair_library_projects.py
```

**执行过程**:
1. 查找默认总库（状态为 active 的第一个）
2. 遍历所有项目
3. 为每个尚未关联的项目创建关联记录
4. 自动创建缺失的业务线分类（5个）

**幂等性**: ✅ 可安全重复运行（已存在的关联会跳过）

**风险等级**: 低（只添加数据，不删除）

---

## 3. fix_category_id.py - 分类关联修复脚本

**用途**: 为已有项目分配正确的业务线分类

**何时使用**:
- 总库有项目但分类的项目数都是 0
- `repair_library_projects.py` 执行后分类仍未正确
- 项目业务线与分类不匹配

**运行方式**:
```bash
cd "03_主程序/01_主程序核心代码"
python fix_category_id.py
```

**执行逻辑**:
1. 查找所有 `category_id=None` 的关联记录
2. 通过 project_id 找到对应项目的 business_line
3. 根据 BusinessLine 枚举匹配到对应的 Category
4. 更新关联记录的 category_id

**依赖**: 必须先运行 `repair_library_projects.py` 确保关联记录存在

---

## 4. check_templates.py - 模板检查脚本

**用途**: 验证内置模板的完整性和正确性

**何时使用**:
- 怀疑模板数据损坏
- 需要确认 6 个模板全部正常
- 模板更新后验证

**运行方式**:
```bash
cd "03_主程序/01_主程序核心代码"
python check_templates.py
```

**检查项**:
- 模板数量是否为 6 个
- 每个 template 的关键字段（ID、名称、版本、structure、templates）
- 缺失或异常的模板

---

## 5. test_refresh.py / test_new_templates.py - 功能测试脚本

**用途**: 自动化测试特定功能（开发调试用）

**运行方式**:
```bash
python test_refresh.py        # 测试模板刷新功能
python test_new_templates.py  # 测试新模板（S001/M001）功能
```

**注意**: 这些脚本是临时测试工具，可能需要根据具体场景调整。

---

## 推荐排查流程

当遇到问题时，按以下顺序使用工具：

```
发现问题
  ↓
① 运行 diagnose_library.py     ← 了解现状
  ↓
② 根据诊断结果选择修复脚本
  ├─ 关联表为空 → repair_library_projects.py
  ├─ 分类为空   → fix_category_id.py
  └─ 模板异常   → check_templates.py
  ↓
③ 修复后重启应用验证
  ↓
④ 如仍有问题 → 查看 logs/app.log 详细日志
```
