# 模板目录结构与文件名规范调整 Spec

## Why

当前内置模板（特别是 TPL-SINGLE-PLC-001 单机设备PLC+HMI）存在两个关键问题：
1. **文件名包含占位符**（如 `{project_code}_需求分析文档.md`），用户无法在GUI中正常编辑/删除这些占位符，且文件系统层面不够整洁
2. **目录编号排序不合理**（00_/10_/20_/30_/40_/07_/90_ 跳号严重），且子目录结构与实际PLC项目工作流不匹配

基于用户提供的实际参考项目（`DJ-2026-000初始项目`）和FB开发实践（输送机/气缸项目），需重新调整模板定义以对齐真实工作流。

## What Changes

### 变更1: 文件名去除占位符（**影响所有5个模板**）

| 修改前 | 修改后 | 说明 |
|--------|--------|------|
| `{project_code}_项目立项表.md` | `项目立项表.md` | 去除文件名中的占位符 |
| `{project_code}_需求分析文档.md` | `需求分析文档.md` | 同上 |
| `{project_code}_IO分配表.md` | `IO分配表.md` | 同上 |
| `{project_code}_操作手册.md` | `操作手册.md` | 同上 |

**规则**: 占位符 `{xxx}` 仅保留在**文件内容**内部，**文件路径(path)** 中不再使用占位符。

## ADDED Requirements

### REQ-1: 文件名不含占位符

所有 `templates[].path` 中文件名不含 `{xxx}`。占位符仅出现在 `content` 字段中。

### REQ-2: 一级目录连续编号 00~07

不允许跳号。编号语义:
- 00=管理 / 01=需求 / 02=PLC / 03=HMI / 04=设备 / 05=测试 / 06=交付 / 07=工具

### REQ-3: 子目录含说明文件

每个二级子目录应包含一个同名的说明性 .md 文件（如 `功能块/功能块说明.md`），用于描述该目录的用途和内容规范。

### REQ-4: 02_PLC程序 对齐FB开发实践

02_PLC程序 下按 `主程序/功能块/变量表/模块配置/程序文档` 划分，其中 `功能块/` 下支持按单个FB创建子目录（含开发文档+程序文件+变量表格的三层结构）。

### REQ-5: 变更管理统一由工具模块处理

**重要**: FB/程序的变更文档（版本变更记录）不在模板目录结构中单独维护。所有项目变更通过工具的「变更管理功能模块」统一管理和监控。模板中的 `06_文档与交付/版本变更记录/版本变更记录.md` 仅作为全局版本摘要台帐，不替代变更管理模块。

### REQ-6: template_editor.py 提示优化

添加文件时提示："文件名建议使用中文纯名称（如：需求分析文档.md），不需要加 {project_code} 等占位符"
