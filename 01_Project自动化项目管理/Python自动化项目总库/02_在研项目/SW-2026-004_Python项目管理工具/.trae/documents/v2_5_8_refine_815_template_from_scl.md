## 一、核心原则

### 以 801 命名规范为准，以实战代码为场景验证

```
权威层级:
  801命名规范 (DEV-V1.0.2)     ← 最高权威，命名示例必须符合此规范
       ↓ 引用
  815接口文档模板 (待更新)      ← 本计划的目标文件
       ↓ 验证场景
  FB_ConveyorControlV4.scl     ← 实战参考（早期项目，用于发现模板缺失的章节）
```

**重要**: `FB_ConveyorControlV4` 是早期项目，其命名（如 `tmp_` 前缀、缺少类型前缀）**不符合 801 规范**。模板中的示例应使用 **801 合规的命名**，而非照搬早期代码。

## 二、差距分析（模板 V1.0.0 vs 实战需求）

### 差距 1：命名规范引用缺失（严重）

**现状**: 模板第 3 章只有通用术语定义（PLC/FB/Modbus 等），**无 PLC 变量命名约定**。

**应有**: 引用 801 规范的命名规则作为接口文档的变量命名标准。

**801 规范要点**（需在模板中体现）:

| 变量类别 | 801 格式 | 合规示例 | 不合规(早期项目) |
|----------|----------|----------|----------------|
| VAR_INPUT | `i_` + 类型前缀 + 描述 | `i_bStartButton`, `i_nSpeedFreq` | `i_Start` ❌ |
| VAR_OUTPUT | `q_` + 类型前缀 + 描述 | `q_bMotorRun`, `q_rSpeedOutput` | `q_MotorRunning` ❌ |
| VAR_INOUT | `iq_` + 类型前缀 + 描述 | `iq_rSetSpeed` | `i_SpeedFrequency` ❌ |
| **VAR (内部)** | **类型前缀 + 描述（无作用域前缀！）** | `bManualMode`, `nCurrentMode`, `rCurrentSpeed` | `tmp_bManualMode` ❌ |
| 全局变量 | 类型前缀 + 描述 | `bSysAutoMode` | — |
| 沿检测 | `LDP_` / `LDF_` + 类型 + 描述 | `LDP_bStart` | — |

**类型前缀表**（来自 801 §2.2）:

| 类型 | 前缀 | 示例 |
|------|------|------|
| BOOL | `b` | `bStart`, `bAlarmActive` |
| INT | `i` | `iCount`, `iCurrentMode` |
| DINT | `li` | `liNoProductDelay` |
| REAL | `r` | `rCurrentSpeed`, `rSpeedInput` |
| STRING | `s` | `sProductName` |
| 数组 | `a` | `aTimerIn[10]` |

### 差距 2：内部变量章节缺失（严重）

**现状**: 模板只有 INPUT / INOUT / OUTPUT 三类表格。

**实际问题**: 即使按 801 规范正确命名的内部变量（如 `bManualMode`, `nCurrentMode`, `bAlarmActive`, `nStatusWord`），在理解 FB 行为时仍然至关重要。

从 `FB_ConveyorControlV4` 中提取的**关键内部变量**（名称已修正为 801 合规）:

| 内部变量 (801合规名) | 类型 | 为什么需要文档化 |
|---------------------|------|-----------------|
| `nCurrentMode` | INT | 状态机核心：当前运行模式 (0停止/1手动/2自动) |
| `bManualMode` | BOOL | 手动模式激活标志 |
| `bAutoMode` | BOOL | 自动模式激活标志 |
| `bMotorRunning` | BOOL | 电机运行内部状态 |
| `bMotorFault` | BOOL | 电机故障内部状态 |
| `bAlarmActive` | BOOL | 报警激活状态（影响所有输出行为） |
| `bAlarmReadyForReset` | BOOL | 报警可复位条件（需5秒延时后） |
| `bModeError` | BOOL | 模式切换错误标志 |
| `bPosition1Detected` | BOOL | 产品位置1检测标志 |
| `bProductInPlaceDone` | BOOL | 产品到位完成标志 |
| `bStartRequested` / `bStopRequested` | BOOL | 启动/停止请求标志 |
| `nStatusWord` | INT | 状态字（位组合输出） |
| `nCurrentMotorDirection` | INT | 当前电机方向 |
| `nSpeedMode` | INT | 当前速度模式 (0停/1慢/2快) |
| `nNoProductDelay` | DINT | 无产品检测延时计数器 |
| `rCurrentSpeed` | REAL | 当前速度频率值 |
| `rSpeedInput` | REAL | 速度输入处理值 |
| `aTimerIn[0..9]` | BOOL数组 | TONR 计时器 IN 输入 |
| `aTimerQ[0..9]` | BOOL数组 | TONR 计时器 Q 输出 |
| `aTimerPT[0..9]` | DINT数组 | 计时器预设值 |
| `aTimerET[0..9]` | DINT数组 | 计时器当前值 |

**模板需要新增**: **5.x 内部变量章节**（含完整表格 + 关键变量行为说明）

### 差距 3：位字段(状态字) 文档化缺失（中等）

**实际模式**: 输出 `nStatusWord` (INT) 通过位操作编码多个状态：

```scl
// 位分配（从实际代码提取）
nStatusWord := nStatusWord OR 16#0001;   // Bit0: ModeError (模式错误)
nStatusWord := nStatusWord OR 16#0002;   // Bit1: DriveAlarm (驱动报警)
nStatusWord := nStatusWord OR 16#0004;   // Bit2: DirInputError (方向输入错误)
```

**模板需要新增**: **位字段定义表**格式

### 差距 4：状态机/模式转换无结构化描述（中等）

**FB 的核心逻辑是状态机**（CASE 语句驱动），但模板只有自由文本「核心控制逻辑」占位符。

**模板需要新增**: 运行模式与状态转换的结构化描述格式

### 差距 5：计时器和报警流程无专项章节（低）

实际 FB 使用 3 个 TONR 计时器各有明确用途，且有完整的报警→延时→复位链路。

**模板需要新增**: 计时器资源汇总 + 报警处理流程说明

### 差距 6：其他细节改进（低）

- INOUT 变量缺「双向行为」说明列
- 「触发条件」改为「激活条件」更准确
- 变更记录「人员」字段应标为可选
- 调用示例增加硬件地址映射版本

```
### 5.1.10 位字段定义

适用于 INT/WORD/DWORD 型输出变量中包含多位语义的情况。

**{StatusWord_Variable}** 位定义:

| 位位置 | 掩码值 | 名称 | 含义 | 置位条件 | 清除条件 |
```

**5.1.12 故障/报警处理流程**:
```
### 5.1.12 故障/报警处理流程

**报警响应**:
1. 报警信号激活 → bAlarmActive := TRUE, q_bMotorFault := TRUE
2. 报警期间 → 只响应停止信号，屏蔽启动信号
3. 运行中报警 → 立即停止电机

**报警解除**:
1. 报警信号消失 → 开始5秒倒计时
2. 倒计时结束 → bAlarmReadyForReset := TRUE
3. 按下复位 → bAlarmActive := FALSE, q_bMotorFault := FALSE
```


**INOUT 字段表格特有列说明**:
- 「读写属性」: `读`(仅读取外部值) / `写`(可修改传回) / `读写`(双向)
- 「关联输出」: 该 INOUT 变量的修改会影响到哪个输出变量
