# 模板结构整改计划

## 1. 项目概况

### 1.1 项目背景
根据模板结构规范分析报告，当前Python项目管理工具的内置模板结构不符合Obsidian规范文件仓库中的标准规范，需要进行全面整改。

### 1.2 整改目标
将所有内置模板的目录结构、文档命名和内容格式调整为符合规范的标准格式，确保项目结构的一致性和规范性。

## 2. 整改内容

### 2.1 目录结构调整

**当前目录结构**：
- `00_项目管理`
- `10_技术设计`
- `20_软件程序`
- `30_设备配置`
- `40_交付与文档`
- `07_交付文档`
- `90_知识库_本项目`

**规范目录结构**：
- `00_项目基础信息`
- `01_项目文档`
- `02_开发文件`
- `03_测试文档`
- `05_部署文档`
- `07_交付文档`
- `08_技术知识库`

### 2.2 文档命名规范

**当前命名格式**：
- `{project_code}_项目立项表.md`
- `{project_code}_需求分析文档.md`

**规范命名格式**：
- `[序号]-[文档名称]_[类型]-V[版本号].md`
- 例如：`000_{project_code}_项目立项表_PROJ-V1.0.0.md`

### 2.3 模板结构调整

需要调整的模板：
1. **TPL-FULLLINE-AUTO-001** (自动化整线项目)
2. **TPL-SINGLE-ROBOT-001** (单机设备-机器人)
3. **TPL-SINGLE-PLC-001** (单机设备-PLC+HMI)
4. **TPL-UPGRADE-STD-001** (系统升级改造)
5. **TPL-UPPER-STD-001** (上位机/数据系统)

## 3. 整改步骤

### 3.1 步骤一：更新DEFAULT_TEMPLATES配置

1. **修改constants.py文件**：
   - 更新所有模板的 `structure` 字段，将目录结构调整为规范格式
   - 更新所有模板的 `templates` 字段，将文档路径和命名调整为规范格式
   - 确保所有模板都包含规范要求的目录

2. **具体调整内容**：
   - 将 `00_项目管理` 改为 `00_项目基础信息`
   - 将 `10_技术设计` 改为 `01_项目文档`
   - 将 `20_软件程序` 改为 `02_开发文件`
   - 新增 `03_测试文档` 目录
   - 新增 `05_部署文档` 目录
   - 将 `90_知识库_本项目` 改为 `08_技术知识库`
   - 更新所有文档路径为规范命名格式

### 3.2 步骤二：更新模板服务

1. **检查template_service.py**：
   - 确保模板服务能够正确处理新的目录结构
   - 验证模板验证逻辑是否支持新的文档命名格式
   - 确保模板导入导出功能能够正确处理新的模板结构

2. **必要时修改服务代码**：
   - 调整模板验证逻辑
   - 更新模板导入导出功能
   - 确保模板重置功能能够正确处理新的模板结构

### 3.3 步骤三：验证整改结果

1. **重置内置模板**：
   - 运行 `TemplateService.reset_builtin_templates()` 重置所有内置模板
   - 验证模板是否正确加载

2. **测试模板创建**：
   - 使用整改后的模板创建新项目
   - 验证项目结构是否符合规范
   - 检查文档命名是否符合规范

3. **验证文档内容**：
   - 检查生成的文档内容是否符合规范
   - 验证文档格式是否一致

## 4. 风险评估

### 4.1 潜在风险

1. **兼容性风险**：
   - 现有项目可能使用旧的模板结构
   - 模板导入导出可能受到影响

2. **功能风险**：
   - 模板服务可能需要调整以支持新的目录结构
   - 文档生成功能可能需要更新

### 4.2 风险应对措施

1. **兼容性处理**：
   - 保留旧模板的备份
   - 提供模板迁移工具

2. **功能保障**：
   - 充分测试模板服务的所有功能
   - 确保模板重置功能能够正确处理新旧模板结构
