# V2.5.5 质量规范持久化 + 总库管理修复计划

## 问题背景

用户提出两个关键问题：

### 问题 1：质量保证流程的持久性存疑
**用户原话**："你所谓的标准化质量保证流程怎么建立的？你记住了？还是补充了全局规范？"

**现状分析**：
- ✅ V2.5.4 已创建 `gui_test_plan.md` (58KB) 和 `module_iteration_plan.md`
- ❌ **但这些文档只在 `.trae/specs/v2_5_4_template_focus_fix/` 目录下**
- ❌ **未纳入全局规范仓库** `00_Obsidian_Base全局规范文件仓库`
- ❌ **后续迭代不会自动参考这些流程**（除非手动去查看）

**用户合理担忧**：如果流程只存在于单次 iteration 的 spec 目录下，那就不是真正的"标准化"，只是"一次性产出"。

### 问题 2：总库管理模块不显示项目数据
**现象**（用户提供截图）：
- "项目管理"选项卡：显示 **3 个项目**（DJ-2026-003, DJ-2026-002, DJ-2026-001）
- "总库管理"选项卡：显示 **总项目数: 0, 分类数: 0**

**代码分析结果**：

#### 数据流追踪：
```
创建项目 (project_service.py:353-369)
  ↓
自动调用 LibraryService.add_project_to_library()
  ↓
写入 LibraryProject 关联表 (library_dao.py:127-147)
  ↓
总库查询统计 (library_dao.py:192-227)
  通过 JOIN LibraryProject 表获取项目列表
```

#### 可能的根因：
1. **默认总库 ID 不匹配**
   - `project_service.py:69` 硬编码 `library_id = "LIB-DEFAULT-001"`
   - 但 `initialize_default_library()` 动态生成 UUID 格式 ID（如 `LIB-20260416-abc12345`）
   - 导致查找总库失败 → 关联失败

2. **add_project_to_library 静默失败**
   - 第 368-369 行只有 warning 日志，没有抛出异常
   - 用户看不到错误提示，以为成功了

3. **缓存问题**
   - `library_dao.py:139` 使用 cache 清除机制
   - 可能缓存未正确失效

### Task 2: 修复总库管理数据显示问题（P0）

#### 目标
确保创建的项目能正确显示在总库管理模块中，解决"项目管理有数据但总库显示 0"的问题。

#### 诊断步骤（必须先完成）

**2.1 检查数据库实际状态**

编写诊断脚本检查：
```sql
-- 检查 1: 总库表
SELECT library_id, name, status FROM libraries;

-- 检查 2: 项目表
SELECT project_id, code, name, status FROM projects;

-- 检查 3: 关联表（关键！）
SELECT * FROM library_projects;

-- 检查 4: 如果关联表为空，说明问题确认
```

预期发现：
- `libraries` 表：可能有 1 个总库（ID 不是 LIB-DEFAULT-001）
- `projects` 表：有 3 个项目记录
- `library_projects` 表：**为空**（这就是 bug 根因）

**2.2 检查日志中的警告信息**

搜索日志文件 `logs/app.log` 中的关键词：
- `"项目归档到总库失败"`
- `"总库不存在"`
- `"initialize_default_library"`

这会告诉我们具体是哪个环节失败了。

#### 修复方案（根据诊断结果选择）

**方案 A：修复默认总库 ID 匹配问题（最可能）**

修改文件：`src/services/project_service.py`

当前代码（第 356-359 行）：
```python
lib = LibraryService.get_library(library_id)
if not lib and library_id == "LIB-DEFAULT-001":
    lib, _ = LibraryService.initialize_default_library()
```

问题：`initialize_default_library()` 返回的总库 ID 是动态生成的（如 `LIB-20260416-xxx`），不是硬编码的 `LIB-DEFAULT-001`。

修复策略：
```python
# 方案 A1: 使用名称匹配而非 ID 匹配
if not lib:
    # 尝试通过名称查找默认总库
    libraries, _ = LibraryService.list_libraries(keyword="Python自动化项目总库")
    if libraries:
        lib = libraries[0]
        logger.info(f"通过名称匹配到默认总库: {lib.library_id}")
    else:
        # 真正不存在才初始化
        lib, _ = LibraryService.initialize_default_library()
```

或者更彻底的：

```python
# 方案 A2: 统一使用常量定义默认总库 ID
# 在 constants.py 中定义:
DEFAULT_LIBRARY_ID = "LIB-DEFAULT-001"

# 在 initialize_default_library() 中强制使用此 ID
# 而不是动态生成 UUID
```

**方案 B：增强错误提示和日志**

修改文件：`src/services/project_service.py`（第 366-369 行）

当前代码：
```python
if add_ok:
    logger.info(f"项目 {project.code} 已自动归档到总库 {lib.name}")
else:
    logger.warning(f"项目归档到总库失败: {add_msg}")  # ← 只是 warning!
```

修复：升级为 ERROR 并考虑是否应该阻止项目创建成功
```python
if add_ok:
    logger.info(f"项目 {project.code} 已自动归档到总库 {lib.name}")
else:
    logger.error(f"⚠️ 项目归档到总库失败: {add_msg}")
    # 可选：是否要返回错误给用户？
    # 当前行为：项目创建成功但不在总库中（可能导致困惑）
```

**方案 C：提供手动补救措施**

在总库管理 UI 中增加"同步项目"按钮：
- 扫描 projects 表中所有项目

- 批量添加到默认总库
