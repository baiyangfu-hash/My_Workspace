### 2.3 10步自动化流程详解

`package.py` 将完整打包过程分为 **5个Phase**，每个Phase包含若干具体步骤:

---

#### Phase 1: 准备与校验

**步骤 1 — 读取版本号**
- 从 [src/core/version.py](../03_主程序/01_主程序核心代码/src/core/version.py) 中解析 `VERSION = "x.y.z"` 变量
- 若使用 `--version` 参数则跳过文件读取，直接使用命令行指定值
- 版本号格式校验: 必须匹配 `\d+\.\d+\.\d+` 正则表达式

**步骤 2 — 三处版本一致性校验**
- 校验点 A: `src/core/version.py` 的 VERSION 变量
- 校验点 B: `config/app_config.json` 的 version 字段
- 校验点 C: `06_交付物/01_可执行文件/config/app_config.json` 的 version 字段（首次打包时该文件不存在属于正常情况）
- 不一致时打印警告详情，但**不阻断流程**（仅告警继续执行）

**预期输出示例**:
```
============================================================
Phase 1: 版本一致性校验
============================================================
  [OK] version.py: 2.5.9
  [OK] 源码 config/app_config.json: 2.5.9
  [OK] 交付物 config/app_config.json: 2.5.9
[OK] 所有版本号一致: V2.5.9
```

---

#### Phase 2: 数据库预处理

**步骤 3 — 验证源码数据库存在**
- 检查 `data/project_manager.db` 是否存在
- 不存在则报错终止

**步骤 4 — 复制DB到两个交付物位置**
- 目标位置 1: `06_交付物/01_可执行文件/data/project_manager.db`
- 目标位置 2: `06_交付物/data/project_manager.db`（备份副本）

**步骤 5 — 清理绝对路径 root_path**
- 执行 SQL: `UPDATE libraries SET root_path='' WHERE root_path LIKE '%:%'`
- 对两个目标DB都执行清理操作
- 输出清理的记录数量

**步骤 6 — 验证数据完整性**
- categories 表记录数 >= 5 （否则 WARN）
- projects 表记录数 >= 1 （否则 WARN）
- libraries.root_path 无含盘符的值 （否则 FAIL）

**注意**: Phase 2 失败会**阻断后续流程**（退出码=2）

---

#### Phase 3: PyInstaller 打包

**步骤 7 — 执行 PyInstaller 编译**
- 命令: `pyinstaller --noconfirm Python项目管理工具.spec`
- 超时设置: 600秒（10分钟）
- 使用 spec 文件而非命令行参数（保证构建配置的一致性和可重复性）

**步骤 8 — 验证 EXE 文件**
- 检查 `dist/Python项目管理工具.exe` 是否存在
- 文件大小检查: 必须 > 50MB（阈值常量 `MIN_EXE_SIZE_BYTES`），偏小时发出警告

**预期输出**:
```
============================================================
Phase 3: PyInstaller 打包
============================================================
  [OK] Spec 文件存在: Python项目管理工具.spec
  正在执行 PyInstaller 打包...
  [OK] PyInstaller 执行成功
  [OK] EXE 文件已生成: Python项目管理工具.exe (57.95 MB)
```

**注意**: Phase 3 失败会**阻断后续流程**（退出码=3）

---

#### Phase 4: 交付物组装

**步骤 9 — 整理交付物目录结构**

| 操作 | 来源 | 目标 |
|------|------|------|
| 复制EXE | `dist/Python项目管理工具.exe` | `06_交付物/01_可执行文件/` |
| 同步配置(4个JSON) | `config/*.json` | `06_交付物/01_可执行文件/config/` |
| 更新版本号 | — | 交付物 `app_config.json` 的 version 字段 |
| 确保.gitkeep | — | `06_交付物/Projects/.gitkeep` |

同步的4个配置文件:
1. `app_config.json` — 应用基础配置（含版本号、语言、主题等）
2. `api_config.json` — API服务配置（host、port等）
3. `database_config.json` — 数据库连接配置
4. `spec_version_config.json` — 规范版本映射配置

**注意**: Phase 4 失败会**阻断后续流程**（退出码=4）

#### Phase 5: 归档与记录

**步骤 10 — 创建ZIP归档 + 更新版本记录**

## 3. 底层构建 (build.py)

### 3.1 build.py 与 package.py 的关系

```
package.py (上层编排脚本)
  |
  |---> Phase 1: 版本校验
  |---> Phase 2: DB预处理 (sync + clean + verify)
  |---> Phase 3: 调用 PyInstaller (通过 .spec 文件)
  |         (build.py 不被 package.py 直接调用)
  |---> Phase 4: 交付物组装
  |---> Phase 5: ZIP归档 + 版本记录

build.py (独立底层脚本)
  |
  |---> clean_build()           # 清理 build/dist/__pycache__
  |---> build_exe()            # 直接调用 PyInstaller 命令行
  |     |-- hiddenimports 硬编码在脚本中
  |     |-- add-data 动态检测 config/ 和 src/plugins/
  |     |-- excludes 排除不必要模块
  |---> copy_extra_files()     # 复制配置和插件到输出目录
```

**关键区别**:

| 特性 | package.py | build.py |
|------|-----------|----------|
| 构建方式 | 通过 `.spec` 文件调用 PyInstaller | 通过命令行参数直接调用 PyInstaller |
| DB处理 | 有（同步、清理、验证） | 无 |
| 交付物组装 | 有（完整目录结构整理） | 仅复制 config/plugins/data |
| ZIP归档 | 有 | 无 |
| 版本管理 | 有（三处一致性校验） | 无 |
| 适用场景 | **正式发布打包** | 快速测试编译 / 调试构建 |

## 4. PyInstaller 配置 (spec文件)

### 4.1 spec文件关键配置

Spec文件路径: [Python项目管理工具.spec](../03_主程序/01_主程序核心代码/Python项目管理工具.spec)

**Analysis 配置块**:

```python
a = Analysis(
    ['main.py'],                          # 入口文件
    pathex=['.'],                         # 搜索路径
    binaries=[],                           # 二进制依赖（无额外）
    datas=[                               # 数据文件打包规则
        ('config', 'config'),              # config/ -> config/
        ('src/plugins', 'src/plugins')     # src/plugins/ -> src/plugins/
    ],
    hiddenimports=[...],                   # 隐式导入列表（见下文）
    excludes=[...],                        # 排除模块列表（见下文）
    noarchive=False,
    optimize=0,
)
```

**PYZ 配置块** (归档Python纯模块):

```python
pyz = PYZ(a.pure)  # 将纯Python模块打包为 .pyz 归档
```

**EXE 配置块** (生成可执行文件):

```python
exe = EXE(
    pyz,
    a.scripts,
    a.binaries,
    a.datas,
    [],                                   # 无额外二进制排除
    name='Python项目管理工具',            # 输出文件名
    debug=False,                          # 非调试模式
    bootloader_ignore_signals=False,
    strip=False,                          # 不剥离符号表
    upx=True,                             # 启用UPX压缩
    upx_exclude=[],                       # UPX排除列表（空）
    runtime_tmpdir=None,
    console=False,                        # 无控制台窗口（GUI模式）
    disable_windowed_traceback=False,
    argv_emulation=False,
    target_arch=None,
    codesign_identity=None,               # 不进行代码签名
    entitlements_file=None,
)
```

**关键设计决策**:
- **单文件模式** (`onefile`): 所有依赖打包进单个 EXE，分发便捷
- **无控制台** (`console=False`): GUI应用不需要命令行窗口
- **UPX压缩启用** (`upx=True`): 减小EXE体积（需要系统安装UPX）
- **无COLLECT块**: onefile模式下不需要COLLECT步骤

### 4.2 datas 配置详解

哪些目录/文件被打入 EXE:

| 目录/文件 | 打包? | 目标路径 | 说明 |
|-----------|-------|---------|------|
| `config/*` | 是 | `config/` | 4个JSON配置文件，运行时必需 |
| `src/plugins/**` | 是 | `src/plugins/` | 插件代码和数据，功能必需 |
| `templates/` | 否 | — | 未打入，按需外置 |
| `data/` | **否** | — | **外部文件，不打入EXE**（用户数据，体积大且动态变化） |
| `alembic/` | 否 | — | 开发期迁移工具，无需打包 |

**为什么 data/ 不打入EXE**:
- `data/project_manager.db` 是SQLite数据库，包含用户的项目数据
- 数据库文件由 `package.py` Phase 2 单独复制到交付物目录
- 打入EXE会导致每次更新数据都需要重新打包
- 且数据库可能很大（含测试报告等），显著增加EXE体积

### 4.3 hiddenimports 完整列表

spec文件中的 hiddenimports（与 build.py 一致）:

```python
[
    # PyQt5 GUI框架
    'PyQt5', 'PyQt5.QtCore', 'PyQt5.QtGui', 'PyQt5.QtWidgets',

    # Web框架
    'flask',

    # ORM框架
    'sqlalchemy', 'sqlalchemy.dialects.sqlite',
    'sqlalchemy.orm', 'sqlalchemy.ext.declarative',

    # 工具库
    'click', 'markdown', 'dateutil',

    # 项目自有模块（隐式导入，PyInstaller无法自动检测）
    'src', 'src.core', 'src.models', 'src.dao', 'src.services',
    'src.ui', 'src.utils', 'src.api', 'src.plugins',
    'src.plugins.code_check', 'src.plugins.document_generator',
]
```

**为什么需要声明 hiddenimports**:
- PyInstaller 的静态分析无法检测到动态导入（如 `__import__()`, `importlib`）
- `src.*` 子模块通过 `sys.path` 注入后延迟导入，需显式声明
- 插件模块按需加载，不会被入口文件的静态分析覆盖

### 4.4 hiddenimports 常见问题

| 缺失模块 | 错误现象 | 解决方案 |
|---------|---------|---------|
| `_cffi_backend` | `ModuleNotFoundError: No module named '_cffi_backend'` | `pip install cffi` |
| `sip` | PyQt5 相关导入失败 | `pip install PyQt5-sip` |
| `MySQLdb` | 可忽略 | 本项目使用 SQLite，不需要 MySQL 驱动 |
| `src.core.*` | 自有模块导入失败 | 已在 hiddenimports 中声明；若仍有问题，检查 `sys.path` 设置 |
| `jinja2` | Flask 模板渲染失败 | `pip install jinja2`（Flask依赖，通常自动安装） |
| `markupsafe` | Jinja2 子依赖缺失 | `pip install markupsafe` |

**排查方法**:
1. 使用 `--debug` 模式运行（build.py）或 `console=True`（spec文件），查看控制台错误堆栈
2. 错误信息通常形如 `ModuleNotFoundError: No module named 'xxx'`
3. 将缺失模块添加到 spec 文件的 `hiddenimports` 列表中
4. 如果是第三方库的子模块，尝试安装对应的包

## 5. 常见构建错误及解决方案

### 5.1 PyInstaller 相关

| 错误信息 | 原因 | 解决方案 |
|---------|------|---------|
| `Hidden import not found: "xxx"` | 缺少隐式依赖声明 | 将模块名添加到 spec 文件的 `hiddenimports` 列表中 |
| `RecursionError: maximum recursion depth exceeded` | 存在循环引用或递归导入 | 将涉及模块添加到 `excludes` 列表中排除 |
| `EXE过大 (>100MB)` | 打入了不必要的数据或未启用UPX | 检查 datas 配置，确认 `data/` 未被打入；确认系统安装了UPX |
| `UPX is not available` | 系统未安装UPX压缩工具 | 下载UPX并放入PATH，或在spec中将 `upx改为False` |
| `TypeError: expected str, bytes or os.PathLike object` | datas 路径配置错误 | 确认datas元组格式为 `(源路径, 目标路径)` |
| `FileNotFoundError: main.py` | 工作目录不对 | `cd` 到 `01_主程序核心代码/` 目录后再执行 |

### 5.2 数据库相关

| 错误信息 | 原因 | 解决方案 |
|---------|------|---------|
| `database is locked` | 其他进程正在占用SQLite DB文件 | 关闭正在运行的程序（GUI/API/其他终端）；检查是否有ORM连接未关闭 |
| `no such table: xxx` | 数据库未完成初始化/表结构不匹配 | 先运行一次 `python main.py` 完成首次初始化；或执行 `alembic upgrade head` |
| `categories 表: 仅 N 条记录 (期望 >= 5)` | DB缺少预置分类数据 | 运行程序触发自动初始化；或手动检查数据库内容 |
| `libraries.root_path: 仍有N条含盘符记录` | 绝对路径清理失败 | 检查SQL语句是否正确执行；手动执行 `UPDATE libraries SET root_path='' WHERE root_path LIKE '%:%'` |
| `源码数据库不存在: data/project_manager.db` | 从未运行过程序 | 先执行 `python main.py` 进行首次初始化 |

### 5.3 路径相关

| 错误信息 | 原因 | 解决方案 |
|---------|------|---------|
| `FileNotFoundError: config` | 工作目录不是源码根目录 | 确认在 `03_主程序/01_主程序核心代码/` 下执行命令 |
| `路径显示 D:\xxx\...` (root_path含盘符) | DB中有旧的绝对路径记录 | 执行 `package.py` 会自动调用 `clean_root_paths()` 清理 |
| `Config file not found: app_config.json` | config目录缺失或路径错误 | 检查 `config/` 目录是否存在且包含4个JSON文件 |
| `交付物路径计算错误` | PROJECT_ROOT 回退级数不匹配 | `package.py` 中 `PROJECT_ROOT = SRC_DIR.parent.parent.parent`，确保目录结构不变 |

### 5.4 版本相关

| 错误信息 | 原因 | 解决方案 |
|---------|------|---------|
| `版本号格式无效: x.y` | 版本号不符合 `x.y.z` 格式 | 使用三位语义化版本号，如 `2.6.0` |
| `版本不一致警告` | 三处版本号不同步 | 统一修改 `version.py` 和 `config/app_config.json` 中的版本号 |
| `无法在 version.py 中找到 VERSION 变量` | version.py 文件损坏或格式变化 | 检查文件是否存在且包含 `VERSION = "x.y.z"` 格式的赋值语句 |
| `标题栏显示旧版本号` | app_config.json 中的 version 未更新 | 打包前同步更新所有三处版本号 |

### 5.5 网络与环境相关

| 错误信息 | 原因 | 解决方案 |
|---------|------|---------|
| `未找到 pyinstaller 命令` | PyInstaller 未安装 | `pip install pyinstaller` |
| `PyInstaller 执行超时（超过10分钟）` | 机器性能不足或依赖过多 | 使用 `--clean` 清理后重试；考虑使用 `--onedir` 模式减少打包时间 |
| `PermissionError` | 目标目录被占用或权限不足 | 关闭占用文件的程序；以管理员身份运行终端 |
| `zipfile.BadZipFile` | ZIP创建过程中中断 | 删除残留的ZIP文件后重新执行 |

## 附录B: 版本号管理规范

本项目采用**三位语义化版本号** (`MAJOR.MINOR.PATCH`):

| 位 | 含义 | 示例 | 触发条件 |
|----|------|------|---------|
| MAJOR | 主版本 | 2 | 架构重构、不兼容变更 |
| MINOR | 次版本 | 5 | 新增功能、向后兼容增强 |
| PATCH | 修订号 | 9 | Bug修复、小改进 |

**需要同步更新的位置**（共3处）:

1. [src/core/version.py](../03_主程序/01_主程序核心代码/src/core/version.py) — 第6行 `VERSION = "x.y.z"`
2. [config/app_config.json](../03_主程序/01_主程序核心代码/config/app_config.json) — `"version": "x.y.z"`
3. `06_交付物/01_可执行文件/config/app_config.json` — 由 `package.py` Phase 4 自动同步
