## 三、新发现问题

### 3.1 使用者视角新发现

#### NEW-A: 新建变更对话框缺少V2.1.0分类字段（高严重度）

**文件**: `change_manager.py` 第792-872行 `NewChangeDialog`

**描述**: 变更管理UI已升级到V2.1.0，表格支持领域/性质/范围筛选，详情页显示domain/nature/scope信息。但新建变更对话框仍使用旧版字段（仅有 `type_combo`），无 domain/nature/scope 选择器。

**影响**: 通过UI创建的所有变更单的 domain/nature/scope 字段为空，导致V2.1.0的筛选、分级审批、传播链分析功能全部失效。**这是V2.1.0升级后遗留的最严重的数据完整性问题。**

#### NEW-B: plugin_config 参数布局类型错误导致运行时崩溃（高严重度）

**文件**: `plugin_config.py` 第110行、第211行

**描述**: `self.params_layout` 在第110行定义为 `QVBoxLayout`，但第211行调用 `self.params_layout.addRow(label, value_label)`。`addRow` 是 `QFormLayout` 的方法，`QVBoxLayout` 没有此方法。

**影响**: 当插件有自定义配置参数时，点击该插件会触发 `AttributeError: 'QVBoxLayout' object has no attribute 'addRow'`，导致插件配置页面崩溃。

#### NEW-C: report_center 调用私有方法且参数类型不匹配（中严重度）

**文件**: `report_center.py` 第180行

**描述**: `ExportService._generate_project_md(project, content)` 调用了私有方法，且该方法第二个参数名为 `stats: dict`，但传入的是 `StatisticsService.get_project_statistics()` 的返回值，类型可能不匹配。

#### NEW-D: plugin_config 启用/禁用未处理返回值（中严重度）

**文件**: `plugin_config.py` 第216-224行

**描述**: `_on_enabled_changed()` 调用 `PluginService.enable/disable_plugin()` 返回 `(bool, str)` 元组，但返回值被完全忽略。操作失败时checkbox状态已变但实际状态未变，UI与数据不一致。

#### NEW-E: 变更管理表头仍含箭头前缀（低严重度）

**文件**: `change_manager.py` 第162行

**描述**: 数据行的 `"→ "` 前缀已修复，但表头仍为 `"→ 变更单"`，应改为 `"变更单号"`。

## 五、需求诊断（未变化，摘要）

前次诊断的核心发现仍然成立：

1. **PRD定位偏移约30%** — 仍声称"多技术栈全生命周期管理平台"，实际是Python项目元数据管理工具
2. **4项核心功能完全未实现** — FR-012(统一配置管理)/FR-014(统一测试管理)/FR-015(文档管理)/US-001(用户管理)，均无排期
3. **PRD中"插件市场"描述与实际严重不符** — 仅1个内置插件，无市场后端
4. **迭代需求文档仍为空壳** — 仅2行内容

**人工审核备注（来自前次报告）**：
- 主要目标是项目标准化（目录结构、程序结构、文档结构），依托全局规范和各技术栈规范
- 使用人员：产品型PM、电气工程师、上位机工程师(Python技术栈)
- 明确标注"不直接编辑PLC/HMI/Eplan文件，但要保存有技术设计方案文档"
- 无需用户管理，本地任何人可用
- 插件市场初衷是模块化开发，功能分散组合，方便迭代检查
- 3-5人小团队使用，规范项目管理和开发流程，将工作流固化

***

## 六、技术诊断（未变化，摘要）

前次诊断的核心技术问题仍然成立：

1. **DI容器空壳化** — 12个服务仅注册1个，`dependency-injector` 依赖形同虚设
2. **常量文件膨胀** — `constants.py` 620行混合5个领域，DEFAULT_TEMPLATES占440行
3. **高耦合证据** — `change_service.py` 直接静态导入5个其他服务
4. **Config类硬编码路径** — 使用 `Path(__file__).parent.parent.parent / "config"` 相对路径
5. **静态方法滥用** — 大量Service使用 `@staticmethod`，无法DI注入、无法mock测试

**改善项**：
- 服务层薄包装问题部分改善：approval/notification/impact 三个服务已升级为有实质逻辑（但仍有占位实现）
- 散装脚本已归位

***

## 七、项目管理诊断（未变化，摘要）

1. **文档"待更新"债务** — 测试报告数据为模板占位，交付清单签字栏空
