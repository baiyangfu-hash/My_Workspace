## V2.5.1 - 模板对齐变更管理模块

**目标**: 确保使用模板生成的项目包含完整的变更管理目录结构

**主要变更**:
- 更新 `constants.py` 中 DEFAULT_TEMPLATES 的模板定义
- 增强变更管理相关文件的模板内容
- 修复 `project_dao.py` count_by_status 方法的缓存键问题
- 更新 `.spec` 文件 pathex 配置
- 新增版本历史功能到 main_window.py

**发现的问题**:
- 模板数量与参考规范不一致（5 vs 6）
- 测试数据污染数据库

**经验教训**:
- 一次迭代范围过大会导致质量下降
- 需要真实的 GUI 测试而非脚本模拟

## V2.5.2 - 综合性修复

**目标**: 修复 V2.5.1 遗留问题和新增功能

**主要变更**:
- 增强 TemplateService 和 ProjectDAO 的缓存机制（TTL 60s→30s）
- 增强 LibraryManager UI 刷新逻辑
- 更新 LibraryDAO 缓存清除
- 创建 test_templates.py 自动化测试

**发现的问题**:
- 用户反馈"全面测试？测试的什么？" — 测试报告不被信任
- 刷新后模板表可能空白

**经验教训**:
- 测试必须真实运行 GUI，不能模拟
- WARNING 级别的日志可能掩盖严重问题

## V2.5.4 - 模板功能专项聚焦 ⭐

**目标**: 用户明确要求"重点解决模板功能模块问题"

**主要变更**:

## 经验总结（跨迭代）

### 做得好的 ✅
1. **Scope 聚焦**（V2.5.4）: 一次只解决 1-3 个核心问题
2. **Spec 驱动**: 先诊断再修复，有清晰的 tasks/checklist
3. **真实 GUI 测试**: 运行实际程序而非模拟
4. **增量式验证**: 每完成一步就验证
5. **详细日志**: 增强调试信息便于排查

### 需要改进 ⚠️
1. **数据库同步**: 代码改了但数据未必更新（需要显式清理/迁移）
2. **配置级联**: 多层配置文件的关系要文档化
3. **静默失败**: WARNING 可能掩盖严重问题（应升级为 ERROR）
4. **测试真实性**: 用户明确拒绝模拟测试报告
