# 规范同步功能使用说明

## 1. 功能概述

规范同步功能用于管理项目引用的全局规范版本，实现以下目标：

- **自动检查更新**：定期检查全局规范是否有新版本
- **版本对比**：对比当前版本与最新版本的差异
- **一键同步**：将项目引用的规范同步到最新版本
- **备份管理**：同步前自动备份旧版本规范
- **可视化界面**：提供友好的图形界面操作

## 2. 核心组件

### 2.1 配置文件

**文件路径**：`config/spec_version_config.json`

**功能**：
- 管理项目引用的全局规范清单
- 记录规范的当前版本和最新版本
- 配置同步和通知选项
- 设置自动检查频率

**配置项说明**：

```json
{
  "全局规范路径": "../../01_全局规范",
  "规范清单": {
    "规范名称": {
      "规范ID": "唯一标识",
      "当前版本": "V1.0.0",
      "最新版本": "",
      "规范路径": "相对路径",
      "自动更新": false,
      "重要性": "高/中/低"
    }
  },
  "同步配置": {
    "自动检查更新": true,
    "检查频率": "每天/每周/每月",
    "发现更新时": "提示用户"
  }
}
```

### 2.2 核心模块

**文件路径**：`src/core/spec_manager.py`

**主要功能**：
- `check_updates()`：检查规范更新
- `sync_spec()`：同步单个规范
- `sync_all_specs()`：同步所有规范
- `get_update_summary()`：获取更新摘要

### 2.3 UI界面

**文件路径**：`src/gui/spec_sync_dialog.py`

**功能特点**：
- 可更新规范列表展示
- 所有规范状态查看
- 同步日志记录
- 设置管理

python main.py check-spec --auto-sync

```bash

# 同步时不备份旧版本
python main.py sync-spec --no-backup
```

### 3.2 图形界面方式（GUI）

#### 3.2.1 打开规范同步中心

在主界面的「规范中心」标签页中，点击「规范同步」按钮

#### 3.2.2 界面功能说明

**规范状态表格**：
- 显示所有规范的当前状态
- 包含规范名称、当前版本、最新版本、状态和操作列
- 可更新的规范状态以红色显示
- 点击「同步」按钮同步单个规范

**同步工具栏**：
- 「检查更新」按钮：检查规范是否有新版本
- 「同步所有」按钮：同步所有可更新的规范
- 「备份旧版本」复选框：控制是否备份旧版本

**同步日志区域**：
- 记录所有同步操作的详细日志
- 显示操作时间、状态和结果
- 便于追踪历史操作和排查问题

**进度条**：
- 显示同步操作的进度
- 实时反馈同步状态

#### 3.2.3 操作步骤

1. **检查更新**：
   - 点击「检查更新」按钮
   - 等待检查完成
   - 查看规范状态表格中的更新状态
   - 可更新的规范会以红色显示

2. **执行同步**：
   - **同步单个规范**：在规范状态表格中点击对应规范的「同步」按钮
   - **同步所有规范**：点击「同步所有」按钮
   - 选择是否备份旧版本（默认勾选）
   - 等待同步完成
   - 查看同步结果和日志

3. **查看同步日志**：
   - 在同步日志区域查看详细的操作记录
   - 了解每个规范的同步状态和结果

4. **完成操作**：
   - 同步完成后，规范状态表格会自动更新
   - 点击「关闭」按钮退出对话框

## 4. 版本更新策略

### 4.1 版本号规则

规范版本号格式：`V主版本.次版本.修订号`

- **主版本号变化（V1.x.x → V2.x.x）**：重大更新，可能包含破坏性变更
- **次版本号变化（Vx.1.x → Vx.2.x）**：功能更新，新增功能或改进
- **修订号变化（Vx.x.1 → Vx.x.2）**：修订更新，修复错误或小幅改进

### 4.2 同步策略

| 更新类型 | 自动同步 | 人工确认 | 说明 |
|---------|---------|---------|------|
| 修订更新 | ✓ | 可选 | 小版本号变化，可自动同步 |
| 次版本更新 | ✗ | 必需 | 功能更新，建议查看差异 |
| 主版本更新 | ✗ | 必需 | 重大更新，必须人工确认 |

### 4.3 备份策略

- 默认开启备份功能
- 备份文件保存在 `config/backup/specs/` 目录
- 备份文件名格式：`规范名称_原版本_时间戳.md`
- 可随时恢复旧版本

## 6. 常见问题

### Q1: 如何添加新的规范到管理清单？

**A**: 编辑 `config/spec_version_config.json` 文件，在「规范清单」中添加新的规范条目：

```json
{
  "规范清单": {
    "新的规范名称": {
      "规范ID": "SPEC-XXX-001",
      "当前版本": "V1.0.0",
      "规范路径": "路径/规范文件_DOC-V1.0.0.md",
      "描述": "规范描述",
      "重要性": "高"
    }
  }
}
```

### Q2: 同步失败怎么办？

**A**: 
1. 检查全局规范路径是否正确
2. 确认规范文件是否存在
3. 查看同步日志获取详细错误信息
4. 手动检查规范文件权限

### Q3: 如何恢复旧版本规范？

**A**: 
1. 打开备份目录 `config/backup/specs/`
2. 找到需要恢复的备份文件
3. 手动复制备份文件到原位置
4. 更新配置文件中的版本号

### Q4: 可以跳过某些规范的更新吗？

**A**: 可以。在「可更新规范」列表中，只勾选需要同步的规范，不勾选的规范将被跳过。

### Q5: 如何查看规范的具体变更内容？

**A**: 
1. 在「所有规范」选项卡中双击规范名称
2. 查看规范详情对话框
3. 对比当前版本和最新版本的文件内容

## 7. 最佳实践

### 7.1 定期检查

建议每周至少检查一次规范更新，确保项目使用的规范始终是最新版本。

### 7.2 重要更新确认

对于主版本和次版本更新，务必仔细查看更新内容，评估对项目的影响后再同步。

### 7.3 备份保留

建议保留至少3个历史版本的备份，以便在需要时恢复。

### 7.4 团队同步

规范更新后，及时通知团队成员，确保所有人都使用最新版本的规范。
