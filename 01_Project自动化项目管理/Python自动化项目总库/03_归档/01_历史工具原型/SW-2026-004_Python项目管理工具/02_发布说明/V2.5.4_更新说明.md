#### 2. 模板变量解析逻辑增强

**问题描述**：

模板中的占位变量（如 `{project_name}`、`{date}` 等）在某些边界场景下解析不正确或解析失败。

**问题表现**：
- 变量嵌套时（如 `{project_name}_{date}`）解析顺序异常
- 特殊字符（如下划线、连字符）与变量边界冲突
- 未定义变量未做兜底处理，导致生成文件中出现原始占位符文本

**修复方案**：

1. **正则引擎升级**：采用更严格的变量匹配模式
   ```python
   # 修复前：简单字符串替换
   template.replace("{variable}", value)

   # 修复后：正则精确匹配 + 边界检测
   re.sub(r'\{(\w+)\}', lambda m: resolve_var(m.group(1)), template)
   ```

2. **嵌套变量支持**：实现多轮解析机制
   - 第一轮：解析基础变量（`{project_name}`, `{version}`）
   - 第二轮：解析组合变量（`{project_name}_{version}`）
   - 最大递归深度：3层（防止无限循环）

3. **未知变量兜底策略**：
   - 开发模式：输出 WARNING 日志并保留原占位符
   - 生产模式：替换为空字符串，确保生成文件干净

**影响范围**：所有模板的变量替换功能

**实现位置**：
- `src/services/template_service.py` - `resolve_variables()` 方法重写
- `src/core/template_engine.py` - 新增嵌套解析器类

#### 3. 模板目录结构校验加强

**问题描述**：

模板加载和生成过程中缺少严格的目录结构校验，可能导致以下异常情况：
- 模板定义中声明的目录与实际文件系统不一致
- 必需文件缺失时无明确提示
- 循环引用或非法路径未被拦截

**新增校验规则**：

| 校验维度 | 规则说明 | 处理方式 |
|----------|----------|----------|
| 结构完整性 | 模板声明目录必须100%存在于文件系统 | 加载时报错，阻断使用 |
| 必需文件检查 | 标记为 required 的文件必须存在 | 缺失时警告 + 自动跳过该模板 |
| 路径合法性 | 禁止包含 `..`、绝对路径、特殊字符 | 非法路径直接拒绝加载 |
| 循环引用检测 | 模板间不允许互相引用形成环 | 检测到循环时中断并报警 |
| 权限预检 | 目标路径可写性预检查 | 提前告知用户权限不足 |

**新增功能**：
- `TemplateValidator` 校验器类（独立模块）
- 模板健康度评分机制（0~100分）
- 校验报告自动生成（JSON格式）

**影响范围**：模板加载、项目管理、GUI提示
