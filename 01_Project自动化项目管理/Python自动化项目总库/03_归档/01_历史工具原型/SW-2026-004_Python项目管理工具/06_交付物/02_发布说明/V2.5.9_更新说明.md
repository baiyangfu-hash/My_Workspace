## 设计理念

### 核心目标

本版本的核心设计理念是：**彻底消除路径残留、统一版本标识、增强系统自愈能力**

### 解决的问题

在 V2.5.8 版本中，虽然已实现相对路径方案，但仍存在以下遗留问题：

1. **路径不一致性** - 新建项目路径在跨机器部署时仍可能显示旧绝对路径（PyInstaller 冻结环境兼容性问题）
2. **版本号混乱** - 标题栏显示的版本号与实际打包版本不一致，造成用户困惑
3. **数据库污染** - 交付物数据库中仍残留旧机器的绝对路径记录
4. **缺乏自愈机制** - 启动时无法自动清理无效路径数据

### 解决方案

采用**多层防御策略**：
- **Config 延迟安全导入**: 解决 PyInstaller 冻结环境的模块导入问题
- **4层路径优先级链路**: Config 配置 → 跳过不可信DB路径 → 自动检测 → 硬兜底
- **版本号三处统一**: version.py + 源码 app_config.json + 交付物 app_config.json
- **数据库自愈机制**: 启动时自动检测并清空含盘符的 root_path

## 变更清单

### F1: 路径一致性修复 (CRITICAL)

**涉及文件**: `src/ui/dialogs/new_project_dialog.py`

**问题根因**:
在 PyInstaller 冻结环境中，直接导入 Config 模块可能导致程序闪退。原代码在模块加载时就尝试读取配置，但在某些环境下配置文件尚未就绪。

**修复内容**:
1. 实现 **Config 延迟安全导入** - 在方法内部动态导入，避免启动时崩溃
2. 重构 **路径优先级链路**（4层降级策略）:

```
优先级1: Config.get_resolved_project_path()     ← 最高优先级（用户配置）
    ↓ 失败时降级
优先级2: 跳过不可信DB路径                      ← 过滤含盘符的 root_path
    ↓ 失败时降级
优先级3: 自动检测 {base_dir}/Projects            ← 基于程序位置
    ↓ 失败时降级
优先级4: exe_dir/Projects 硬兜底                ← 最终保底方案
```

**代码改进点**:

```python
# 修复前: 直接导入（可能在冻结环境闪退）
from src.core.config import Config

# 修复后: 延迟安全导入
def _update_default_path(self):
    try:
        from src.core.config import Config
        config_path = Config.get_resolved_project_path()
        if config_path:
            self.path_edit.setText(str(config_path))
            return
    except Exception:
        pass  # 优雅降级到下一优先级
```

**影响范围**: 新建项目对话框的默认路径显示

## 技术架构改进

### PyInstaller 冻结环境兼容性增强

**问题背景**:
PyInstaller 将 Python 程序打包成单个 EXE 文件时，会创建一个临时解压目录（`sys._MEIPASS`）。在此环境下：
- 模块导入顺序可能与开发环境不同
- 配置文件的相对路径解析需要特殊处理
- 某些模块在冻结环境可能缺失或行为异常

**解决方案**:

```python
# 安全导入模式
def safe_import(module_name: str):
    """
    安全导入模块（兼容 PyInstaller 冻结环境）
    
    Args:
        module_name: 模块名称
        
    Returns:
        模块对象或 None（导入失败时）
    """
    try:
        import importlib
        return importlib.import_module(module_name)
    except ImportError as e:
        logger.warning(f"模块导入失败: {module_name}, 错误: {e}")
        return None
    except Exception as e:
        logger.error(f"未知错误: {module_name}, 错误: {e}")
        return None
```

### 路径解析优先级重构

**新架构（4层优先级 + 最终降级）**:

```
用户点击"新建项目"
    ↓
[优先级1] Config.get_resolved_project_path()
    ├── 成功 → 使用配置路径 ✅
    └── 失败/异常 → 降级 ↓

[优先级2] 跳过不可信DB路径
    ├── DB路径不含盘符 → 使用DB路径 ✅
    └── DB路径含盘符 → 跳过，降级 ↓

[优先级3] 自动检测 {base_dir}/Projects
    ├── 目录存在或可创建 → 使用该路径 ✅
    └── 创建失败 → 降级 ↓

[优先级4] exe_dir/Projects 硬兜底
    └── 最终保底方案（几乎不会失败）✅
```

**优势**:
- 每一层都有失败保护
- 优雅降级，不会因单点故障导致功能不可用
- 兼容各种部署场景（本地/U盘/网络驱动器）

### 数据库零污染策略

**设计原则**: 交付物数据库不应包含任何机器相关的绝对路径

**实施措施**:
1. **打包前预清理** - 手动清空 root_path
2. **运行时自愈** - 启动时自动检测并清理
3. **写入时过滤** - 写入数据库前校验路径合法性

**代码示例**:

```python
def _is_trustworthy_path(self, path: str) -> bool:
    """
    判断路径是否可信（不含盘符）
    
    Args:
        path: 待检测路径
        
    Returns:
        True: 可信（相对路径或空）
        False: 不可信（含绝对路径）
    """
    if not path or path.strip() == '':
        return True  # 空路径视为可信
    
    # 检测 Windows 盘符 (C:, D:, E: 等)
    if len(path) >= 2 and path[1] == ':':
        return False
    
    # 检测 UNC 路径 (\\server\share)
    if path.startswith('\\\\'):
        return False
    
    return True
```

### 使用限制

1. **路径长度限制**: Windows 系统最大路径长度为 260 字符（除非启用长路径支持）
   - 建议: 避免过深的目录嵌套
   - 解决: 启用 Windows 长路径支持（Windows 10 1607+）

2. **权限要求**:
   - 常规使用: 标准用户权限即可
   - 安装到 Program Files: 可能需要管理员权限
   - U盘使用: 注意写保护开关状态

3. **字符编码**:
   - 支持中文路径和文件名
   - 建议避免使用特殊符号（如 `< > : " \| ? *`）

4. **数据库自愈限制**:
   - 自愈机制仅在启动时执行
   - 如需立即清理，可重启程序
   - 自愈操作会记录日志，可在日志文件中查看详情

### B. 术语表

| 术语 | 定义 |
|------|------|
| **Config 延迟安全导入** | 在方法内部动态导入 Config 模块，而非模块顶层导入，避免 PyInstaller 冻结环境闪退 |
| **4层路径优先级** | 路径解析的降级策略：Config配置 → 跳过不可信DB路径 → 自动检测 → 硬兜底 |
| **数据库自愈能力** | 程序启动时自动检测并清理数据库中的无效数据（如旧绝对路径） |
| **策略0** | LibraryService 的最高优先级路径返回策略，直接返回 `{base_dir}/Projects` |
| **root_path 污染** | 数据库 libraries 表的 root_path 字段包含特定机器的绝对路径 |
| **PyInstaller 冻结环境** | 使用 PyInstaller 打包后的 EXE 运行环境，模块导入行为与开发环境不同 |
| **不可信路径** | 包含盘符（如 D:\, C:\）或 UNC 路径（\\server\）的绝对路径 |
