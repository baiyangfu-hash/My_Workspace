# 同步项目文档到交付物方案

## Why

### 当前状态

**`01_项目文档/` 目录** 包含 25 个项目管理过程文档（按 PMBOK 5 大过程组组织）：

| 过程组 | 文档数 | 关键内容 |
|--------|--------|---------|
| 01_启动过程 | 3 | 项目章程、产品路线图、存量资产基线清单 |
| 02_规划过程 | 7 | 需求规格、技术方案、架构设计、详细设计、API文档、风险登记册 |
| 03_执行过程 | 4 | 用户操作手册、测试计划、综合测试报告 |
| 04_监控和控制 | 5 | 变更管理、变更记录、文档审查、版本台帐、规范诊断报告 |
| 05_收尾过程 | 2 | 项目总结、验收管理 |

**`06_交付物/02_发布说明/` 当前内容**：
- 只有交付清单（DEL）和版本更新说明
- **缺少项目核心文档**（需求规格、架构设计、操作手册等）

### 问题

1. 交付物中不包含项目的**过程文档**，用户拿到 ZIP 后无法了解项目背景和设计决策
2. `01_项目文档` 的更新不会自动反映到交付物中
3. 没有机制确保交付物文档与项目实际状态一致

## What Changes

### 方案：在 package.py 中增加"文档同步"Phase

#### 新增 Phase 6: 项目文档同步（插入在 Phase 4 之后、Phase 5 之前）

```
当前流程:
  Phase 1 → Phase 2 → Phase 3 → Phase 4 → Phase 5
                              ↓
修改后:
  Phase 1 → Phase 2 → Phase 3 → Phase 4 → Phase 6(新) → Phase 5
```

#### 具体操作

**Step A**: 在 `06_交付物/` 下创建 `03_项目文档/` 目录（与 `01_可执行文件/`、`02_发布说明/` 并列）

**Step B**: 将 `01_项目文档/` 下的所有 `.md` 文件**复制**到 `06_交付物/03_项目文档/`，保持原有目录结构：

```
06_交付物/
├── 01_可执行文件/      ← EXE + config + data (已有)
├── 02_发布说明/        ← 交付清单 + 更新说明 (已有)
├── 03_项目文档/        ← ★ 新增：从 01_项目文档/ 同步
│   ├── 01_启动过程/
│   │   ├── 006_产品化项目章程_PM-V1.0.0.md
│   │   ├── 007_产品路线图_PM-V1.0.0.md
│   │   └── 01_存量资产基线清单_BASELINE-V1.1.1.md
│   ├── 02_规划过程/
│   │   └── ... (7个文件)
│   ├── 03_执行过程/
│   │   └── ... (4个文件)
│   ├── 04_监控和控制/
│   │   └── ... (5个文件)
│   └── 05_收尾过程/
│       └── ... (2个文件)
└── Projects/           ← .gitkeep (已有)
```

**Step C**: ZIP 打包时自动包含 `03_项目文档/` 目录（因为 ZIP 是对整个 `01_可执行文件/` 或扩展为整个 `06_交付物/` 打包）

**Step D**: 更新交付清单模板，增加"项目文档"章节

### 对 package.py 的修改

在 [package.py](file:///d:/BaiduSyncdisk/My_Workspace/01_Project自动化项目管理/Python自动化项目总库/02_在研项目/SW-2026-004_Python项目管理工具/03_主程序/01_主程序核心代码/package.py) 中：

1. **新增常量**:
```python
SOURCE_DOCS_DIR = PROJECT_ROOT / "01_项目文档"
DELIVERY_DOCS_DIR = DELIVERY_DIR / "03_项目文档"
```

2. **新增函数** `sync_project_docs(dry_run=False)`:
   - 复制 `01_项目文档/**/*.md` → `06_交付物/03_项目文档/`
   - 保持目录结构
   - 统计复制的文件数
   - 返回 (成功与否, 文件数量)

3. **修改 main() 流程**: 在 Phase 4 和 Phase 5 之间插入 Phase 6 调用

4. **修改 ZIP 归档范围**: 确认 ZIP 包含 `03_项目文档/`（取决于当前 ZIP 是打包 `01_可执行文件/` 还是整个 `06_交付物/`）

### ZIP 打包策略调整

**当前**: ZIP 只打包 `06_交付物/01_可执行文件/` 目录（~58MB）

**选项分析**:

| 选项 | ZIP大小 | 优缺点 |
|------|--------|-------|
| A: 保持现状只打EXE目录 | ~58MB | ✅ 小；❌ 文档不在ZIP中 |
| B: 打包整个 06_交付物/ | ~60MB+ | ✅ 完整（EXE+文档）；❌ 稍大 |
| C: 单独打一个文档ZIP | ~1MB | ✅ 分离；❌ 用户需要下载两个文件 |

**推荐选项 B**: 将 ZIP 范围扩展为整个 `06_交付物/` 目录，这样：
- 用户解压一个 ZIP 就得到全部内容（EXE + 配置 + 数据库 + 文档）
- 符合"解压即用"的设计理念
- 增量约 2MB（25个md文件），可接受
