## 1. 概述

SpecMgr 是规范管理体系的一站式管理工具，提供 CLI（命令行）和 GUI（图形界面）两种使用方式，帮助开发者、AI 助手和其他工作人员高效管理多技术栈工作空间中的规范文件。

### 1.1 核心功能

| 功能 | 说明 | CLI | GUI |
|------|------|-----|-----|
| 规范健康检查 | 检测8类规范问题（重复/版本漂移/废弃引用等） | ✅ V0.2.0 | 🔜 V0.3.0 |
| 自动修复 | 自动修复版本漂移和frontmatter缺失 | ✅ V0.2.0 | 🔜 V0.3.0 |
| 索引生成 | 从注册表自动生成规范索引文件 | ✅ V0.2.0 | 🔜 V0.4.0 |
| Frontmatter管理 | 批量添加/更新规范文件YAML头 | ✅ V0.2.0 | 🔜 V0.4.0 |
| 报告生成 | 生成规范元数据汇总报告 | ✅ V0.2.0 | 🔜 V0.4.0 |
| 仪表盘 | 规范总览与健康状态统计 | — | 🔜 V0.3.0 |

### 1.2 适用场景

- **开发者**：日常维护规范时，通过 CLI 快速检查和修复
- **AI 助手**：通过 CLI 的 JSON 输出格式集成调用
- **其他工作人员**：通过 GUI 界面直观操作，降低使用门槛
- **CI/CD 流程**：作为门禁工具自动检查规范健康

## 2. 安装与配置

### 2.1 环境要求

| 要求 | 说明 |
|------|------|
| Python | >= 3.9 |
| 操作系统 | Windows / macOS / Linux |
| 依赖 | click >= 8.0, pyyaml >= 6.0 |

GUI 额外要求（V0.3.0+）：

| 要求 | 说明 |
|------|------|
| PySide6 | >= 6.5（`pip install specmgr[gui]`） |

### 2.2 安装方式

**开发模式安装（推荐）**：

```bash
cd <项目路径>/02_源代码
pip install -e .
```

安装后即可使用 `specmgr` 命令。

**含 GUI 依赖安装**：

```bash
pip install -e ".[gui]"
```

**含开发依赖安装**：

```bash
pip install -e ".[dev]"
```

**验证安装**：

```bash
specmgr --version
specmgr --help
```

### 2.3 替代调用方式

除 `specmgr` 命令外，还支持通过 Python 模块方式调用：

```bash
python -m specmgr [命令] [选项]
```

### 2.4 配置文件（可选）

SpecMgr 支持可选的 YAML 配置文件 `specmgr.yaml` 或 `.specmgr.yaml`，放置在工作空间根目录或项目目录下。不创建配置文件时，使用命令行参数或默认值。

配置文件示例：

```yaml
workspace: "c:\\Users\\fubai\\Desktop\\My_Workspace"
registry_path: "00_Obsidian_Base全局规范文件仓库/spec_registry.json"
spec_dirs:
  - "00_Obsidian_Base全局规范文件仓库/01_项目管理域"
  - "0100_PLC自动化/00_通用规范"
  - "01_Project自动化项目管理/00_通用规范"
archive_dir: "00_Obsidian_Base全局规范文件仓库/_archive"
output:
  pm_index: "00_Obsidian_Base全局规范文件仓库/00_INDEX_全局规范索引_V2.0.0.md"
  plc_readme: "0100_PLC自动化/00_通用规范/README.md"
  python_readme: "01_Project自动化项目管理/00_通用规范/README.md"
  report: "00_Obsidian_Base全局规范文件仓库/规范元数据汇总报告.md"
```

### 2.5 工作空间结构要求

SpecMgr 依赖以下工作空间结构：

```
<工作空间根目录>/
├── 00_Obsidian_Base全局规范文件仓库/
│   ├── spec_registry.json          ← 规范注册表（核心数据源）
│   ├── 01_项目管理域/               ← PM域规范目录
│   └── _archive/                   ← 归档目录
├── 0100_PLC自动化/
│   └── 00_通用规范/                 ← PLC域规范目录
├── 01_Project自动化项目管理/
│   └── 00_通用规范/                 ← Python域规范目录
└── .trae/rules/                    ← AI规则目录（SHC-008检查目标）
```

**关键前提**：`spec_registry.json` 必须存在且格式正确，所有命令都依赖它作为数据源。

## 3. CLI 使用指南

### 3.1 全局选项

所有子命令共享以下全局选项：

| 选项 | 短选项 | 说明 | 默认值 |
|------|--------|------|--------|
| `--workspace` | `-w` | 工作空间根目录（必需） | 无，必须指定 |
| `--verbose` | `-v` | 详细输出 | False |
| `--version` | | 显示版本号 | — |
| `--help` | | 显示帮助信息 | — |

`--workspace` 也支持通过环境变量 `SPECMGR_WORKSPACE` 设置：

```bash
# 设置环境变量后无需每次指定 -w
export SPECMGR_WORKSPACE=/path/to/workspace   # Linux/macOS
set SPECMGR_WORKSPACE=c:\path\to\workspace    # Windows

specmgr check
```

### 3.2 specmgr check — 规范健康检查

运行8项规范健康检查，检测工作空间中的规范问题。

#### 基本用法

```bash
specmgr check -w <工作空间路径>
```

#### 完整选项

| 选项 | 说明 | 默认值 |
|------|------|--------|
| `--format` | 输出格式：`table`（终端表格）或 `json`（程序调用） | `table` |
| `--check-id` / `-c` | 只运行指定检查项，可多次使用 | 运行全部 |
| `--severity` | 最低严重级别：`error` / `warning` / `info` | `info` |
| `--auto-fix` | 自动修复可修复的问题 | False |
| `--dry-run` | 仅预览修复操作，不实际修改文件 | False |

#### 8项检查说明

| 检查ID | 检查内容 | 严重级别 | 可自动修复 |
|--------|----------|----------|-----------|
| SHC-001 | 同一规范ID在多个位置存在活跃副本 | 🔴 ERROR | 否 |
| SHC-002 | 规范文件版本与注册表记录不一致 | 🟡 WARNING | ✅ 是 |
| SHC-003 | deprecated规范仍被其他文件引用 | 🟡 WARNING | 否 |
| SHC-004 | INDEX中列出的文件实际不存在 | 🔴 ERROR | 否 |
| SHC-005 | 实际存在的规范未在INDEX中列出 | 🟡 WARNING | 否 |
| SHC-006 | Obsidian [[链接]]指向不存在的文件 | 🟡 WARNING | 否 |
| SHC-007 | 规范文件缺少必要frontmatter | 🟢 INFO | ✅ 是 |
| SHC-008 | .trae/rules中引用的规范路径无效 | 🔴 ERROR | 否 |

#### 使用示例

**基本检查**：

```bash
specmgr check -w c:\Users\fubai\Desktop\My_Workspace
```

输出示例：

```
  🔴 错误: 规范 CODE-210 存在重复文件
    详情: 文件列表: ...\CODE-210_xxx.md, ...\CODE-210_yyy.md
    建议: 保留一个主文件，将其余文件移至归档目录并更新注册表
  🟡 警告: 规范 LSP-905 版本不一致
    详情: 注册表版本: V1.1.0, 文件版本: V1.0.0, 文件: ...\LSP-905_xxx.md
    建议: 更新注册表中的版本号或更新文件内容使其一致

  ------------------------------------------------------------
  汇总: 🔴 错误 1 | 🟡 警告 1 | 🟢 提示 0 | 共 2 项
```

**JSON格式输出**（供程序/AI助手调用）：

```bash
specmgr check -w <工作空间路径> --format json
```

输出示例：

```json
{
  "check_results": [
    {
      "check_id": "SHC-002",
      "severity": "WARNING",
      "message": "规范 LSP-905 版本不一致",
      "details": "注册表版本: V1.1.0, 文件版本: V1.0.0, 文件: ...",
      "fix_suggestion": "更新注册表中的版本号或更新文件内容使其一致",
      "auto_fixable": true
    }
  ]
}
```

**只运行指定检查项**：

```bash
# 只检查版本漂移
specmgr check -w <工作空间路径> -c SHC-002

# 只检查frontmatter和版本漂移
specmgr check -w <工作空间路径> -c SHC-002 -c SHC-007
```

**只显示错误级别**：

```bash
specmgr check -w <工作空间路径> --severity error
```

**预览自动修复**（不修改文件）：

```bash
specmgr check -w <工作空间路径> --auto-fix --dry-run
```

输出示例：

```
  🔧 修复结果:
    ⏭️ [SHC-002] [预览] 重命名: LSP-905_xxx-V1.0.0.md → LSP-905_xxx-V1.1.0.md
    ⏭️ [SHC-007] [预览] 补全frontmatter字段: spec_id, title, version, lifecycle
  修复汇总: ✅ 已修复 0 | ⏭️ 跳过 2
```

**执行自动修复**：

```bash
specmgr check -w <工作空间路径> --auto-fix
```

输出示例：

```
  🔧 修复结果:
    ✅ [SHC-002] 重命名: LSP-905_xxx-V1.0.0.md → LSP-905_xxx-V1.1.0.md
    ✅ [SHC-007] 补全frontmatter: spec_id, title, version, lifecycle
  修复汇总: ✅ 已修复 2 | ⏭️ 跳过 0
```

**自动修复说明**：

| 检查ID | 修复行为 |
|--------|----------|
| SHC-002 | 将文件重命名为注册表中的版本号，同步更新frontmatter中的canonical_path |
| SHC-007 | 从注册表数据自动补全spec_id/title/version/lifecycle/canonical_path字段 |

> ⚠️ **建议**：始终先使用 `--dry-run` 预览修复结果，确认无误后再执行实际修复。

#### 退出码

| 退出码 | 含义 |
|--------|------|
| 0 | 全部检查通过，无错误无警告 |
| 1 | 存在错误级别问题 |
| 2 | 仅有警告级别问题 |

退出码可用于 CI/CD 脚本判断：

```bash
specmgr check -w <工作空间路径>
if [ $? -ne 0 ]; then
    echo "规范检查未通过！"
    exit 1
fi
```

### 3.4 specmgr frontmatter — 批量管理Frontmatter

从 `spec_registry.json` 读取元数据，为缺少 frontmatter 的活跃规范文件添加 YAML 头。

#### 基本用法

```bash
specmgr frontmatter -w <工作空间路径>
```

#### 完整选项

| 选项 | 说明 | 默认值 |
|------|------|--------|
| `--dry-run` | 仅预览不修改文件 | False |
| `--spec-id` | 只处理指定规范ID | 处理全部 |

#### 处理规则

- 从注册表读取规范元数据，生成包含 `spec_id`、`title`、`version`、`lifecycle`、`canonical_path` 的 YAML frontmatter
- **跳过**已有完整 frontmatter 的文件
- **跳过** `deprecated` 和 `archived` 状态的规范
- 文件不存在时给出警告

#### 使用示例

**预览模式**（推荐先运行）：

```bash
specmgr frontmatter -w <工作空间路径> --dry-run
```

输出示例：

```
扫描到 25 个规范，其中 3 个需要添加frontmatter
模式: DRY-RUN（仅预览）
--------------------------------------------------
  [DRY-RUN] 将添加frontmatter到: CODE-211
    spec_id: "CODE-211"...
  [DRY-RUN] 将添加frontmatter到: LSP-907
    spec_id: "LSP-907"...
  ⚠️ 文件不存在: ...\INT-215_xxx.md
--------------------------------------------------
预览完成！待修改: 2, 跳过: 22, 错误: 1
```

**实际执行**：

```bash
specmgr frontmatter -w <工作空间路径>
```

输出示例：

```
扫描到 25 个规范，其中 2 个需要添加frontmatter
模式: 实际修改
--------------------------------------------------
  📝 添加frontmatter到: CODE-211
  📝 添加frontmatter到: LSP-907
--------------------------------------------------
完成！修改: 2, 跳过: 22, 错误: 1
```

**只处理指定规范**：

```bash
specmgr frontmatter -w <工作空间路径> --spec-id CODE-211
```

### 3.5 specmgr report — 报告生成

生成规范元数据汇总报告，包含总览统计、按域分布、替代关系图和完整清单。

#### 基本用法

```bash
specmgr report -w <工作空间路径>
```

#### 完整选项

| 选项 | 短选项 | 说明 | 默认值 |
|------|--------|------|--------|
| `--output` | `-o` | 输出文件路径 | 默认输出到工作空间内的报告路径 |
| `--format` | | 输出格式：`markdown` 或 `json` | `markdown` |

#### 报告内容

Markdown 格式报告包含以下章节：

1. **总览统计**：规范总数、活跃数、废弃数、归档数
2. **按域分布**：PM / PLC / Python / Cross-Domain 各域规范数量
3. **替代关系图**：Mermaid 格式的规范替代关系图
4. **按域分类表**：每个域的规范详细列表
5. **完整YAML清单**：所有规范的完整元数据

#### 使用示例

**生成Markdown报告**：

```bash
specmgr report -w c:\Users\fubai\Desktop\My_Workspace
```

输出示例：

```
✅ 报告已生成: 00_Obsidian_Base全局规范文件仓库/规范元数据汇总报告.md
```

**生成JSON格式报告**：

```bash
specmgr report -w <工作空间路径> --format json
```

**指定输出路径**：

```bash
specmgr report -w <工作空间路径> -o c:\reports\spec_report.md
```

GUI 需要安装 PySide6 依赖：

V0.5.0 打包后，可直接双击 `SpecMgr.exe` 启动。

主窗口采用左侧导航栏 + 右侧内容区的经典布局：


### 4.3 仪表盘页

仪表盘提供规范体系的总览视图。

**统计卡片**：

| 卡片 | 内容 |
|------|------|
| 规范总数 | 所有已注册规范的数量 |
| 活跃规范 | lifecycle = stable/draft 的规范数 |
| 废弃规范 | lifecycle = deprecated 的规范数 |
| 归档规范 | lifecycle = archived 的规范数 |

**最近检查结果摘要**：显示上一次健康检查的汇总信息。

### 4.4 健康检查页

**操作流程**：

1. 点击"运行检查"按钮
2. 检查在后台线程执行，界面保持响应
3. 检查完成后，结果以表格形式展示
4. 可按严重级别（错误/警告/提示）筛选结果
5. 点击某条结果可查看详情和修复建议
6. 可自动修复的问题会显示"修复"按钮

**交互元素**：

| 元素 | 说明 |
|------|------|
| 运行检查按钮 | 启动8项健康检查 |
| 严重级别筛选 | 按ERROR/WARNING/INFO筛选 |
| 结果表格 | 显示检查ID、严重级别、消息、详情 |
| 详情面板 | 显示完整详情和修复建议 |
| 修复按钮 | 对可自动修复的问题执行修复 |
| 进度指示 | 检查运行中显示进度 |

### 4.5 索引生成页

**操作流程**：

1. 选择要生成的域（PM / PLC / Python），支持多选
2. 点击"生成"按钮
3. 进度指示显示生成状态
4. 生成完成后显示结果预览

**交互元素**：

| 元素 | 说明 |
|------|------|
| 域选择器 | 多选框，选择要生成索引的域 |
| 生成按钮 | 启动索引生成 |
| 进度条 | 显示生成进度 |
| 结果预览 | 显示生成的索引文件路径 |

### 4.6 Frontmatter管理页

**操作流程**：

1. 点击"扫描"按钮，列出所有需要添加 frontmatter 的规范文件
2. 查看前后对比预览（添加前的文件内容 vs 添加后的文件内容）
3. 切换 dry-run / 实际执行模式
4. 点击"应用"执行修改

**交互元素**：

| 元素 | 说明 |
|------|------|
| 扫描按钮 | 扫描缺少 frontmatter 的文件 |
| 文件列表 | 显示待处理的规范文件 |
| 前后对比 | 预览 frontmatter 添加效果 |
| dry-run开关 | 切换预览/实际执行模式 |
| 应用按钮 | 执行 frontmatter 添加 |

### 4.7 报告生成页

**操作流程**：

1. 选择输出格式（Markdown / JSON）
2. 可选指定输出路径

**交互元素**：

| 元素 | 说明 |

| 配置项 | 说明 |

**操作**：

- 重置配置：恢复为默认值

## 5. 常见使用场景

### 场景1：新增规范文件后的验证

```bash
# 1. 运行健康检查，确认新规范已正确注册
specmgr check -w <工作空间路径>

# 2. 如果新规范缺少frontmatter，先预览再修复
specmgr frontmatter -w <工作空间路径> --dry-run
specmgr frontmatter -w <工作空间路径>

# 3. 重新生成索引，使新规范出现在索引中
specmgr index -w <工作空间路径>
```

### 场景2：发现版本漂移并修复

```bash
# 1. 运行检查，发现版本漂移问题
specmgr check -w <工作空间路径>

# 2. 预览自动修复操作
specmgr check -w <工作空间路径> --auto-fix --dry-run

# 3. 确认无误后执行修复
specmgr check -w <工作空间路径> --auto-fix

# 4. 重新生成索引和报告
specmgr index -w <工作空间路径>
specmgr report -w <工作空间路径>
```

### 场景3：规范目录结构变更后

```bash
# 1. 运行完整检查
specmgr check -w <工作空间路径>

# 2. 重新生成所有域的索引
specmgr index -w <工作空间路径>

# 3. 补全可能缺失的frontmatter
specmgr frontmatter -w <工作空间路径> --dry-run
specmgr frontmatter -w <工作空间路径>

# 4. 生成最新报告
specmgr report -w <工作空间路径>
```

### 场景4：定期审查规范体系

```bash
# 1. 运行健康检查
specmgr check -w <工作空间路径>

# 2. 生成元数据报告
specmgr report -w <工作空间路径>

# 3. 生成JSON格式报告供分析
specmgr report -w <工作空间路径> --format json -o spec_audit.json
```

### 场景5：AI助手集成调用

```bash
# JSON格式输出，便于程序解析
specmgr check -w <工作空间路径> --format json

# 只检查特定项
specmgr check -w <工作空间路径> -c SHC-002 -c SHC-007 --format json

# 自动修复并获取修复结果
specmgr check -w <工作空间路径> --auto-fix --format json
```

### 场景6：CI/CD 门禁检查

```bash
# 只检查错误级别，退出码非0则阻断流水线
specmgr check -w <工作空间路径> --severity error
```

## 6. 故障排除

### 6.1 常见问题

| 问题 | 原因 | 解决方法 |
|------|------|----------|
| `缺少工作空间路径` | 未指定 -w 参数且未设置环境变量 | 使用 `-w` 指定路径，或设置 `SPECMGR_WORKSPACE` 环境变量 |
| `工作空间路径不存在` | 指定的路径无效 | 检查路径是否正确，使用绝对路径 |
| `注册表文件不存在或格式错误` | spec_registry.json 缺失或JSON格式错误 | 确认工作空间根目录下存在 `00_Obsidian_Base全局规范文件仓库/spec_registry.json` |
| `specmgr 命令未找到` | 未安装或未激活虚拟环境 | 执行 `pip install -e .` 安装，或确认虚拟环境已激活 |
| 检查结果为空 | 注册表加载失败 | 检查 spec_registry.json 格式是否正确 |
| 自动修复未生效 | 未添加 `--auto-fix` 参数 | 添加 `--auto-fix` 参数，建议先配合 `--dry-run` 预览 |

### 6.2 退出码参考

| 退出码 | 含义 |
|--------|------|
| 0 | 全部通过 |
| 1 | 存在错误 |
| 2 | 仅有警告 |

### 6.3 获取帮助

每个命令都支持 `--help` 查看详细用法：

```bash
specmgr --help
specmgr check --help
specmgr index --help
specmgr frontmatter --help
specmgr report --help
```
