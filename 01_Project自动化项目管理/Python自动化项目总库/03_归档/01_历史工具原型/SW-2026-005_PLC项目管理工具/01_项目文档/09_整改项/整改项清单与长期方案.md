## 三、项目经理视角的长期架构方案

### 3.1 变更单结构化存储（替代正则匹配修改）

**现状问题**：当前变更单使用纯 Markdown 文本 + 正则表达式匹配修改，这种方法有以下固有问题：
- 正则匹配在不同模板格式下容易失败（如 P0-1 根因）
- 无法保证写入位置的一致性
- 每次解析都要重新扫描全文

**长期方案**：引入中间表示层（IR）

```
Markdown 文件  ←→  ChangeRequest (dataclass)  ←→  Markdown 文件
     解析                 内存操作                  序列化
```

1. **读取**：`ChgParser.parse()` → `ChangeRequest` 对象（已实现）
2. **修改**：直接操作 `ChangeRequest` 对象的字段（当前用正则匹配文件文本 → 改为操作 dataclass）
3. **写入**：`ChgSerializer.serialize()` → 回写完整 Markdown 文件

**优点**：
- 字段修改精确到属性级别，不会出现正则匹配偏移
- 可以添加 `__eq__` 比较，检测是否有人手动编辑了文件
- 支持版本号递增、时间戳自动更新

**实施难度**：中等。需要实现 `ChgSerializer` 类（基于 CHG-040 模板反向渲染），约 200 行。

**预计工期**：1 个迭代（0.5 人天）

### 3.2 事务性写入机制

**现状问题**：当前修改文件的流程是"边写边校验"，校验失败时已写入的数据无法回滚。

**长期方案**：两阶段提交

```
Phase 1: 预写临时文件
  ├── 复制原始文件内容
  ├── 执行所有修改操作
  └── 写入 .tmp 文件

Phase 2: 校验 + 原子替换
  ├── 解析 .tmp 文件验证完整性
  ├── 执行门禁校验
  ├── 通过 → .tmp 原子替换原文件（os.replace）
  └── 失败 → 删除 .tmp，原文件不受影响
```

**关键实现**：

```python
def _safe_write_change_file(self, file_path: str, transform_fn: Callable[[str], str]) -> None:
    """事务性写入变更单文件"""
    original = read_file(file_path)
    tmp_path = file_path + ".tmp"
    bak_path = file_path + ".bak"

    try:
        modified = transform_fn(original)
        write_file(tmp_path, modified)

        # 校验：可成功解析
        self._parser.parse(tmp_path)

        # 备份原文件
        os.replace(file_path, bak_path)
        # 原子替换
        os.replace(tmp_path, file_path)
        # 成功后删除备份
        os.remove(bak_path)
    except Exception:
        # 清理临时文件
        if os.path.exists(tmp_path):
            os.remove(tmp_path)
        raise
```

**预计工期**：0.5 人天（与 §3.1 配合实施）

### 3.3 统一错误处理框架

**现状问题**：
- CLI 未捕获业务异常，直接抛 Traceback
- GUI 的错误序列化分散在 Bridge 层，CLI 完全独立处理
- 门禁校验失败和程序崩溃无法区分

**长期方案**：分层错误体系

```
应用层
  ├── Bridge 层 → _error_result() 统一序列化（已实现）
  └── CLI 层  → 统一装饰器捕获业务异常（待实现）

业务异常类（已实现）
  ├── SpecViolationError    — 规范校验失败
  ├── TransitionGuardError  — 门禁条件不满足
  └── PathTraversalError    — 路径遍历攻击

基础设施异常
  └── FileNotFoundError / PermissionError → InternalError
```

**CLI 统一异常处理装饰器**：

```python
def handle_cli_errors(func):
    """统一 CLI 异常处理：业务异常输出人类可读信息，系统异常输出 Traceback"""
    @functools.wraps(func)
    def wrapper(args):
        try:
            return func(args)
        except (SpecViolationError, TransitionGuardError, PathTraversalError) as e:
            print(f"[{type(e).__name__}] {e}", file=sys.stderr)
        except Exception:
            log.exception("CLI 未预期异常")
            print("内部错误，请查看日志", file=sys.stderr)
    return wrapper
```
