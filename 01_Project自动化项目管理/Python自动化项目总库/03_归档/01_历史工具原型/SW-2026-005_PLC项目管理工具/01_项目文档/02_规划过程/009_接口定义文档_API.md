# 接口定义文档（API）- V1.0.0

## 1. 概述

### 1.1 文档目的

本文档定义 PLC 项目管理工具的所有对外接口，包括：

- **Service 层 API**：Python 内部调用接口
- **WebViewBridge API**：JS → Python 的 IPC 接口
- **CLI 接口**：命令行调用接口
- **数据模型**：请求/响应的数据结构
- **错误类型**：异常分类及序列化格式

**原则**：代码必须与本文档保持同步。任何接口变更必须先更新本文档，再改代码。

### 1.2 版本

| 版本 | 日期 | 变更内容 |
|------|------|----------|
| V1.0.0 | 2026-06-04 | 初始版本，基于 Phase 1a 代码提取 |

## 3. 规范枚举常量

来源：CHG-040 变更管理规范，所有模块必须从此处读取，禁止硬编码。

### 3.1 技术领域（DOMAINS）

| 代码 | 名称 | 描述 |
|------|------|------|
| `ELEC` | 电气设计 | Eplan/接线图/IO表/BOM/柜体布局 |
| `MECH` | 机械结构 | SolidWorks 3D/装配图/加工图 |
| `PLC` | PLC程序 | SCL/ST/LD/GVL/功能块库 |
| `HMI` | HMI程序 | 触摸屏画面/变量映射/报警配置 |
| `SCPT` | Python脚本 | 数据采集/MES接口/上位机应用 |
| `DOCU` | 工程文档 | 设计说明书/操作手册/验收报告 |
| `SAFE` | 安全功能 | 急停回路/安全矩阵/SIL评估 |

### 3.2 业务性质（BUSINESS_NATURES）

| 代码 | 名称 | 描述 |
|------|------|------|
| `REQ` | 需求变更 | 客户新增功能/工艺调整/范围扩展 |
| `DEF` | 缺陷修复 | Bug修复/故障排除/设计纠错 |
| `OPT` | 优化改进 | 性能提升/可维护性改善/重构 |
| `CFG` | 配置调整 | 参数修改/IO地址调整/通信配置 |
| `EMRG` | 紧急变更 | 安全相关/生产中断(需特殊审批流程) |

### 3.3 影响范围（IMPACT_SCOPES）

| 代码 | 名称 | 审批要求 |
|------|------|----------|
| `LOCAL` | 局部变更 | 仅单个POU/画面/IO点 → 项目经理审批 |
| `MODULE` | 模块级变更 | 单个设备/单条线 → 项目负责人审批 |
| `SYSTEM` | 系统级变更 | 多模块联动/联锁逻辑 → 技术总监审批 |
| `CROSS` | 跨系统变更 | PLC+HMI+电气多领域联动 → 高层管理层审批 |
| `SAFE` | 安全相关变更 | 急停/SIL/安全功能 → 安全负责人+高层联合审批 |

### 3.4 紧急程度（URGENCY_LEVELS）

| 代码 | 名称 |
|------|------|
| `normal` | 一般 |
| `urgent` | 紧急 |
| `critical` | 非常紧急 |

### 3.5 状态流转（STATUS_FLOW）

```
draft → submitted
submitted → under_review | draft
under_review → approved | conditionally_approved | rejected | submitted
approved → implementing
conditionally_approved → implementing
implementing → completed | approved
completed → closed
rejected → draft
closed → (终态)
```

## 4. Service 层 API

### 4.1 ProjectOverviewService

**构造**: `ProjectOverviewService(workspace_root: str)`

| 方法 | 签名 | 返回值 | 异常 |
|------|------|--------|------|
| 获取项目列表 | `get_workspace_projects()` | `list[ProjectInfo]` | 无 |
| 获取项目详情 | `get_project_detail(project_id: str)` | `ProjectInfo \| None` | 无 |
| 获取项目变更 | `get_project_changes(project_id: str)` | `list[ChangeSummary]` | 无 |
| 刷新缓存 | `refresh(project_id: str \| None = None)` | `None` | 无 |

**行为说明**:

- `get_workspace_projects()`: 扫描工作空间下所有子目录，解析立项表，返回项目概览。工作空间不存在时返回空列表。
- `get_project_detail(project_id)`: 返回项目完整信息。项目不存在时返回 `None`。
- `get_project_changes(project_id)`: 返回项目下所有变更单摘要。项目路径未找到时返回空列表。
- `refresh(project_id)`: 清除指定项目的缓存，下次访问时重新解析。`project_id` 为 `None` 时清除全部缓存。

### 4.2 ChangeManagementService

**构造**: `ChangeManagementService(workspace_root: str)`

#### 4.2.1 创建变更单

```
create_change_request(
    project_id: str,
    domain: str,           # 必须在 DOMAINS 中
    business_nature: str,  # 必须在 BUSINESS_NATURES 中
    impact_scope: list[str],  # 每项必须在 IMPACT_SCOPES 中
    applicant: str,
    background: str,
    necessity: str,
    references: str = "",
    planned_date: str | None = None,
    urgency: str = "normal",  # 必须在 URGENCY_LEVELS 中
) -> ChangeRequest
```

**异常**:

| 异常类型 | 触发条件 | message 示例 |
|----------|----------|-------------|
| `ValueError` | 项目不存在 | `"项目不存在: DJ-2026-999"` |
| `SpecViolationError` | domain 不合法 | `"技术领域 'INVALID' 不合法，允许值: ['ELEC', 'MECH', ...]"` |
| `SpecViolationError` | business_nature 不合法 | `"业务性质 'XXX' 不合法，允许值: ['REQ', 'DEF', ...]"` |
| `SpecViolationError` | impact_scope 不合法 | `"影响范围 ['XXX'] 不合法，允许值: ['LOCAL', 'MODULE', ...]"` |
| `SpecViolationError` | urgency 不合法 | `"紧急程度 'XXX' 不合法，允许值: ['normal', 'urgent', 'critical']"` |

**副作用**: 创建变更单 Markdown 文件 + 更新版本变更台帐

#### 4.2.2 列出变更单

```
list_change_requests(
    project_id: str,
    status: str | None = None,
    domain: str | None = None,
) -> list[ChangeSummary]
```

**异常**: 无（项目不存在时返回空列表）

#### 4.2.3 获取变更单

```
get_change_request(change_number: str) -> ChangeRequest | None
```

**异常**: 无（文件未找到时返回 `None`）

#### 4.2.4 状态流转

```
transition_status(
    change_number: str,
    new_status: str,
    approver: str = "",
    comment: str = "",
) -> ChangeRequest | None
```

**异常**:

| 异常类型 | 触发条件 | message 示例 |
|----------|----------|-------------|
| `SpecViolationError` | 状态流转不合法 | `"状态流转 'submitted' → 'approved' 不合法，允许的下一状态: {'draft', 'under_review'}"` |
| `TransitionGuardError` | 门禁条件不满足 | `"变更单 CHG-DOCU-2026-002 不满足 'submitted' 的门禁条件:\n  - §4 变更原因未填写"` |

**门禁规则**:

| 目标状态 | 前置条件 |
|----------|----------|
| `submitted` | §3.1~3.4 已填写 + §4 变更原因非空 |
| `under_review` | 无额外条件 |
| `approved` | §8.1 有审批记录 或 approver 非空 + approver 非空 |
| `conditionally_approved` | 同 approved + comment 非空 |
| `rejected` | approver 非空 + comment 非空 |
| `implementing` | §7 实施计划至少一条任务 |
| `completed` | §9 实施记录 + §10.1 验证项 + §10.2 结论为"全部通过" |
| `closed` | 无额外条件 |
| `draft` | 无额外条件（仅 rejected → draft 允许） |

**副作用**: 更新 §3.4 变更状态字段 + 更新 §8/§9/§10 相关表格

## 5. WebViewBridge API

### 5.1 概述

WebViewBridge 是 JS → Python 的 IPC 桥接层，通过 `window.pywebview.api` 暴露给前端。

**调用方式**:

```javascript
const bridge = window.pywebview.api;
const result = await bridge.get_workspace_projects();
```

**所有方法均为异步**，返回 `Promise`。

### 5.2 API 列表

#### 5.2.1 项目总览

| JS 方法 | Python 对应 | 返回类型 |
|---------|------------|----------|
| `bridge.get_workspace_projects()` | `ProjectOverviewService.get_workspace_projects()` | `Promise<list[dict]>` |
| `bridge.get_project_detail(project_id)` | `ProjectOverviewService.get_project_detail(project_id)` | `Promise<dict \| null>` |
| `bridge.get_project_changes(project_id)` | `ProjectOverviewService.get_project_changes(project_id)` | `Promise<list[dict]>` |
| `bridge.refresh_cache(project_id?)` | `ProjectOverviewService.refresh(project_id)` | `Promise<null>` |

#### 5.2.2 变更管理

| JS 方法 | Python 对应 | 返回类型 |
|---------|------------|----------|
| `bridge.create_change_request(project_id, fields)` | `ChangeManagementService.create_change_request(...)` | `Promise<dict>` |
| `bridge.list_change_requests(project_id, filters?)` | `ChangeManagementService.list_change_requests(...)` | `Promise<list[dict]>` |
| `bridge.get_change_request(change_number)` | `ChangeManagementService.get_change_request(change_number)` | `Promise<dict \| null>` |
| `bridge.transition_status(change_number, new_status, kwargs?)` | `ChangeManagementService.transition_status(...)` | `Promise<dict>` |

### 5.4 错误序列化

Python 异常必须序列化为 JSON，JS 端通过 `try/catch` 捕获。

**序列化格式**:

```json
{
    "error": "SpecViolationError",
    "message": "技术领域 'INVALID' 不合法，允许值: ['ELEC', 'MECH', ...]"
}
```

```json
{
    "error": "TransitionGuardError",
    "message": "变更单 CHG-DOCU-2026-002 不满足 'submitted' 的门禁条件:\n  - §4 变更原因未填写\n  - §3.1 技术领域未填写"
}
```

```json
{
    "error": "ValueError",
    "message": "项目不存在: DJ-2026-999"
}
```

**异常类型映射**:

| Python 异常 | JSON error 字段 | JS 处理建议 |
|-------------|----------------|-------------|
| `SpecViolationError` | `"SpecViolationError"` | 显示错误消息，提示用户修正输入 |
| `TransitionGuardError` | `"TransitionGuardError"` | 弹出门禁提示模态框，逐条列出未满足条件 |
| `ValueError` | `"ValueError"` | 显示错误消息 |
| 其他异常 | `"InternalError"` | 显示"内部错误，请查看日志" |

### 5.5 返回值序列化

所有 dataclass 返回值通过 `dataclasses.asdict()` 序列化为 dict，再由 PyWebView 自动转为 JSON。

**注意**: `list[str]` 类型的字段（如 `impact_scope`）序列化为 JSON 数组；`float` 类型（如 `file_mtime`）序列化为 JSON 数字。

## 7. 校验体系

### 7.1 三层校验关系

| 校验类型 | 触发时机 | 失败行为 | 目的 |
|----------|----------|----------|------|
| 规范校验 (SpecViolationError) | 创建时 + 流转时 | 拒绝操作 | 数据格式合法 |
| 门禁校验 (TransitionGuardError) | 状态流转时 | 拒绝流转 | 流程合规 |
| 结构校验 (_validate_spec_compliance) | 解析时 | WARNING 日志 | 文档结构完整 |

### 7.2 规范校验函数

| 函数 | 校验内容 | 异常 |
|------|----------|------|
| `validate_domain(domain)` | domain ∈ DOMAINS | SpecViolationError |
| `validate_business_nature(nature)` | nature ∈ BUSINESS_NATURES | SpecViolationError |
| `validate_impact_scope(scopes)` | 每项 ∈ IMPACT_SCOPES | SpecViolationError |
| `validate_urgency(urgency)` | urgency ∈ URGENCY_LEVELS | SpecViolationError |
| `validate_status_transition(current, target)` | target ∈ STATUS_FLOW[current] | SpecViolationError |

### 7.3 门禁校验规则

| 目标状态 | 前置条件 | 审批要求 |
|----------|----------|----------|
| `submitted` | §3.1~3.4 已填写 + §4 变更原因非空 | 无 |
| `under_review` | 无额外条件 | 系统自动 |
| `approved` | §8.1 有审批记录 或 approver 非空 + approver 非空 | 由 §3.3 影响范围决定 |
| `conditionally_approved` | 同 approved + comment 非空 | 同 approved |
| `rejected` | approver 非空 + comment 非空 | 同 approved |
| `implementing` | §7 实施计划至少一条任务 | 无 |
| `completed` | §9 实施记录 + §10.1 验证项 + §10.2 结论"全部通过" | 无 |
| `closed` | 无额外条件 | 无 |
| `draft` | 无额外条件（仅 rejected → draft） | 无 |
