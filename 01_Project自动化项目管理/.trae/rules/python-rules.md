## 关键编码规则

### 命名规范（210规范§4）

1. 局部变量: snake_case（如 `user_name`）
2. 全局变量/常量: SNAKE_CASE（如 `MAX_RETRY_COUNT`）
3. 函数: snake_case（如 `get_user_info()`）
4. 类: CamelCase（如 `ProjectService`）
5. 模块/包: snake_case（如 `project_service.py`）

### 代码风格（210规范§5）

6. 缩进使用4个空格，禁止Tab
7. 行宽不超过120字符
8. 字符串优先使用双引号
9. 类型注解: 函数参数和返回值必须添加类型注解

### 架构模式（210规范，基于SW-2026-004实践）

10. Service层架构: 业务逻辑封装在Service类中
11. 常量集中管理: 使用constants.py统一管理
12. UI组件化: 界面与逻辑分离

### 代码审查（211规范）

13. 提交代码前必须通过211规范的审查清单
14. 重点检查: 类型安全、异常处理、资源释放

### 项目打包（220规范）

15. 使用pyproject.toml管理项目元数据
16. 依赖版本必须锁定
17. 发布前运行完整测试套件

## 开发流程速查

```
1. 项目初始化
   └→ 阅读编程规范 (210)

2. 日常开发
   └→ 遵循命名/代码风格 (210§4~5)

3. 代码审查
   └→ 使用审查清单 (211)

4. 项目交付
   └→ 执行打包规范 (220)
```
