# SW-2026-008 驾驶舱迁移收口与退路决策

## 1. 收口范围

- 代码运行真源：`00_Infrastructure/auto_pm`
- 历史母体：`01_Project自动化项目管理/Python自动化项目总库/02_在研项目/SW-2026-008_auto-pm_自动化项目管理工具`
- 根入口：`main.py`
- 安装入口：`setup_env.bat`
- 稳定版本证据：`b603bd4`（WBS7）和 `f73f5eb`（WBS8）

## 2. 迁移核查

| 核查项 | 结果 | 判断 |
|---|---|---|
| 根入口优先级 | `main.py` 优先解析 `00_Infrastructure/auto_pm` | 代码运行单轨已成立 |
| 安装入口优先级 | `setup_env.bat` 优先 editable install 基础设施位 | 新环境默认进入基础设施位 |
| Python 文件一致性 | 旧母体与基础设施位 180 个对应 Python 文件中，169 个一致、11 个存在差异、0 个缺失 | 两边不能继续并行维护 |
| 稳定版本数量 | `b603bd4`、`f73f5eb` 均已通过对应批次门禁 | 达到 WBS9 最低稳定性条件 |
| 文档归属 | 活跃规划、变更历史和交付资料仍在旧母体 | 文档暂不迁移，避免双份真源 |
| 变更资产 | 旧母体变更单和台账仍可追溯 | 不删除、不改写历史审计资产 |

## 3. 退路决策

### 3.1 本轮保留

保留根入口和安装入口中的旧母体回退路径，但将其定义为灾备参考，不作为日常开发源。旧母体代码冻结，后续驾驶舱代码只允许写入 `00_Infrastructure/auto_pm`。

### 3.2 本轮不删除的原因

1. 旧母体仍承载活跃产品规划、交付文档和完整变更历史。
2. 旧母体与基础设施位存在 11 个 Python 文件差异，删除前还需要形成明确的差异处置和恢复演练证据。
3. 驾驶舱仍在 Dogfooding 优化期，保留可回退路径能降低入口、依赖或桌面运行回归的恢复成本。
4. 工作空间规则要求涉及删除和回退策略的变更由用户单独批准；本轮不把 WBS 总体批准解释为删除授权。

## 4. 单轨运行规则

- 日常运行、开发、测试和发布只使用 `00_Infrastructure/auto_pm`。
- 旧母体只读，不接受功能修复、模板更新或版本推进。
- 任何需要使用回退路径的情况必须记录原因、入口、版本和恢复结果，并形成新的变更记录。
- 活跃文档迁移另立任务，先确定唯一真源、同步策略、链接修复和文档门禁。
- 后续若要移除回退，必须先完成差异收敛、恢复演练、文档迁移决策，并取得用户明确批准。

## 5. WBS9 结论

WBS9 评估通过，迁移收口采用“代码单轨、历史母体保留、回退路径暂留”的非破坏方案。驾驶舱已从项目母体切换为工作空间基础设施运行，但尚未进行旧代码删除；后续进入迁移后观察和活跃文档真源治理。
