## 4. 变更原因

**变更背景**：
NG-WP-15 切流后用户报告 GUI 闪退：双击启动驾驶舱.bat 启动即秒退且无任何错误可见。诊断结论：(1) 直接诱因是启动窗口期的 SQLite 运行库锁竞态（残留调试实例持锁），叠加 start 控制台随进程关闭吞掉全部报错证据；(2) 首次启动同步曾出现 FOREIGN KEY constraint failed（迁移瞬态，重试自愈，运行库 integrity ok 且 fk_check 0 违规，但暴露 release 同步层与历史运行库的兼容风险）；(3) Gate 2 深查发现 release 为逐包最小实现回收，较稳定平铺源码缺 14 个模块（pm/dogfood/handoff/decision/git-hook 等 CLI 与 saga 服务）、156 个文件内容漂移（如 ai_handoff_service 54KB->6KB），功能面存在真实差距。热修复尝试（bat 崩溃留痕加固）因 cmd 嵌套引号叠加中英双代码页解析撕裂而引入二次故障，已全部回退至 dc0b2fb。

**变更必要性**：
生产入口的失败必须可诊断、可追溯；release 功能差距必须以正式变更单立项逐项回收，严禁在无变更单状态下继续对入口脚本和 release 做试验性改动。本单为唯一处置入口，后续修复动作须在本单获批后按精确 pathspec 分批实施。

**参考依据**：
CHG-SCPT-2026-017,CHG-SCPT-2026-016,NG-WP-14_gate2_report_2026-09-05.md,NG-WP-15_switchover_report_2026-09-05.md

## 12. 附录

### 12.1 填写指南

#### 如何选择技术领域?
- 主要改哪个专业的交付物,就选哪个领域
- 如果同时涉及多个专业,选**最主要**的那个作为主领域,其他在§6.2中标注

#### 如何判断影响范围?
- **LOCAL**: 改一个变量/一行代码/一个接线端子
- **MODULE**: 改一个FB/一条输送线/一台设备
- **SYSTEM**: 改全局变量/联锁逻辑/通讯接口
- **CROSS**: 改了电气,PLC和HMI都要跟着改
- **SAFE**: 动了急停回路/安全继电器/SIL相关
