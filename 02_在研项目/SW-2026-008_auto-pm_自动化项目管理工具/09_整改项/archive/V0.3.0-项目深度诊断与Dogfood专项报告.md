## 1. 结论摘要

本项目当前**已经不处于 2026-06-25 原报告所说的“先做 M0.5 再谈 M1/M2/M3”阶段**。

综合文档、代码与运行证据，当前更准确的判断如下：

1. **主线开发已显著前进**  
   `PM_SESSION` 当前真源明确指向：`V0.3.6 / M3-4 全部完成`，下一步为 `M4 Dogfooding 持续化`。这说明 M0.5、M1、M2、M3.5、M3-2、M3-3、M3-4 都已被记录为完成，而不再是“待启动”。

2. **原报告中的 4 类产品级断点，绝大部分已被代码关闭**  
   已确认落地的修复包括：
   - `ProjectScanner` 已兼容 `project_description`，并支持从 `pyproject.toml` 回退读取版本；
   - `path_resolver.get_or_create_ledger_file()` 已按项目类型选择 PLC/Python 路径，而非固定走 PLC 路径；
   - `verification_conclusion` 门禁已从“必须等于全部通过”放宽为“包含通过且不含否定词”；
   - `change ledger` 已从计划中移除，`change edit` CLI 命令已实现。

3. **但项目仍未达到“所有高层文档都与当前事实完全一致”的状态**  
   当前最大问题已经从“代码和计划完全分叉”变成了**“主真源基本正确，但若干历史/高层文档仍保持活动态表述，容易误导新执行者”**。

4. **当前仍存在一个真实产品问题：`project show` 的阶段字段为空**  
   实测 `auto-pm -w "<workspace>" project show SW-2026-008` 输出中，`版本=0.3.6`、`描述` 正常，但 `阶段=-`。根因不是 `.copier-answers.yml` 契约兼容失败，而是 `ProjectScanner._read_phase_from_pm_session()` 只会从 PM_SESSION 中读取独立的 `phase:` frontmatter 行；而当前 `PM_SESSION_SW-2026-008.md` 实际并没有这样的 frontmatter 字段。

5. **下一步不应该回头重做 M0.5/M1/M2/M3，而应该做“收尾型治理”**  
   当前最合理的推进不是重新插入 M0.5，也不是再讨论 M1/M2/M3 是否开工，而是：
   - 修补仍然活跃的文档漂移；
   - 修复 `phase` 元数据回退策略；
   - 把 M4 dogfood 持续化真正跑起来；
   - 形成当前版本的发布证据闭环。

一句话结论：

> `auto-pm` 现在最大的风险已不再是“路线还没进场”，而是“主线已经做到 V0.3.6 / M3-4 完成，但若干高层文档和元数据边角仍停留在旧状态”，如果不及时收尾，会继续损耗项目可信度。

### 4.2 原 P0-2：项目元数据契约不一致

**结论：大部分已修复，剩余一个新的边界问题。**

原报告指出 `version / description / phase` 都为空。当前代码和实测表明：

- `description` 已通过 `project_description or description` 兼容逻辑修复；
- `version` 已通过 `answers.version -> pyproject.toml` 回退逻辑修复；
- `phase` 仍为空。

当前代码证据：

- `project_scanner.py` 中 `read_copier_answers()` 已兼容：
  - `description = answers.get("project_description", "") or answers.get("description", "")`
  - `version` 为空时回退读取 `pyproject.toml`
  - `phase` 为空时回退读取 `PM_SESSION`

当前运行证据：

```text
项目ID: SW-2026-008
名称:   auto-pm
技术栈: python
版本:   0.3.6
阶段:   -
描述:   自动化项目管理工具 - 统一CLI管理PLC/Python多技术栈项目
```

1. `.copier-answers.yml` 中确实没有 `phase`
2. `ProjectScanner._read_phase_from_pm_session()` 只用正则查找独立的 `phase:` 行
3. 当前 `PM_SESSION_SW-2026-008.md` 顶部并没有 frontmatter 形式的 `phase:` 字段
4. 因此回退逻辑自然返回空字符串

所以当前准确表述应为：

> **元数据契约兼容问题已基本关闭，但“阶段字段回退策略与 PM_SESSION 实际格式不匹配”仍然是真问题。**
