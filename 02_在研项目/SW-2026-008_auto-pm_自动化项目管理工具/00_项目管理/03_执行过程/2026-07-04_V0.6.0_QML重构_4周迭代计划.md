# V0.6.0 GUI QML 重构 4 周迭代计划

## 0. 触发背景

V0.5.x 系列深度审查与稳定性加固完成后，PySide6 QWidget 方案的 GUI 长期维护痛点显现：

1. **资产规模庞大但低复用**：UI 层 53 文件 11,300 行 + pytest-qt 测试 28 文件 10,000 行，其中 PySide6 特有代码 21,300 行（占 77%），QSS 样式与 Python 逻辑深度耦合，UI 改动需重新编译运行验证。
2. **AI 主力维护成本高**：QWidget 每次界面微调都要修改 .py 文件、调整布局代码、跑 pytest-qt 回归，单页改动平均需 5-8 次迭代才能稳定。
3. **复杂组件实现吃力**：ApprovalTimeline / PropagationView / StatusMachineView 等可视化组件在 QWidget 下需手写 QPainter 或嵌 QWebEngineView，维护复杂度高。
4. **离线场景适配不足**：用户 90% 离线使用（PLC 工程师同时做 PLC + Python 脚本 + 项目管理），无法依赖浏览器方案（NiceGUI/Flet 等）。

## 1. 方案选型结论（已与用户确认）

### 1.1 候选方案对比

| 维度 | 方案 B：NiceGUI | 方案 D：PySide6 + QML |
|------|----------------|----------------------|
| 长期迭代（5） | 5（Vue + Python，前后端解耦）| 5（QML 声明式 UI，前端解耦）|
| AI 主力（5） | 4（Python + Vue 混合，AI 需切换上下文）| 5（QML 简洁声明式，AI 易生成）|
| 测试方便（5） | 4（Playwright + pytest，浏览器依赖）| 5（QML TestCase + pytest-qt 复用）|
| 模块化（4） | 4（FastAPI 路由 + Vue 组件）| 4（QML Component + 模块）|
| 现代化（4） | 5（Tailwind + 现代浏览器）| 4（Material 风格 + 自定义主题）|
| 离线使用（5） | 2（需浏览器 + WebSocket 服务）| 5（原生进程，零浏览器依赖）|
| **加权合计** | **130** | **130** |

### 1.2 决策：方案 D（QML）

QML 在 6 个关键差异点胜出：
- 离线使用：原生进程，无浏览器依赖
- 变量表编辑器：QML TableView 原生虚拟化，万行数据流畅
- 打包分发：PyInstaller 单文件 exe，无浏览器运行时
- 长期维护：QML 声明式 UI 改动不破坏 Python 逻辑
- 现有代码迁移：main_window / nav_tree / Service 层可复用
- 生态稳定：Qt 官方主推方向，文档/示例/工具链完整

### 1.3 重构边界

| 保留 | 重写 |
|------|------|
| 后端 Service 层（core/ 12 文件 2,850 行）| UI 层 8 大模块（navigation/project_list/workspace/change_center/dialogs/global_pages/vartable/widgets/models）|
| DB 层（5 文件 968 行）| main_window.py（部分保留：QQuickWidget 容器逻辑）|
| CLI 层（9 文件 2,429 行）| styles.py（QSS → QML 主题）|
| models 层（数据类，无 Qt 依赖）| pytest-qt 测试套件（28 文件 10,000 行）|
| HTML 原型设计语言（设计系统保留）| |

**预期复用率**：23%（6,247 行后端可复用）/ 77%（21,300 行 QWidget 特有需重写为 QML）
