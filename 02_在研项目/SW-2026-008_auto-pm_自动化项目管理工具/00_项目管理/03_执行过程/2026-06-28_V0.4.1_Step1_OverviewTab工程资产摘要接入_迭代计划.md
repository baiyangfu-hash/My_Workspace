## 2. 本轮目标

让 GUI 概览页能消费 `asset_summary`，使选中 PLC 项目后可在第一屏直接看到工程资产健康状态、三类资产数量和前 3 条问题摘要；同时通过 CHG-073 dogfooding 闭环验证变更管理流程对小 UI 变更的支撑能力。

## 3. 范围边界

### 3.1 本轮包含

- 在 `OverviewTab` 增加"工程资产摘要"区块，展示：
  - 健康状态徽标（healthy 绿 / warning 黄 / missing 红 / not_applicable 灰）
  - 三类资产数量（IO 点数 / 程序块数 / 通讯对象数）
  - 前 3 条问题摘要（来自 `issue_messages`）
- 从 `ProjectInfo.extra` 或 `ProjectScanner` 取 `asset_summary`，走 Service 层入口，不直接读文件
- 非 PLC 项目（Python / unknown）显示"工程资产不适用"友好提示，不抛异常
- 至少补 1 组 UI/DTO 焦点测试，覆盖 PLC 项目展示 / 非 PLC 不适用 / 缺资产目录三种场景
- 创建 CHG-SCPT-2026-073 走 dogfooding 第 6 次闭环（draft→closed）

### 3.2 本轮不包含

- **不扩 `DashboardService`**：交接清单明确指出"首页驾驶舱应保持聚合层轻量，不应过早承载细粒度工程资产展示"

- 不修改 `ProjectScanner` 的 `extra.asset_summary` 注入逻辑
- 不补 `AssetSummaryDTO` Pydantic 模型（当前 dict 结构足以支撑 OverviewTab 单层展示；若后续驾驶舱要聚合，再补 DTO）
- 不进入 V0.4.1 Step 2（历史 PLC 项目自动区标记 retrofit）和 Step 3（Python 项目 `plc check` "不适用"口径）

- 不触发版本号升级（保持 0.3.8；待 V0.4.1 Step 1~3 全部完成后再统一升 0.4.0 → 0.4.1）

## 4. 执行策略

### 4.1 决策

- **最小接入原则**：只在 `OverviewTab` 单点接入，不触动 `DashboardService` / `ProjectScanner` / `AssetSummaryService`，回归范围可控
- **GUI 不直接读文件**：通过 `ProjectInfo.extra.asset_summary` 取数据；若 `extra` 缺失则降级为"暂无资产摘要"
- **复用现有徽标样式**：参考 `_STACK_BADGE` / `_PHASE_LABEL` 的颜色与样式约定，新增 `_ASSET_STATUS_BADGE` 表，不引入新 CSS 框架
- **dogfooding 先行**：CHG-073 在实施前创建并流转到 `approved`，实施完成后流转到 `closed`，确保变更管理对小 UI 变更同样适用

### 4.2 数据流

```
ProjectScanner.scan()  →  ProjectInfo.extra.asset_summary (dict)
                                       ↓
                              OverviewTab.set_project(project_info)
                                       ↓
                  _render_asset_summary_block(asset_summary)  →  QFrame/QLabel
```

### 4.3 UI 布局

工程资产摘要区块位于"项目元数据卡"与"立项表信息卡"之间（或末尾，由实施时根据现有布局确定），包含：
- 区块标题："工程资产摘要"
- 健康状态徽标 + 状态文案
- 三列数量展示：IO 点数 / 程序块数 / 通讯对象数
- 问题摘要列表（最多 3 条，超出显示"+N 更多")

## 6. 风险与依赖

- **`extra` 字段缺失风险**：历史项目扫描时若 `asset_summary` 未注入，UI 需降级为"暂无资产摘要"，不能抛异常；需在 `_render_asset_summary_block` 入口做 `dict.get("asset_summary")` 防御
- **样式回归风险**：OverviewTab 已有较多区块（元数据/立项表/变更概览/最近活动），新增区块可能影响整体布局；实施时需用 `QScrollArea` 包裹并验证既有测试不回归
- **测试可见性风险**：offscreen 模式下 `isVisible()` 恒 False，需使用 `isVisibleTo(parent)` 断言（参考 V2.0 阶段C ProjectCard 经验）
- **CHG-073 dogfooding 风险**：小 UI 变更走完整 8 步生命周期可能略重；但为保持 dogfooding 连续性，本轮仍按标准流程走，验证变更管理对小变更的适用性
- **依赖**：本轮依赖 `AssetSummaryService.build_summary()` 返回的字典结构稳定；不依赖 `ProjectScanner` 修改；不依赖 `DashboardService`
