## 4. 变更原因

**变更背景**：
V0.6.0 完成 GUI QML 重构 4 周迭代（CHG-086），8 大页面 + 8 对话框 + 4 复杂组件 QML 化完成。但 V0.6.0 采取保守策略，main_window.py 添加 DeprecationWarning 保留旧 QWidget 作 fallback，未激进删除。原因：QML UI 尚未覆盖规范中心/报告/模板/全局设置页（main.qml 中为占位），激进删除会导致功能丢失。

V0.7.0 完成 PM_SESSION 三层真源架构（CHG-087/088/089），未涉及 QML 工作。

V0.8.0 启动 QML 完整覆盖 + 旧代码激进清理，分 3 个 CHG：
- **CHG-090（Phase 1，本次）**：QmlBridge 扩展 + main.qml 侧边栏补全
- **CHG-091（Phase 2）**：4 个 QML 页面新增（SpecCenter/Report/Template/Settings）
- **CHG-092（Phase 3+4+5）**：默认入口切换 + A 类激进清理 + 旧测试迁移

**变更必要性**：
Phase 1 是 Phase 2/3 的前置条件：
1. **QmlBridge 扩展**：4 个新 QML 页面需要调用 ReportService/TemplateService/PmSessionService 等 6 个 Service，必须先暴露给 QML 端
2. **main.qml 侧边栏补全**：当前 QML 侧边栏只有 4 入口（项目列表/变更中心/规范中心占位/设置占位），缺少报告和模板入口，QML UI 当前根本无法访问 report_page 和 template_page 功能
3. **占位激活**：规范中心和设置入口当前是灰色占位，需要激活可点击

**参考依据**：
- V0.6.0 计划：`00_项目管理/03_执行过程/2026-07-04_V0.6.0_QML重构_4周迭代计划.md`
- 旧代码扫描清单：本次 V0.7+ 扫描报告（A 类 32 文件 / B 类 14 文件 / C 类 V0.8 新增 QML 工作）
- 02_设计/GUI原型设计.md §15 V0.6.0 QML 重构方案

## 6. 影响分析

### 6.1 质量影响
- **正面**：QML 端获得完整后端能力，为 Phase 2 4 个 QML 页面新增做前置准备
- **正面**：main.qml 侧边栏补全后，QML UI 可访问全部 6 大功能页（项目列表/变更中心/规范中心/报告/模板/设置）
- **风险**：6 个 Service 注入增加 QmlBridge 初始化复杂度，需保证向后兼容（W1/W2 测试零回归）

### 6.2 风险影响
- **风险 1**：6 个 Service 中部分依赖外部资源（如 ReportService 依赖 workspace_root + db），QML 启动时若资源不可用可能崩溃
- **缓解**：所有 Service 可选注入 + Slot 内部 try/except 返回空数据 + hasXxxService Property 反映真实状态
- **风险 2**：qml_main_window.py 实例化逻辑变更可能影响 QML 启动
- **缓解**：保持现有 ProjectService/ChangeService/SpecService 注入不变，仅新增 6 个 Service 可选注入

### 6.3 缓解措施
1. 所有新 Slot 内部 try/except 包裹，异常时返回空数据/False，不让异常冒泡到 QML 端
2. 新增 `make_dashboard_service()` / `make_report_service()` 等工厂函数（参考现有 `make_spec_check_service()`），处理资源不可用情况
3. 完整回归 W1/W2 既有测试，确保零回归
