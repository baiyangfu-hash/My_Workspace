## 4. 变更原因

**变更背景**：
CHG-087 Stage 1 已通过 PowerShell 手动操作完成 PM_SESSION 拆分归档（489KB → 62KB 主文件 + 328KB 归档），但 Stage 1 为一次性手动操作，存在以下问题：
1. **不可重复**：每次 PM_SESSION 膨胀都需手动行切片 + 边界校验 + 备份管理，流程繁琐易错
2. **无健康检查**：缺乏自动检测机制，PM_SESSION 膨胀只能靠人工发现（已发生 V0.3.0~V0.6.0 多轮迭代后膨胀至 489KB）
3. **无视图生成**：用户/会话起手需读取整个 PM_SESSION 才能掌握 §2 Current Focus + §3 Status Summary + §9 Next Actions，浪费 token
4. **无元测试门禁**：缺乏 CI 层面的 PM_SESSION 规模门禁，无法在迭代中自动预警

**变更必要性**：
将 Stage 1 手动流程升级为 auto-pm 工具子命令，实现：
1. `pm-session check`：自动检测 PM_SESSION 文件健康状态（规模 + 章节完整性 + §7 回归）
2. `pm-session archive`：章节级归档（支持 keep_recent 保留最新 N 行 + 自动备份）
3. `pm-session view`：生成只读视图（提取 §2/§3/§9）
4. 元测试规模门禁：CI 层面检测真实 PM_SESSION_SW-2026-008.md 文件规模

**参考依据**：
- CHG-087 Stage 1 完成（PM_SESSION 489KB → 62KB + 328KB 归档）
- 用户硬约束：记录全部都要，迭代走过的路是教训也是经验
- 用户硬约束：CHG 模板暂时不希望你改动；其他还好
- 用户最终指令：完成剩下的所有工作（Stage 2 + Stage 3 + 最终同步）

### 12.3 填写指南

#### 如何选择技术领域?
- 主要改哪个专业的交付物,就选哪个领域
- 如果同时涉及多个专业,选**最主要**的那个作为主领域,其他在§6.2中标注

#### 如何判断影响范围?
- **LOCAL**: 改一个变量/一行代码/一个接线端子
- **MODULE**: 改一个FB/一条输送线/一台设备
- **SYSTEM**: 改全局变量/联锁逻辑/通讯接口
- **CROSS**: 改了电气,PLC和HMI都要跟着改
- **SAFE**: 动了急停回路/安全继电器/SIL相关
