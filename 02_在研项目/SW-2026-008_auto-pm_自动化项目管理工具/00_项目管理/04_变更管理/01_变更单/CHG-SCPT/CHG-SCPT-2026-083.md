电气部门试用前3个P1缺陷修复+日志FileHandler持久化+spec子命令-w语义统一

**变更必要性**：
解除电气部门试用前阻塞:P1缺陷影响GUI项目刷新/业务线丢失/异常追溯;日志无文件持久化导致问题无法追溯;spec子命令-w与全局-w语义不一致。修复后方可交付试用

## 5. 变更内容

### 5.1 变更前（当前状态）

| 项目 | 当前值/描述 |
|------|-----------|
| 涉及文件/交付物 | ① `auto_pm/ui/main_window.py` `_do_refresh` 方法仅调用 `_load_projects()`，DB 缓存非空时不回退文件系统扫描，GUI 外部创建项目不可见；② `auto_pm/db/sync.py` L166 `business_line=extract_business_line(proj.project_id)` 始终覆盖元数据字段，丢失用户显式指定的业务线；③ `auto_pm/change/change_service.py` L250-258 `except Exception` 仅 `log.warning` 后跳过，异常信息不足且静默；④ `auto_pm/logging/logging.py` 仅 StreamHandler 无 FileHandler，运行日志无文件持久化；⑤ 无审计日志能力（`auto_pm/logging/audit.py` 不存在）；⑥ `auto_pm/cli/gui.py` 无 GUI 崩溃捕获，未捕获异常丢失；⑦ `auto_pm/cli/spec.py` 4 子命令（check/index/frontmatter/report）`-w` 参数 required=True，与全局 `-w` 语义不一致 |
| 关键参数/配置 | ① P1-① GUI 缓存回退缺陷；② P1-② business_line 覆盖缺陷；③ P1-③ 异常吞没缺陷；④ 日志无文件持久化；⑤ 无审计日志；⑥ 无 GUI 崩溃捕获；⑦ spec `-w` 语义不一致 |

### 5.2 变更后（目标状态）

| 项目 | 目标值/描述 |
|------|-----------|
| 涉及文件/交付物 | ① `auto_pm/ui/main_window.py` `_do_refresh` 增加 `sync_to_cache(force_full=False)` 增量同步（L441-454）；② `auto_pm/db/sync.py` L166 改为 `business_line=proj.business_line or extract_business_line(proj.project_id)`（优先用元数据字段）；③ `auto_pm/change/change_service.py` L250-258 改为 `log.error(..., exc_info=True)` 完整记录 traceback；④ `auto_pm/logging/logging.py` 新增 `_SilentTimedRotatingFileHandler` 类 + `setup_logger` 集成 TimedRotatingFileHandler（按天轮转保留 30 天，写入 `~/.auto-pm/logs/auto-pm.log`）；⑤ 新建 `auto_pm/logging/audit.py` 提供 `audit_log(action, **details)` 写入 `~/.auto-pm/audit/audit.log`（保留 90 天）；⑥ `auto_pm/cli/gui.py` 新增 `_install_crash_handler()` 安装 `sys.excepthook` 写入 `~/.auto-pm/logs/crash.log`；⑦ `auto_pm/cli/project.py` cmd_create/cmd_delete 插入 `audit_log()` 调用；⑧ `auto_pm/cli/change.py` cmd_transition 插入 `audit_log()` 调用；⑨ `auto_pm/cli/spec.py` `_resolve_workspace` 支持从 `ctx.obj/AppContext` 回退全局 `-w`，4 子命令 `-w` 改为 `default=None` + `@click.pass_context` |
| 关键参数/配置 | ① P1-① `_do_refresh` 增量同步；② P1-② 优先 `proj.business_line`；③ P1-③ `log.error + exc_info=True`；④ `_SilentTimedRotatingFileHandler` 静默处理 emit 失败避免污染 Click 测试；⑤ 审计日志 `propagate=False` 避免污染运行日志；⑥ `sys.excepthook` 捕获未处理异常 + 写入 crash.log；⑦ spec `-w` 可选 + 回退全局 |

## 6. 变更影响分析

### 6.1 项目约束影响（PMBOK五大约束）

| 约束维度 | 影响程度 | 影响描述 | 应对措施 |
|---------|:--------:|----------|----------|
| **范围(Scope)** | ☑低 | 9 个文件修改（3 个 P1 缺陷修复 + 4 个日志/审计能力新增 + 1 个 spec -w 统一 + 1 个 audit 调用插入） | 严格限制在本变更单 §5.2 范围内，不涉及其他模块 |
| **进度(Schedule)** | ☑无 | 不延迟（所有修复已实施完成，本变更单为 dogfooding 闭环登记） | - |
| **成本(Cost)** | ☑无 | 不增加成本 | - |
| **质量(Quality)** | ☑低 | 提升日志持久化与异常追溯能力，P1 缺陷修复提升 GUI/CLI 鲁棒性 | 全量回归 1438 passed 0 failed + ruff/mypy 0 errors 验证无回归 |
| **风险(Risk)** | ☑低 | _SilentTimedRotatingFileHandler 静默 emit 失败可能掩盖真实文件写入问题；audit_log 插入可能影响 CLI 输出 | ① 静默 handler 仅在 Trae Sandbox 等极端环境触发，实际使用环境不受影响；② audit_log 使用独立 logger（propagate=False）不污染 stdout |

**风险等级**（PMBOK风险评估）：☑低

**缓解措施**（风险应对策略）：
① 全量回归测试（非 GUI 913 passed + GUI 525 passed = 1438 passed 0 failed）+ ruff/mypy 0 errors 三轨门禁；② `_SilentTimedRotatingFileHandler.handleError` 在移除自身前尝试清理所有 logger 引用，避免泄漏；③ audit_log 使用独立 logger 名称 `auto_pm.audit` + `propagate=False`，确保不影响 Click 测试的 result.output；④ spec `-w` 统一后保留显式错误提示，未指定时给出明确指引

### 6.2 技术领域影响（跨领域变更必填！）

**无跨领域影响**：本变更仅涉及 SCPT（Python 脚本）域的 UI/DB/change/logging/cli 模块，不涉及 ELEC/MECH/HMI/DOCU/SAFE 域。变更影响范围已在 §6.1 评估为"低"，可跳过 §6.2 详细填写。

### 6.3 变更传播链（跨领域变更必填！）

**无跨领域影响**（本变更为 SCPT 单领域变更，无传播链）。

> **注**: 如果本变更不涉及其他领域,可填写"无跨领域影响"并跳过§6.2和§6.3

### 12.1 填写指南

#### 如何选择技术领域?
- 主要改哪个专业的交付物,就选哪个领域
- 如果同时涉及多个专业,选**最主要**的那个作为主领域,其他在§6.2中标注

#### 如何判断影响范围?
- **LOCAL**: 改一个变量/一行代码/一个接线端子
- **MODULE**: 改一个FB/一条输送线/一台设备
- **SYSTEM**: 改全局变量/联锁逻辑/通讯接口
- **CROSS**: 改了电气,PLC和HMI都要跟着改
- **SAFE**: 动了急停回路/安全继电器/SIL相关
