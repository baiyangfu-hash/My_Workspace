# 项目1_单线圈气缸需求分析报告

## 1. 项目概述

### 1.1 核心需求
根据项目规范和用户反馈，用户需求主要包括：
- 组织和标准化"项目1_单线圈气缸"项目文件结构
- 修复混乱的文件命名和格式
- 添加历史版本管理
- 完善模板文件
- 更新项目规范
- 基于新规范修订项目文件
- 修复自动化工作流配置问题
- 验证自动化工具执行结果

### 1.2 技术标准
- 严格遵循IEC 61131-3编程标准
- 使用SCL语言开发PLC功能块(FB)
- 变量表CSV文件使用GBK编码（Autoshop兼容要求）
- 遵循项目规则和用户规则中的所有约束

## 2. 文件结构需求

用户期望建立清晰的文件夹结构，包括：
```
项目1_单线圈气缸/
```

### 2.2 文件夹功能定义

- **历史版本**：按版本号归档旧版本文件，便于追溯和管理

## 3. 程序需求

### 3.1 FB功能要求
- 实现单线圈气缸的伸缩控制
- 支持动点传感器和原点传感器监控
- 实现到位状态检测
- 包含异常报警处理
- 实现状态机管理

### 3.2 代码结构要求
FB必须包含五大模块：
1. **初始化模块**：系统初始化逻辑
2. **手动控制模块**：手动操作逻辑
3. **自动控制模块**：自动运行逻辑
4. **报警处理模块**：异常报警逻辑
5. **状态机模块**：状态管理逻辑

### 3.3 编码规范
- 严格符合IEC 61131-3标准
- 禁用枚举类型
- 优先使用SCL语言，禁用STL语言
- 代码缩进统一，提高可读性

### 3.4 注释要求
- **FB头部**：包含功能描述、输入/输出变量释义
- **核心逻辑**：标注状态机切换条件、计时器参数
- **交互逻辑**：标注上下游信号交互规则、状态监控点
- **变更记录**：代码修改行上方标注`// [YYYY-MM-DD] 变更原因：xxx 变更内容：xxx`

## 4. 变量表需求

### 4.1 格式要求
- **文件格式**：CSV（逗号分隔值）
- **编码要求**：必须使用GBK编码（Autoshop兼容）
- **表头格式**：`序号,类别,名称,数据类型,隐藏初始值,初始值,掉电保持,注释,`

### 4.2 变量命名规则
- **输入变量**：前缀`i_` + 功能描述（如`i_动点传感器`）
- **输出变量**：前缀`q_` + 功能描述（如`q_气缸动点动作`）
- **内部变量**：
  - 布尔型：前缀`b_`或`tmp_` + 功能描述
  - 数值型：前缀`n_`或`tmp_` + 功能描述
  - 直接功能描述或可选`tmp_`前缀

### 4.3 数组处理规则
- **主定义行**：包含数组声明，序号递增
- **元素行**：以两个逗号开头，序号为空，类别为空，依次列出每个数组元素

### 4.4 完整性要求
- 变量表是变量定义的唯一来源，程序中使用的所有变量必须在变量表中定义
- 禁止定义未在FB代码中使用的冗余变量
- 变量地址字段留空，不填写具体地址

## 5. 命名与版本管理需求

### 5.1 文件命名规范
- **变量表文件**：`FB_导入变量_单线圈气缸控制_YYYYMMDD_HHMM_vX.Y.Z.csv`
- **SCL文件**：`FB_气缸控制_YYYYMMDD_HHMM_vX.Y.Z.scl`
- **测试文件**：`Test_FB_导入变量_单线圈气缸控制_YYYYMMDD_HHMM_vX.Y.Z.csv`

### 5.2 时间戳规范
- 时间戳格式：`YYYYMMDD_HHMM`
- 必须包含在文件名中，确保文件唯一性
- 用于版本追溯和文件区分

### 5.3 版本号规范
- 版本命名格式：`vX.Y.Z`
- **X**：主版本号，功能重大变更时递增
- **Y**：次版本号，功能新增时递增
- **Z**：修订版本号，bug修复或小改动时递增
- 版本号必须与时间戳结合使用
- 变量表和对应的SCL文件必须使用相同的版本号

### 5.4 历史版本管理
- 旧版本文件统一存放在`历史版本`文件夹
- 按版本号创建子文件夹（如`v1.0.3`）
- 包含完整的旧版本变量表和程序文件
- 便于追溯和回滚
