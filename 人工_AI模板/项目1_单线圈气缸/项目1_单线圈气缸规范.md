# 项目1_单线圈气缸规范

## 1. 项目概述

### 1.1 项目简介
- **项目名称**：项目1_单线圈气缸
- **功能描述**：实现单线圈气缸的伸缩控制、动点报警等功能
- **技术标准**：严格遵循IEC 61131-3标准
- **编程语言**：SCL语言

### 1.2 核心功能
- 单线圈气缸伸缩控制
- 动点传感器和原点传感器监控
- 到位状态检测
- 异常报警处理
- 状态机管理

## 3. 命名规范

### 3.1 文件命名
- **变量表文件**：`FB_导入变量_单线圈气缸控制_YYYYMMDD_HHMM_vX.Y.Z.csv`
- **SCL文件**：`FB_气缸控制_YYYYMMDD_HHMM_vX.Y.Z.scl`
- **测试文件**：`Test_FB_导入变量_单线圈气缸控制_YYYYMMDD_HHMM_vX.Y.Z.csv`

### 3.2 变量命名
- **输入变量**：前缀`i_` + 功能描述（如`i_动点传感器`）
- **输出变量**：前缀`q_` + 功能描述（如`q_气缸动点动作`）
- **内部变量**：
  - 布尔型：前缀`b_`或`tmp_` + 功能描述
  - 数值型：前缀`n_`或`tmp_` + 功能描述
  - 直接功能描述或可选`tmp_`前缀

### 3.3 FB/DB命名
- **FB命名**：`FB_功能描述`（如`FB_CylinderControl`）
- **DB命名**：`DB_参数描述`（如`DB_CylinderParams`）

## 4. 版本管理规范

### 4.1 版本命名格式
- 格式：`vX.Y.Z`
- **X**：主版本号，功能重大变更时递增
- **Y**：次版本号，功能新增时递增
- **Z**：修订版本号，bug修复或小改动时递增

### 4.2 版本号与时间戳结合
- 文件名中包含版本号和时间戳：`_YYYYMMDD_HHMM_vX.Y.Z`
- 示例：`FB_气缸控制_20260125_1657_V1.0.4.scl`

### 4.3 历史版本管理
- 旧版本文件统一存放在`历史版本`文件夹
- 版本变更记录在文件头部注释中明确标注

## 6. 代码规范

### 6.1 注释规范
- **FB头部**：包含功能描述、输入/输出变量释义
- **核心逻辑**：标注状态机切换条件、计时器参数
- **交互逻辑**：标注上下游信号交互规则、状态监控点
- **变更记录**：代码修改行上方标注`// [YYYY-MM-DD] 变更原因：xxx 变更内容：xxx`

### 6.2 结构化要求
FB必须包含五大模块：
1. **初始化模块**：系统初始化逻辑
2. **手动控制模块**：手动操作逻辑
3. **自动控制模块**：自动运行逻辑
4. **报警处理模块**：异常报警逻辑
5. **状态机模块**：状态管理逻辑

### 6.3 编码规范
- 严格符合IEC 61131-3标准
- 禁用枚举类型
- 优先使用SCL语言，禁用STL语言
- 代码缩进统一，提高可读性

## 7. 变量表规范

### 7.1 变量表格式
- **文件格式**：CSV（逗号分隔值）
- **编码要求**：必须使用GBK编码
- **表头格式**：`序号,类别,名称,数据类型,隐藏初始值,初始值,掉电保持,注释,`

### 7.2 变量定义规则
- **序号**：从1开始递增
- **类别**：IN/OUT/INOUT/VAR
- **名称**：遵循变量命名规范
- **数据类型**：BOOL/INT/DINT/DWORD/REAL等
- **初始值**：根据变量类型设置合理初始值
- **掉电保持**：根据需求设置保持/不保持
- **注释**：详细描述变量功能

### 7.3 数组处理
- **主定义行**：包含数组声明，序号递增
- **元素行**：以两个逗号开头，序号为空，类别为空，依次列出每个数组元素

### 8.1 辅助工具
- 所有Python辅助工具存放在项目根目录下的`AI_Python辅助工具`文件夹

## 9. 常见错误及解决方案

### 9.1 变量表乱码
- **原因**：变量表CSV文件编码与模板文件不同
- **解决方案**：使用`convert_to_gbk_improved.py`工具转换编码

### 9.2 变量未定义
- **原因**：FB中使用了变量表格中未定义的变量
- **解决方案**：检查FB代码中的所有变量，确保都在变量表格中定义

### 9.3 数组格式错误
- **原因**：数组元素行格式不正确
- **解决方案**：修正为正确格式`,,变量名[索引],类型,隐藏初始值,初始值,掉电保持,注释,`

### 9.4 编码自动转换问题
- **原因**：使用普通文本编辑器修改变量表导致编码转换
- **解决方案**：禁止使用普通文本编辑器，使用专用工具修改

## 10. 最佳实践

1. **使用工具创建**：始终使用指定工具创建和修改变量表
2. **定期备份**：每次修改前备份原文件
3. **多重验证**：使用工具验证+Autoshop验证
4. **保持格式一致**：遵循统一的命名和格式规范
5. **记录变更**：详细记录变量表的变更历史
6. **避免冗余变量**：只定义FB代码实际使用的变量
7. **确保文件完整性**：确认CSV文件末尾有换行符

## 11. 禁止操作

1. 禁止使用普通文本编辑器直接创建变量表CSV文件
2. 禁止变量表CSV文件使用非GBK编码
3. 禁止在变量表格中填写具体地址
4. 禁止使用未在变量表格中定义的变量
5. 禁止在逻辑程序中放置计时器
6. 禁止定义未在FB代码中使用的冗余变量
7. 禁止创建没有换行符的变量表CSV文件
