# 项目文档版本管理与变更核心规范
## 文档标识
- 适用场景：研发全流程文档（需求/设计/接口/开发/使用/变更台账）
- 核心规则：不同文档独立版本前缀+三级版本号+唯一变更标识+无重复变更记录
- 管理原则：版本独立可溯、变更唯一极简、流程闭环权责明确

## 一、专属版本号规范（不同文档不同前缀）
### 1. 版本号结构
固定格式：前缀-VX.Y.Z
- 前缀：文档类型唯一标识（团队二选一，统一即可）
- X（主版本）：重大变更（需求重构/设计大改/接口核心调整/功能删改，编译器更换，从单机控制改成联网控制；）
- Y（次版本）：重要功能新增 / 接口大改 / 模板升级，比如增加新的通讯接口，变更变量表
- Z（修订版本）：小需求变更 / BUG 修复 / 参数调整 / 文档更新，比如现场调试的参数优化，接口细节修改。
示例：V1.0.0（初始版本，需求确认）→ V1.0.1（接口细节修改）
### 2. 全文档前缀与初始版本配置表
| 文档类型         | 英文前缀 | 中文前缀 | 初始版本号  | 版本升级触发条件                     |
|------------------|----------|----------|-------------|--------------------------------------|
| 需求文档         | REQ      | 需求     | REQ-V1.0.0  | 需求新增/修改/重构/勘误              |
| 详细设计说明书   | DES      | 设计     | DES-V1.0.0  | 设计逻辑/架构/流程调整/优化          |
| 接口文档         | INT      | 接口     | INT-V1.0.0  | 接口参数/返回值/调用方式/新增/删除   |
| 开发文档         | DEV      | 开发     | DEV-V1.0.0  | 代码逻辑/部署方式/依赖配置变更       |
| 使用文档         | USE      | 使用     | USE-V1.0.0  | 功能使用方式/操作步骤/示例调整       |
| 版本变更台账     | CHG      | 变更     | CHG-V1.0.0  | 任意文档版本升级/新增变更记录        |

### 3. 版本独立升级规则
- 无关联变更：仅修改单文档，仅升级该文档版本（如需求勘误→仅REQ升级，其他不变）
- 关联变更：多文档联动修改（如设计优化→DES+INT+DEV+USE同步升级）
- 重大重构：全流程文档主版本号统一升级（X+1，Y/Z归0）

## 二、变更管理核心规范（杜绝重复+可解析）
### 1. 变更唯一标识规则（核心避重）
固定格式：文档前缀-变更类型-年月-序号
- 文档前缀：对应变更的文档类型前缀（REQ/DES/INT等）
- 变更类型：ADD(新增)/OPT(优化)/BUG(修复)/DEL(删除)/RECON(重构)
- 年月：8位数字（如202601）
- 序号：3位自增数字（如001/002）
- 示例：REQ-BUG-202601-001、DES-OPT-202601-002

### 2. 变更记录必录核心字段（无冗余，适配解析）
| 必录字段         | 字段说明/格式要求                     | 示例                                  |
|------------------|--------------------------------------|---------------------------------------|
| 变更唯一标识     | 按上述规则生成，团队内唯一           | INT-ADD-202601-003                    |
| 关联文档         | 前缀-版本号（多文档用<br>分隔）| DES-V1.0.0→DES-V1.1.0<br>INT-V1.0.0→INT-V1.1.0 |
| 变更类型         | 仅选ADD/OPT/BUG/DEL/RECON            | OPT                                   |
| 变更原因         | 简明描述，不超过50字                 | 优化输送线控制FB模块设计逻辑          |
| 变更内容         | 核心动作，分点描述（≤3点）| 1. 调整FB模块调用流程；2. 补充参数说明 |
| 变更人/时间      | 姓名+YYYY-MM-DD HH:MM                | 张三+2026-01-28 10:00                 |
| 审核人           | 姓名（小团队可填自审）| 李四                                  |

### 3. 变更前置避重校验规则
1. 检索维度：变更唯一标识前缀+变更类型+核心变更内容
2. 校验动作：变更前在变更台账中检索，存在同类记录需说明差异，无差异则合并
3. 重复判定：同时满足「同一文档前缀+同一变更类型+核心内容一致」即为重复

## 三、标准化变更流程（5步闭环，可落地）
1. 触发变更：确认变更触发源（程序修改/需求变更/文档勘误），明确需修改的文档前缀
2. 检索避重：在变更台账中检索同类记录，生成唯一变更标识
3. 文档修改：按原格式修改内容，变更处做粗体高亮，确保与程序/需求一致
4. 核对审核：自核对（小变更）/交叉审核（重大变更），确认内容无错、版本号正确
5. 归档发布：更新变更台账，升级文档版本号，归档历史版本，发布最新版

## 四、文档文件命名规范（固定格式）
### 1. 命名规则
序号-文档完整名称_前缀-版本号.md
### 2. 命名示例
1-自动化测试需求文档_REQ-V1.0.1.md
2-自动化测试详细设计说明书_DES-V1.1.0.md
3-自动化测试接口文档_INT-V1.1.0.md
4-自动化测试开发文档_DEV-V1.1.0.md
5-自动化测试使用文档_USE-V1.1.0.md
6-自动化测试版本变更台账_CHG-V1.1.0.md
