# 修正DJ-2026-014变更管理目录结构与缺失变更单 Spec v2

## Why

V2.0变更管理规范定义了完整的目录结构（043 V2.0.0）和变更单格式（040 V2.0.0），但在实际执行中存在严重偏差：

### 🔴 核心问题：规范定义 vs 实际执行的差距

| 规范要求 (043 V2.0.0 §3) | DJ-2026-014实际情况 | 差距 |
|:---|:---|:---:|
| `01_变更单/` 目录 + 7个领域子目录 | ❌ **完全不存在** | 🔴 致命 |
| 变更单文件 `CHG-[DOMAIN]-[YYYY]-XXX.md` | ❌ **没有任何变更单文件** | 🔴 致命 |
| 每个变更独立一份变更单(040模板) | 仅在台帐中写了表格行 | 🟡 格式不符 |
| 台帐用引用模式指向独立变更单 | 用内嵌模式把所有细节塞进台帐 | 🟡 组织错误 |

### 🔵 用户反馈：精简原则

> "变更报告有必要存在么？报告的部分内容是不是可以合并到变更单里？目前只有我和AI使用，可能会加载到自动化工具上。"

**功能重叠分析**:

| 功能点 | 044变更报告模板 | 040变更单模板 | 041台帐模板 | 结论 |
|:---|:---|:---|:---|:---|
| 基本信息(编号/日期/类型) | §2 | §3 | §4 | **三重重复** |
| 变更原因/背景 | §3.1 | §4 | - | **双重重复** |
| 变更前后对比 | §3.2 | §5 | - | **双重重复** |
| 影响分析 | - | §6(三维) | §5(摘要) | 变更单更完整 |
| 审批记录 | - | §8 | - | 仅变更单有 |
| 实施记录 | §4.1 | §9 | - | **双重重复** |
| 验证结果 | §5 | §10 | - | **双重重复** |
| 多维统计(领域/性质/范围) | - | - | §3 | **仅台帐有** |
| 趋势分析 | - | - | §5.2 | **仅台帐有** |

**结论**: 044变更报告与040变更单存在**约70%内容重叠**。在个人/AI/自动化工具的使用场景下，独立的变更报告目录是**过度设计**。

## What Changes

### 一、采用精简版目录结构（基于用户反馈优化）

```
00_项目管理/04_变更管理/
├── 01_变更单/                          ← 核心工作单元 (每个变更1份文件)
│   ├── CHG-PLC/                       ← PLC程序类变更单 (13份)
│   │   ├── CHG-PLC-2026-001.md
│   │   ├── CHG-PLC-2026-002.md
│   │   └── ... (共13份)
│   ├── CHG-DOCU/                      ← 文档类变更单 (3份)
│   │   ├── CHG-DOCU-2026-001.md
│   │   └── ... (共3份)
│   ├── CHG-ELEC/                      ← 电气类 (预留, 当前空)
│   ├── CHG-MECH/                      ← 机械类 (预留, 当前空)
│   ├── CHG-HMI/                       ← HMI类 (预留, 当前空)
│   ├── CHG-SCPT/                      ← Python脚本类 (预留, 当前空)
│   └── CHG-SAFE/                      ← 安全类 (预留, 当前空)
│
├── DJ-2026-014_版本变更台帐.md         ← 汇总统计 + 引用到各变更单
└── README.md                           ← 目录说明 + 使用指南
```

**❌ 不再创建 `02_变更报告/` 目录**

**理由**:
1. 变更单(040)的§10验证结论已覆盖单次变更的报告需求
2. 台帐(041)的§3多维统计+§5趋势分析已覆盖多变更的汇总需求
3. 如需阶段性总结, 可在台帐末尾追加"阶段回顾"段落, 无需独立文档
4. 更简洁的结构更适合AI解析和自动化工具集成

### 二、创建16份正式变更单文件（按040 V2.0.0模板）

每份变更单是**完整的、自包含的变更档案**, 包含:
- ✅ §3 二维分类 (领域×性质×范围) — 自动打标签
- ✅ §4 变更原因 — 为什么改
- ✅ §5 变更前后对比 — 改了什么
- ✅ §6 三维影响评估 — 影响谁 + 传播链
- ✅ §7 实施计划 — 怎么改
- ✅ §8 分级审批 — 谁批准 (SYSTEM/CROSS/SAFE自动升级)
- ✅ §9 实施记录 — 改的结果
- ✅ §10 验证结论 — 改对了没

### 三、将台帐从"内嵌模式"改为"引用模式"

**当前问题**: 台帐§4.2把FB-V2-001~016的所有细节(变更原因/内容/根因)都内嵌在表格单元格里

**修正后**:
```markdown
| 编号 | 变更单链接 | 领域 | 性质 | 范围 | 标题 | 优先级 | 状态 |
|------|-----------|:----:|:----:|:----:|:-----|:------:|:----:|
| FB-V2-001 | [→ CHG-PLC-2026-001](./01_变更单/CHG-PLC/CHG-PLC-2026-001.md) | PLC | REQ | MOD | 新增状态字输出q_StatusWord | P1 | ✅完成 |
```

台帐只保留**一行摘要**, 详细信息全部在独立的变更单文件中。

### 四、更新README.md

重点说明:
- 精简后的目录结构（为什么没有02_变更报告/）
- 变更单命名规则和存放位置
- 台帐与变更单的引用关系
- 如何新建一份变更单（可复制的最小流程）

## ADDED Requirements

### Requirement: 精简版变更管理目录结构

项目 `00_项目管理/04_变更管理/` SHALL 采用以下精简结构:

```
04_变更管理/
├── 01_变更单/              ← 必需, 按领域分子目录
│   ├── CHG-[DOMAIN]/      ← 7个领域子目录
├── [项目]_版本变更台帐.md  ← 必需, 汇总统计+引用
└── README.md               ← 推荐, 使用指南
```

SHALL NOT 包含 `02_变更报告/` 目录 (报告功能已合并到变更单§10和台帐§3/§5)。

#### Scenario: 目录验证

- **WHEN** 执行 `ls 00_项目管理/04_变更管理/`
- **THEN** 输出包含: `01_变更单/`, `*_版本变更台帐.md`, `README.md`
- **AND** SHALL NOT 包含 `02_变更报告/`

### Requirement: 变更单作为唯一变更记录载体

每个变更 SHALL 有且仅有**一份**对应的变更单文件(`CHG-[DOMAIN]-[YYYY]-XXX.md`), 该文件是此变更的**权威数据源** (Single Source of Truth):

- 变更单 SHALL 包含完整的生命周期记录 (申请→审批→实施→验证)
- 台帐 SHALL 只存放指向变更单的引用 + 统计摘要
- 其他文档(设计文档/代码注释) 如需提及变更, 应引用变更单编号而非复制内容

#### Scenario: Single Source of Truth验证

- **WHEN** 需要查询 FB-V2-005 (接口重构) 的完整信息
- **THEN** 唯一权威来源是 `01_变更单/CHG-PLC/CHG-PLC-2026-004.md`
- **AND** 台帐/其他文档中的相关信息均为该文件的摘要或引用

### Requirement: 变更单完整性 (按040 V2.0.0模板)

每份变更单文件 SHALL 符合 [040_通用变更单模板_CHG-V2.0.0](../../../00_Obsidian_Base全局规范文件仓库/04_监控和控制/01_变更管理/01_变更单/040_通用变更单模板_CHG-V2.0.0.md):

- **必填章节**: §3(分类), §4(原因), §5(内容), §6(影响), §8(审批), §10(验证)
- **SYSTEM/CROSS/SAFE级变更**: 必须包含§6.2跨领域影响 + §6.3传播链 + §8复审记录
- **P0级Bug修复**: 必须包含§5中的详细根因分析(现象→根因→修复→验证)

#### Scenario: SYSTEM级变更单完整性

- **WHEN** 打开 CHG-PLC-2026-004.md (FB-V2-005 接口重构, SYSTEM级)
- **THEN** 文件包含:
  - §3.3 范围=SYSTEM ☑
  - §6.2 标注DOCU受影响(注释需同步)
  - §6.3 传播链图: [PLC接口]→[PLC变量]→[PLC模式检查]
  - §6.3 关联单: CHG-PLC-2026-005, CHG-PLC-2026-008
  - §8.1 复审栏: 技术总监

## REMOVED Requirements

### Requirement: 02_变更报告/ 目录 (从初始spec中移除)

**移除原因**: 与040变更单存在约70%内容重叠, 在个人/AI/自动化工具场景下属于过度设计。
**替代方案**:
- 单次变更的完整记录 → 变更单§10验证结论
- 多变更的汇总分析 → 台帐§3多维统计 + §5趋势分析
- 阶段性总结 → 台帐末尾追加"阶段回顾"段落(可选)
