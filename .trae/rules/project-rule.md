# 全局开发规则

## 规则层级

本工作空间采用三层规则架构：

1. **全局规则**（本文件）：适用于所有项目的通用开发准则
2. **技术栈规则**：针对特定技术栈的详细规范
   - PLC: `0100_PLC自动化/.trae/rules/plc-rules.md`
   - Python: `01_Project自动化项目管理/.trae/rules/python-rules.md`
3. **项目级规则**：单个项目的特殊约定

**冲突处理**：当全局规则与技术栈规则冲突时，以技术栈规则为准。

## 规范体系

项目规范权威目录：

- 全局PM规范: `00_Obsidian_Base全局规范文件仓库/`
- PLC技术栈规范: `0100_PLC自动化/00_通用规范/PLC编程/`
- Python技术栈规范: `01_Project自动化项目管理/00_通用规范/Python开发/`
- 规范注册表: `00_Obsidian_Base全局规范文件仓库/spec_registry.json`

### SpecMgr CLI — 规范管理工具

使用 SpecMgr CLI（SW-2026-006）管理全域规范（PM/PLC/Python），工具路径：`01_Project自动化项目管理/Python自动化项目总库/02_在研项目/SW-2026-006_规范管理工具/02_源代码/`

```bash
# 运行规范健康检查（检查重复/版本漂移/废弃引用等）
specmgr check -w <工作空间根目录>

# 自动生成规范索引文件（按域生成README）
specmgr index -w <工作空间根目录>
specmgr index -w <工作空间根目录> --domain plc    # 只生成PLC域

# 批量添加/更新规范frontmatter
specmgr frontmatter -w <工作空间根目录> --dry-run   # 先预览
specmgr frontmatter -w <工作空间根目录>              # 实际修改

# 生成规范元数据汇总报告
specmgr report -w <工作空间根目录>
specmgr report -w <工作空间根目录> --format json    # JSON格式
```

**使用场景**：
- 新增/修改规范文件后 → 运行 `specmgr check` 验证规范性
- 规范目录结构变更后 → 运行 `specmgr index` 重新生成索引
- 规范文件缺少frontmatter → 运行 `specmgr frontmatter` 补全
- 定期审查规范体系 → 运行 `specmgr report` 生成报告

## 一、编码前准备

1. **方案描述**：编写任何代码之前，必须详细描述方案，包括功能、实现方式、依赖项等。如果需求不明确，必须先与项目负责人沟通确认需求，禁止在未确认需求的情况下假设需求。

2. **任务分解**：当任务复杂、需要修改或编写的文件较多时，必须先停下来进行分解，每个任务只负责一个功能模块。

## 二、编码过程

3. **规范遵循**：编码时必须遵循当前工作目录对应的技术栈编码规范：
   - PLC/SCL: 遵循905编程规范（命名、语法、代码结构）
   - Python: 遵循210编程规范（命名、风格、架构）
   - 不确定时，查阅对应技术栈的规则文件

4. **质量要求**：代码必须满足：
   - 可维护性：函数/功能块单一职责，命名清晰，注释充分
   - 可扩展性：避免硬编码，使用配置/常量，预留扩展接口
   - 可测试性：关键逻辑可独立测试，避免全局状态依赖

## 三、编码后验证

5. **问题预判**：编码完成后，列出可能出现的问题和解决方法，并建议用相应的测试用例进行验证。

6. **Bug修复**：当发现bug时，首先编写能重现bug的代码，确认bug的存在，然后不断测试代码直到bug被修复。

## 四、持续改进

7. **规则迭代**：每次被纠正后，必须重新审视对话，确认是否需要在本规则中添加新规则，这样才能保证不再发生类似的情况。

## 安全红线

- 禁止在代码中硬编码密钥、Token、密码等敏感信息
- 禁止将敏感信息文件（如 \*.key, \*.token, \*.secret）提交到版本库
- 禁止在日志中输出敏感信息

## 版本管理

- 提交信息必须遵循 `git-commit-message.md` 规范
- 每次提交应该是原子性的（一个逻辑变更一次提交）
- 禁止提交无法编译/运行的代码

## 禁止事项

- 禁止跳过方案描述直接编码
- 禁止忽略已有规范自行发明新的编码风格
- 禁止提交包含敏感信息的代码
