在此处编写规则，自定义 AI 生成提交信息的风格。
    **允许的类型**：
    - `feat`：新增功能/逻辑/功能块
    - `fix`：修复bug、逻辑错误、参数错误
    - `docs`：更新文档、说明、报警码定义
    - `refactor`：重构代码结构、优化逻辑、整理变量
    - `chore`：配置文件、版本号、依赖等非代码变更
    - `test`：新增/修改测试逻辑、仿真脚本
     **模块命名规则**：
    - 必须使用项目中实际的模块名，不能使用伪模块名
    - 模块名必须与项目中使用的模块名一致
    **描述要求**：
    - 必须用中文，清晰说明变更内容，控制在50字以内
    - 禁止模糊描述，如“修改了代码”“优化了逻辑”等
    - 描述必须与变更内容相关，不能与项目无关
     **参考示例**：
    - `feat: 新增取放料机构功能块`
    - `fix: 修复了取放料机构的逻辑错误`
    - `docs: 更新了取放料机构的说明`
    - `refactor: 优化了取放料机构的代码结构`
    - `chore: 更新了取放料机构的版本号`
    - `test: 新增了取放料机构的测试逻辑`
