# 规范仓库拆分重构 + 目录重命名方案

> **版本**: V2.0 (Plan - 含重命名)
> **日期**: 2026-05-06
> **状态**: 待审核
> **变更**: 新增 `0100_项目` → `0100_PLC自动化` 重命名及影响消除

## 一、问题诊断

### 1.1 当前结构的问题

```
00_Obsidian_Base全局规范文件仓库/
├── 01_项目管理域/          ✅ 通用（应保留）
├── 02_技术开发域/          ❌ 混合了多种技术栈
│   ├── 00_编码基础/        ❌ Python特定
│   ├── 01_PLC开发工作流/    ❌ PLC特定（已重复）
│   ├── 02_工具链集成/      ⚠️ 部分通用/部分特定
│   └── 03_文档模板/        ⚠️ 部分通用/部分特定
```

**核心矛盾：**
- 全局仓库定位为"全局"，却包含了**技术栈特定**的内容
- 不同技术栈工程师需要在不同地方查找规范，造成混乱
- PLC规范已经实际存在于两个位置（全局仓库 + 0100_项目）
- Python规范只在全局仓库，但实际开发在 01_Project 目录
- **目录命名不明确**：`0100_项目` 名称过于泛化，无法体现PLC自动化定位

### 1.2 实际使用现状

| 技术栈 | 项目位置 | 规范当前位置 | 问题 |
|--------|----------|--------------|------|
| **PLC** | `0100_项目/` (需改名) | 全局仓库 + `0100_项目/00_通用规范/PLC编程/` | 🔴 双重维护 + 命名不明 |
| **Python** | `01_Project自动化项目管理/` | 仅全局仓库 | 🟡 远离使用场景 |
| **单片机** | (未来) | 无 | 🟢 未开始 |

## 二、设计原则

### 2.1 分层管理策略

```
┌─────────────────────────────────────────────────────┐
│           全局规范仓库 (00_Obsidian)                  │
│  ┌───────────────────────────────────────────────┐  │
│  │  01_项目管理域 (PM通用)                         │  │
│  │  - 立项/规划/执行/变更/收尾                     │  │
│  │  - 通用文档模板（非技术特定）                    │  │
│  │  - 通用变更管理流程                             │  │
│  └───────────────────────────────────────────────┘  │
│  ┌───────────────────────────────────────────────┐  │
│  │  02_跨域通用规范                                │  │
│  │  - Git工作流（所有项目共用）                    │  │
│  │  - AI输出质量检查                              │  │
│  │  - MCP工具使用                                 │  │
│  └───────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────┘

┌──────────────────────┐  ┌──────────────────┐  ┌──────────────────┐
│ 0100_PLC自动化/     │  │ 01_Project/      │  │ 未来单片机项目/   │
│ 00_通用规范/        │  │ xx_通用规范/     │  │ xx_通用规范/     │
│ ├─ PLC编程/         │  │ ├─ Python开发/   │  │ ├─ MCU开发/      │
│ └─ 项目管理(引用)    │  │ └─ 项目管理(引用)│  │ └─ 项目管理(引用)│
└──────────────────────┘  └──────────────────┘  └──────────────────┘
```

### 2.2 分类标准

| 类别 | 判断标准 | 存放位置 |
|------|----------|----------|
| **PM通用** | 与技术栈无关的项目管理流程 | 全局仓库 |
| **跨域工具** | 所有技术栈共用的工具/流程 | 全局仓库 |
| **技术特定** | 仅适用于某一种技术栈 | 对应项目目录 |

### 2.3 目录命名规范

**新命名规则：**
- 格式：`NNNN_技术领域简称`
- 示例：
  - `0100_PLC自动化` - PLC项目主目录
  - `0200_Python自动化` (未来可选) - Python项目目录
  - `0300_MCU嵌入式` (未来) - 单片机项目目录

**优势：**
- 编号排序清晰（0100 < 0200 < 0300）
- 技术领域一目了然
- 避免泛化的"项目"命名
