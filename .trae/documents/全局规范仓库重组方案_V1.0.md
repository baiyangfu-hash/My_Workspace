# 全局规范仓库重组方案 - V1.0

## 一、背景与目标

### 1.1 背景
- 全局规范仓库（`00_Obsidian_Base全局规范文件仓库`）原有80+个md文件，通过Git Stash成功恢复
- 原有结构按**项目生命周期**（启动→规划→执行→监控→收尾）组织
- 实际使用中发现：**项目管理规范**和**技术开发规范**混在一起，查找不便

### 1.2 目标
1. **双域分离**：将规范按"项目管理域"和"技术开发域"两大维度重新组织
2. **流程导向**：技术开发的规范要按照实际开发流程排序（编码基础→PLC→Python→工具→测试）
3. **经验融合**：将`0100_项目`实战中总结的906/907等新规范纳入全局仓库
4. **去重合并**：解决4处规范重叠问题（PLC命名/注释/定时器/变更管理）
5. **索引重建**：建立清晰的INDEX索引文件
