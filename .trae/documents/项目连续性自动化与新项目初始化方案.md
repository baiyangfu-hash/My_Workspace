# 项目连续性自动化与新项目初始化方案

## 目标

为工作区内两类项目建立统一且可持续的协作机制：

- 软件项目
- PLC/电气项目

核心原则：

- `PM_SESSION_<项目编号>.md` 是唯一项目状态真源
- hooks 负责恢复上下文、提醒和生成交接草稿
- `apply-handoff.ps1` 负责在人工确认后半自动写回 `PM_SESSION`
- 新项目通过 bootstrap 初始化，不再从旧项目手工复制真实状态文件

## 适用范围

### 软件项目

典型结构：

- `pyproject.toml`
- `src/`
- `tests/`
- `ui/`
- `main.py`

### PLC/电气项目

典型结构：

- `02_PLC程序/`
- `03_HMI设计/`
- `04_现场调试/`
- `06_文档与交付/`

## 组成部分

### 1. PM_SESSION

项目根目录必须存在：

```text
PM_SESSION_<项目编号>.md
```

最少包含：

- `0. Meta`
- `1. Positioning`
- `2. Current Focus`
- `3. Status Summary`
- `4. Artifacts Index`
- `5. Logs`
- `6. Implementation Log`
- `7. Verification Log`
- `8. Handoff Notes`
- `9. Next Actions`

### 2. Hooks

项目根目录下的：

```text
.github/hooks/
```

标准事件：

- `sessionStart`
- `agentStop`
- `sessionEnd`

标准脚本：

- `session-start.ps1`
- `agent-stop.ps1`
- `session-end.ps1`
- `apply-handoff.ps1`

### 3. Handoff Drafts

项目根目录下的：

```text
.trae/handoffs/
```

用途：

- 保存最新交接草稿
- 保存带时间戳的历史草稿

## 事件职责

### sessionStart

- 读取 `PM_SESSION`
- 恢复 `current_focus / milestone / handoff / next_action`
- 检查是否存在未合并的最新 draft

### agentStop

- 结束前提醒：
  - 是否已经补写 `PM_SESSION`
  - 是否存在未合并的 draft
  - 软件项目的测试/冒烟/打包状态
  - PLC 项目的编译/现场/人工复核状态

### sessionEnd

- 生成带时间戳的交接草稿
- 更新 `latest-session-handoff-draft.md`
- 提示下一步执行 `apply-handoff.ps1`

### apply-handoff

- 读取最新 draft
- 校验 `6-9` 区块完整性
- 备份 `PM_SESSION`
- 将 review 后的交接内容追加进 `PM_SESSION`

## 新项目初始化

工作区统一使用：

```powershell
powershell -ExecutionPolicy Bypass -File "c:\Users\fubai\Desktop\My_Workspace\.trae\bin\bootstrap-project-continuity.ps1" -ProjectRoot "<项目根目录>" -ProjectId "<项目编号>" -ProjectName "<项目名称>" -ProjectType <software|plc>
```

初始化来源：

- `c:\Users\fubai\Desktop\My_Workspace\.trae\project-bootstrap\software`
- `c:\Users\fubai\Desktop\My_Workspace\.trae\project-bootstrap\plc`

初始化结果：

- 生成 `PM_SESSION_<项目编号>.md`
- 安装 `.github/hooks/`
- 创建 `.trae/handoffs/`

## 技能分工

### pm-workflow

- 负责初始化项目治理骨架
- 负责需求、计划、变更、发布与项目状态维护

### fullstack-engineer

- 负责软件项目实现、联调、评审、调试
- 若发现没有 `PM_SESSION`，回退到 `pm-workflow` 初始化

### plc-electrical-engineer

- 负责 PLC 程序、规范、程序文档、调试与交付资料
- 若发现没有 `PM_SESSION`，回退到 `pm-workflow` 初始化

## 风险边界

### 软件项目

- hooks 不替代测试结论
- 打包与交付仍需独立验证

### PLC/电气项目

- 文档一致性不等于可上机
- 编译验证、现场验证、安全相关人工复核必须保留
- 自动化不能替代工程审核责任

## 推荐使用顺序

1. 新项目先执行 bootstrap
2. 用 `pm-workflow` 建立定位、焦点和文档索引
3. 进入 `fullstack-engineer` 或 `plc-electrical-engineer`
4. 会话结束后 review draft
5. 执行 `apply-handoff.ps1`
6. 保持 `PM_SESSION` 为唯一状态真源
