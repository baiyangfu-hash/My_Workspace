### 1.2 当前规范的变更类型定义（问题核心）

#### ❌ 现状：变更单模板(040)中的变更类型（第24行）
```
变更类型: □ 需求变更 □ 技术变更 □ 资源变更 □ 进度变更 □ 其他
```

**问题**: 这是**纯软件项目管理视角**的分类，完全不适用于自动化工程项目！

#### ❌ 现状：变更影响分析字段（第39-45行）
```
| 影响领域 | 影响程度 | 应对措施 | 备注 |
|---------|----------|----------|------|
| 范围     |          |          |      |
| 进度     |          |          |      |
| 成本     |          |          |      |
| 质量     |          |          |      |
| 其他     |          |          |      |
```

**问题**: 影响领域是PMBOK五大约束，没有**工程交付物维度**的分类！

#### ❌ 现状：流程规范(042)的范围声明（第20行）
```
本规范适用于所有Python项目的变更管理活动，
包括需求变更、技术变更、资源变更、进度变更等。
```

**问题**: 明确写死了"**Python项目**"，直接排除了PLC/HMI/电气/机械等工程领域！

## 二、根因分析：为什么当前规范不适配？

### 2.1 规范创建时的定位偏差

| 维度 | 当前规范的设计假设 | 自动化工程项目的实际需求 |
|------|-------------------|------------------------|
| **项目类型** | Python软件开发项目 | 多学科集成项目(软+硬+电+控) |
| **交付物** | 代码 + 文档 | 电气图纸 + 机械3D + PLC程序 + HMI画面 + Python脚本 + 结构文档 |
| **变更触发源** | 需求文档/代码Review | 现场调试/传感器更换/工艺调整/客户临时要求 |
| **影响传播路径** | 模块→接口→系统 | 电气→IO分配→PLC程序→HMI画面→联锁逻辑→安全矩阵 |
| **审批角色** | PM/Tech Lead/Manager | 电气工程师/机械工程师/PLC工程师/项目经理/安全负责人 |
| **验证方式** | 单元测试/集成测试/系统测试 | 仿真测试/现场空载/带料试运行/FAT/SAT |

### 2.2 缺失的关键维度

#### 维度A：变更的技术领域（WHO - 哪个专业？）

| 领域代码 | 领域名称 | 典型交付物 | 当前规范状态 |
|---------|----------|-----------|-------------|
| **ELEC** | 电气设计 | Eplan原理图/接线图/IO表/BOM | ❌ 完全缺失 |
| **MECH** | 机械结构 | SolidWorks 3D/装配图/加工图 | ❌ 完全缺失 |
| **PLC** | PLC程序 | SCL/ST/LD源码/GVL/变量表 | ⚠️ 被归入"技术变更" |
| **HMI** | HMI画面 | ProFace/WinCC画面/变量映射 | ⚠️ 被归入"技术变更" |
| **SCPT** | Python脚本 | 数据采集/MES接口/工具脚本 | ⚠️ 被归入"技术变更"(唯一被覆盖的) |
| **DOCU** | 工程文档 | 设计说明书/操作手册/验收报告 | ⚠️ 被归入"需求变更"或"其他" |
| **SAFE** | 安全功能 | 安全矩阵/SIL评估/急停回路 | ❌ 完全缺失 |

#### 维度B：变更的业务性质（WHY - 为什么变？）

| 性质代码 | 性质名称 | 说明 | 当前规范状态 |
|---------|----------|------|-------------|
| **REQ** | 需求变更 | 客户/市场驱动的新需求 | ✅ 已有 |
| **DEF** | 缺陷修复 | Bug/故障/设计错误 | ⚠️ 被归入"技术变更" |
| **OPT** | 优化改进 | 性能/可维护性/用户体验提升 | ⚠️ 被归入"技术变更" |
| **CFG** | 配置调整 | 参数/设定值/IO地址修改 | ❌ 完全缺失 |
| **EMRG** | 紧急变更 | 安全/生产中断等紧急情况 | ❌ 完全缺失(仅有"紧急"字样无独立分类) |

#### 维度C：变更的影响范围（WHERE - 影响到哪些东西？）

| 范围代码 | 范围名称 | 典型影响链 | 当前规范状态 |
|---------|----------|-----------|-------------|
| **LOCAL** | 局部变更 | 仅影响单个POU/单个画面/单个IO点 | ❌ 无法区分 |
| **MODULE** | 模块级变更 | 影响单个设备/单条输送线 | ❌ 无法区分 |
| **SYSTEM** | 系统级变更 | 影响多模块联动/联锁逻辑/通讯接口 | ❌ 无法区分 |
| **CROSS** | 跨系统变更 | 影响PLC+HMI+电气+机械多个子系统 | ❌ 完全缺失 |
| **SAFE** | 安全相关变更 | 影响急停/安全回路/SIL等级 | ❌ 完全缺失 |

## 四、改进方案

### 4.1 方案总览：从"软件变更管理"升级为"工程变更管理"

```
┌─────────────────────────────────────────────────────────────┐
│                   改进前 (当前状态)                          │
│                                                             │
│   变更类型 = {需求, 技术, 资源, 进度, 其他}                │
│   影响领域 = {范围, 进度, 成本, 质量}                       │
│   适用范围 = "所有Python项目"                               │
│                                                             │
│   ❌ 无法表达 "PLC程序因电气IO调整而修改" 这类变更           │
│   ❌ 无法追踪 "传感器换型号→接线改→程序改→HMI改" 的链条    │
└─────────────────────────────────────────────────────────────┘
                            ↓ 改进后
┌─────────────────────────────────────────────────────────────┐
│                   改进后 (目标状态)                          │
│                                                             │
│   变更类型 = 二维分类:                                       │
│     第一维(技术领域): ELEC / MECH / PLC / HMI / SCPT / DOCU / SAFE │
│     第二维(业务性质): REQ / DEF / OPT / CFG / EMRG         │
│                                                             │
│   影响领域 = 三维评估:                                       │
│     项目约束: 范围 / 进度 / 成本 / 质量 / 风险             │
│     技术领域: 电气 / 机械 / PLC / HMI / 文档 / 安全        │
│     影响范围: LOCAL / MODULE / SYSTEM / CROSS / SAFE       │
│                                                             │
│   适用范围 = "所有自动化工程项目(Python/PLC/HMI/电气/机械)" │
│                                                             │
│   ✅ 可精确表达: CHG-ELEC-001 (电气IO点位调整)              │
│   ✅ 可追踪传播: ELEC变更 → 触发PLC变更 → 触发HMI变更      │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 详细改动计划

#### 改动 #1: 042_通用变更管理流程规范_PM-V1.1.0 → 升级到 V2.0.0

**改动位置**: §3 范围（第18-21行）

**改动前**:
```markdown
## 3. 范围
本规范适用于所有Python项目的变更管理活动，包括需求变更、技术变更、资源变更、进度变更等。
```

**改动后**:
```markdown
## 3. 范围
本规范适用于所有**自动化工程项目**的变更管理活动，涵盖以下技术领域：
- **电气设计(ELEC)**: Eplan原理图、接线图、IO分配表、BOM清单、柜体布局
- **机械结构(MECH)**: 3D模型、装配图、加工图、结构件选型
- **PLC程序(PLC)**: IEC 61131-3标准程序(SCL/ST/LD/FBD)、变量表、功能块库
- **HMI程序(HMI)**: 触摸屏画面、变量映射、报警配置、配方管理
- **Python脚本(SCPT)**: 数据采集、MES接口、上位机应用、工具脚本
- **工程文档(DOCU)**: 设计说明书、操作手册、验收报告、培训材料
- **安全功能(SAFE)**: 急停回路、安全矩阵、SIL等级评估、安全PLC

同时支持以下业务性质的变更：
- **需求变更(REQ)**: 客户/市场驱动的功能新增或修改
- **缺陷修复(DEF)**: Bug修复、故障排除、设计纠错
- **优化改进(OPT)**: 性能提升、可维护性改善、用户体验优化
- **配置调整(CFG)**: 参数修改、IO地址调整、通信配置变更
- **紧急变更(EMRG)**: 安全相关、生产中断等需立即处理的变更
```
