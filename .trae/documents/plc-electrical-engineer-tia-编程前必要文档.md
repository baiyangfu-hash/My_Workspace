## 3. 后续正式编程前应补齐的设计内容

如果下一步进入真正的技能增强实现，建议先补齐以下设计章节。

### 3.1 平台适配声明

必须明确写清：

- 主适配平台：TIA Portal
- 主 CPU 范围：S7-1200 / S7-1500
- 主语言：SCL / ST
- 扩展范围：LAD / FBD / TO / WinCC / 通信 / 硬件配置

### 3.2 结论分层机制

技能输出必须能给每个结论打标签：

- `TIA 平台事实`
- `本地规范偏差`
- `项目实现偏差`
- `源码-文档不同步`
- `证据不足，保守推断`

### 3.3 审查顺序设计

技能固定采用以下审查顺序：

1. 工艺对象
2. 执行器 / 传感器 / 互锁 / 安全态
3. 状态机 / 手自动边界 / 故障态
4. TIA / SCL 实现方式
5. 本地规范检查
6. 文档一致性检查

### 3.4 示例场景模板

至少应规划四类模板：

1. 气缸 / 双位置电磁阀
2. 真空 / 破真空
3. 输送机 / 上下游握手
4. 报警 / 联锁 / 超时

### 3.5 输出模板

正式编程前，技能应确定统一输出骨架：

1. 工艺视角
2. TIA 实现视角
3. 本地规范视角
4. 文档一致性视角
5. 风险与人工复核

### 3.6 模板联动机制

正式编程前，技能还应确定模板如何与规范联动，而不是只保存一份静态模板。

最低要求：

1. FB 设计模板绑定：
   - `023_PLC程序设计文档模板_PLC.md`
   - `815_PLC接口文档模板_INT.md`
   - `903/904/905/906/907`
2. 结构体设计模板绑定：
   - `815_PLC接口文档模板_INT.md`
   - `904/905`
3. 每次输出模板前，检查规范的：
   - `spec_id`
   - `version`
   - `lifecycle`
   - `canonical_path`
4. 发现规范升级或项目实现偏差时，模板必须同步复核

## 4. 本次从 `FB_1011` 抽取的关键建模对象

后续技能增强时，至少要把下列对象固化为“标准审查维度”：

### 4.1 执行器语义

- 动点
- 原点
- 得电动作
- 失电复位
- 单线圈两位阀默认行为

### 4.2 反馈语义

- 动点到位
- 原点到位
- 反馈消抖
- 两点同时到位冲突
- 反馈缺失 / 单传感器

### 4.3 风险语义

- 超时不到位
- 极性接反
- 空闲安全态
- 手动模式绕过互锁
- 文档与代码不一致

## 5. 编程前接受标准

只有当以下条件满足，才进入下一步真正的技能实现：

1. 已有资料基线文档
2. 已确认技能主适配平台就是 TIA Portal / S7-1200 / S7-1500 / SCL
3. 已明确“平台事实 / 本地规范 / 项目偏差”的三层边界
4. 已确认示例功能块 `FB_1011` 用作技能场景化模板之一
5. 已确定输出模板不是泛泛建议，而是工程师可交付结构
6. 已确定模板会随规范版本变化而迭代，不是静态文案
