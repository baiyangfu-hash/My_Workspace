# Trae CN 迁移影响分析计划

## 背景

您当前使用的是 **Trae 国际版**（trae.ai），计划切换到 **Trae 国内版**（trae.com.cn）。本文档全面分析切换可能产生的影响。

---

## 一、Trae CN vs Trae 国际版 核心差异

| 维度 | 国际版 (trae.ai) | 国内版 (trae.com.cn) |
|------|-----------------|---------------------|
| 登录方式 | Google 授权 | 手机号 / 掘金社区授权 |
| 账号体系 | 完全独立 | 完全独立（与国际版不互通） |
| AI 模型 | GPT-5.x、Gemini、Claude 等海外模型 | 豆包、DeepSeek、GLM、Kimi、Qwen、MiniMax 等国产模型 |
| Builder 模式 | Beta | Alpha（功能可能滞后） |
| 图片上传 | 支持（Claude/GPT 多模态） | 部分模型支持（豆包 Seed-2.0 支持视觉） |
| 网络 | 需科学上网 | 国内直连，速度更快 |
| 费用 | 免费（部分模型有快速请求配额） | 完全免费 |

## 二、常见问题（FAQ）

### Q1: 安装 Trae CN 后，项目文件会重复占用磁盘空间吗？

**不会。** 项目文件完全不会被复制。

原因如下：

| 文件类别 | 存储位置 | 是否会重复 | 说明 |
|---------|---------|-----------|------|
| 项目源码/配置 | `c:\Users\fubai\Desktop\My_Workspace\` | ❌ 不重复 | 两个 IDE 打开同一个工作区目录 |
| `.trae/` 目录（规则/specs/计划） | 项目根目录下 | ❌ 不重复 | 共享，两个 IDE 都能读取 |
| IDE 自身程序文件 | `%LOCALAPPDATA%\Programs\` 下各自目录 | ✅ 会重复 | 每个 IDE 约 300-500MB |
| IDE 用户设置 | `%APPDATA%\` 下各自目录 | ✅ 会重复 | 设置文件很小，几乎可忽略 |
| 已安装的扩展 | 各自 IDE 的扩展目录 | ✅ 会重复 | 扩展文件大小因扩展而异 |

**结论**：项目文件零重复。只有 IDE 自身程序 + 扩展会多占一些磁盘空间（总计约 1-2GB），远小于项目本身。

---

### Q2: 插件/扩展需要重新安装和配置吗？

**需要重新安装，但有便捷的一键导入功能。**

原理：
- Trae 国际版和 Trae CN 是**两个独立应用**，各自有独立的扩展安装目录
- 但是 Trae 提供了 **"从 VS Code / 其他编辑器导入"** 功能

**推荐操作流程：**

1. 安装并打开 Trae CN
2. 菜单 → `文件 → 首选项 → 导入配置`（或首次启动时选择）
3. 选择从 Trae 国际版导入
4. Trae CN 会自动：
   - 迁移你的快捷键设置
   - 迁移主题、字体等外观设置
   - **列出并提示安装你国际版中的扩展**

**哪些不需要重新配置（项目级配置自动共享）：**

因为两个 IDE 打开同一个项目目录，以下配置自动共享、无需额外操作：
- `.trae/rules/` 下的规则文件 ✅
- `.trae/specs/` 下的需求规格 ✅
- `.trae/documents/` 下的计划文档 ✅
- `.vscode/settings.json`（如有） ✅
- `.plc.json`（Siemens LSP 配置） ✅

**哪些确实需要重新配置（IDE 级配置）：**
- 扩展安装 — 用导入功能批量安装
- 用户级 settings.json — 用导入功能迁移
- MCP Server 配置 — 可能需要重新在 Trae CN 的 MCP 管理界面添加（或确认项目级 `.trae/mcp.json` 是否被识别）

## 三、影响分析（按优先级排序）

### 3.1 AI 编程能力影响 ⭐⭐⭐⭐⭐

**当前模型（国际版）**: GPT-5.x / Claude / Gemini 系列

**切换后模型（国内版）**: DeepSeek V3.1 / R1、豆包 Seed-Code、GLM-5、Kimi K2.5、Qwen3-Coder 等

**对 PLC ST 编程任务的影响：**
- DeepSeek V3.1 代码生成能力强，处理结构化文本 (ST) 语言效果较好
- 豆包 Seed-Code 是针对编程优化的模型
- 国产模型对中文技术文档理解更深入
- **潜在风险**：国际版模型（特别是 Claude）在复杂逻辑推理上可能更优；国产模型对西门子 PLC 特定语法支持需实测验证

**建议**：先用国内版跑一遍现有的 .scltest 测试用例，对比生成质量。

---

### 3.2 账号与历史数据迁移 ⭐⭐⭐⭐⭐

- **账号不互通**：国际版和国内版账号完全隔离，需要重新注册（手机号）
- **对话历史**：无法从国际版迁移到国内版
- **用户偏好设置**：需要重新配置
- **不影响**：本地项目文件、Git 仓库不受任何影响

---

### 3.3 VS Code 配置与扩展兼容性 ⭐⭐⭐⭐

Trae 基于 VS Code 内核，**可以导入 VS Code 配置**：

| 可导入项 | 兼容性 |
|---------|--------|
| 快捷键设置 | ✅ 完全兼容 |
| 主题/字体 | ✅ 完全兼容 |
| VS Code 扩展 | ✅ 绝大多数兼容（少数依赖 VS Code 私有 API 的可能有问题） |
| settings.json | ✅ 可导入 |

**您项目中的关键扩展兼容性预估：**
- Siemens LSP (PLC 语言支持) - 需实测
- GitLens - 应兼容
- MCP 相关配置 - 详见 2.4

---

### 3.4 MCP 配置影响 ⭐⭐⭐⭐

**当前 MCP 配置（.trae/mcp.json 或类似配置）：**
- PaddleOCR MCP (PP-StructureV3)
- GitHub MCP
- GitKraken MCP

**影响评估：**
- MCP 协议本身是通用标准，国内版应同样支持
- MCP server 配置文件路径和格式可能需要确认
- PaddleOCR 等本地 MCP 不受影响（本地 Python 环境不变）
- GitHub MCP 服务端连接不受影响

**需要验证**：Trae CN 的 MCP 配置文件位置是否与国际版一致

---

### 3.5 项目规则文件 (.trae/rules/) ⭐⭐⭐

项目根目录下的规则文件：
- `.trae/rules/Claude.md` - AI 行为规则
- `.trae/rules/git-commit-message.md` - Git 提交规范
- `.trae/rules/project-rule.md` - 项目规则

**影响评估：**
- 规则文件格式应兼容（Markdown 通用格式）
- 但 AI 行为规则名称 `Claude.md` 暗示当前依赖 Claude 模型，国内版没有 Claude
- **建议重命名或调整规则文件**以适配新的模型生态

---

### 3.6 网络与稳定性 ⭐⭐⭐⭐

| 维度 | 国际版 | 国内版 |
|------|--------|--------|
| 访问速度 | 依赖科学上网，可能不稳定 | 国内直连，稳定快速 |
| 服务可用性 | 海外节点 | 国内节点 |
| 任务中断风险 | 网络波动可能导致中断 | 风险大幅降低 |

**正面影响**：国内版网络体验远优于国际版，无需代理即可稳定使用。

---

### 3.7 Siemens PLC 项目兼容性 ⭐⭐⭐

您的 DJ-2026-005 项目包含：
- TIA Portal V19 项目文件
- S7-1200 CPU1217 配置
- .scltest 测试文件
- PLC 程序（ST/FBD/LAD）

**影响评估：**
- 所有项目文件本身不受影响（它们只是磁盘上的文件）
- .plc.json 中的配置（如 libraries 字段）保持不变
- 但 AI 助手对西门子 PLC 语法的理解能力取决于模型质量，需要实测

## 四、迁移计划步骤

### Step 1: 环境准备
- [ ] 从 trae.com.cn 下载 Trae CN 安装包
- [ ] 安装 Trae CN（可与国际版共存）
- [ ] 注册国内版账号（手机号）

### Step 2: 配置迁移
- [ ] 从当前 Trae 国际版导出配置（设置 → 导入/导出）
- [ ] 导入到 Trae CN
- [ ] 验证快捷键、主题、字体是否正常

### Step 3: 扩展验证
- [ ] 安装 Siemens LSP 扩展
- [ ] 安装 GitLens
- [ ] 验证 .plc.json 库引用是否正常工作

### Step 4: MCP 验证
- [ ] 确认 Trae CN MCP 配置文件位置
- [ ] 复制 MCP 配置
- [ ] 测试 GitHub MCP 连接
- [ ] 测试 PaddleOCR MCP 连接
- [ ] 测试 GitKraken MCP 连接

### Step 5: 规则适配
- [ ] 审查 .trae/rules/ 下的规则文件
- [ ] 评估是否需要针对新模型调整 AI 行为规则
- [ ] 考虑将 `Claude.md` 重命名或调整内容

### Step 6: AI 能力验证
- [ ] 运行 basic_test.scltest 测试用例
- [ ] 用国内版模型执行一次简单的 PLC 编程任务

### Step 7: 确认切换
- [ ] 确认所有核心功能正常后，可将国内版设为主要开发工具
- [ ] 国际版保留作为备选

## 五、风险与缓解措施

| 风险 | 影响程度 | 缓解措施 |
|------|---------|---------|
| 国产模型对 ST/PLC 特定语法理解不足 | 高 | 国际版保留备用；编写更详细的规则文件指导 AI |
| MCP 配置不兼容 | 中 | 确认兼容后迁移；如不兼容可使用国际版做 MCP 任务 |
| 部分 VS Code 扩展不可用 | 中 | 寻找替代扩展；大部分常用扩展应兼容 |
| Builder 模式功能落后 | 低 | 国内版主要用 Chat 模式，Builder 非核心依赖 |
| 账号数据无法迁移 | 低 | 重新配置一次即可，长期来看影响很小 |

---

## 六、建议

1. **推荐切换**：国内版网络稳定性优势明显，且完全免费、无请求限制
2. **双版本共存**：初期两个版本都保留，逐步过渡
3. **先验证再切换**：不要立即卸载国际版，先在国内版上跑一遍完整工作流
4. **关注模型能力**：DeepSeek V3.1 和豆包 Seed-Code 对代码任务能力较强，对 PLC ST 语言的适配情况需要实际使用后评估
