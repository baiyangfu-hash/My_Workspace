# DJ-2026-005 规范遵循诊断计划

## 0. 摘要

目标：诊断 `0100_PLC自动化/DJ-2026-005` 项目是否遵守：
- 全局PM规范仓库：`00_Obsidian_Base全局规范文件仓库`
- PLC技术栈规范：`0100_PLC自动化/00_通用规范`

输出：一份“合规性诊断结论 + 风险点 + 可执行整改建议”的报告（默认在对话中交付；如需落盘则在执行阶段按你指定路径生成 Markdown 报告）。

## 1. 当前状态分析（基于已探索事实）

### 1.1 项目结构与关键资产
- 项目目录存在并较完整：`00_项目管理/`、`01_需求与设计/`、`02_PLC程序/`、`03_HMI设计/`、`04_现场调试/`、`05_测试与验证/`、`06_文档与交付/`、`10_知识库/` 等，整体与 `907_项目配置规范.md` 的 PLC 项目目录布局一致。
- `02_PLC程序/通用ST程序及变量表/` 下存在完整 ST 源码结构：`DB1/`、`OB1/`、`common/`、`conveyor/`、`external/`、`feeder/`、`pickplace/`、`Test/`，符合 `907` 要求。
- `My_Workspace/.gitignore` 已包含 `**/.plc-out/` 与 `.plc-out/` 忽略规则，满足 `907` 对编译产物忽略的要求。

### 1.2 .plc.json 配置现状（潜在冲突点）
- 存在两份 `.plc.json`：
  - `DJ-2026-005/.plc.json`：`name=DJ-2026-005_边框缓存机`、`version=1.0.0`、`libraries=["../01_SharedLibraries/SysLib"]`
  - `DJ-2026-005/02_PLC程序/通用ST程序及变量表/.plc.json`：`name=DJ-2026-005`、`version=V6.0.0`、`libraries=["../../../01_SharedLibraries/SysLib"]`
- 两处均生成了 `.plc-out/`，说明 Siemens LSP/go-gen 可能在两个 PLC root 上均执行过，存在“PLC root 不唯一/重复编译产物/调试配置歧义”的风险。

### 1.3 文档规范引用一致性（可整改项）
- 项目内多份文档的“遵循规范”字段仍引用旧/已迁移/疑似不存在于当前权威路径的规范版本，例如：
  - `801_PLC变量命名与功能块命名规范_DEV-V1.0.5`（项目内实际存在版本为 `DEV-V1.0.3`）
  - `810_PLC编程规范_DEV-V1.0.3`（在全局仓库中已标记为 deprecated；当前 PLC 技术栈权威应以 `00_通用规范/PLC编程/905/904/903/907` 为主）
- 这类问题通常不影响程序运行，但会导致“规范追溯”与“审计一致性”失真，建议批量同步修正。

## 3. 执行阶段的具体工作项（不做额外决策即可实施）

### 3.1 自动化扫描（只读）
00. 扫描 `.plc.json` 的字段合法性与 SysLib 相对路径正确性
01. 扫描项目内 `.plc-out/` 分布，判断是否存在多 PLC root 副作用
