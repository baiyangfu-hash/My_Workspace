# SW-2026-008 约束/工作流执行系统 实现方案

## 摘要

当前 auto-pm 的规则（如"禁止用 Python 脚本写磁盘"、"禁止文件名含版本号后缀"等）仅以 Markdown 文档形式存在，缺乏强制约束力。AI 技能（pm-workflow、fullstack-engineer、plc-electrical-engineer）可以绕过这些规则，导致反复出现 VS Code 缓冲区陈旧、文件命名不规范等问题。

本方案设计一个**约束/工作流执行系统**，通过 CLI 命令 `auto-pm constraint` 和 `auto-pm workflow` 实现强制约束，技能在执行文件操作前必须调用 CLI 进行预检，驾驶舱可实时展示约束状态和违规记录。

## 真实案例：BOM 累积事件（2026-07-20）

### 事件经过

PM_SESSION_SW-2026-008.md 在 67 次 dogfooding 闭环中，每次修改保存都追加了一个 UTF-8 BOM（`\xef\xbb\xbf`），累积到 **146 个 BOM = 438 字节垃圾数据**。

### 影响链

```
Python 脚本用 utf-8-sig 写磁盘 → 追加 BOM
  → Read 工具剥离 BOM 但磁盘保留 BOM
  → Edit 工具 old_string 与磁盘不匹配 → 失败
  → 再次用 Python 脚本写磁盘 → 又追加 BOM
  → 循环恶化，累积 146 个 BOM
  → 所有 Edit/Write 操作全部失败
```

### 如果有约束系统

```bash
# 第一次 BOM 出现时就会被检测到
$ auto-pm constraint check --file PM_SESSION_SW-2026-008.md
❌ CST-FILE-002 文件编码完整性
   文件包含 1 个多余 BOM（正常应为 0）
   建议: auto-pm constraint heal --file PM_SESSION_SW-2026-008.md
```

**结论**：BOM 不会累积到 146 个，Edit 工具不会持续失败。

#### 2.1 guard.py 核心实现

```python
# auto_pm/constraint/guard.py

import hashlib
import json
from datetime import datetime
from pathlib import Path
from typing import Any

from auto_pm.logging.audit import audit_log

BOM = b"\xef\xbb\xbf"


class FileGuard:
    """文件修改守护：通过哈希快照检测外部修改

    核心职责：
    1. take_snapshot(): 文件操作前登记 sha256 快照
    2. verify_snapshot(): 文件操作后验证快照一致性
    3. detect_bom_accumulation(): 检测 BOM 累积（CST-FILE-002）
    4. check_encoding(): 文件编码完整性检查
    """

    def __init__(self, workspace_root: Path) -> None:
        self._workspace_root = workspace_root
        self._data_dir = Path.home() / ".auto-pm" / "constraint"
        self._data_dir.mkdir(parents=True, exist_ok=True)
        self._snapshot_file = self._data_dir / "guard_snapshots.json"

    # ── 快照管理 ──

    def take_snapshot(self, file_path: Path) -> dict[str, Any]:
        """文件操作前登记快照，返回 snapshot_id"""
        raw = file_path.read_bytes()
        snap = {
            "snapshot_id": hashlib.sha256(
                f"{file_path}:{datetime.now().isoformat()}".encode()
            ).hexdigest()[:12],
            "file_path": str(file_path),
            "sha256": hashlib.sha256(raw).hexdigest(),
            "size": len(raw),
            "mtime": file_path.stat().st_mtime,
            "bom_count": self._count_bom(raw),
            "taken_at": datetime.now().isoformat(),
        }
        self._save_snapshot(snap)
        audit_log("constraint_guard", file_path=str(file_path),
                  snapshot_id=snap["snapshot_id"], sha256=snap["sha256"][:16])
        return snap

    def verify_snapshot(self, file_path: Path) -> dict[str, Any]:
        """文件操作后验证：返回 {"verified": bool, "changes": {...}}"""
        raw = file_path.read_bytes()
        current_hash = hashlib.sha256(raw).hexdigest()
        current_bom = self._count_bom(raw)

        # 查找最近快照
        snap = self._find_latest_snapshot(file_path)
        if snap is None:
            return {"verified": False, "error": "no_snapshot",
                    "message": "未找到守护快照，文件可能被外部修改"}

        result = {
            "verified": current_hash == snap["sha256"],
            "snapshot_id": snap["snapshot_id"],
            "hash_changed": current_hash != snap["sha256"],
            "size_delta": len(raw) - snap["size"],
            "bom_delta": current_bom - snap["bom_count"],
            "bom_accumulated": current_bom > snap["bom_count"],
        }

        if not result["verified"]:
            audit_log("constraint_violation", constraint_id="CST-FILE-001",
                      file_path=str(file_path), **result)

        return result

    # ── BOM / 编码检测 ──

    @staticmethod
    def _count_bom(raw: bytes) -> int:
        """统计文件开头的连续 BOM 数量"""
        count = 0
        i = 0
        while i + 3 <= len(raw) and raw[i:i + 3] == BOM:
            count += 1
            i += 3
        return count

    def check_encoding(self, file_path: Path) -> dict[str, Any]:
        """检查文件编码完整性（CST-FILE-002）"""
        raw = file_path.read_bytes()
        bom_count = self._count_bom(raw)
        has_null = b"\x00" in raw

        return {
            "file_path": str(file_path),
            "bom_count": bom_count,
            "bom_ok": bom_count <= 1,
            "has_null_byte": has_null,
            "is_healthy": bom_count <= 1 and not has_null,
        }

    def heal_bom(self, file_path: Path) -> dict[str, Any]:
        """剥离多余 BOM（CST-FILE-002 auto_fix）"""
        raw = file_path.read_bytes()
        old_count = self._count_bom(raw)
        if old_count <= 1:
            return {"healed": False, "message": "无需修复", "bom_count": old_count}

        clean = raw.lstrip(BOM)
        file_path.write_bytes(clean)
        new_count = self._count_bom(clean)
        audit_log("constraint_heal", constraint_id="CST-FILE-002",
                  file_path=str(file_path), bom_before=old_count, bom_after=new_count)
        return {"healed": True, "bom_before": old_count, "bom_after": new_count,
                "bytes_removed": len(raw) - len(clean)}

    # ── 内部方法 ──

    def _save_snapshot(self, snap: dict) -> None: ...
    def _find_latest_snapshot(self, file_path: Path) -> dict | None: ...
```

class ConstraintChecker:
    """约束检查引擎

    检查类型：
    - file_guard: 哈希快照对比（CST-FILE-001）
    - file_encoding: BOM/编码检测（CST-FILE-002）
    - naming: 正则黑名单匹配（CST-NAME-001）
    - workflow: CLI 创建检测（CST-CHG-001）
    """

    def __init__(self, workspace_root: Path, guard: FileGuard) -> None:
        self._root = workspace_root
        self._guard = guard
        self._constraints = ConstraintLoader(workspace_root).load_all()

    def check_all(self) -> CheckReport:
        """全量检查所有约束，返回 CheckReport"""
        violations: list[Violation] = []
        for cst in self._constraints:
            if cst.type == "file_encoding":
                violations.extend(self._check_encoding(cst))
            elif cst.type == "file_guard":
                violations.extend(self._check_guard(cst))

        return CheckReport(
            total=len(self._constraints),
            passed=len(self._constraints) - len(set(v.constraint_id for v in violations)),

            violations_list=violations,

- 通过 QML context property 注入

### 5. 工作流定义

工作流也存储在 `auto_pm/constraint/definitions/` 下：

**file-modify 工作流**：guard → confirm → modify → verify → audit
**pre-commit 工作流**：ruff → mypy → constraint check → pytest

### 6. 技能调用方式

技能（pm-workflow、fullstack-engineer、plc-electrical-engineer）在需要修改文件时：

```bash
# 方式一：分步调用（细粒度控制）
auto-pm -w "<workspace>" constraint guard "path/to/file.md"
# ... 使用 Edit/Write 工具修改文件 ...
auto-pm -w "<workspace>" constraint verify "path/to/file.md"

# 方式二：工作流一步到位（推荐）
auto-pm -w "<workspace>" workflow run file-modify --file "path/to/file.md"
```

## 假设与决策

### 假设
1. 约束系统不依赖 OS 级文件锁定，通过哈希快照进行事后检测（务实方案）
2. AI 技能会遵循 prompt 中的指令调用 CLI 进行预检
3. 约束定义 YAML 文件存储在项目源码中，随代码版本管理
4. 快照数据存储在 `~/.auto-pm/constraint/` 下，不进入版本控制

### 决策
1. **事后检测而非事前阻断**：无法真正阻止 Python 脚本写磁盘，但可通过哈希快照检测并记录违规
2. **YAML 约束定义**：声明式，便于理解和修改
3. **遵循现有架构**：Facade → Bridge → QML 三层，CLI 使用 Click
4. **独立门禁**：约束检查作为第四轨门禁，独立于 ruff/mypy/pytest
5. **JSON 文件存储**：快照和违规记录使用 JSONL，不增加 DB schema 复杂度
