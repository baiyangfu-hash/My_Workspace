## 一、核心问题的深度分析与解决方案

### 1.1 换人开发：知识传递保障体系

#### 问题本质
AI开发完成后，人类开发者（或换另一个AI）接手时，如何确保：
- 知道为什么这样设计
- 知道每个模块的作用
- 知道如何修改和扩展

#### 解决方案：三层文档体系

```
┌─────────────────────────────────────────────────────────────┐
│                    文档先行原则                              │
├─────────────────────────────────────────────────────────────┤
│  Layer 1: 架构决策记录 (ADR)                                │
│  - 为什么这样分层                                          │
│  - 为什么选择这个技术方案                                    │
│  - 关键设计决策及其替代方案对比                               │
├─────────────────────────────────────────────────────────────┤
│  Layer 2: 模块规格说明书 (Spec)                             │
│  - 每个模块的职责边界                                        │
│  - 输入/输出/前置条件/后置条件                                │
│  - 公开API接口定义                                          │
├─────────────────────────────────────────────────────────────┤
│  Layer 3: 代码级文档                                        │
│  - 类和函数的docstring                                       │
│  - 复杂逻辑的注释说明                                        │
│  - 数据流走向的注释                                          │
└─────────────────────────────────────────────────────────────┘
```

#### 强制执行规则
| 规则 | 说明 | 违反惩罚 |
|------|------|----------|
| 每个模块必须有 `MODULE_SPEC.md` | 描述模块职责、接口、依赖 | 代码审查不通过 |
| 每个类必须有 docstring | 说明用途、用法、注意事项 | Pylint 警告 |
| 每个 public 方法必须有 docstring | 参数、返回值、异常 | Pylint 警告 |
| 架构决策必须记录 | 在 `docs/adr/` 目录 | 新人必须先读 ADR |

#### 换人交接检查清单
```
□ 所有 ADR 已更新到最新
□ 所有模块 SPEC 已完成
□ 代码无 TODO/FIXME/XXX
□ 所有测试通过
□ 部署文档已更新
□ 开发环境搭建指南已更新
□ 本地测试已通过
```

### 1.2 换电脑：路径无关架构设计

#### 问题本质
换电脑后，原有绝对路径全部失效，如何保证：
- 代码零修改即可在新机器运行
- 项目文件可以放在任意位置
- 不依赖特定盘符或目录

#### 解决方案：五层路径体系

参考 SW-2026-004 V2.5.7 跨机器部署能力：

```
┌─────────────────────────────────────────────────────────────┐
│                  五层路径解析优先级 (V2.5.7)                  │
├─────────────────────────────────────────────────────────────┤
│  P1 (最高) │ 用户自定义配置路径    │ 用户明确指定的根目录      │
├─────────────────────────────────────────────────────────────┤
│  P2       │ 环境变量 PROJECT_ROOT │ 企业统一下发              │
├─────────────────────────────────────────────────────────────┤
│  P3       │ EXE相对路径 ./Projects │ 标准解压即用            │
├─────────────────────────────────────────────────────────────┤
│  P4       │ 当前工作目录          │ 开发调试兜底              │
├─────────────────────────────────────────────────────────────┤
│  P5 (最低)│ 默认值                │ 硬编码默认值              │
└─────────────────────────────────────────────────────────────┘
```

#### 路径无关实现要求

**核心原则**：代码中**永远不出现硬编码路径**

```python
# ✅ 正确：使用统一的路径解析
from src.core.path_resolver import project_root, data_dir, config_dir

# 项目数据目录
db_path = data_dir("project_manager.db")

# 配置文件目录
config_path = config_dir("app_config.json")

# 项目根目录
project_path = project_root()
```

**路径解析器必须处理的场景**：
| 场景 | 处理方式 |
|------|----------|
| PyInstaller 单文件冻结 | `sys._MEIPASS` 获取临时解压目录 |
| PyInstaller 目录模式 | `sys.executable` 所在目录 |
| 普通 Python 开发 | `Path(__file__).parent.parent` |
| 虚拟环境 | 与普通 Python 相同 |
| 相对路径项目 | `os.getcwd()` |

**自包含项目结构**：
```
{project_root}/
├── src/                    # 代码（路径无关）
├── data/                   # 数据（相对路径）
├── config/                 # 配置（相对路径）
├── logs/                   # 日志（相对路径）
├── docs/                   # 文档（相对路径）
└── .env                    # 环境配置（相对路径）
```

**禁止行为**：
```python
# ❌ 禁止：硬编码绝对路径
db_path = "D:/BaiduSyncdisk/..."

# ❌ 禁止：依赖特定目录
os.chdir("C:/workspace/project")

# ❌ 禁止：假设特定盘符
if Path("D:/").exists():
```

### 1.3 外部依赖：自包含依赖管理体系

#### 问题本质
- 项目依赖 Python 第三方库
- 换电脑后需要重新安装所有依赖
- 打包交付后用户也需要安装环境

#### 解决方案：三层依赖管理

```
┌─────────────────────────────────────────────────────────────┐
│                   三层依赖管理架构                            │
├─────────────────────────────────────────────────────────────┤
│  Layer 1: 开发依赖 (requirements.txt)                       │
│  - 仅开发时使用                                              │
│  - pip install -r requirements-dev.txt                      │
│  - 包含: pytest, pylint, black, mypy                         │
├─────────────────────────────────────────────────────────────┤
│  Layer 2: 运行依赖 (requirements.txt)                        │
│  - 运行时必须                                               │
│  - pip install -r requirements.txt                          │
│  - 包含: PyQt5, SQLAlchemy, Flask, alembic                  │
├─────────────────────────────────────────────────────────────┤
│  Layer 3: 打包依赖 (PyInstaller)                             │
│  - 打包时自动嵌入                                            │
│  - 打包后用户无需安装任何依赖                                  │
│  - 使用 --onefile 或 --onedir                               │
└─────────────────────────────────────────────────────────────┘
```

#### 依赖管理规范

| 规范 | 说明 |
|------|------|
| 版本锁定 | `package>=1.0.0,<2.0.0` 而非 `package` |
| 定期更新 | 每月检查依赖安全更新 |
| 离线打包 | PyInstaller 打包时嵌入所有依赖 |
| 依赖审核 | 新增依赖必须说明用途 |

#### 自包含打包要求

```
交付物/
├── {program}.exe          # 主程序（含Python解释器）
├── _internal/             # Python运行时+所有依赖
├── config/                 # 配置文件
├── data/                   # 数据文件
└── README.exe              # 运行说明
```

**用户双击即用，无需安装 Python 环境**

### 1.4 高内聚低耦合：严格模块化设计

#### 问题本质
- 如何确保模块边界清晰
- 如何防止模块间过度耦合
- 如何保证代码可测试、可替换

#### 解决方案：六层架构 + 依赖规则

```
┌─────────────────────────────────────────────────────────────┐
│                     六层架构                                 │
├─────────────────────────────────────────────────────────────┤
│  Layer 1: UI层 (src/ui/)                                    │
│  职责: 界面展示、用户交互                                     │
│  依赖: 仅依赖 Service 层                                    │
│  规则: 禁止直接访问数据库                                     │
├─────────────────────────────────────────────────────────────┤
│  Layer 2: API层 (src/api/)                                 │
│  职责: HTTP接口、API路由                                     │
│  依赖: 仅依赖 Service 层                                    │
│  规则: 无状态，每个请求完整                                    │
├─────────────────────────────────────────────────────────────┤
│  Layer 3: Service层 (src/services/)                        │
│  职责: 业务逻辑、事务控制                                    │
│  依赖: 仅依赖 DAO 层                                        │
│  规则: 无 UI 依赖，禁止直接操作文件                           │
├─────────────────────────────────────────────────────────────┤
│  Layer 4: DAO层 (src/dao/)                                │
│  职责: 数据访问、数据校验                                    │
│  依赖: 仅依赖 Model 层                                      │
│  规则: 每个DAO类对应一个Model，SQLAlchemy会话管理             │
├─────────────────────────────────────────────────────────────┤
│  Layer 5: Model层 (src/models/)                            │
│  职责: 数据结构定义、验证规则                                 │
│  依赖: 仅依赖 BaseModel                                     │
│  规则: 无业务逻辑                                           │
├─────────────────────────────────────────────────────────────┤
│  Layer 6: Core层 (src/core/)                               │
│  职责: 基础设施、配置、工具                                  │
│  依赖: 无上层依赖                                            │
│  规则: 全局单例或静态工具                                     │
└─────────────────────────────────────────────────────────────┘
```

#### 依赖方向规则（必须严格执行）

```
UI层 ──────→ Service层 ←────── DAO层
  │              ↑              ↑
  ↓              │              │
API层 ──────→    │         Model层
                 │
                 ↓
              Core层
```

**依赖方向**：箭头指向的方向是依赖的方向，只能外层依赖内层，禁止反向依赖。

**模块边界检查**：
| 检查项 | 说明 | 检查方式 |
|--------|------|----------|
| 循环依赖 | 模块间不能循环导入 | `python -m py_compile` |
| 跨层访问 | 不能跳过中间层 | 代码审查 |
| 直接数据库 | UI层不能直接访问数据库 | 代码审查 |
| 硬编码值 | 配置必须从Config读取 | Pylint |

#### 关键原则

| 原则 | 说明 | 实施方式 |
|------|------|----------|
| **单一职责** | 每个类只做一件事 | 类不超过200行 |
| **开闭原则** | 对扩展开放，对修改关闭 | 使用抽象接口 |
| **依赖注入** | 依赖通过构造函数传入 | 避免硬编码 |
| **接口隔离** | 多个专用接口优于一个通用接口 | 按功能拆分 |

## 六、路径无关的强制实现

### 6.1 路径解析器实现要求

```python
# src/core/path_resolver.py 必须实现以下功能

class PathResolver:
    """路径解析器 - 保证路径无关性"""

    @staticmethod
    def get_project_root() -> Path:
        """
        获取项目根目录
        优先级: 环境变量 > 用户配置 > EXE相对路径 > 当前目录
        """

    @staticmethod
    def get_data_dir(subpath: str = "") -> Path:
        """获取数据目录"""

    @staticmethod
    def get_config_dir(subpath: str = "") -> Path:
        """获取配置目录"""

    @staticmethod
    def get_log_dir(subpath: str = "") -> Path:
        """获取日志目录"""

    @staticmethod
    def resolve(path: str) -> Path:
        """统一路径解析"""
```

### 6.2 禁止的路径用法

```python
# 以下用法在代码中禁止出现

# ❌ 硬编码盘符
Path("D:/Projects/...")

# ❌ os.getcwd() 用于路径拼接
os.path.join(os.getcwd(), "data")

# ❌ 相对当前文件位置
Path(__file__ + "/../data")

# ❌ sys.executable 路径
Path(sys.executable).parent / "data"

# ✅ 正确用法
from src.core.path_resolver import project_root, data_dir
db_path = data_dir("project_manager.db")
```
