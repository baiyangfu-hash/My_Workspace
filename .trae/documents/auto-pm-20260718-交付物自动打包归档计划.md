# 交付物自动打包归档工作流 — 实现计划

> **日期**: 2026-07-18
> **目标**: 将"交付物更新→自动打包→旧版归档"工作流做到规范（220）和工具（auto-pm CLI）中

---

## 1. 背景与问题

### 当前状态
- 220 打包规范定义了 `06_交付物/`（工作目录）和 `06_交付物打包/`（归档目录）两阶段流程
- 但 `06_交付物打包/` 存放所有历史 ZIP，未区分"正式文件"和"归档"
- 归档操作依赖独立脚本 `scripts/build_delivery.py`，未集成到 auto-pm CLI
- 无"旧版归档说明"机制

### 用户需求
1. **交付物**（`06_交付物/`）和**交付物打包**（`06_交付物打包/`）各自只保留一份最新"正式文件"
2. 旧版本**不删除**，而是归档到 `archive/` 子目录，每个旧版附带**归档说明**
3. 交付物更新后**自动触发**交付物打包更新
4. 工作流同时做到**规范里**（220规范）和**工具里**（auto-pm CLI）

## 2. 目录结构设计

### `06_交付物/` — 仅保留最新 + 旧版归档

```
06_交付物/
├── 01_可执行文件/                  # 最新正式 exe
│   ├── {程序名}.exe
│   ├── _internal/                  # PyInstaller 运行时依赖
│   └── config/                     # 配置文件
├── 02_发布说明/                    # 最新发布说明
├── README.md                       # 最新使用文档
├── CHANGELOG.md
└── archive/                        # 旧版归档
    ├── V1.0.0_20260716/
    │   ├── archive_info.md         # 归档说明
    │   ├── 01_可执行文件/
    │   ├── 02_发布说明/
    │   ├── README.md
    │   └── CHANGELOG.md
    └── V1.0.1_20260720/
        └── ...
```

### `06_交付物打包/` — 仅保留最新 ZIP + 旧版归档

```
06_交付物打包/
├── {系统名称}_V{最新版本}_{日期}.zip  # 最新正式 ZIP
└── archive/                            # 旧版 ZIP 归档
    ├── archive_manifest.md             # 归档总清单
    └── {系统名称}_V{旧版本}_{日期}.zip
```

### 归档说明格式 (`archive_info.md`)

```markdown
# 归档信息

| 字段 | 内容 |
|------|------|
| 版本号 | V1.0.0 |
| 归档日期 | 2026-07-18 |
| 原始文件大小 | 156.3 MB |
| 变更摘要 | 初始版本交付，包含基础项目管理功能 |
| 被替代版本 | V1.0.1 |
| 操作人 | auto-pm delivery build |
```

## 3. auto-pm CLI 命令设计

### 命令树

```
auto-pm delivery
├── build       # 构建交付物（编译 + 归档旧版 + 复制新版）
├── package     # 打包 ZIP（归档旧 ZIP + 创建新 ZIP + 验证）
├── archive     # 归档管理
│   ├── list    # 列出归档版本
│   └── clean   # 清理旧归档（保留最近 N 个）
└── status      # 查看当前交付物状态
```

### 关键命令规格

**`delivery build`** — 构建交付物
```
auto-pm delivery build --version V1.0.1 [--skip-pyinstaller] [--auto-package]

流程:
  1. 解析项目路径（自动检测或 --project-root）
  2. [可选] 执行 PyInstaller 编译
  3. 归档旧版：将 06_交付物/ 现有内容 → archive/V{旧版本}_{日期}/
     生成 archive_info.md
  4. 复制新 exe + _internal → 06_交付物/01_可执行文件/
  5. 复制发布文档 → 06_交付物/02_发布说明/
  6. 执行 D-checks 校验
  7. [--auto-package] 自动调用 delivery package
```

**`delivery package`** — 打包 ZIP
```
auto-pm delivery package --version V1.0.1

流程:
  1. 归档旧 ZIP → 06_交付物打包/archive/
  2. 从 06_交付物/ 创建新 ZIP（Python zipfile）
  3. 执行 CHK-checks 验证
  4. 输出验证报告
```

**自动触发**: `delivery build --auto-package` 一键完成两阶段

### 代码结构

遵循现有 CLI 模式（参考 `auto_pm/cli/change.py`）：

| 文件 | 说明 |
|------|------|
| `auto_pm/cli/delivery.py` | Click 命令组（build/package/archive/status） |
| `auto_pm/delivery/__init__.py` | 模块入口 |
| `auto_pm/delivery/delivery_service.py` | 核心服务：编排 build/package/status |
| `auto_pm/delivery/archive_manager.py` | 归档管理：archive/restore/clean + archive_info.md 读写 |
| `auto_pm/delivery/verifier.py` | 验证器：D-checks + CHK-checks（从 build_delivery.py 提取） |
| `auto_pm/delivery/constants.py` | 常量：目录名、阈值、命名模板 |

## 7. 关键设计决策

| 决策 | 选型 | 理由 |
|------|------|------|
| 命令名 | `delivery` | 与目录名 `06_交付物/` 语义一致 |
| 自动触发 | `--auto-package` flag | 显式可控，无需守护进程 |
| 归档方式 | 移动到 `archive/` 子目录 | 保留历史，根目录整洁 |
| 归档说明 | `archive_info.md` | 人类可读，与项目文档格式一致 |
| 验证逻辑 | 从 build_delivery.py 提取 | 可复用、可测试、阈值可配置 |
| 依赖 | 零新增依赖 | 仅用 Python stdlib + Click + Rich（已有） |
