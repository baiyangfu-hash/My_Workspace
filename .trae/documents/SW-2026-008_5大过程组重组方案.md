# SW-2026-008 5大过程组重组方案

## Context（背景与动机）

工作空间有两个008项目，我想知道你干了什么？你复制了一个？之前还没有。是备份？我们有git啊，发生了什么？先回答我在继续

**当前痛点**：SW-2026-008 项目目录散乱，`00_项目基础信息/`、`00_项目管理/`、`02_设计/`、`02_发布说明/`、`09_整改项/` 等目录按功能分类组织，缺乏过程组视角，难以体现项目生命周期阶段。同时当前项目实际使用 PLC 风格的 `00_项目管理/` 目录，偏离了 paths.py 中定义的 Python 项目约定（`01_项目文档/`），存在结构不一致。

**目标**：按高项5大过程组（启动/规划/执行/监控/收尾）物理重组项目目录，同步更新代码层（paths.py + 引用文件）、模板层（copier 模板）、规范层（PROJ-016），并保证 auto-pm CLI 变更管理命令 100% 兼容新结构。

**用户决策**（已确认）：

1. **范围**：全联动（项目+代码+模板+规范）
2. **兼容策略**：破坏性切换（旧路径不再识别，所有现存项目需迁移）
3. **子目录命名**：过程组内重新编号（每个过程组下子目录从 01 开始）

**变更单**：CHG-SCPT-2026-146（待创建）

## 八、风险与回滚

### 8.1 风险清单

| 风险              | 概率 | 影响         | 缓解措施                   |
| --------------- | -- | ---------- | ---------------------- |
| 测试 fixture 改动遗漏 | 高  | 测试失败       | grep 全量搜索旧目录名，确保无遗漏    |
| import 路径破坏     | 中  | 代码无法运行     | 代码目录保持根目录，不移动          |
| PLC 工程文件引用断裂    | 中  | PLC 项目损坏   | 阶段3.2 之前先评估 PLC 工程文件依赖 |

| 规范文档遗漏同步        | 中  | 规范不一致      | 阶段3.3 完成后跑 spec check  |

* 每个阶段独立 git commit，便于定点回滚

* 阶段3.1（代码层）和阶段3.5（项目迁移）分开提交

* 如果阶段3.5 验证失败，回滚项目迁移 commit，代码层改动可保留（向后兼容旧结构需要恢复双路径搜索）
