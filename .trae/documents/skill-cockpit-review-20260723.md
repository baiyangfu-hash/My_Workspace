## 2. 发现问题

### 🔴 P0: 驾驶舱未能有效减少技能上下文

**现象**: 驾驶舱已提供 9 个页面覆盖项目管理全流程，但 `pm-workflow` 技能仍长达 386 行，包含大量本应由驾驶舱承载的流程逻辑。

**具体表现**:

1. **pm-workflow Step 0-1 与驾驶舱 PlatformDashboard 重叠**:
   - 技能 Step 0: 读取 PM_SESSION、运行 `project show`、健康检查、硬约束加载
   - 驾驶舱 PlatformDashboardView 已提供: KPI 网格、项目状态、技术债追踪
   - **结论**: 这些"上下文恢复"工作应是驾驶舱加载时自动完成，不应占用技能 token

2. **pm-workflow Step 1 的"模式判定"与驾驶舱导航重叠**:
   - 技能: 9 种模式选择（需求/PRD/方案/拆解/推进/变更/规范/初始化/补完）
   - 驾驶舱: 4 轨道导航已按业务域组织（Platform Cockpit / Workspace / Active Project / Settings）
   - **结论**: 用户从驾驶舱点击"变更中心"就已经表达了"变更模式"，技能不应再问

3. **pm-workflow Step 3.5-3.8 的质量门禁规则可移至驾驶舱**:
   - Bug 诊断流程 (78 行)
   - CHG 闭环质量门禁 (30 行)
   - 真源一致性校验 (25 行)
   - 门禁实测检查 (20 行)
   - 这些规则**总计约 150 行**，占技能 40%
   - **结论**: 这些是"约束/规则"，不是"交互流程"，应该由驾驶舱的约束系统 (`auto-pm constraint`) 和门禁检查自动执行，而非每次对话都加载到技能上下文中

### 🟡 P1: 三个技能之间存在大量重复规则

**重复内容清单**:

| 文件写入策略 | - | 文件写入策略 | 文件编辑工具纪律 | ✅ |

**影响**: 相同规则在 3-4 处维护，修改时需同步更新，否则出现不一致。例如 Bug 诊断流程在 `pm-workflow` 和 `fullstack-engineer` 中描述略有不同（前者含 fixture 健康检查详细清单，后者含条件断言检测规则）。

### 🟡 P2: 技能与驾驶舱的交互路径不清晰

**当前交互方式**:

```
用户 → Skill (pm-workflow) → auto-pm CLI → 驾驶舱 backend Service
用户 → Skill (fullstack-engineer) → auto-pm CLI → 驾驶舱 backend Service
用户 → Skill (plc-electrical-engineer) → auto-pm CLI → 驾驶舱 backend Service
```

**问题**:
1. 技能从不引用驾驶舱的 GUI 页面，只引用 CLI 命令
2. 驾驶舱的 5 个 Domain Bridge 和 10 个 Protocol 契约在技能中完全不可见
3. 技能执行的结果（如创建变更单、更新 PM_SESSION）需要用户手动刷新驾驶舱才能看到

**理想交互**:

```
用户 → 驾驶舱 GUI (点击导航) → 选择项目 → 触发 Skill
                                    ↓
                              Skill 聚焦于"领域任务"
                              (不包含导航/模式选择/上下文恢复)
                                    ↓
                              Skill 回写 PM_SESSION + 驾驶舱自动刷新
```

### 🟢 P3: 约束系统与技能规则的割裂

**现象**: 驾驶舱已实现 `auto-pm constraint` 约束系统（Phase 1 MVP），但技能中仍有大量"手工约束"：

- **已自动化**: 文件编码完整性 (CST-FILE-002) → 驾驶舱 `constraint check/heal`
- **未自动化**: Python 脚本禁止写磁盘 (CST-FILE-001) → 仍在技能中手工声明
- **未自动化**: CHG 章节完整性校验 → 仍在技能中手工声明
- **未自动化**: 版本号一致性校验 → 仍在技能中手工声明

**结论**: 约束系统应吸收这些"手工规则"，让技能更轻量。

## 3. 改进建议

### 3.1 重构技能分层（核心建议）

**方案**: 将 3 个技能重构为"轻量入口 + 领域知识"结构，通用规则下沉到驾驶舱约束系统。

**新的技能结构**:

```
pm-workflow (缩至 ~120 行)
├── 职责: 需求澄清、PRD/方案、任务拆解、迭代推进
├── 移除: Step 0 上下文恢复、Step 1 模式判定、Step 3.5-3.8 质量门禁
├── 保留: Step 2 最小提问、Step 3 按模式产出、Step 4 同步 PM_SESSION
└── 引用: "质量门禁由驾驶舱 auto-pm constraint gate 自动执行"

fullstack-engineer (缩至 ~150 行)
├── 职责: 编码、评审、调试
├── 移除: Bug 诊断前置纪律（移至驾驶舱）、文件写入策略（移至驾驶舱约束）
├── 保留: 工作模式、工程实践规范（mypy 陷阱、CLI 安全、架构模式）
└── 引用: "操作约束由驾驶舱 auto-pm constraint guard 自动守护"

plc-electrical-engineer (缩至 ~100 行)
├── 职责: SCL 编码、规范检查、LSP 验证
├── 移除: Bug 诊断纪律（移至驾驶舱）、审查报告验证（移至驾驶舱）
├── 保留: 本地规范索引、任务路由、SCL 编码规则
└── 引用: "合规检查由驾驶舱 auto-pm plc check 自动执行"
```

### 3.2 驾驶舱增强（支撑技能轻量化）

**需要驾驶舱新增/增强的能力**:

1. **上下文快照自动注入**: 驾驶舱在触发 Skill 时，自动将当前项目上下文（PM_SESSION §2/§3/§8/§9）注入到 Skill 会话中，节省 Step 0 的 token

2. **门禁自动化**: 
   - `auto-pm constraint gate` → 替代手工 ruff/mypy/pytest 检查
   - `auto-pm constraint check --file PM_SESSION_*.md` → 替代手工 CHG 章节完整性检查
   - `auto-pm ledger reconcile --auto-fix` → 替代手工台账对账

3. **约束规则外化**: 将以下规则从技能中提取到约束 YAML 定义：
   - `CST-PM-001`: PM_SESSION 版本号一致性
   - `CST-PM-002`: CHG 12 章节完整性
   - `CST-PM-003`: 测试数声明确实性
   - `CST-FILE-001`: 禁止 Python 脚本直接写磁盘（已有草稿）

4. **Skill 触发入口**: 在驾驶舱中增加"AI 辅助"按钮（如"智能审查"、"智能创建变更单"），点击后触发对应 Skill 并传入当前上下文

### 3.3 重复规则统一

**方案**: 将 3 个技能 + project_memory 中的重复规则统一到一处：

| 规则 | 统一位置 | 说明 |
|------|---------|------|
| Bug 诊断纪律 | project_memory.md | 所有技能引用"见 project_memory §Bug诊断方法论" |
| 未验证禁止回写 | project_memory.md | 所有技能引用"见 project_memory §未验证禁止回写" |
| 门禁实测检查 | `auto-pm constraint gate` | 驾驶舱自动执行，技能只需声明"已通过门禁" |
| 文件写入策略 | `auto-pm constraint guard` | 驾驶舱文件守护，技能无需声明 |
| 台账对账 | `auto-pm ledger reconcile` | 驾驶舱自动执行 |
| 审查报告验证 | project_memory.md | 所有技能引用"见 project_memory §防失真机制" |

## 5. 总结

**核心判断**: 驾驶舱已经具备减少技能上下文的技术基础（5 Domain Bridge、10 个 Protocol、约束系统、CLI 14 子命令），但**技能侧没有充分利用这些能力**。结果是：

- 驾驶舱做了"界面层"的工作
- 技能做了"界面层 + 规则层 + 业务层"的全部工作
- 两者之间没有形成"驾驶舱管理上下文 + 技能聚焦领域"的分工

**理想状态**: 驾驶舱是"操作台"（管理上下文、导航、约束守护），技能是"专家"（在操作台选定的项目/域内提供领域智能）。当前三者（pm-workflow/fullstack/plc）的"总控流程"角色应该回退给驾驶舱，技能只保留领域专长。
