# GUI 全自动修复计划 - SW-2026-005 中文乱码/显示异常

## 目标
建立 **启动→截图→诊断→修复→再验证** 的全自动闭环流程，无需用户手动截图，直到 GUI 显示完全正常。

## 问题现状（基于用户最新截图）

从用户提供的截图确认：
- ❌ 左侧 ToolBox 侧边栏：**中文文字显示为方块/乱码**（"项目管理"、"文档管理"、"PLC工具" 等）
- ❌ 仪表盘区域：**统计卡片标题乱码**
- ❌ 快捷操作按钮：**文字无法辨认**
- ❌ 底部 Dock 面板：**标签文字异常**

**关键发现**：之前的字体声明修复（Microsoft YaHei → Microsoft YaHei UI）**并未完全解决问题**，说明还存在其他根因。

## 技术方案

### 核心思路：Python 自动化截图 + 视觉验证循环

```
┌─────────────────────────────────────────────────────┐
│  Step 1: 编写 GUI 截图诊断脚本                        │
│    - 使用 PyQt5 截取主窗口                            │
│    - 保存为 PNG 文件                                 │
│    - 输出窗口尺寸/DPI/字体等元数据                    │
├─────────────────────────────────────────────────────┤
│  Step 2: 启动应用 + 延时截图                         │
│    - 子进程启动 main.py                              │
│    - 等待 3 秒让 GUI 完全渲染                        │
│    - 调用 Win32 API 或 Qt 截图                       │
├─────────────────────────────────────────────────────┤
│  Step 3: 读取截图 + AI 视觉分析                      │
│    - 使用 Read 工具读取 PNG                          │
│    - 分析文字渲染质量                                │
│    - 识别具体哪些区域有问题                           │
├─────────────────────────────────────────────────────┤
│  Step 4: 定位代码根因                                │
│    - 根据问题区域追踪到具体组件                       │
│    - 检查字体/QSS/编码/DPI 相关代码                   │
├─────────────────────────────────────────────────────┤
│  Step 5: 实施修复                                    │
│    - 修改源代码                                      │
│    - 终止旧进程                                      │
├─────────────────────────────────────────────────────┤
│  Step 6: 回到 Step 2 循环验证                        │
│    - 直到连续 2 次截图确认正常                       │
└─────────────────────────────────────────────────────┘
```

## 详细执行步骤

### Phase 1: 创建自动化诊断基础设施

#### Task 1.1: 创建 `gui_auto_screenshot.py` 脚本
**路径**: `03_主程序/01_主程序核心代码/gui_auto_screenshot.py`

**功能**:
```python
# 核心能力：
# 1. 启动 main.py 作为子进程
# 2. 等待 GUI 完全渲染（监听窗口句柄）
# 3. 使用 win32gui + win32ui 截取指定窗口
# 4. 保存截图到 data/screenshots/ 目录
# 5. 输出诊断信息（窗口标题、尺寸、DPI、进程ID）
# 6. 可选：使用 pytesseract OCR 提取文字做对比
```

**依赖库** (需确认是否已安装):
- `pywin32` (win32gui, win32ui, win32con) - Windows 窗口操作
- `Pillow` (PIL) - 图片处理
- `pytesseract` (可选) - OCR 文字识别

#### Task 1.2: 创建 `gui_visual_checker.py` 验证脚本
**路径**: `03_主程序/01_主程序核心代码/gui_visual_checker.py`

**功能**:
```python
# 对截图进行自动化检查：
# 1. 读取最新截图
# 2. 检查关键区域的像素特征：
#    - 左侧侧边栏是否有可读中文
#    - 仪表盘卡片标题是否清晰
#    - Tab 标签文字是否正常
#    - 菜单栏文字是否正常
# 3. 输出健康评分 (0-100)
# 4. 列出具体问题区域坐标
```

### Phase 2: 执行自动修复循环

#### Task 2.1: 第一轮 - 启动 + 截图 + 初步诊断
1. 运行 `python gui_auto_screenshot.py`
2. 读取生成的截图
3. 记录所有可见的显示异常
4. 输出诊断报告

#### Task 2.2: 第二轮 - 深度根因分析
根据第一轮截图发现的问题，逐一排查：

**可能的方向** (按优先级):
| # | 排查方向 | 具体检查项 |
|---|---------|-----------|
| A | **字体回退链断裂** | StyleBuilder._resolve_chinese_font 是否真的返回了可用字体？QSS 是否覆盖了 setFont？ |
| B | **高 DPI 渲染问题** | DPR=2.0 时字体是否被错误缩放？AA_UseHighDpiPixmaps 是否生效？ |
| C | **编码问题** | Python 源文件编码声明 vs 实际文件编码？字符串字面量是否正确？ |
| D | **QSS 优先级冲突** | 内联 setStyleSheet vs QSS 文件 vs QApplication.setFont 三者优先级？ |
| E | **Qt 字体数据库** | QFontDatabase.addApplicationFont() 是否需要预加载字体？ |
| F | **平台特定问题** | Windows 下 ClearType 渲染与 Qt 的兼容性？ |

#### Task 2.3: 第三轮~N轮 - 修复 + 再验证
对每个发现的问题：
1. 修改代码
2. 终止旧进程
3. 重新启动
4. 截图对比
5. 确认修复有效
6. 进入下一个问题

### Phase 3: 防回归保障

#### Task 3.1: 将截图验证加入测试套件
- 创建 `test_gui_rendering.py` 
- CI/CD 中可作为冒烟测试

#### Task 3.2: 更新 PM_SESSION
- 记录完整的修复链路
- 归档所有中间截图

## 风险与应对

| 风险 | 应对措施 |
|------|---------|
| pywin32 未安装 | 自动 pip install 或改用 subprocess 调用 PowerShell 截图 |
| 窗口句柄获取失败 | 通过进程名+窗口标题模糊匹配 |
| OCR 识别率低 | 改用像素采样+模板匹配而非纯 OCR |
| 修复引入新回归 | 每次修复后完整截图对比 |
| 应用启动慢导致截图空白 | 增加智能等待（监听窗口 paint 事件） |

## 执行模式

采用 **Task 工具 + 子 Agent** 并行加速：
- 主线程：控制流程、截图、视觉分析
- 子 Agent：代码搜索、批量替换、测试运行
