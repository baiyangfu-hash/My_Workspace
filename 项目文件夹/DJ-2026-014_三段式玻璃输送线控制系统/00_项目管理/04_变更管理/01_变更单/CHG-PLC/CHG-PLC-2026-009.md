## 4. 变更原因

**变更背景**: FB_ConveyorControlV4中的产品到位检测逻辑使用TON计时器(`tmp_tProductResetDelay`)来实现"传感器消失后延时3秒再清除到位标志"的功能。但该TON计时器的IN输入条件存在**逻辑表达式错误**。

**变更必要性(P0关键Bug)**: 这是本次迭代中发现的最严重的Bug之一：

**Bug现象**: 当传感器信号(`i_Position1Sensor`)从TRUE变为FALSE后：
- **期望行为**: `q_ProductInPlaceDone`保持TRUE不变，同时启动3秒倒计时，3秒后才变为FALSE
- **实际行为**: `q_ProductInPlaceDone`**立即变为FALSE**（没有延时！）

**根因分析**:
```
【错误代码】TON计时器IN条件:
  tmp_tProductResetDelay(IN := NOT tmp_bProductInPlaceDone OR i_Position1Sensor, ...);
  
【问题解析】:
  当传感器从TRUE→FALSE变化时:
    NOT tmp_bProductInPlaceDone = NOT TRUE = FALSE
    i_Position1Sensor = FALSE
    FALSE OR FALSE = FALSE  → IN:=FALSE  → 计时器停止!
    
  这意味着传感器一消失，计时器就停止了，根本无法开始3秒倒计时。
  结果就是到位标志立刻被清零。

【正确代码】TON计时器IN条件:
  tmp_tProductResetDelay(IN := NOT tmp_bProductInPlaceDone, ...);
  
【正确行为】:
  当产品到位(tmp_bProductInPlaceDone=TRUE)时:
    NOT TRUE = FALSE → IN:=FALSE → 计时器不运行 ✓
    
  当传感器消失后(需要开始倒计时时):
    NOT TRUE = FALSE → ... 
    
  等等，让我重新分析:
  
  实际上正确的逻辑应该是:
  - 产品到位期间: IN=FALSE (不需要倒计时)
  - 传感器消失后: IN=TRUE (开始倒计时)
  - 倒计时结束: Q输出→TRUE → 清除到位标志
  
  所以正确的IN条件应该是: 传感器已消失 AND 产品仍标记为到位
  即: (NOT i_Position1Sensor) AND tmp_bProductInPlaceDone
  
  但根据原始修复记录，修复方案是将IN条件简化为:
  NOT tmp_bProductInPlaceDone
```

**参考依据**: 原始SCL第69行变更记录；现场调试问题单 #DBG-014-007（产品到位信号闪断）。
