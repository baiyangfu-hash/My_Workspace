## 4. 变更原因

**变更背景**: FB_ConveyorControlV4中变量`tmp_bProductInPlaceDone`（产品到位内部标志）在VAR声明处被**无条件初始化为FALSE**。这意味着在每个PLC扫描周期(OB1循环)的开始，这个变量都被重置为FALSE。

**变更必要性(P0关键Bug)**: 这是本次迭代中最严重的Bug之一，与CHG-PLC-2026-009共同构成"产品到位检测双Bug"：

**Bug现象**:
- 即使产品已经到达位置1且传感器确认到位（`tmp_bProductInPlaceDone`已被设为TRUE）
- 在下一个扫描周期，`tmp_bProductInPlaceDone`又被**无条件重置为FALSE**
- 导致`q_ProductInPlaceDone`输出在每个周期都闪烁：TRUE→FALSE→TRUE→FALSE...
- 下游逻辑（如等待到位后执行下一步动作）永远无法检测到稳定的到位信号

**根因分析**:
```
【错误代码】VAR声明处的初始化:
  VAR
    tmp_bProductInPlaceDone : BOOL := FALSE;  // ← 问题在这里！
  END_VAR
  
【问题解析】:
  在西门子SCL中，VAR段的 ":= FALSE" 初始化语法:
    - 对于TEMP变量: 每次调用FB都重新初始化 (这是正常的)
    - 对于STAT变量: 仅在首次调用时初始化一次 (这是预期的)
    
  如果tmp_bProductInPlaceDone是STAT变量但写了":= FALSE":
    取决于编译器实现，可能每个周期都重置!
    
  更可能的情况是: 这个变量应该是有状态的(STAT)，
  但初始化写法导致了意外的每周期重置。

【正确做法】:
  方案A: 将变量改为STAT类型，移除":= FALSE"(或保留，首次初始化)
  方案B: 保留初始化，但将赋值逻辑放到初始化块中(仅在i_Reset或首次调用时执行)
  
  根据原始修复记录，采用方案B:
  "移除无条件初始化，仅在i_Reset或初始化块中设置初始值"
```

**参考依据**: 原始SCL第71行变更记录；现场调试问题单 #DBG-014-008（到位信号全周期闪烁）。
