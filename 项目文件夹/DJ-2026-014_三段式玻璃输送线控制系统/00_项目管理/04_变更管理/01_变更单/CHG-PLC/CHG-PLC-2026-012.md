## 4. 变更原因

**变更背景**: CHG-PLC-2026-006(速度范式改Hz模式)引入了新的驱动器报警输入信号`i_DriveAlarm`，替代了原来基于"速度模式冲突"的报警检测方式。但原有的驱动器报警响应行为较为简单，缺少精细化的状态管理规则。

**变更必要性**: 优化驱动器报警的处理行为，使其更加符合工业现场的实际情况：

**原有行为(简单)**:
- 收到DriveAlarm → 设置AlarmState → 停止电机
- DriveAlarm消失 → 可立即复位（如果配合CHG-PLC-2026-007的增强机制）

**优化后的行为(精细化)**:
1. **报警期间只响应Stop，不响应Start** — 防止报警状态下误启动
2. **运行中收到报警 → 立即停止电机** — 安全优先
3. **报警信号消失后持续5秒 → 才允许复位解除** — 防止报警抖动导致的反复启停
4. **复位后可直接恢复运行（无需重新按Start）** — 提升操作便利性

**参考依据**: 变频器故障处理规范 VAC-014-003；驱动器通讯协议手册 §8.2"报警信号时序要求"。

```
优化后的报警状态机:

           ┌──────────────┐
           │   Normal     │
           │  (正常运行)   │
           └──────┬───────┘
                  │ i_DriveAlarm=TRUE
                  ↓
           ┌──────────────┐
      ┌───→│    Alarm     │←───┐
      │    │ (报警停止)    │    │
      │    └──────┬───────┘    │
      │           │ i_Stop     │
      │           ↓            │
      │    ┌──────────────┐    │
      │    │ AlarmWait    │    │
      │    │ (等待5秒)     │────┘
      │    └──────┬───────┘
      │           │ 5秒到期 AND i_Reset
      │           ↓
      │    ┌──────────────┐
      └────│   Normal     │ (恢复运行)
           └──────────────┘
           
规则: Alarm态忽略i_Start，只接受i_Stop
```
