## 1. 背景与问题

### 1.1 插件限制

siemens-lsp go-gen 是一个将西门子 SCL PLC 代码转换为 Go 测试代码的插件。在处理 IEC 标准定时器（TON）时，存在以下限制：

```
SCL 源代码:          "IEC_Timer_0_DB".TON(IN:=x, PT:=T#500ms, Q=>y, ET=>z)

插件生成的 Go 代码:
    _ = builtins.B_UNRESOLVED("\"IEC_Timer_0_DB\".TON", x, T#500ms, &y, &z)
                                    ↑
                            这是一个空函数！只返回 0，不修改 y 和 z
```

### 1.2 为什么不能用原生 TON？

| 特性 | 西门子 TIA Portal | siemens-lsp go-gen |
|------|-------------------|-------------------|
| TON 运行时 | 硬件/仿真器内置实现 | ❌ 不内置 |
| B_UNRESOLVED | 不存在 | 存在但为空实现 |
| Q 输出 | 正常更新 | ❌ 始终为初始值 (FALSE) |
| ET 输出 | 正常更新 | ❌ 始终为初始值 (T#0s) |

**结论**: 必须用纯 SCL 逻辑替代 TON 定时器。

## 2. 解决方案总览

### 2.1 核心思路：计数器 + IF 判断

```scl
// 用这个模式替代 TON 定时器
IF bStart THEN           // 对应 TON.IN
    Counter := Counter + 1;   // 每个扫描周期 +1
    IF Counter >= 500 THEN    // 500 = PT (假设每周期 1ms)
        bOut := TRUE;         // 对应 TON.Q
    ELSE
        bOut := FALSE;
    END_IF;
ELSE
    Counter := 0;             // 复位
    bOut := FALSE;
END_IF;
```

### 2.2 参数映射表

| IEC TON 参数 | 类型 | 纯逻辑实现对应 | 类型 |
|-------------|------|---------------|------|
| **IN** (启动) | `BOOL` | `bStart_A` / `bStart_B` | `BOOL` |
| **PT** (预设时间) | `TIME` | `500` (硬编码阈值) | `INT` 常量 |
| **Q** (输出) | `BOOL` | `bOut_A` / `bOut_B` | `BOOL` |
| **ET** (已过时间) | `TIME` | ⚠️ 不支持赋值 | - |
| 内部计时 | 自动 | `Counter_A` / `Counter_B` | `INT` |

### 2.3 两种方案对比

| 维度 | 方案A（独立DB方式） | 方案B（多重实例方式） |
|------|---------------------|---------------------|
| **概念来源** | TIA Portal 的独立背景 DB | TIA Portal 的多重实例 |
| **DB 组织** | 可单独创建 DB 文件 | 变量嵌入全局 DB |
| **变量命名** | 后缀 `_A` | 后缀 `_B` |
| **HMI 按钮** | `Hmibutton[7]` | `Hmibutton[8]` |
| **功能** | ✅ 完全相同 | ✅ 完全相同 |
| **测试结果** | test4 PASS | test5 PASS |

> **实际差异**: 两种方案的 SCL 逻辑完全相同，区别仅在变量名和 DB 组织方式上。

```scl
    END_VAR

```

### 4.2 关键点：为什么 Counter 必须放在 DB 中？

```
┌─────────────────────────────────────────────────────────────┐
│  VAR_TEMP（临时变量）的生命周期                              │
│                                                             │
│  扫描周期 N 开始 → VAR_TEMP 初始化为默认值(0)                │
│       │                                                     │
│       ├→ 执行程序逻辑                                       │
│       │   Counter := Counter + 1;  // Counter = 0 + 1 = 1  │
│       │                                                     │
│  扫描周期 N 结束                                             │
│       │                                                     │
│  扫描周期 N+1 开始 → VAR_TEMP 再次初始化为默认值(0) ❌       │
│       │                                                     │
│       ├→ 执行程序逻辑                                       │
│       │   Counter := Counter + 1;  // Counter = 0 + 1 = 1  │
│       │   （永远无法累加！）                                 │
│                                                             │
│  结论：VAR_TEMP 无法保持跨周期状态                           │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│  DATA_BLOCK（静态变量）的生命周期                             │
│                                                             │
│  首次上电 → DB 变量初始化                                   │
│       │                                                     │
│  扫描周期 N 开始 → DB 变量保持上次的值                       │
│       │                                                     │
│       ├→ 执行程序逻辑                                       │
│       │   Counter := Counter + 1;  // Counter = 0 + 1 = 1  │
│       │                                                     │
│  扫描周期 N 结束 → DB 变量保存当前值                         │
│       │                                                     │
│  扫描周期 N+1 开始 → DB 变量仍为 1 ✅                        │
│       │                                                     │
│       ├→ 执行程序逻辑                                       │
│       │   Counter := Counter + 1;  // Counter = 1 + 1 = 2  │
│       │   （可以正常累加！）                                 │
│                                                             │
│  结论：DB 变量可以保持跨周期状态 ✅                          │
└─────────────────────────────────────────────────────────────┘
```

### 4.3 关于 tElapsed 未使用的说明

SCL 语言存在以下类型限制：

```scl
// ❌ 错误写法 1：直接赋值
tElapsed_A := Counter_A;           
// 编译错误: cannot assign INT to TIME without explicit conversion (TC100)

// ❌ 错误写法 2：乘法转换
tElapsed_A := Counter_A * T#1ms;   
// 编译错误: 不支持 INT * TIME 运算

// ❌ 错误写法 3：类型转换函数
tElapsed_A := TIME_TO_T(Counter_A); 
// 编译错误: 返回的是 T (时间戳) 类型，不是 TIME 类型
```

**如需记录已过时间的解决方案**：
```scl
// 推荐：改用 DINT 类型存储毫秒值
Elapsed_ms_A : DINT;  // 在 DB 中声明
// 使用时:
Elapsed_ms_A := Counter_A;  // DINT ← INT，允许隐式转换
```

## 6. 代码详解 - OB1/OB1.scl（核心逻辑）

### 6.1 完整代码（带注释）

```scl
ORGANIZATION_BLOCK OB1
BEGIN

// ===== 第一部分：阀门控制（与定时器无关）=====
GlobalVars.ValveCtrl(
    AutoManual  := GlobalVars.Hmibutton[0],
    OpenCmd     := GlobalVars.Hmibutton[1],
    CloseCmd    := GlobalVars.Hmibutton[2],
    OverCurrent := GlobalVars.Hmibutton[3],
    OpenLimit   := GlobalVars.Hmibutton[4],
    CloseLimit  := GlobalVars.Hmibutton[5],
    FaultReset  := GlobalVars.Hmibutton[6],
    FaultStatus => GlobalVars.FaultStatus,
    ValveOpen   => GlobalVars.ValveOpen,
    ValveClose  => GlobalVars.ValveClose
);

// ===== 第二部分：方案A 定时器 =====
GlobalVars.bStart_A := GlobalVars.Hmibutton[7];  // 步骤1: 读取启动信号

IF GlobalVars.bStart_A THEN                        // 步骤2: 判断是否启动
    GlobalVars.Counter_A := GlobalVars.Counter_A + 1;  // 步骤3: 计数器+1
    
    IF GlobalVars.Counter_A >= 500 THEN            // 步骤4: 是否达到阈值？
        GlobalVars.bOut_A := TRUE;                 // 是 → 输出TRUE
    ELSE
        GlobalVars.bOut_A := FALSE;                // 否 → 输出FALSE
    END_IF;
ELSE                                               // 启动信号为FALSE
    GlobalVars.Counter_A := 0;                     // 复位计数器
    GlobalVars.bOut_A := FALSE;                    // 复位输出
END_IF;

// ===== 第三部分：方案B 定时器（逻辑完全对称）=====
GlobalVars.bStart_B := GlobalVars.Hmibutton[8];

IF GlobalVars.bStart_B THEN
    GlobalVars.Counter_B := GlobalVars.Counter_B + 1;
    
    IF GlobalVars.Counter_B >= 500 THEN
        GlobalVars.bOut_B := TRUE;
    ELSE
        GlobalVars.bOut_B := FALSE;
    END_IF;
ELSE
    GlobalVars.Counter_B := 0;
    GlobalVars.bOut_B := FALSE;
END_IF;

END_ORGANIZATION_BLOCK
```

### 7.2 test4 详细解读

```scl
TEST_CASE "test4"
    // 【步骤1】启动定时器
    SET GlobalVars.Hmibutton[7] := TRUE;
    // 效果: GlobalVars.bStart_A = TRUE
    
    // 【步骤2】等待 1000 个扫描周期
    WAIT_CYCLES 1000;
    // 效果: OB1 被执行 1000 次
    //       每次: Counter_A += 1
    //       第1次后: Counter_A = 1,  bOut_A = F
    //       第2次后: Counter_A = 2,  bOut_A = F
    //       ...
    //       第499次后: Counter_A = 499, bOut_A = F
    //       第500次后: Counter_A = 500, bOut_A = T  ← 触发!
    //       ...
    //       第1000次后: Counter_A = 1000, bOut_A = T  ← 保持
    
    // 【步骤3】断言结果
    ASSERT GlobalVars.bOut_A = TRUE;
    // 因为 1000 > 500，所以 bOut_A 必须为 TRUE
END_TEST_CASE
```

### 7.3 为什么 WAIT_CYCLES 是 1000 而不是 500？

```
如果 WAIT_CYCLES 500:
  - 最佳情况: 恰好第 500 次触发 → PASS
  - 边界情况: 计数偏差 1 个周期 → FAIL (499 < 500)
  - 风险: 可能因边界问题导致间歇性失败

如果 WAIT_CYCLES 1000:
  - 任何情况: 1000 >> 500，一定已经触发 → 稳定 PASS
  - 代价: 多等了 500 个周期（约 0.5 秒），可接受
```

## 9. 关键设计决策说明

### 决策1：为什么选择纯逻辑而非修改 Go 代码？

| 方案 | 优点 | 缺点 |
|------|------|------|
| **纯 SCL 逻辑（采用）** | 可移植、符合规范、无需维护 Go 代码 | SCL 语法受限（无 ET 支持） |
| **修改 B_UNRESOLVED** | 功能完整、支持 ET | 违反"不改 Go"要求、需维护 |

### 决策2：为什么两种方案都实现？

- **对比验证**: 证明两种组织方式都能工作
- **文档价值**: 为后续项目提供选择参考
- **学习目的**: 理解不同 DB 组织方式的优劣

### 决策3：硬编码阈值 500 而非参数化

```scl
// 当前: 硬编码
IF Counter_A >= 500 THEN ...

// 替代方案: 参数化（未采用）
Timer_PT_A : INT := 500;  // 在 DB 中声明
IF Counter_A >= Timer_PT_A THEN ...
```

**原因**: 当前阶段以验证可行性为主，后续可重构为参数化版本。

## 10. 常见问题 FAQ

### Q1: 可以精确控制定时时间吗？比如 500ms？

**A**: 当前实现的精度取决于 PLC 扫描周期。如果每个扫描周期恰好是 1ms，则 500 个周期 ≈ 500ms。实际精度受以下因素影响：

- 程序复杂度（影响单次扫描时间）
- 系统负载
- 硬件性能

对于高精度定时需求，建议使用硬件定时器或专用定时中断。

### Q2: 如何修改定时时间？

**A**: 修改 OB1.scl 中的阈值常量：

```scl
IF GlobalVars.Counter_A >= 500 THEN

// 改为 1秒 (1000ms):
IF GlobalVars.Counter_A >= 1000 THEN

// 改为 100ms:
IF GlobalVars.Counter_A >= 100 THEN
```

### Q3: 如何实现 TOF（断开延时定时器）？

**A**: 修改判断逻辑：

```scl
// TON (接通延时): IN=TRUE 时开始计时
IF bStart THEN
    Counter++; 
    bOut = (Counter >= PT);
ELSE
    Counter = 0;
    bOut = FALSE;
END_IF;

// TOF (断开延时): IN=FALSE 时开始计时
IF NOT bStart THEN
    Counter++;
    bOut = (Counter < PT);  // 注意: 条件相反
ELSE
    Counter = 0;
    bOut = TRUE;
END_IF;
```

### Q4: 测试间会互相干扰吗？

**A**: 不会。每个测试用例（TEST_CASE）都会初始化独立的 `Runner` 和 `Memory` 实例，互不影响。这是通过 Go 的 `t.Parallel()` 和独立内存空间保证的。

### Q5: 如何添加新的定时器？


2. **在 OB1.scl 中添加逻辑**:
```scl
GlobalVars.bStart_C := GlobalVars.Hmibutton[9];
IF GlobalVars.bStart_C THEN
    GlobalVars.Counter_C := GlobalVars.Counter_C + 1;
    IF GlobalVars.Counter_C >= 500 THEN
        GlobalVars.bOut_C := TRUE;
    ELSE
        GlobalVars.bOut_C := FALSE;
    END_IF;
ELSE
    GlobalVars.Counter_C := 0;
    GlobalVars.bOut_C := FALSE;
END_IF;
```

3. **在 valve_test.scltest 中添加测试**:

```scl
END_TEST_CASE
```
