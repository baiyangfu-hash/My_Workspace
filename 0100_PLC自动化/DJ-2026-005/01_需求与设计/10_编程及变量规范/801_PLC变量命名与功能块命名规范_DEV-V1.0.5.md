## 1. 总则

### 1.1 目的

为了统一PLC变量命名规范，提高代码可读性和可维护性，特制定本规则。

### 1.2 适用范围

本规范适用于所有PLC编程系统，包括Autoshop、Work3等，确保跨系统的命名一致性。

### 1.3 核心原则

1. **可读性**：变量名应清晰表达其用途和含义
2. **一致性**：在整个项目中使用一致的命名风格
3. **简洁性**：在保证可读性的前提下，变量名应尽可能简洁
4. **避免歧义**：变量名应避免使用容易引起歧义的词汇

## 2. 变量命名规范

### 2.1 变量命名规则

#### 2.1.1 FB，FC等功能块输入变量

- **命名格式**：`i_变量类型_变量描述`
- **示例**：`i_bStartButton`（启动按钮信号）

#### 2.1.2 FB，FC输出变量

- **命名格式**：`q_变量类型_变量描述`
- **示例**：`q_bMotorRun`（电机运行输出）

#### 2.1.3 FB，FC等功能块输入输出变量

- **命名格式**：`iq_变量类型_变量描述`
- **示例**：`iq_bMotorRun`（电机运行双向信号）

#### 2.1.4 内部变量

- **命名格式**：`变量类型_变量描述`
- **示例**：`bRunning`（运行状态内部变量）

#### 2.1.5 全局变量

- **命名格式**：`变量类型_变量描述`
- **示例**：`bSysAutoMode`（系统自动模式全局变量）

#### 2.1.6 上升沿/下降沿检测变量

- **命名格式**：`LDP_变量类型_变量描述`（上升沿）或 `LDF_变量类型_变量描述`（下降沿）
- **示例**：`LDP_bStart`（启动信号上升沿）或 `LDF_bStop`（停止信号下降沿）

#### 2.1.7 硬件IO变量

- **命名格式**：`In_变量类型_变量描述`（输入）或 `Out_变量类型_变量描述`（输出）
- **示例**：`In_bStartButton`（启动按钮硬件输入）或 `Out_bMotorRun`（电机运行硬件输出）

### 2.2 变量类型前缀

| 变量类型 | 前缀 | 示例                                    |
| ---- | -- | ------------------------------------- |
| 布尔型  | b  | `bStart`, `bStop`, `bAlarm`           |
| 字节型  | by | `byStatus`, `byData`, `byFlags`       |
| 整数型  | i  | `iSpeed`, `iCount`, `iTemperature`    |
| 长整数型 | li | `liSpeed`, `liCount`, `liTemperature` |
| 字型   | w  | `wAlarmCode`, `wStatusWord`, `wFlagWord` |
| 双字型  | dw | `dwAlarmCode`, `dwCounterValue`, `dwFlags` |
| 实数型  | r  | `rPressure`, `rFlow`, `rLevel`        |
| 字符串型 | s  | `sProductName`, `sRecipeID`           |
| 浮点数型 | f  | `fPressure`, `fFlow`, `fLevel`        |
| 数组   | a  | `aMotorSpeed[3]`, `aSensorData[10]`   |

### 2.3 常量命名

- 常量名应使用全大写字母，单词之间用下划线分隔
- 示例：`MAX_SPEED`, `MIN_TEMPERATURE`, `DEFAULT_PRESSURE`

## 3. 功能块命名规范

### 3.1 功能块命名格式

- **命名格式**：`FB_编号_英文功能描述_设备对象`
- **示例**：`FB_1001_ConveyorControl_BeltConveyor`（皮带输送机启停控制）

### 3.2 输入输出变量前缀规范

#### 3.2.1 输入变量前缀 (VAR_INPUT)

| 前缀格式 | 适用范围 | 示例 | 说明 |
|----------|----------|------|------|
| `i_` + 变量类型 + `_` + 功能描述 | 标准输入变量 | `i_bStartButton`, `i_iSpeedSetpoint` | FB/FC的标准输入参数 |
| `i_b` + `Lx_` + 功能描述 | HMI手动操作缓存变量（从M区读取后传给FB） | `i_bLx_BlockDown`, `i_bLx_ConvFwd` | Lx = Logic auxiliary（逻辑辅助），用于区分直接DI映射的输入变量与经主程序缓存后的HMI操作变量 |

> **HMI辅助缓存变量特殊说明**：当主程序从M区（HMI辅助控制区）读取手动操作信号后，需缓存为中间变量再传给功能块时，使用 `i_bLx_` 前缀。其中 `Lx` 表示"联锁/逻辑辅助"(Logic auxiliary)，用于与直接DI映射的输入变量做视觉区分。

#### 3.2.2 输出变量前缀 (VAR_OUTPUT)

| 前缀格式 | 适用范围 | 示例 | 说明 |
|----------|----------|------|------|
| `q_` + 变量类型 + `_` + 功能描述 | 标准输出变量 | `q_bMotorRun`, `q_rCurrentPosition` | FB/FC的标准输出参数 |

### 3.3 功能块编号规则

#### 3.3.1 基础控制模块

- **编号区间**：0100-1999
- **说明**：按工作流内功能优先级编排（如先启停、再调节、后报警）
- **唯一性**：同一工作流内编号唯一，跨工作流可重复（通过工作流编号区分）

#### 3.3.2 主控模块

- **编号区间**：2000-2999
- **说明**：主控层 FB（总调度 / 全局监控 / 模式切换）
- **唯一性**：同一项目内编号唯一，跨项目可重复（通过项目号区分）

### 3.4 功能块命名示例

#### 工作流功能块示例：

- `FB_1001_ConveyorControl_BeltConveyor`（皮带输送机启停控制）
- `FB_1002_SpeedRegulation_VFDMainConveyor`（主输送线变频无级调速）
- `FB_1001_GraspControl_EndEffectorGripper`（机械臂末端夹爪开合控制）
- `FB_1001_DataAcquisition_SlaveDevice`（从站设备状态采集上传）
- `FB_1002_CommandIssuance_Actuator`（执行机构运行参数指令下发）

#### 主控层功能块示例：

- `FB_2000_MainDispatch_AllEquipment`（全设备工作流调度+模式切换）
- `FB_2001_MainStatusMonitor_AllStation`（全局状态监控+故障汇总）
- `FB_2002_MainModeSwitch_OperationMode`（手动/自动/调试模式切换）

## 4. 注释规范

### 4.1 变量注释

- 所有变量都应添加注释，说明其用途和含义
- 注释应简洁明了，避免冗余
- 对于复杂变量，应详细说明其使用方法和注意事项

### 4.2 功能块注释

- 功能块应包含头部注释，说明功能、版本、输入输出变量等信息
- 注释应包含变更记录，便于追踪历史修改

### 4.3 SCL/ST 语言注释风格指南（DEV-V1.0.4 新增）

#### 4.3.1 注释格式选择

PLC 编程支持多种注释风格，应根据场景合理选择：

| 注释格式 | 适用场景 | 兼容性 | 推荐度 |
|----------|----------|--------|--------|
| `(* *)` 块注释 | 文件头、段落分隔、多行说明 | IEC 61131-3 标准，全平台兼容 | ⭐⭐⭐⭐⭐ 强制 |
| `//` 单行注释 | 行内简短注释、变量说明 | SCL/ST 专用，简洁明了 | ⭐⭐⭐⭐ 推荐 |

**强制性规则**：
- ✅ **文件头注释必须使用 `(* *)` 块注释格式**
- ✅ **逻辑段落分隔必须使用 `(* ==== 段落名 ==== *)` 格式**
- ✅ **变量声明后的注释可使用 `(* *)` 或 `//`（保持一致）**
- ✅ **行内逻辑说明推荐使用 `//`（SCL语言简洁性）**

#### 4.3.2 标准文件头模板

每个 FB/FC/PRG 必须包含以下标准文件头：

```pascal

(*  功能块名称：FB_1001_ConveyorControl_LineConveyor                *)
```

#### 4.3.3 内部变量前缀使用规则

**禁止使用的非标准前缀**：

| 前缀 | 问题 | 正确做法 |
|------|------|----------|
| `tmp_` | 增加阅读噪音，无语义价值 | 直接使用有意义的业务前缀（见§2.2）|
| `temp_` | 同上 | 仅在方法内部临时计算时使用 |

**正确示例**：

```pascal
VAR
    (* ❌ 错误：使用 tmp_ 前缀 *)
    (* tmp_bManualMode : BOOL := FALSE; *)

    (* ✅ 正确：直接使用业务前缀 *)
    bManualMode : BOOL := FALSE;          (* 手动模式标志 *)
    bAutoMode : BOOL := FALSE;            (* 自动模式标志 *)
    nCurrentMode : INT := 0;              (* 当前运行模式 *)
END_VAR
```

**特殊场景变量命名**（DEV-V1.0.5 优化）：

| 变量类型 | 命名格式 | 示例 | 字符数 | 说明 |
|----------|----------|------|--------|------|
| 启停请求标志 | `bXxxRequested` | `bStartRequested`, `bStopRequested` | 15 | 驼峰式，表示内部请求状态 |
| **定时器输入** | **`tIn`** | **`tIn[0..2]`** | **5** | **t=Timer, In=输入 (推荐)** |
| **定时器输出** | **`tQ`** | **`tQ[0..2]`** | **4** | **Q=输出完成 (推荐)** |
| **定时器复位** | **`tR`** | **`tR[0..2]`** | **4** | **R=复位信号 (推荐)** |
| **定时器预设值** | **`tPt`** | **`tPt[0..2]`** | **5** | **Pt=Preset预设值 (推荐)** |
| **定时器当前值** | **`tEt`** | **`tEt[0..2]`** | **5** | **Et=Elapsed当前值 (推荐)** |
| 边沿检测实例 | `trigXxxRise/Fall` | `trigStartRise`, `trigStopFall` | 16 | R_TRIG/F_TRIG 实例名 |
| **计数器执行条件** | **`cCoil`** | **`cCoil[0..1]`** | **7** | **c=Counter, Coil=执行条件** |
| **计数器设定值** | **`cPreset`** | **`cPreset[0..1]`** | **10** | **Preset=设定值** |
| **计数器初始/当前值** | **`cValue`** | **`cValueIn/cValueOut`** | **10-13** | **ValueIn=初始值, ValueOut=当前值** |
| **计数器状态输出** | **`cStatus`** | **`cStatus[0..1]`** | **9** | **Status=输出状态** |

> **命名优化说明 (V1.0.5更新)**：
> - 定时器数组命名从 `abTimerXxXxx`(9~12字符) 简化为 `tXxx`(4~5字符)，减少50%+长度
> - 采用**单字母前缀+功能后缀**模式：`t`=Timer, `c`=Counter，简洁且语义明确
> - 后缀采用**驼峰首字母大写**：`In/Q/R/Pt/Et` 对应 TONR/TON 的标准接口名
> - 旧版 `abTimerXx` 格式仍可识别，但新项目应优先使用简化版

#### 4.3.4 逻辑段落分隔标准

FB 内部的主要逻辑段应使用统一的分隔注释：

```pascal
(* ==================== 定时器调用段 ==================== *)
TONR(...);

(* ==================== 变量初始化段 ==================== *)
IF ... THEN
    ...
END_IF;

(* ==================== 模式切换段 ==================== *)
CASE ... OF
    ...
END_CASE;

(* ==================== 输出赋值段 ==================== *)
q_bOutput := bInternalState;
```

**常用段落名称建议**：
- 定时器调用段 / 变量初始化段 / 输入参数验证段
- 模式切换段 / 状态机执行段 / 启停控制段
- 报警管理段 / 故障处理段 / 安全互锁段
- 状态字计算段 / 输出赋值段 / 参数更新段

#### 4.3.5 SCL测试文件(.scltest)断言注释规范（DEV-V1.0.7 新增）

**目的**：解决测试断言中英文变量名可读性差的问题，使测试用例自文档化。

**强制规则**：每条 `ASSERT` 语句的行尾 **必须** 追加 `// 中文注释`，说明该变量的功能含义。

**注释来源（优先级从高到低）**：
1. `GlobalVars.db` 变量声明行内注释（权威源，与代码100%同步）
2. FB接口文档(IFC-*.md) 的"说明"列
3. 根据变量名英文语义翻译（最后手段）

**格式标准**：

```scl
(* ✅ 正确: ASSERT + 行尾中文注释 *)
ASSERT GlobalVars.stExternal.o_bFrameMachine_Ready = TRUE;          // 本机就绪,可接收边框
ASSERT GlobalVars.stPickPlace.o_bFrontClamp_Action = TRUE;           // 前夹爪夹紧电磁阀
ASSERT GlobalVars.stGlobal.o_wGlobalAlarmWord = 0;                   // 全局报警字(D400,HMI报警灯)
ASSERT GlobalVars.stPickPlace.o_iCurrentState = 1;                   // 当前状态机步骤(0~10,99=故障) [S21_UP_TO_PICK]

(* ❌ 错误: 无注释或使用emoji替代 *)
ASSERT GlobalVars.stExternal.o_bFrameMachine_Ready = TRUE;
ASSERT GlobalVars.stPickPlace.o_bFrontClamp_Action = TRUE;  // ✅
```

**注释内容规范**：

| 规则 | 说明 | 示例 |
|------|------|------|
| 使用简体中文 | 与项目文档语言一致 | `升降气缸上升电磁阀` |
| 精简来自DB1 | 复制GlobalVars.db的`//`后文本，可删减IO地址 | DB1: `// 前夹爪夹紧电磁阀 -> Y地址` → 注释: `前夹爪夹紧电磁阀` |
| 枚举值附加说明 | 状态码/步序号后追加[枚举名] | `[S21_UP_TO_PICK]`, `[S22_CLAMP_AND_DETECT]` |
| 对齐到统一列(可选) | 多条ASSERT对齐提升可读性 | 推荐对齐到第70列附近 |

**SET语句注释（推荐但非强制）**：输入变量的SET行也可追加注释以提升上下文连贯性。

```scl
SET GlobalVars.stExternal.i_bEnable := TRUE;                        // 系统使能
SET GlobalVars.stExternal.i_bAutoMode := TRUE;                      // 自动模式选择
SET GlobalVars.stPickPlace.i_iPickLayer_Input := 1;                 // 外部指定的当前取料层号(1~4)
```

## 附录 D：IDE 工具兼容性注意事项

### D.1 中文标识符支持现状

| IDE/工具 | 中文标识符支持 | 备注 |
|----------|---------------|------|
| 博图(TIA Portal) | ✅ 完全支持 | 西门子官方IDE |
| Autoshop | ✅ 完全支持 | 欧姆龙官方IDE |
| Work3 | ✅ 完全支持 | 三菱官方IDE |
| Codesys | ✅ 完全支持 | IEC 61131-3 标准环境 |
| Dynamic Siemens Language Support(VS Code插件) | ⚠️ 部分支持 | FUNCTION_BLOCK 类型中中文标识符可能触发 TC001 误报 |
| 其他第三方LSP/编辑器 | ❓ 视具体实现而定 | |

### D.2 推荐做法

1. **变量名和功能块名**：**强制使用英文标识符**（如 `bStartButton`, `FB_1001_Conveyor4Layer_BufferFraming`），不得使用中文
2. **注释和文档**：鼓励使用中文，提高可读性
3. **VS Code + Siemens LSP 开发环境**：中文标识符会导致 TC001 误报，必须使用英文
4. **已有项目**：已使用中文标识符的变量应逐步重构为英文

### D.3 LSP误报处理指南

当使用 Dynamic Siemens Language Support 等 VS Code 插件遇到 TC001 "undeclared symbol" 误报时：

1. 确认变量已在 VAR 区域正确声明
2. 检查拼写是否完全一致（含全角/半角字符）
3. 若确认为中文标识符导致的误报，可安全忽略该错误
4. 最终编译以实际PLC编程软件（博图/Autoshop/Work3）为准

### E.2 详细检查流程

#### Step 1: 文件头检查
```
□ 文件头使用 (* *) 块注释格式
□ 包含功能块名称（符合§3.1格式）
□ 包含功能描述（一句话说明核心功能）
□ 包含创建日期和版本号
□ 包含编制人和审核人
□ 包含遵循的规范列表及版本号
□ 包含变更记录（最新版本在前）
```

#### Step 2: 变量声明检查
```
VAR_INPUT 区域：
  □ 所有变量以 i_ 开头
  □ 类型前缀正确（b/i/r/s等）
  □ 每个变量有 (* 注释 *) 说明用途
  □ 无 tmp_ 或其他非标准前缀
  □ 无中文标识符

VAR_OUTPUT 区域：
  □ 所有变量以 q_ 开头
  □ 类型前缀正确
  □ 每个变量有注释
  □ 无中文标识符

VAR_IN_OUT 区域（如有）：
  □ 双向参数命名清晰

VAR 区域（内部变量）：
  □ 无 i_/q_ 前缀（仅用于接口）
  □ 使用有意义的业务前缀
  □ 无 tmp_ 前缀
  □ 无中文标识符
  □ 特殊变量（定时器数组、请求标志）符合§4.3.3规范
```

#### Step 3: 代码一致性检查
```
□ VAR 中声明的所有变量在代码中都有使用（无死代码）
□ 代码中使用的所有变量都在 VAR 中已声明（无未声明变量）
□ 变量名拼写完全一致（区分大小写）
□ 无硬编码的魔法数字（应使用常量或参数化）
```

#### Step 4: 注释质量检查
```
□ 主要逻辑段有 (* ==== 段落名 ==== *) 分隔注释
□ 复杂算法有"为什么"的解释性注释（而非仅重复代码）
□ 状态字、模式值等枚举类型有清晰的位定义/值定义注释
□ 定时器数组有索引功能说明注释
□ 无注释掉的废代码（如被注释的旧VAR声明块）
```

### E.3 常见违规示例与修正

| 违规类型 | 错误示例 | 正确示例 | 违反条款 |
|----------|----------|----------|----------|
| 输入变量缺前缀 | `i_Start : BOOL;` | `i_bStart : BOOL;` | §2.1.1 + §2.2 |
| 输出变量缺前缀 | `q_MotorRunning : BOOL;` | `q_bMotorRunning : BOOL;` | §2.1.2 + §2.2 |
| 内部变量用tmp_ | `tmp_bMode : BOOL;` | `bMode : BOOL;` | §4.3.3 |
| FB名称不规范 | `FB_ConveyorV4` | `FB_1001_ConveyorControl_LineConveyor` | §3.1 |
| 文件头不完整 | 仅一行注释 | 完整标准文件头模板 | §4.3.2 |
| 变量声明与使用不一致 | 声明`tmp_bXxx`，代码用`bXxx` | 统一命名为`bXxx` | 通用 |
| 定时器数组命名混乱 | `In_tTimer1` | `abTimerIn[0..2]` 或 `tIn[0..2]`(推荐) | §4.3.3 |
