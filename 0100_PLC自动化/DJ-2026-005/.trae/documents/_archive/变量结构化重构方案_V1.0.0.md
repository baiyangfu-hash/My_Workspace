### 参考基准: SV_jog 结构体

用户提供的项目实际伺服jog控制结构体:

```pascal
TYPE ST_ServoJog :
STRUCT
    Enable         : BOOL;   // jog执行      (偏移 1)
    Forward        : BOOL;   // jog正转        (偏移 2)
    Backward       : BOOL;   // jog反转        (偏移 3)
    Velocity       : REAL;   // jog目标速度    (偏移 4)
    Deceleration   : REAL;   // jog减速度      (偏移 5)
    Acceleration   : REAL;   // jog加速度      (偏移 6)
    Curvetype      : INT;    // jog曲线类型    (偏移 7)
    Busy           : BOOL;   // jog繁忙        (偏移 8)
    Commandaborted : BOOL;   // jog停止执行    (偏移 9)
    Error          : BOOL;   // jog错误        (偏移 10)
    ErrorID        : INT;    // jog错误代码    (偏移 11)
END_STRUCT
END_TYPE
```

**设计启示**:
- 输入/输出/状态 字段在同一 STRUCT 中（扁平结构，无嵌套）
- BOOL 控制命令在前，REAL 参数居中，BOOL/INT 状态输出在后
- 符合 PLCopen 运动控制 FB 的接口模式
- **本项目所有结构体应遵循此模式：输入→参数→输出 三段式**

## 1. 问题诊断：当前变量"散装"现状

### 1.1 散装变量统计

通过对 [GlobalVars.db](../DJ-2026-005/02_PLC程序/通用ST程序及变量表/DB1/GlobalVars.db) 和各FB接口文档的深度分析，识别出以下**重复模式**：

#### 🔴 问题1：伺服轴信号分散在3个位置（最严重）

**当前散装方式（以stPickPlace为例）**：
```pascal
// Z轴信号 - 分散在stPickPlace中
i_bZAxis_HomePos           : BOOL;   // 原点
i_bZAxis_ServoFault        : BOOL;   // 故障
i_bZAxis_FwdLimit          : BOOL;   // 正限位
i_bZAxis_RevLimit          : BOOL;   // 负限位
o_bZAxis_PulseOutput       : BOOL;   // 脉冲输出
o_bZAxis_DirectionOutput   : BOOL;   // 方向输出
o_bZAxis_Enable            : BOOL;   // 伺服使能
o_rZAxisCurrentPos         : REAL;   // 位置反馈

// X1轴信号 - 同样分散
i_bX1Axis_HomePos          : BOOL;
i_bX1Axis_ServoFault       : BOOL;
i_bX1Axis_FwdLimit         : BOOL;
i_bX1Axis_RevLimit         : BOOL;
o_rX1AxisCurrentPos        : REAL;

// X2轴信号 - 在stFeeder中又重复一遍
i_bX2Axis_Home             : BOOL;    // 命名还不一致！
i_bX2Axis_ForwardLimit     : BOOL;
i_bX2Axis_ReverseLimit     : BOOL;
i_bX2Axis_ServoFault       : BOOL;
```

**问题量化**：
- 3个轴 × 每轴8~10个信号 = **24~30个散装BOOL/REAL**
- 命名不一致：`_HomePos` vs `_Home`，`_FwdLimit` vs `_ForwardLimit`
- 跨FB重复定义：FB_1003有Z/X1轴，FB_1004有X2轴，DB1又汇总一遍

## 2. 解决方案：通用结构体库设计

### 2.1 设计原则

| 原则 | 说明 |
|------|------|
| **高内聚** | 同一执行机构的所有信号封装在一个STRUCT中 |
| **低耦合** | 结构体之间通过最小接口通信 |
| **可复用** | 放入SysLib作为跨项目共享类型 |
| **向后兼容** | 支持从现有散装变量平滑迁移 |
| **命名规范** | 统一使用 `ST_` 前缀 + 功能域命名 |

### 2.2 结构体清单（8个通用类型）

#### 📦 **ST_ServoAxis** - 伺服轴完整控制结构体

**适用场景**：Z轴、X1轴、X2轴及未来扩展轴

```pascal
TYPE ST_ServoAxis :
STRUCT
    // === 传感器输入 (6个) ===
    bHomePos        : BOOL := FALSE;   // 原点信号 (Home/ORG)
    bFwdLimit       : BOOL := FALSE;   // 正向限位
    bRevLimit       : BOOL := FALSE;   // 反向限位
    bServoFault     : BOOL := FALSE;   // 驱动器故障 (ALM)
    bInPosition     : BOOL := FALSE;   // 到位信号 (可选, INP)
    bAlarmReset     : BOOL := FALSE;   // 报警复位确认

    // === 控制输出 (5个) ===
    bPulseEnable    : BOOL := FALSE;   // 脉冲输出使能
    bDirection      : BOOL := FALSE;   // 方向控制 (TRUE=正向)
    bServoEnable    : BOOL := FALSE;   // 伺服励磁 (SON)
    bHomeRequest    : BOOL := FALSE;   // 回原点请求
    bMoveAbsRequest : BOOL := FALSE;   // 绝对定位请求

    // === 位置数据 (3个) ===
    rTargetPos      : REAL := 0.0;    // 目标位置 (mm或度)
    rCurrentPos     : REAL := 0.0;    // 当前位置反馈 (mm)
    rSpeed          : REAL := 100.0;  // 速度设定 (mm/s)

    // === 状态输出 (4个) ===
    bIsHomed        : BOOL := FALSE;   // 已回原点标志
    bIsMoving       : BOOL := FALSE;   // 正在运动中
    bLimitActive    : BOOL := FALSE;   // 限位触发标志
    iAxisAlarmCode  : INT := 0;        // 轴专用报警码
END_STRUCT
END_TYPE
```

**复用效果**：
```
当前: 3轴 × 10个散装变量 = 30个独立变量
优化: 3个 ST_ServoAxis 实例 = 3个结构体变量 (内部仍30字段，但逻辑聚合)
```

**使用示例**：
```pascal
// 在 GlobalVars.db 中
stZAxis   : ST_ServoAxis;   // Z轴
stX1Axis  : ST_ServoAxis;   // X1轴
stX2Axis  : ST_ServoAxis;   // X2轴

// 访问方式 (比散装更清晰)
IF stZAxis.bHomePos THEN
    stZAxis.bMoveAbsRequest := TRUE;
    stZAxis.rTargetPos := 100.0;
END_IF;
```

#### 📦 **ST_Cylinder** - 双线圈气缸控制结构体

**适用场景**：阻挡气缸、分料气缸、升降气缸、夹紧/松开气缸等

```pascal
TYPE ST_Cylinder :
STRUCT
    // === 传感器输入 (2个) ===
    bExtendedPos    : BOOL := FALSE;   // 伸出位/下位/夹紧位/工作点
    bRetractedPos   : BOOL := FALSE;   // 收回位/上位/松开位/原点

    // === 控制输出 (2个) ===
    bExtend         : BOOL := FALSE;   // 伸出命令/下降/夹紧
    bRetract        : BOOL := FALSE;   // 收回命令/上升/松开

    // === 状态输出 (4个) ===
    bIsExtended     : BOOL := FALSE;   // 已伸出到位
    bIsRetracted    : BOOL := FALSE;   // 已收回到位
    bTimeout        : BOOL := FALSE;   // 动作超时
    bSensorFault    : BOOL := FALSE;   // 传感器冲突 (上下位同时ON)

    // === 配置参数 (1个) ===
    iTimeoutMs      : INT := 5000;     // 超时时间 (ms)
END_STRUCT
END_TYPE
```

**复用效果**：
```
当前: 7组气缸 × 8个散装变量 = 56个变量
优化: 7个 ST_Cylinder 实例 = 7个结构体变量
```

**使用示例**：
```pascal
// 在 stPickPlace 中
stLiftCylinder     : ST_Cylinder;   // 升降气缸
stFrontClamp       : ST_Cylinder;   // 前夹爪
stRearClamp        : ST_Cylinder;   // 后夹爪
stFrontClamp2      : ST_Cylinder;   // 前夹爪2
stRearClamp2       : ST_Cylinder;   // 后夹爪2

// 在 stConveyor 中 (每层2组)
astLayerCylinder[1..4] : STRUCT
    stBlock      : ST_Cylinder;   // 阻挡气缸
    stSeparate   : ST_Cylinder;   // 分料气缸
END_STRUCT;

// 访问示例
stLiftCylinder.bExtend := TRUE;   // 下降
IF stLiftCylinder.bExtendedPos THEN
    // 到位处理
END_IF;
```

#### 📦 **ST_DualSensor** - 双传感器冗余检测结构体

**适用场景**：到位检测、边框检测等需要冗余校验的场合

```pascal
TYPE ST_DualSensor :
STRUCT

    bSensor1        : BOOL := FALSE;   // 主传感器
    bSensor2        : BOOL := FALSE;   // 冗余传感器

    // === 一致性判断 (3个) ===
    bBothActive     : BOOL := FALSE;   // 双传感器同时激活
    bBothInactive   : BOOL := FALSE;   // 双传感器同时失活
    bConsistent     : BOOL := TRUE;    // 一致性标志 (默认TRUE)

    // === 汇总输出 (1个) ===
    bValidSignal    : BOOL := FALSE;   // 有效信号 (一致性OK时= Sensor1 OR Sensor2)
END_STRUCT
END_TYPE
```

**复用效果**：
```
当前: 4对冗余传感器 × 2个BOOL = 8个散装 + 外部一致性判断逻辑
优化: 4个 ST_DualSensor 实例 = 内置一致性判断
```

#### 📦 **ST_ConveyorLayer** - 单层输送机完整结构体

**适用场景**：4层输送机的每一层（替代当前的14个ARRAY + 10个ARRAY）

```pascal
TYPE ST_ConveyorLayer :
STRUCT
    // === 传感器组 (用子结构体) ===
    stPreSeparate       : ST_DualSensor;    // 分料前感应器 (可扩展为双传感器)

    // === 执行器组 (用子结构体) ===
    stBlockCylinder     : ST_Cylinder;      // 阻挡气缸
    stSeparateCylinder  : ST_Cylinder;      // 分料气缸
    stMotor             : ST_ConveyorMotor; // 输送电机 (见下文)

    // === 手动操作面板 ===
    stManualOp          : ST_ManualPanel_Conveyor; // 本层手动按钮

    // === 状态汇总 (5个) ===
    iStep               : INT := 0;         // 当前步序 0~70
    iAlarmCode          : INT := 0;         // 本层报警码
    bRunning            : BOOL := FALSE;    // 运行中
    bFault              : BOOL := FALSE;    // 故障
    bFeedDone           : BOOL := FALSE;    // 放料完成脉冲
    bPickupConfirmed    : BOOL := FALSE;    // 取料确认 (来自FB_1003)
END_STRUCT
END_TYPE
```

**复用效果**：
```
当前: stConveyor 用 14个ARRAY输入 + 10个ARRAY输出 + 3个汇总 = 27个顶层变量
优化: astConveyorLayer[1..4] : ARRAY[1..4] OF ST_ConveyorLayer;

```

## 5. 风险评估与缓解

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|:----:|----------|
| **FB接口不兼容** | FB需同步修改 | 高 | 渐进迁移，保留旧接口1~2个版本 |
| **OB1复杂度增加** | 映射逻辑变多 | 中 | 封装映射FC，如 `FC_MapIoToServoAxis()` |
| **数组索引越界** | 运行时错误 | 低 | 使用常量枚举 `#Z_AXIS := 1; #X1_AXIS := 2;` |
| **过度工程** | 结构体嵌套过深 | 低 | 控制嵌套层数≤3层，提供扁平访问别名 |
| **Siemens LSP不支持UDT** | 编译错误 | 低 | 先验证LSP对TYPE...END_TYPE的支持 |

## 7. 待决策事项

在开始实施前，需要您确认以下问题：

### ✋ 决策1：结构体存放位置

| 选项 | 说明 | 优缺点 |
|------|------|--------|
| **A. SysLib/types/** | 作为共享库的一部分 | ✅ 跨项目复用 ⚠️ 需要更新.plc.json |
| **B. 项目内 types/** | 仅在本项目使用 | ✅ 简单直接 ❌ 其他项目无法使用 |
| **C. 混合方案** | 基础类型放SysLib，项目特定类型放本地 | ✅ 平衡复用性与灵活性 |

**推荐**：选项 C（混合方案）

### ✋ 决策2：是否同步重构FB接口

| 选项 | 说明 | 工作量 |
|------|------|:------:|
| **A. 仅DB1重构** | 只改GlobalVars.db结构，FB接口保持散装参数 | 小 (2天) |
| **B. DB1 + FB同步重构** | FB也改为接受结构体参数 | 大 (5天) |
| **C. 分阶段** | 先DB1，后续迭代再改FB | 中 (3+3天) |

**推荐**：选项 C（先DB1让结构体落地验证，再推动FB改造）
