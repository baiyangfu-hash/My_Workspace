## 5. 变更内容

### 5.1 变更前（当前状态）

| 项目 | 当前值/描述 |
|------|-----------|
| FB_1004 轴控架构 | 间接请求模式：通过 GlobalVars 中转 q_bX2Req + q_rTargetPos，未使用 VAR_IN_OUT |
| 安全门信号管理 | FB_ExternalDeviceInteraction 未连接安全门 X140-X147 到各工站 FB |
| FB_1003 诊断输出 | q_bX1Fault/q_bZFault/q_bX2Fault 等诊断位未接入 GlobalVars |
| 文档状态机步数 | 部分 PRD 文档描述的步数与实际 .scl 代码不一致 |
| 版本号体系 | 6个 FB 各自独立版本号（V2.1.1~V10.0.1），与项目版本 V7.1.1 无关联 |

### 5.2 变更后（目标状态）

| 项目 | 目标值/描述 |
|------|-----------|
| FB_1004 轴控架构 | 升级为 VAR_IN_OUT 直连模式，与 FB_1003 架构统一，通过 `io_stX2Axis: ST_ServoAxis` 直接操作 PLCopen 接口 |
| 安全门信号管理 | FB_ExternalDeviceInteraction 输出 q_bSafetyDoorClosed 汇总信号，OB1 传递给各工站 FB |
| FB_1003 诊断输出 | 新增 q_bX1Fault/q_bZFault/q_bX2Fault 连接到 GlobalVars.stPickPlace |
| 文档状态机步数 | 逐份核对 PRD 文档与 .scl 源码，修正步数描述不一致处 |
| 版本号体系 | 保持 FB 独立版本号（符合 SCL 惯例），但确保 .plc.json 和 .copier-answers.yml 统一为最新版本 |

## 12. 附录

### 12.1 填写指南

#### 如何选择技术领域?
- 主要改哪个专业的交付物,就选哪个领域
- 如果同时涉及多个专业,选**最主要**的那个作为主领域,其他在§6.2中标注

#### 如何判断影响范围?
- **LOCAL**: 改一个变量/一行代码/一个接线端子
- **MODULE**: 改一个FB/一条输送线/一台设备
- **SYSTEM**: 改全局变量/联锁逻辑/通讯接口
- **CROSS**: 改了电气,PLC和HMI都要跟着改
- **SAFE**: 动了急停回路/安全继电器/SIL相关
