# 测试失败修复计划

## 1. 问题分析

### 1.1 错误现象

测试执行时出现 `panic: STUB BUILTIN: B_fbExternalDevice` 错误，所有测试用例失败。

### 1.2 根本原因

**功能块目录结构不兼容测试框架**：

| 项目 | 功能块目录 | 测试状态 |
|------|------------|----------|
| DJ-2026-000 | `FB100/`（单一目录） | ✅ 通过 |
| DJ-2026-005 | `external/`, `conveyor/`, `pickplace/`, `feeder/`, `common/`（多目录） | ❌ 失败 |

测试框架只扫描 `FB*/` 格式的目录，导致分散在其他目录的功能块无法被编译。

### 1.3 错误链路

```
测试运行 → OB1调用 fbExternalDevice → 找不到 FB_ExternalDeviceInteraction → panic
```

## 2. 修复方案

### 2.1 方案：集中功能块到统一目录

将所有功能块移动到 `FB*/` 格式的目录中，确保测试框架能够扫描到。

### 2.2 实施步骤

| 步骤 | 操作 | 文件 |
|------|------|------|
| 1 | 创建统一功能块目录 | `FB000/` |
| 2 | 移动外部设备交互功能块 | `external/FB_ExternalDeviceInteraction.scl` → `FB000/` |
| 3 | 移动输送机功能块 | `conveyor/FB_1001_Conveyor4Layer_BufferFraming.scl` → `FB000/` |
| 4 | 移动取放料功能块 | `pickplace/FB_1003_PickPlace_BufferFraming.scl` → `FB000/` |
| 5 | 移动公共报警功能块 | `common/FB_2001_CommonAlarm_AllStation.scl` → `FB000/` |
| 6 | 更新 OB1 中的功能块引用路径 | `OB1/OB1.scl` |
| 7 | 更新测试用例 | `Test/simple_test.scltest` |

### 2.3 风险评估

| 风险 | 级别 | 应对措施 |
|------|------|----------|
| 路径引用错误 | 中 | 更新 OB1 时仔细检查所有功能块实例化 |
| 文档失效 | 低 | 更新相关文档中的路径引用 |

## 3. 预期结果

修复后测试应全部通过，验证功能块能够被正确编译和调用。

## 4. 验证步骤

1. 运行测试用例 `simple_test.scltest`
2. 验证所有测试用例通过
3. 验证功能块调用正常
