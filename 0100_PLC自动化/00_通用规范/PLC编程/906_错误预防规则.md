# PLC 编程错误预防规则

> 版本: V1.0.0
> 状态: 已验证
> 更新日期: 2026-05-04
> 来源: DJ-2026-005 项目实战经验

## 1. 定时器使用错误预防

### 规则 1.1: FB_TON 的 PT/ET 参数是 DINT 类型, 不是 TIME 类型
- 项目使用自定义 FB_TON(来自 SysLib 共享库), PT 和 ET 参数类型为 DINT(扫描周期数)
- 禁止使用 TIME 类型字面量(如 T#0ms, T#500ms)赋给 PT 参数
- 禁止将 ET 输出声明为 TIME 类型, 必须声明为 DINT 类型

错误示例:
```scl
fb_tActionTimer(IN := FALSE, PT := T#0ms, Q => s_bQ, ET => q_eElapsed);  // T#0ms 是 TIME 类型
q_eElapsed : TIME;  // ET 应该是 DINT 类型
```

正确示例:
```scl
fb_tActionTimer(IN := FALSE, PT := 0, Q => s_bQ, ET => q_eElapsed);  // 0 是 DINT 类型
q_eElapsed : DINT;  // ET 使用 DINT 类型
```

### 规则 1.2: 定时器调用必须包含所有参数, Q 参数不能省略
- FB_TON 调用时, IN/PT/Q/ET 四个参数都必须指定
- Q 参数必须指定接收变量, 不能使用 `Q => ,` 空参数语法
- 需要在 VAR 区域预先声明 Q 输出的接收变量

错误示例:
```scl
fb_tActionTimer(IN := TRUE, PT := 500, Q => , ET => q_eElapsed);  // Q 参数为空
```

正确示例:
```scl
// VAR 区域声明
s_bActionTimer_Q : BOOL;

// 调用时指定 Q 接收变量
fb_tActionTimer(IN := TRUE, PT := 500, Q => s_bActionTimer_Q, ET => q_eElapsed);
```

### 规则 1.3: 复位定时器使用 DINT 零值, 不使用 TIME 字面量
- 复位/停止定时器时, PT 参数使用 `0`(DINT 零值), 不使用 `T#0ms`

错误示例:
```scl
fb_tActionTimer(IN := FALSE, PT := T#0ms, Q => s_bQ, ET => q_eElapsed);
```

正确示例:
```scl
fb_tActionTimer(IN := FALSE, PT := 0, Q => s_bQ, ET => q_eElapsed);
```

## 2. 自动生成文件保护

### 规则 2.1: 禁止修改 .plc-out 目录下的自动生成文件
- `.plc-out/golang/` 目录下的所有 Go 文件是由 Siemens LSP 插件自动生成的
- 修改这些文件无法解决根本问题, 下次编译会被覆盖
- 测试失败或运行时错误应从 SCL 源码层面解决

错误做法:
- 直接修改 `.plc-out/golang/builtins/b_fb_ton.go` 来实现 TON 定时器
- 修改 `.plc-out/golang/builtins/stub_support.go` 来跳过 stub 错误

正确做法:
- 检查 SCL 源码中的定时器调用是否符合 FB_TON 的接口规范
- 检查 .plc.json 是否正确配置了 libraryDirectories
- 确保 SysLib 共享库中的 FB_TON 定义可被 LSP 正确解析

## 3. 项目配置检查

### 规则 3.1: .plc.json 必须配置 libraryDirectories
- 如果项目使用了 SysLib 共享库中的功能块(如 FB_TON), 必须在 .plc.json 中配置 libraryDirectories
- libraryDirectories 使用相对于项目根目录的相对路径

错误示例:
```json
{
  "name": "DJ-2026-005",
  "description": "边框缓存机 PLC 控制系统",
  "version": "V5.0.0"
}
```

正确示例:
```json
{
  "name": "DJ-2026-005",
  "description": "边框缓存机 PLC 控制系统",
  "version": "V5.0.0",
  "libraryDirectories": [
    "../01_SharedLibraries/SysLib"
  ]
}
```

## 4. METHOD 命名规范

### 规则 4.1: METHOD 名称不使用 CALL_ 前缀
- METHOD 定义时, 名称直接使用功能描述, 不加 CALL_ 前缀
- METHOD 调用时, 直接使用方法名加括号

错误示例:
```scl
METHOD CALL_AutoModeStateMachine : VOID
    // ...
END_METHOD

// 调用
CALL_AutoModeStateMachine();
```

正确示例:
```scl
METHOD AutoModeStateMachine : VOID
    // ...
END_METHOD

// 调用
AutoModeStateMachine();
```

## 5. 类型转换限制

### 规则 5.1: 禁止 INT 直接赋值给 TIME 变量
- SCL 不支持 INT → TIME 隐式转换
- 如需记录已过时间, 使用 DINT 类型存储毫秒值或扫描周期数

错误示例:
```scl
tElapsed := iCounter;           // INT → TIME 隐式转换, 编译错误
tElapsed := iCounter * T#1ms;   // INT × TIME 运算, 不支持
```

正确示例:
```scl
diElapsed_ms := iCounter * 10;  // DINT 存储毫秒值(扫描周期 × 10ms)
```

### 规则 5.2: 禁止 TIME 字面量赋给 DINT 参数
- FB_TON 的 PT 参数是 DINT 类型, 不能接受 TIME 字面量

错误示例:
```scl
fb_tTimer(IN := TRUE, PT := T#500ms, Q => bQ, ET => diET);  // T#500ms 是 TIME 类型
```

正确示例:
```scl
fb_tTimer(IN := TRUE, PT := 500, Q => bQ, ET => diET);  // 500 是 DINT 类型(扫描周期数)
```

## 6. 代码修改前检查清单

在修改任何 PLC SCL 代码之前, 必须逐项检查:

- [ ] 是否已阅读 903_定时器使用规范?
- [ ] 定时器调用是否使用 FB_TON(不是标准 TON)?
- [ ] PT 参数是否为 DINT 类型(不是 TIME)?
- [ ] ET 输出变量是否为 DINT 类型(不是 TIME)?
- [ ] Q 参数是否指定了接收变量(不是空参数)?
- [ ] 是否在修改 .plc-out 自动生成文件?(如果是, 立即停止)
- [ ] .plc.json 是否配置了 libraryDirectories?
- [ ] METHOD 名称是否使用了 CALL_ 前缀?(如果是, 移除前缀)
- [ ] 是否有 INT → TIME 的隐式转换?(如果有, 改用 DINT)
