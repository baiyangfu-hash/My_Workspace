## 变更管理流程

### 7步变更管理流程

1. **变更提出阶段**：
   - 确认变更触发源（需求方提出/执行方主动提出）
   - 明确变更的目标、范围和预期效果
   - 生成变更需求文件，存储在 `02_变更需求/` 目录

2. **需求分析阶段**：
   - 执行方分析变更需求
   - 进行需求拆解，评估变更的影响范围、风险和成本
   - 制定详细的实施方案
   - 更新变更需求文件

3. **方案确认阶段**：
   - 执行方向需求方提交需求分析和实施方案
   - 需求方审核方案，确认变更的必要性和可行性
   - 更新变更需求文件

4. **变更单生成阶段**：
   - 执行方根据确认的方案生成变更单
   - 变更单包含变更范围、详细内容、实施计划、验收标准等
   - 存储变更单文件在 `01_变更单/` 目录

5. **变更实施阶段**：
   - 执行方按照变更单实施变更
   - 更新相关文档和代码
   - 记录变更过程和结果
   - 生成变更实施记录，存储在 `04_变更实施/` 目录

6. **变更验收阶段**：
   - 执行方完成变更后，向需求方申请验收
   - 需求方进行变更验收，验证变更效果
   - 生成变更验收记录，存储在 `05_变更验收/` 目录

7. **变更归档阶段**：
   - 执行方更新变更台帐
   - 记录变更结果，归档变更单和相关文档
   - 输出变更总结报告
   - 生成变更归档记录，存储在 `06_变更归档/` 目录
   - 更新 `03_变更记录/版本变更台帐.md`

## 变更类型定义

| 变更类型 | 说明 | 示例 |
|----------|------|------|
| ADD | 新增 | 新增功能块、新增变量、新增文档 |
| OPT | 优化 | 优化程序逻辑、优化变量命名、优化文档结构 |
| BUG | 修复 | 修复程序BUG、修复变量错误、修复文档错误 |
| DEL | 删除 | 删除冗余功能块、删除废弃变量、删除过期文档 |
| RECON | 重构 | 重构程序架构、重构变量表结构、重构文档体系 |
