## 1. 总则

### 1.1 目的

为了统一PLC变量命名规范，提高代码可读性和可维护性，特制定本规则。

### 1.2 适用范围

本规范适用于所有PLC编程系统，包括Autoshop、Work3等，确保跨系统的命名一致性。

### 1.3 核心原则

1. **可读性**：变量名应清晰表达其用途和含义
2. **一致性**：在整个项目中使用一致的命名风格
3. **简洁性**：在保证可读性的前提下，变量名应尽可能简洁
4. **避免歧义**：变量名应避免使用容易引起歧义的词汇

## 2. 变量命名规范

### 2.1 变量命名规则

#### 2.1.1 FB，FC等功能块输入变量

- **命名格式**：`i_变量类型_变量描述`
- **示例**：`i_bStartButton`（启动按钮信号）

#### 2.1.2 FB，FC输出变量

- **命名格式**：`q_变量类型_变量描述`
- **示例**：`q_bMotorRun`（电机运行输出）

#### 2.1.3 FB，FC等功能块输入输出变量

- **命名格式**：`iq_变量类型_变量描述`
- **示例**：`iq_bMotorRun`（电机运行双向信号）

#### 2.1.4 内部变量

- **命名格式**：`变量类型_变量描述`
- **示例**：`bRunning`（运行状态内部变量）

#### 2.1.5 全局变量

- **命名格式**：`变量类型_变量描述`
- **示例**：`bSysAutoMode`（系统自动模式全局变量）

#### 2.1.6 上升沿/下降沿检测变量

- **命名格式**：`LDP_变量类型_变量描述`（上升沿）或 `LDF_变量类型_变量描述`（下降沿）
- **示例**：`LDP_bStart`（启动信号上升沿）或 `LDF_bStop`（停止信号下降沿）

#### 2.1.7 硬件IO变量

- **命名格式**：`In_变量类型_变量描述`（输入）或 `Out_变量类型_变量描述`（输出）
- **示例**：`In_bStartButton`（启动按钮硬件输入）或 `Out_bMotorRun`（电机运行硬件输出）

### 2.2 变量类型前缀

| 变量类型 | 前缀 | 示例                                    |
| ---- | -- | ------------------------------------- |
| 布尔型  | b  | `bStart`, `bStop`, `bAlarm`           |
| 整数型  | i  | `iSpeed`, `iCount`, `iTemperature`    |
| 长整数型 | li | `liSpeed`, `liCount`, `liTemperature` |
| 实数型  | r  | `rPressure`, `rFlow`, `rLevel`        |
| 字符串型 | s  | `sProductName`, `sRecipeID`           |
| 浮点数型 | f  | `fPressure`, `fFlow`, `fLevel`        |
| 数组   | a  | `aMotorSpeed[3]`, `aSensorData[10]`   |

### 2.3 常量命名

- 常量名应使用全大写字母，单词之间用下划线分隔
- 示例：`MAX_SPEED`, `MIN_TEMPERATURE`, `DEFAULT_PRESSURE`

## 3. 功能块命名规范

### 3.1 功能块命名格式

- **命名格式**：`FB_编号_英文功能描述_设备对象`
- **示例**：`FB_1001_ConveyorControl_BeltConveyor`（皮带输送机启停控制）

### 3.2 输入输出变量前缀规范

#### 3.2.1 输入变量前缀 (VAR_INPUT)

| 前缀格式 | 适用范围 | 示例 | 说明 |
|----------|----------|------|------|
| `i_` + 变量类型 + `_` + 功能描述 | 标准输入变量 | `i_bStartButton`, `i_iSpeedSetpoint` | FB/FC的标准输入参数 |
| `i_b` + `Lx_` + 功能描述 | HMI手动操作缓存变量（从M区读取后传给FB） | `i_bLx_阻挡下降`, `i_bLx_输送正转` | Lx = Logic auxiliary（逻辑辅助），用于区分直接DI映射的输入变量与经主程序缓存后的HMI操作变量 |

> **HMI辅助缓存变量特殊说明**：当主程序从M区（HMI辅助控制区）读取手动操作信号后，需缓存为中间变量再传给功能块时，使用 `i_bLx_` 前缀。其中 `Lx` 表示"联锁/逻辑辅助"(Logic auxiliary)，用于与直接DI映射的输入变量做视觉区分。

#### 3.2.2 输出变量前缀 (VAR_OUTPUT)

| 前缀格式 | 适用范围 | 示例 | 说明 |
|----------|----------|------|------|
| `q_` + 变量类型 + `_` + 功能描述 | 标准输出变量 | `q_bMotorRun`, `q_rCurrentPosition` | FB/FC的标准输出参数 |

### 3.3 功能块编号规则

#### 3.3.1 基础控制模块

- **编号区间**：0100-1999
- **说明**：按工作流内功能优先级编排（如先启停、再调节、后报警）
- **唯一性**：同一工作流内编号唯一，跨工作流可重复（通过工作流编号区分）

#### 3.3.2 主控模块

- **编号区间**：2000-2999
- **说明**：主控层 FB（总调度 / 全局监控 / 模式切换）
- **唯一性**：同一项目内编号唯一，跨项目可重复（通过项目号区分）

### 3.4 功能块命名示例

#### 工作流功能块示例：

- `FB_1001_ConveyorControl_BeltConveyor`（皮带输送机启停控制）
- `FB_1002_SpeedRegulation_VFDMainConveyor`（主输送线变频无级调速）
- `FB_1001_GraspControl_EndEffectorGripper`（机械臂末端夹爪开合控制）
- `FB_1001_DataAcquisition_SlaveDevice`（从站设备状态采集上传）
- `FB_1002_CommandIssuance_Actuator`（执行机构运行参数指令下发）

#### 主控层功能块示例：

- `FB_2000_MainDispatch_AllEquipment`（全设备工作流调度+模式切换）
- `FB_2001_MainStatusMonitor_AllStation`（全局状态监控+故障汇总）
- `FB_2002_MainModeSwitch_OperationMode`（手动/自动/调试模式切换）

## 4. 注释规范

### 4.1 变量注释

- 所有变量都应添加注释，说明其用途和含义
- 注释应简洁明了，避免冗余
- 对于复杂变量，应详细说明其使用方法和注意事项

### 4.2 功能块注释

- 功能块应包含头部注释，说明功能、版本、输入输出变量等信息
- 注释应包含变更记录，便于追踪历史修改

### 4.3 SCL/ST 语言注释风格指南（DEV-V1.0.4 新增）

#### 4.3.1 注释格式选择

PLC 编程支持多种注释风格，应根据场景合理选择：

| 注释格式 | 适用场景 | 兼容性 | 推荐度 |
|----------|----------|--------|--------|
| `(* *)` 块注释 | 文件头、段落分隔、多行说明 | IEC 61131-3 标准，全平台兼容 | ⭐⭐⭐⭐⭐ 强制 |
| `//` 单行注释 | 行内简短注释、变量说明 | SCL/ST 专用，简洁明了 | ⭐⭐⭐⭐ 推荐 |

**强制性规则**：
- ✅ **文件头注释必须使用 `(* *)` 块注释格式**
- ✅ **逻辑段落分隔必须使用 `(* ==== 段落名 ==== *)` 格式**
- ✅ **变量声明后的注释可使用 `(* *)` 或 `//`（保持一致）**
- ✅ **行内逻辑说明推荐使用 `//`（SCL语言简洁性）**

#### 4.3.2 标准文件头模板

每个 FB/FC/PRG 必须包含以下标准文件头：


#### 4.3.3 内部变量前缀使用规则

**禁止使用的非标准前缀**：

| 前缀 | 问题 | 正确做法 |
|------|------|----------|
| `tmp_` | 增加阅读噪音，无语义价值 | 直接使用有意义的业务前缀（见§2.2）|
| `temp_` | 同上 | 仅在方法内部临时计算时使用 |

**正确示例**：

```pascal
VAR
    (* ❌ 错误：使用 tmp_ 前缀 *)
    (* tmp_bManualMode : BOOL := FALSE; *)

    (* ✅ 正确：直接使用业务前缀 *)
    bManualMode : BOOL := FALSE;          (* 手动模式标志 *)
    bAutoMode : BOOL := FALSE;            (* 自动模式标志 *)
    nCurrentMode : INT := 0;              (* 当前运行模式 *)
END_VAR
```

**特殊场景变量命名**（DEV-V1.0.5 优化）：

| 变量类型 | 命名格式 | 示例 | 字符数 | 说明 |
|----------|----------|------|--------|------|
| 启停请求标志 | `bXxxRequested` | `bStartRequested`, `bStopRequested` | 15 | 驼峰式，表示内部请求状态 |
| **定时器输入** | **`tIn`** | **`tIn[0..2]`** | **5** | **t=Timer, In=输入 (推荐)** |
| **定时器输出** | **`tQ`** | **`tQ[0..2]`** | **4** | **Q=输出完成 (推荐)** |
| **定时器复位** | **`tR`** | **`tR[0..2]`** | **4** | **R=复位信号 (推荐)** |
| **定时器预设值** | **`tPt`** | **`tPt[0..2]`** | **5** | **Pt=Preset预设值 (推荐)** |
| **定时器当前值** | **`tEt`** | **`tEt[0..2]`** | **5** | **Et=Elapsed当前值 (推荐)** |
| 定时器输入(旧) | `abTimerIn` | `abTimerIn[0..2]` | 11 | 旧版兼容，不推荐新项目使用 |
| 边沿检测实例 | `trigXxxRise/Fall` | `trigStartRise`, `trigStopFall` | 16 | R_TRIG/F_TRIG 实例名 |
| **计数器执行条件** | **`cCoil`** | **`cCoil[0..1]`** | **7** | **c=Counter, Coil=执行条件 (三菱FX5风格)** |
| **计数器设定值** | **`cPreset`** | **`cPreset[0..1]`** | **10** | **Preset=设定值** |
| **计数器初始/当前值** | **`cValue`** | **`cValueIn/cValueOut`** | **10-13** | **ValueIn=初始值, ValueOut=当前值** |
| **计数器状态输出** | **`cStatus`** | **`cStatus[0..1]`** | **9** | **Status=输出状态** |

> **命名优化说明 (V1.0.5更新)**：
> - 定时器数组命名从 `abTimerXxXxx`(9~12字符) 简化为 `tXxx`(4~5字符)，减少50%+长度
> - 采用**单字母前缀+功能后缀**模式：`t`=Timer, `c`=Counter，简洁且语义明确
> - 后缀采用**驼峰首字母大写**：`In/Q/R/Pt/Et` 对应 TONR/TON 的标准接口名
> - 旧版 `abTimerXx` 格式仍可识别，但新项目应优先使用简化版

#### 4.3.4 逻辑段落分隔标准

FB 内部的主要逻辑段应使用统一的分隔注释：

```pascal
(* ==================== 定时器调用段 ==================== *)
TONR(...);

(* ==================== 变量初始化段 ==================== *)
IF ... THEN
    ...
END_IF;

(* ==================== 模式切换段 ==================== *)
CASE ... OF
    ...
END_CASE;

(* ==================== 输出赋值段 ==================== *)
q_bOutput := bInternalState;
```

**常用段落名称建议**：
- 定时器调用段 / 变量初始化段 / 输入参数验证段
- 模式切换段 / 状态机执行段 / 启停控制段
- 报警管理段 / 故障处理段 / 安全互锁段
- 状态字计算段 / 输出赋值段 / 参数更新段

## 附录 D：IDE 工具兼容性注意事项

### D.1 中文标识符支持现状

| IDE/工具 | 中文标识符支持 | 备注 |
|----------|---------------|------|
| 博图(TIA Portal) | ✅ 完全支持 | 西门子官方IDE |
| Autoshop | ✅ 完全支持 | 欧姆龙官方IDE |
| Work3 | ✅ 完全支持 | 三菱官方IDE |
| Codesys | ✅ 完全支持 | IEC 61131-3 标准环境 |
| Dynamic Siemens Language Support(VS Code插件) | ⚠️ 部分支持 | FUNCTION_BLOCK 类型中中文标识符可能触发 TC001 误报 |
| 其他第三方LSP/编辑器 | ❓ 视具体实现而定 | |

### D.2 推荐做法

1. **变量名和功能块名**：优先使用英文或拼音标识符（如 `bStartButton`, `FB_1001_Conveyor4Layer_BufferFraming`）
2. **注释和文档**：鼓励使用中文，提高可读性
3. **项目决策**：若团队统一使用博图等官方IDE开发，可放宽此限制；若使用VS Code+第三方LSP开发，建议遵循英文标识符原则
4. **已有项目**：已使用中文标识符的项目无需强制重构，但新项目建议采用英文标识符

### D.3 LSP误报处理指南

当使用 Dynamic Siemens Language Support 等 VS Code 插件遇到 TC001 "undeclared symbol" 误报时：

1. 确认变量已在 VAR 区域正确声明
2. 检查拼写是否完全一致（含全角/半角字符）
3. 若确认为中文标识符导致的误报，可安全忽略该错误
4. 最终编译以实际PLC编程软件（博图/Autoshop/Work3）为准

### E.2 详细检查流程

#### Step 1: 文件头检查
```
□ 文件头使用 (* *) 块注释格式
□ 包含功能块名称（符合§3.1格式）
□ 包含功能描述（一句话说明核心功能）
□ 包含创建日期和版本号
□ 包含编制人和审核人
□ 包含遵循的规范列表及版本号
□ 包含变更记录（最新版本在前）
```

#### Step 2: 变量声明检查
```
VAR_INPUT 区域：
  □ 所有变量以 i_ 开头
  □ 类型前缀正确（b/i/r/s等）
  □ 每个变量有 (* 注释 *) 说明用途
  □ 无 tmp_ 或其他非标准前缀

VAR_OUTPUT 区域：
  □ 所有变量以 q_ 开头
  □ 类型前缀正确
  □ 每个变量有注释

VAR_IN_OUT 区域（如有）：
  □ 双向参数命名清晰

VAR 区域（内部变量）：
  □ 无 i_/q_ 前缀（仅用于接口）
  □ 使用有意义的业务前缀
  □ 无 tmp_ 前缀
  □ 特殊变量（定时器数组、请求标志）符合§4.3.3规范
```

#### Step 3: 代码一致性检查
```
□ VAR 中声明的所有变量在代码中都有使用（无死代码）
□ 代码中使用的所有变量都在 VAR 中已声明（无未声明变量）
□ 变量名拼写完全一致（区分大小写）
□ 无硬编码的魔法数字（应使用常量或参数化）
```

#### Step 4: 注释质量检查
```
□ 主要逻辑段有 (* ==== 段落名 ==== *) 分隔注释
□ 复杂算法有"为什么"的解释性注释（而非仅重复代码）
□ 状态字、模式值等枚举类型有清晰的位定义/值定义注释
□ 定时器数组有索引功能说明注释
□ 无注释掉的废代码（如被注释的旧VAR声明块）
```

### 7.1.4 定时器实例命名规范（DEV-V1.0.4 优化）

#### 7.1.4.1 IEC 61131-3 标准定时器成员简化映射表

基于项目实践经验，推荐使用简化后的成员访问方式，可减少约50%的字符输入量：

| 成员 | 标准写法 | 推荐简写 | 示例用法 | 字符节省 |
|------|---------|---------|---------|----------|
| `.IN` | `.IN` | `.tIn` | `s_tAction.tIn := TRUE` | 0 (相同长度) |
| `.Q` | `.Q` | `.tQ` | `IF s_tAction.tQ THEN` | -1 (更短) |
| `.R` | `.R` | `.tR` | `s_tAction.tR := TRUE` | 0 (相同长度) |
| `.PT` | `.PT` | `.tPt` | `s_tAction.tPt := T#3S` | -1 (更短) |
| `.ET` | `.ET` | `.tEt` | `nElapsed := s_tAction.tEt` | -1 (更短) |

> **使用说明**：
> - **标准写法**（`.IN`, `.Q` 等）：IEC 61131-3 标准定义的原始成员名，所有平台完全兼容
> - **推荐简写**（`.tIn`, `.tQ` 等）：基于驼峰扩展的语义化别名，增强可读性
> - 在实际项目中，两种写法均可使用；新项目**优先推荐简写形式**
> - 当使用结构体封装定时器实例时（如 `s_tAction`），简写形式的语义优势更加明显

#### 7.1.4.2 典型使用场景示例

```pascal
(* 场景1：动作延时执行 *)
VAR
    s_tActionDelay : TON;  (* 动作延时定时器 *)
END_VAR

(* 使用推荐简写方式 *)
s_tActionDelay.tIn := bStartCondition;
s_tActionDelay.tPt := T#3S;

IF s_tActionDelay.tQ THEN
    (* 延时到达，执行动作 *)
    q_bOutput := TRUE;
END_IF;

(* 获取已延时时间 *)
nElapsedTime := s_tActionDelay.tEt;
```

```pascal
(* 场景2：带复位的累积定时器 *)
VAR
    s_tAccumulate : TONR;  (* 累积定时器 *)
END_VAR

s_tAccumulate.tIn := bRunning;
s_tAccumulate.tPt := T#60S;

IF bResetCommand THEN
    s_tAccumulate.tR := TRUE;  (* 复位累积时间 *)
END_IF;

IF s_tAccumulate.tQ THEN
    (* 运行时间达到60秒 *)
    bTimeOver := TRUE;
END_IF;
```

### 7.1.5 计数器选型与命名指南（DEV-V1.0.5 新增）

#### 7.1.5.1 IEC 61131-3 标准计数器类型

| 类型 | 功能 | 典型应用 | 实例命名示例 |
|------|------|---------|-------------|
| CTU | 加计数器(上升沿计数) | 产品计数、循环计数 | ctProductCount, ctCycleNum |
| CTD | 减计数器(下降沿计数) | 批次倒计时、剩余量 | ctBatchRemain, ctDownCounter |
| CTUD | 加减计数器(双向计数) | 进出库统计、队列长度 | ctQueueLen, ctInOutDiff |

#### 7.1.5.2 三菱FX5系列 COUNTER_FB 使用示例(ST语言)

(* 三菱FX5系列推荐使用 FB_Counter_U/FB_Counter_D 替代传统C指令 *)
(* 基于 DJ-2026-005 边框缓存机项目验证 *)

```pascal
VAR
    (* 三菱FX5系列标准计数器功能块实例 *)
    ctProductCount : FB_Counter_U;     (* 加计数器实例 - 用于产品计数 *)
    ctBatchRemain  : FB_Counter_D;     (* 减计数器实例 - 用于批次倒计时 *)

    (* 接口变量 *)
    i_b产品检测信号 : BOOL;            (* 计数输入: 上升沿有效 *)
    i_b复位信号    : BOOL;             (* 复位输入 *)
    i_b减计数触发  : BOOL;             (* 减计数输入: 上升沿有效 *)

    (* 输出变量 *)
    nCurrentCount  : INT;              (* 当前计数值输出 *)
    nRemainCount   : INT;              (* 剩余计数值输出 *)
    nTargetCount   : INT := 100;       (* 目标数量设定 *)
END_VAR

(* ============================================ *)
(* 加计数器调用方式 - 产品计数场景               *)
(* ============================================ *)
ctProductCount(
    CU := i_b产品检测信号,     (* 计数输入: 上升沿有效 *)
    R  := i_b复位信号,          (* 复位输入: 清零当前值 *)
    CV => nCurrentCount         (* 当前计数值输出 => 表示赋值给变量 *)
);

(* 判断是否达到目标数量 *)
IF ctProductCount.Q AND (nCurrentCount >= nTargetCount) THEN
    (* 达到目标数量，触发相应逻辑 *)
    bTargetReached := TRUE;
ELSE
    bTargetReached := FALSE;
END_IF;

(* ============================================ *)
(* 减计数器调用方式 - 批次倒计时场景             *)
(* ============================================ *)
ctBatchRemain(
    CD := i_b减计数触发,      (* 减计数输入: 上升沿有效 *)
    LD := i_b复位信号,         (* 载入输入: 重新载入设定值 *)
    PV := nTargetCount,        (* 设定值输入: 初始计数值 *)
    CV => nRemainCount         (* 剩余计数值输出 *)
);

(* 判断批次是否完成 *)
IF ctBatchRemain.Q THEN
    (* 计数减至零，批次处理完成 *)
    bBatchComplete := TRUE;
END_IF;
```

#### 7.1.5.3 计数器命名最佳实践

| 命名元素 | 规范 | 示例 | 说明 |
|----------|------|------|------|
| 实例名前缀 | `ct` | `ctProductCount` | c=Counter, t=实例 |
| 加计数器类型 | `FB_Counter_U` | `ctUpCounter : FB_Counter_U` | U=Up (向上计数) |
| 减计数器类型 | `FB_Counter_D` | `ctDownCounter : FB_Counter_D` | D=Down (向下计数) |
| CU输入 | `CU := xxx` | 上升沿触发的计数信号 | Count Up input |
| CD输入 | `CD := xxx` | 上升沿触发的减数信号 | Count Down input |
| R/LD复位 | `R := xxx` / `LD := xxx` | 复位或重新载入 | Reset / Load |
| CV输出 | `CV => xxx` | 当前计数值输出 | Current Value |
| Q状态 | `ctXxx.Q` | 计数完成标志输出 | Status output |

> **重要提示**：
> - 三菱 FX5 系列的 `FB_Counter_U/D` 是功能块(Function Block)实例，必须先在 VAR 区域声明
> - 使用 `=>` 进行输出参数赋值（ST语言特性），区别于 `:=` 的输入参数赋值
> - `CU` 和 `CD` 都是**上升沿敏感**输入，无需额外使用 R_TRIG
> - 计数器的 `.Q` 输出在达到设定值(PV)时置位（CTU）或减至零时置位（CTD）

### 7.1.6 预处理与条件编译使用说明（DEV-V1.0.5 新增）

#### 7.1.6.1 IEC 61131-3 预处理指令概览

| 指令 | 语法 | 用途 | 典型应用场景 | 兼容性 |
|------|------|------|-------------|--------|
| {DEFINE} | `{DEFINE constant_name:=value}` | 定义编译时常量 | 调试开关、平台标识 | ⚠️ 部分IDE支持 |
| {IFDEF} | `{IFDEF constant_name}...{ENDIF}` | 条件编译（如果已定义） | 功能开关、代码裁剪 | ⚠️ 部分IDE支持 |
| {IFNDEF} | `{IFNDEF constant_name}...{ENDIF}` | 反向条件编译（如果未定义） | 默认实现、兼容处理 | ⚠️ 部分IDE支持 |
| {IF} | `{IF expression}...{ENDIF}` | 条件表达式编译 | 版本判断、复杂条件 | ❌ 极少支持 |

| **Work3 (三菱)** | ⚠️ 有限支持 | ⚠️ 有限支持 | ⚠️ 有限支持 | GX Works3 部分支持 |

> **兼容性提示**：预处理指令的支持程度因 IDE 而异。在使用前，请查阅目标平台的编程手册确认具体语法和支持情况。

#### 7.1.6.4 预处理使用最佳实践

| 实践项 | 建议 | 原因 |
|--------|------|------|
| 常量命名 | 使用大写下划线风格 | 与运行时常量区分，如 `DEBUG_MODE` vs `nDebugMode` |
| 条件嵌套 | 避免超过3层嵌套 | 保持代码可读性和可维护性 |
| 注释说明 | 每个 {IFDEF} 块添加用途注释 | 方便其他开发者理解条件编译意图 |
| 默认行为 | 提供 {IFNDEF} 默认分支 | 确保未定义时常量时代码仍可编译 |
| 版本管理 | 将 {DEFINE} 集中管理 | 建议单独文件或在文件头统一定义 |
| 测试验证 | 分别测试开启/关闭条件 | 确保两种路径下的代码都经过验证 |

#### 7.1.6.5 常见问题与解决方案

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 预处理指令被当作注释 | IDE不完全支持该指令 | 查阅目标IDE手册，改用运行时 IF 替代 |

| 条件编译代码仍被执行 | 缺少 {ENDIF} 或语法错误 | 检查配对完整性，确认语法符合目标IDE要求 |
