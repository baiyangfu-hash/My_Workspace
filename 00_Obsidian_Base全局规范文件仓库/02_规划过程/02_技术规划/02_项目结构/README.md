## 💡 选择建议

### 如何判断我的项目类型？

#### 问自己这些问题：

**Q1: 项目的主要输出是什么？**
- A: 可执行程序、Web 服务、API → **Python 软件项目**
- B: PLC 程序、HMI 画面、电气图纸、机器人程序 → **自动化工程项目**

**Q2: 项目使用的核心工具是什么？**
- A: VS Code/PyCharm、Git、Docker → **Python 软件项目**
- B: TIA Portal、Autoshop、ProFace、Eplan → **自动化工程项目**

**Q3: 项目的变更如何管理？**
- A: Git commit、Pull Request、Code Review → **Python 软件项目**
- B: 变更单申请、项目经理审批、台帐记录 → **自动化工程项目**

**Q4: 项目的交付物包含什么？**
- A: 源代码、测试报告、用户手册、部署包 → **Python 软件项目**
- B: PLC 程序、HMI 工程、IO 表、操作手册、验收报告 → **自动化工程项目**

---

### 特殊情况处理

#### 情况 1: 项目同时涉及两者
**示例**: 开发一个上位机系统，需要与 PLC 通讯

**建议**:
- 上位机部分：参考 `016_Python软件项目结构规范`
- 通讯接口部分：参考 `TPL-UPPER-STD-001` 模板
- 或直接使用 `TPL-UPPER-STD-001`（已包含完整的项目管理）

#### 情况 2: 不确定项目规模
**建议**:
- 先从**小型模板**开始（如 S001）
- 随着项目推进，按需补充中大型模板的模块
- 宁可开始简单，后续扩展；不要一开始就过度设计

#### 情况 3: 团队混合（软件 + 电气）
**建议**:
- 明确分工界面
- 软件工程师：遵循 Python 规范
- 电气工程师：遵循 TPL 模板
- 通过接口文档（`815_PLC接口文档`）协调

## ⚠️ 重要提醒

### 两个规范的关系
- ✅ **互补关系，不冲突**
- ✅ **适用于不同场景，不互相替代**
- ✅ **可以共存于同一公司/团队**

### 维护责任
- `016_Python软件项目结构规范`: 由**软件开发团队**维护
- `05_模板规范/TPL-*`: 由**电气工程团队**维护

### 使用原则
1. **根据项目类型选择合适的规范**
2. **不要混用两种规范的目录结构**
3. **保持团队内部的一致性**
4. **定期回顾和优化规范**
