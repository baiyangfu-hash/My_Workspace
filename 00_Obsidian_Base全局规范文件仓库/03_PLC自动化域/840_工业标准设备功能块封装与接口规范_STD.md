# STD-840: 工业标准设备功能块封装与接口规范

> **规范定位**：参考汽车制造行业标准（SICAR Standard Typical Libraries）与面向对象工业控制哲学，将所有物理执行元件（气缸、电机、伺服驱动器、机器人接口）100% 封装为标准典型功能块（Typical FBs）。
> **核心铁律**：**工艺状态机（大脑）只管调度，严禁亲自下场搬砖；执行对象（手脚）独立封装，只暴露纯净的命令与状态接口。**

---

## 1. 核心设计哲学：设备对象化解耦定律 (Device-as-an-Object Law)

### 1.1 概念定义与抽象边界
在 SCL 工业自动化控制程序中，**状态机功能块不是 PLC 底层硬件编译器**，不需要在状态机内部手写脉冲加减速、插补计算或寄存器地址换算。
- **工艺状态机（Caller）**：只负责将轴控、气缸、变频器视为**外部对象接口**——在相应工步发出命令输出（如 `Cmd.Execute := TRUE`、设定目标值），并等待对象反馈状态输入（如 `Sts.Done := TRUE`），收到输入后推进一步；
- **底层执行层（Callee）**：由真实的 PLC 硬件驱动块（如 Siemens `MC_MoveAbsolute`、Profidrive 通信报文、三菱轴定位模块）或仿真驱动统一消化。

```
┌────────────────────────────────────────────────────────┐
│               工艺状态机 FB (例如 FB_1003)              │
│  · Step N: 给出命令输出 io_stZAxis.stAbs.Execute:=TRUE  │
│  · Step N: 等待状态输入 IF io_stZAxis.stAbs.Done THEN  │
└───────────────────────────┬────────────────────────────┘
                            │ (标准结构体引用 VAR_IN_OUT)
┌───────────────────────────▼────────────────────────────┐
│              标准轴/气缸对象接口 (ST_ServoAxis)          │
│   stCmd (命令结构体: Position/Velocity/Execute)        │
│   stSts (状态结构体: Done/Busy/Error/ActPos)           │
└───────────────────────────┬────────────────────────────┘
                            │ (硬件适配层)
┌───────────────────────────▼────────────────────────────┐
│      底层驱动实现 (西门子 MC_ / 三菱专用 / 汇川 / 仿真)   │
└────────────────────────────────────────────────────────┘
```

## 2. 用户故事 (User Stories)

### 故事 1：现场电气工程师老李的痛点 —— *“为什么换个 PLC 品牌，我的工艺逻辑全废了？”*
- **背景**：老李在三菱 FX5U 上开发了一套边框分料机，梯形图里到处散落着 `DDRVI D514 D200 Y0 Y4`、专用脉冲完成标志 `M8029`，以及直接拉低线圈的 `SET Y30`；
- **痛点**：第二年客户要求将同一款机台移植到西门子 S7-1500。老李发现，因为工艺步进链和三菱的专有指令深度纠缠，整个程序必须全部推倒重写，稍微漏掉一个脉冲边沿就撞机；
- **解法（对象化解耦）**：老李将 Z 轴抽象为标准接口 `io_stZAxis`。在工艺步序里只写 `io_stZAxis.stAbs.Position := 514.0; io_stZAxis.stAbs.Execute := TRUE;`。在三菱下挂载三菱轴驱动，在西门子下挂载西门子轴驱动，**工艺状态机 100% 零修改，直接跨平台复用！**

### 故事 2：AI 协作中的灾难 —— *“AI 试图在 SCL 里自己‘造’一台伺服电机”*
- **背景**：某 AI 在编写打胶送料 `FB_1004` 时，发现需要控制 X2 轴，于是 AI 在 FB 内部自己写了一大堆寄存器计算和加减速模拟代码，甚至自己发明了 20 多个中间标志；
- **后果**：代码变得极其臃肿难懂，工艺时序完全被淹没在杂乱的底层代码中，更致命的是把真实的物理到时延时和干涉逻辑搞丢了；
- **规范约束**：AI 必须明白——**“你不是 PLC 固件编译器，你不需要去实现电机是怎么转的，你只需要给输出（命令），然后收输入（反馈）！”**

## 3. 具象化代码对比举例 (Concrete Examples)

### ❌ 错误示范：反模式（混杂底层专有逻辑，违背解耦原则）
```scl
// 错误写法：在工艺状态机里直接写底层控制字、专有标志或脑补伺服内部过程
CASE iCurrentState OF
    1: // 上升取料
        D510 := 514.0;        // 硬编码三菱寄存器
        Y000 := TRUE;         // 直接拉底层脉冲输出
        IF M8029 THEN         // 强依赖特定硬件完成标志
            M8029 := FALSE;
            iCurrentState := 2;
        END_IF;
END_CASE;
```

### ✅ 正确示范：标准规范（100% 对象接口化，工艺极度清晰）
```scl
// 正确写法：状态机只与轴接口对象交互 (命令输出 ➔ 状态输入 ➔ 状态转移)
CASE s_iCurrentState OF

    STEP_21_UP_TO_PICK: (* 1 - Z轴上升到取料高度 *)
        // 1. 给出命令输出
        IF s_bStepEntry THEN
            io_stZAxis.stAbs.Position  := s_rPickHeight; // 514.0mm
            io_stZAxis.stAbs.Velocity  := io_stPickPlace.i_rZSpeed;
            io_stZAxis.stAbs.Execute   := TRUE;          // 触发定位请求
            s_bStepEntry := FALSE;
        END_IF;

        // 2. 得到状态输入 (轴完成反馈)
        IF io_stZAxis.stAbs.Done THEN
            io_stZAxis.stAbs.Execute := FALSE;           // 复位请求
            s_bStepEntry := TRUE;
            s_iCurrentState := STEP_22_CLAMP_AND_DETECT; // 平稳推进一步

        // 3. 得到异常输入 (超时或伺服报警)
        ELSIF io_stZAxis.stAbs.Error THEN
            io_stZAxis.stAbs.Execute := FALSE;
            io_stZAxis.stStop.Execute := TRUE;           // 触发轴停止
            s_iAlarmCode := 75;                          // 伺服定位故障
            s_iCurrentState := STEP_20_IDLE;
        END_IF;

END_CASE;
```

## 4. 结构体整块传递契约 (Struct Chunk Passing)

所有典型功能块必须采用统一的 **`1 入 1 出` 强类型结构体引脚规范**（符合 LSP-905 §3.1 与 SysLib 统一标准）：

- **`i_stCmd : ST_<Device>Cmd`**：输入命令结构体（由上层步进链或 HMI 驱动）；
- **`q_stSts : ST_<Device>Sts`**：输出状态结构体（反馈给上层状态机或 HMI 展示）。

## 5. 核心典型功能块 (Typical FBs) 库规范

### 5.1 `FB_1011_CylinderControl` (双位置执行器/气缸典型块)
- **来源**：直接复用 `01_SharedLibraries/SysLib/actuator/FB_1011_CylinderControl/`
- **内建机制**：
  1. 单线圈弹簧复位 / 双线圈中封阀模式切换（`SolenoidType`）；
  2. 原位与动位双向限位防抖滤波（`DebounceTime`）；
  3. 动作超时看门狗监控（`TimeoutLimit`）；
  4. 防呆参数锁存：运动中（`Moving=TRUE`）参数锁定，防止参数跳变引起气缸误动作。

### 5.2 `FB_1020_AxisPos` (Profidrive 伺服轴控典型块)
- **来源**：`02_PLC程序/PLC_ST/01_Typical_Libraries/`
- **内建机制**：
  1. 伺服使能、绝对定位（`MoveAbsolute`）、相对定位与点动控制；
  2. 软件正负软限位防冲撞硬拦截（`SoftLimitPos` / `SoftLimitNeg`）；
  3. 毫秒级定位超时看门狗监控；
  4. 到位窗口容差计算与原点状态校验。

### 5.3 `FB_1012_ConveyorMotor` (输送线电机典型块)
- **来源**：直接复用 `01_SharedLibraries/SysLib/actuator/FB_1012_ConveyorMotor/`
- **内建机制**：启停延时、电机热过载保护互锁、正反转切换防死锁互锁。
