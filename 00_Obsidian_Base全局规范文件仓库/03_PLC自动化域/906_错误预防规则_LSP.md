# PLC 编程错误预防规则

> 版本: V2.1.0
> 状态: 已验证
> 更新日期: 2026-08-25
> 来源: DJ-2026-005 项目实战经验

## 1. 定时器使用错误预防 (FB_TON / FB_TONR)

### 规则 1.1: FB_TON 的 PT/ET 参数是 DINT 类型, 不是 TIME 类型
- 项目使用自定义 FB_TON(来自 SysLib 共享库), PT 和 ET 参数类型为 DINT(扫描周期数)
- 禁止使用 TIME 类型字面量(如 T#0ms, T#500ms)赋给 PT 参数
- 禁止将 ET 输出声明为 TIME 类型, 必须声明为 DINT 类型

错误示例:
```scl
fb_tActionTimer(IN := FALSE, PT := T#0ms, Q => s_bQ, ET => q_eElapsed);  // T#0ms 是 TIME 类型
q_eElapsed : TIME;  // ET 应该是 DINT 类型
```

正确示例:
```scl
fb_tActionTimer(IN := FALSE, PT := 0, Q => s_bQ, ET => q_eElapsed);  // 0 是 DINT 类型
q_eElapsed : DINT;  // ET 使用 DINT 类型
```

### 规则 1.2: 定时器调用必须包含所有参数, Q 参数不能省略
- FB_TON 调用时, IN/PT/Q/ET 四个参数都必须指定
- Q 参数必须指定接收变量, 不能使用 `Q => ,` 空参数语法
- 需要在 VAR 区域预先声明 Q 输出的接收变量

错误示例:
```scl
fb_tActionTimer(IN := TRUE, PT := 500, Q => , ET => q_eElapsed);  // Q 参数为空
```

正确示例:
```scl
// VAR 区域声明
s_bActionTimer_Q : BOOL;

// 调用时指定 Q 接收变量
fb_tActionTimer(IN := TRUE, PT := 500, Q => s_bActionTimer_Q, ET => q_eElapsed);
```

### 规则 1.3: 复位定时器使用 DINT 零值, 不使用 TIME 字面量
- 复位/停止定时器时, PT 参数使用 `0`(DINT 零值), 不使用 `T#0ms`

错误示例:
```scl
fb_tActionTimer(IN := FALSE, PT := T#0ms, Q => s_bQ, ET => q_eElapsed);
```

正确示例:
```scl
fb_tActionTimer(IN := FALSE, PT := 0, Q => s_bQ, ET => q_eElapsed);
```

### 规则 1.4: FB_TONR 的 PT/ET 参数是 DINT 类型, R 参数用于复位
- FB_TONR(保持型接通延时定时器)同样来自 SysLib 共享库, PT 和 ET 参数类型为 DINT(扫描周期数)
- FB_TONR 比 FB_TON 多一个 R(复位)输入参数, R=TRUE 时清零 ET 并复位 Q
- 禁止使用 TIME 类型字面量赋给 FB_TONR 的 PT 参数

错误示例:
```scl
fb_tTimeout(IN := TRUE, R := FALSE, PT := T#3000ms, Q => s_bQ, ET => q_eElapsed);  // T#3000ms 是 TIME 类型
```

正确示例:
```scl
fb_tTimeout(IN := TRUE, R := FALSE, PT := 3000, Q => s_bQ, ET => q_eElapsed);  // 3000 是 DINT 类型(扫描周期数)
```

### 规则 1.5: 定时器调用必须遵循三段式标准模式
- 所有 FB_TON / FB_TONR 调用必须遵循 **预赋值 → 全参数调用 → 读输出** 三段式(详见 903 §3.1)
- 禁止内联直接传值, 禁止裸调用

错误示例:
```scl
// 内联直接传值(禁止)
fb_tActionTimer(IN := TRUE, PT := 500, Q => s_bQ, ET => q_eElapsed);

// 裸调用(禁止)
fb_tActionTimer();
```

正确示例:
```scl
// Step 1: 预赋值
fb_tActionTimer.IN := TRUE;
fb_tActionTimer.PT := 500;

// Step 2: 全参数调用
fb_tActionTimer(IN := fb_tActionTimer.IN, PT := fb_tActionTimer.PT,
                 Q => fb_tActionTimer.Q, ET => fb_tActionTimer.ET);

// Step 3: 读输出
s_bActionDone := fb_tActionTimer.Q;
```

### 规则 1.6: 定时器必须在 FB 顶部无条件批量调用
- 所有 FB_TON / FB_TONR 的 `()` 调用必须集中在 FB 顶部一个连续的"定时器批量调用区"
- 该区域不能被任何 IF/ELSIF/ELSE/CASE 块包裹, 每周期必须执行全部定时器调用
- 定时器调用与业务逻辑解耦: 调用归调用, 参数归参数, 读值归读值

错误示例:
```scl
// 定时器调用放在 IF 分支内(禁止)
IF i_bStart THEN
    fb_tActionTimer(IN := fb_tActionTimer.IN, PT := fb_tActionTimer.PT,
                     Q => fb_tActionTimer.Q, ET => fb_tActionTimer.ET);
END_IF;
```

正确示例:
```scl
(* ==================== 定时器批量调用 (无条件, 每周期执行) ==================== *)
fb_tDebounceExt(IN := fb_tDebounceExt.IN, PT := fb_tDebounceExt.PT,
                 Q => fb_tDebounceExt.Q, ET => fb_tDebounceExt.ET);

fb_tTimeout(IN := fb_tTimeout.IN, R := fb_tTimeout.R, PT := fb_tTimeout.PT,
             Q => fb_tTimeout.Q, ET => fb_tTimeout.ET);

(* ==================== 以下业务逻辑: 只设 IN/PT/R, 只读 Q/ET ==================== *)
IF i_bStart THEN
    fb_tDebounceExt.IN := i_bSensor;       // 设参数, 不调用
    fb_tDebounceExt.PT := i_dDebounceMs;
    s_bDebounced := fb_tDebounceExt.Q;     // 读输出
END_IF;
```

## 2. 自动生成文件保护

### 规则 2.1: 禁止修改 .plc-out 目录下的自动生成文件
- `.plc-out/golang/` 目录下的所有 Go 文件是由 Siemens LSP 插件自动生成的
- 修改这些文件无法解决根本问题, 下次编译会被覆盖
- 测试失败或运行时错误应从 SCL 源码层面解决

错误做法:
- 直接修改 `.plc-out/golang/builtins/b_fb_ton.go` 来实现 TON 定时器
- 修改 `.plc-out/golang/builtins/stub_support.go` 来跳过 stub 错误

正确做法:
- 检查 SCL 源码中的定时器调用是否符合 FB_TON 的接口规范
- 检查 .plc.json 是否正确配置了 libraries
- 确保 SysLib 共享库中的 FB_TON 定义可被 LSP 正确解析

## 3. 项目配置检查

### 规则 3.1: .plc.json 必须配置 libraries
- 如果项目使用了 SysLib 共享库中的功能块(如 FB_TON, FB_TONR), 必须在 .plc.json 中配置 libraries
- libraries 使用相对于项目根目录的相对路径
- **注意: 字段名必须为 `libraries`, 不是 `libraryDirectories`(后者不是 Siemens LSP 的有效字段, 详见 907 §1.2)**

错误示例:
```json
{
  "name": "DJ-2026-005",
  "description": "边框缓存机 PLC 控制系统",
  "version": "V5.0.0"
}
```

正确示例:
```json
{
  "name": "DJ-2026-005",
  "description": "边框缓存机 PLC 控制系统",
  "version": "V5.0.0",
  "libraries": [
    "../01_SharedLibraries/SysLib"
  ]
}
```

## 4. METHOD 语法禁用

### 规则 4.1: 禁止使用 METHOD / METHODS / END_METHOD
- Siemens LSP 与本工作空间白名单均不支持 METHOD 语法
- 旧模板中出现的 `CALL_XXX`、`METHODS`、`END_METHODS` 均视为历史残留, 必须删除
- 需要拆分逻辑时:
  - 单个 FB 内的步序与模式分支 → 保留在 FB 主体 `CASE/IF` 中
  - 纯计算或无状态复用逻辑 → 提取为独立 `FC`
  - 带静态状态的子设备逻辑 → 提取为独立 `FB`

错误示例:
```scl
METHOD AutoModeStateMachine : VOID
    // ...
END_METHOD
```

正确示例:
```scl
CASE s_iStep OF
    0:
        // 初始化
    10:
        // 自动模式步序
ELSE
    s_iStep := 0;
END_CASE;
```

## 5. 类型转换限制

### 规则 5.1: 禁止 INT 直接赋值给 TIME 变量
- SCL 不支持 INT → TIME 隐式转换
- 如需记录已过时间, 使用 DINT 类型存储毫秒值或扫描周期数

错误示例:
```scl
tElapsed := iCounter;           // INT → TIME 隐式转换, 编译错误
tElapsed := iCounter * T#1ms;   // INT × TIME 运算, 不支持
```

正确示例:
```scl
diElapsed_ms := iCounter * 10;  // DINT 存储毫秒值(扫描周期 × 10ms)
```

### 规则 5.2: 禁止 TIME 字面量赋给 DINT 参数
- FB_TON 的 PT 参数是 DINT 类型, 不能接受 TIME 字面量

错误示例:
```scl
fb_tTimer(IN := TRUE, PT := T#500ms, Q => bQ, ET => diET);  // T#500ms 是 TIME 类型
```

正确示例:
```scl
fb_tTimer(IN := TRUE, PT := 500, Q => bQ, ET => diET);  // 500 是 DINT 类型(扫描周期数)
```

## 6. 代码修改前检查清单

在修改任何 PLC SCL 代码之前, 必须逐项检查:

- [ ] 是否已阅读 903_定时器使用规范?
- [ ] 定时器调用是否使用 FB_TON / FB_TONR(不是标准 TON)?
- [ ] PT 参数是否为 DINT 类型(不是 TIME)?
- [ ] ET 输出变量是否为 DINT 类型(不是 TIME)?
- [ ] Q 参数是否指定了接收变量(不是空参数)?
- [ ] FB_TONR 的 R 参数是否正确处理(复位时 R=TRUE)?
- [ ] 定时器调用是否遵循三段式(预赋值→全参数调用→读输出)?
- [ ] 定时器 `()` 调用是否集中在 FB 顶部无条件批量调用区?
- [ ] 是否在修改 .plc-out 自动生成文件?(如果是, 立即停止)
- [ ] .plc.json 是否配置了 libraries(不是 libraryDirectories)?
- [ ] 是否出现 METHOD / METHODS / END_METHOD 残留?(如果是, 删除并改为 FB 主体或独立 FC/FB)
- [ ] 是否有 INT → TIME 的隐式转换?(如果有, 改用 DINT)
