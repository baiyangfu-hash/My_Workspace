## 3. 检查清单总览

### 3.1 适用范围

本检查清单适用于 `00_Obsidian_Base全局规范文件仓库` 中所有规范文件的发布前审查和发布后验证，确保每份规范在正式生效前满足完整性、合规性和一致性要求。

### 3.2 使用说明

- **必查项（A类）**：全部勾选通过后方可发布，任一不通过即退回修改
- **验证项（B类）**：发布后执行的功能性验证，发现问题需立即回滚修复
- **参考项（C类）**：快速参考卡和工具命令，供日常操作查阅

## 4. A. 发布前必查项（全部通过方可发布）

### 4.1 A.1 基础信息完整性

> 核查目标：确保文档元数据完整、准确、可追溯。

| 序号 | 检查项 | 通过标准 | 检查方法 |
|------|--------|----------|----------|
| A1-01 | 文档标题 | 清晰准确，反映文档实质内容 | 目视确认 |
| A1-02 | 文档版本号 | 遵循语义化版本 `V MAJOR.MINOR.PATCH` 格式 | 正则匹配 |
| A1-03 | 编制日期 | `YYYY-MM-DD` 格式，与实际完成日期一致 | 格式校验 |
| A1-04 | 编制人 | 已填写真实姓名（非占位符如 `[姓名]` 或 `待填写`） | 内容核查 |
| A1-05 | 审核人 | 已填写或明确标注 `[待审核]` | 内容核查 |
| A1-06 | 遵循规范 | 列出了所有引用的相关规范及版本号 | 交叉核对 |

### 4.2 A.2 结构合规性

> 核查目标：确保文档结构符合 050_模板结构规范_TPL 约定的标准结构（该幽灵模板已按 CHG-SPEC-2026-001 除名，结构要求内联为下方 A2 类检查项）。

| 序号 | 检查项 | 通过标准 | 检查方法 |
|------|--------|----------|----------|
| A2-01 | 包含「文档基础信息」章节 | 遵循050模板规范的标准7字段表格格式 | 结构扫描 |
| A2-02 | 包含「版本变更记录」章节 | 采用5列标准表格（版本号/变更内容/变更人/变更日期/详细说明） | 结构扫描 |
| A2-03 | 标题层级正确 | 严格按 `#` → `##` → `###` → `####` 层级递进，无跳跃 | 层级遍历 |
| A2-04 | 章节编号连续无跳跃 | 一级章节编号连续（如 1, 2, 3...），子章节编号连续 | 编号校验 |

## 6. C. 快速参考卡

### 6.1 规范更新SOP（标准操作流程）

```
1. Read   -> 读取原文件完整内容，理解现有结构和上下文
2. Edit   -> SearchReplace 原地修改（严格禁止 Write 新建文件！）
3. Ver    -> 更新版本号 + 追加变更记录行到版本变更记录表
4. Check  -> Grep 全仓库验证无旧版残留 + 所有引用链接有效
5. Archive -> 将旧版文件移入 _archive/YYYY-MM-DD_操作描述/ 目录
6. Notify -> 通知相关人员规范已更新（含版本号和变更摘要）
```

### 6.2 常见错误预防

| 错误现象 | 根因分析 | 预防措施 | 对应SOP步骤 |
|----------|----------|----------|-------------|
| 新旧版本共存 | 使用 Write 新建文件而非 SearchReplace 编辑原文件 | 强制要求第2步使用 SearchReplace | Step 2 |
| 引用链接404 | 更新了被引用文件的文件名但未同步更新所有引用方 | 第4步 Grep 全仓库搜索旧文件名并批量替换 | Step 4 |
| 目录分裂 | 在错误的目录路径下创建了副本而非编辑原文件 | 操作前确认唯一正确路径，禁止自行创建新目录 | Step 1 |
| 冲突文件遗留 | 并发编辑时 Obsidian 生成的 `_conflict` 文件未清理 | 发布前扫描并删除所有 `_conflict` 后缀文件 | Step 5 |
| 版本号未递增 | 直接修改内容后忘记更新版本号字段和变更记录 | 第3步强制要求同步更新三处：文件名、基础信息表、变更记录表 | Step 3 |
| 归档遗漏 | 发布新版后未将旧版移入归档目录导致新旧并存 | 第5步强制归档，归档目录含日期和操作描述便于追溯 | Step 5 |

## 7. 附录: 检查工具命令

### 7.1 旧版本号残留搜索

```bash
# 在规范仓库根目录下搜索指定旧版本号残留
# 用法：将 V1\.0\.0 替换为你要排查的具体旧版本号
grep -r "V1\.0\.0\|V1\.1\.0" --include="*.md" .
```

### 7.2 损坏链接检测

```bash
# 检查所有 Markdown 链接的目标文件是否存在
grep -r "\[.*\](.*\.md)" --include="*.md" . | while read line; do
  target=$(echo "$line" | grep -oP '\(\K[^)]+')
  test -f "$target" || echo "BROKEN: $line"
done
```

### 7.3 冲突文件扫描

```bash
# 扫描所有 Obsidian 冲突文件
find . -name "*_conflict*" -type f

# 统计冲突文件数量
find . -name "*_conflict*" -type f | wc -l
```

### 7.4 版本号格式校验

```bash
# 校验所有 .md 文件的文件名是否符合命名格式（不含版本号）
find . -name "*.md" -type f | grep -v "_archive" | while read f; do
  basename="$$(basename "$f")"
  echo "$$basename" | grep -qE "_[A-Z]+\.md$" || echo "INVALID_NAME: $$basename"
done
```
