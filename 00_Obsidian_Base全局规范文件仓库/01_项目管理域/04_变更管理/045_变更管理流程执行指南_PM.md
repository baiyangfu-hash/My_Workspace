## 3. 适用范围

本指南适用于所有变更管理流程的执行，包括需求变更、技术变更、资源变更、进度变更等。

## 4. 术语定义

| 术语 | 定义 |
|------|------|
| 变更 | 对项目计划、范围、进度、成本、质量或其他方面的修改 |
| 变更请求 | 正式提出的变更申请 |
| 变更审批 | 对变更请求进行评估和批准的过程 |
| 变更实施 | 执行已批准的变更的过程 |
| 变更验证 | 确认变更是否成功实施的过程 |

## 5. 变更管理流程执行步骤

### 5.1 变更申请

1. **填写变更单**：
   - 使用[040_通用变更单模板](04_监控和控制/01_变更管理/01_变更单/040_通用变更单模板_CHG.md)
   - 详细描述变更原因、变更内容和变更影响
   - 明确变更优先级和期望完成时间

2. **提交变更单**：
   - 通过项目管理工具提交变更单
   - 通知相关人员变更申请已提交

### 5.2 变更评估

1. **组建评估团队**：
   - 项目经理作为评估负责人
   - 技术负责人评估技术可行性
   - 相关团队成员评估变更影响

2. **评估内容**：
   - 变更的必要性和合理性
   - 变更对项目范围、进度、成本、质量的影响
   - 变更的可行性和风险

3. **影响分析**：
   - 使用系统自动分析功能进行影响分析
   - 查看受影响的组件列表
   - 评估风险等级（低/中/高）
   - 审查系统生成的缓解措施
   - 必要时手动调整影响分析结果

4. **评估报告**：
   - 形成书面评估报告
   - 明确评估结论和建议
   - 附上影响分析结果

### 5.3 变更审批

1. **确定审批人**：
   - 轻微变更：项目经理审批
   - 中等变更：项目负责人审批
   - 重大变更：高层管理层审批

2. **审批流程**：
   - 审批人审核变更评估报告
   - 签署审批意见
   - 通知变更申请人和相关团队成员

3. **审批历史记录**：
   - 系统自动记录所有审批操作
   - 查看审批历史：审批人、审批动作（通过/驳回）、审批意见、审批时间
   - 审批历史不可删除，只能追加
   - 变更申请人和相关团队成员可查看审批历史

### 5.4 变更实施

1. **制定实施计划**：
   - 明确实施步骤和责任人
   - 确定实施时间和资源需求
   - 制定风险应对措施

2. **执行变更**：
   - 按照实施计划执行变更
   - 及时沟通实施进展
   - 记录实施过程中的问题和解决方案

3. **实施完成**：
   - 确认变更实施完成
   - 通知相关人员变更实施情况

### 5.5 变更验证

1. **组建验证团队**：
   - 项目经理作为验证负责人
   - 技术负责人验证技术实现
   - 质量保证人员验证质量

2. **验证内容**：
   - 变更是否按照批准的内容实施
   - 变更是否达到预期效果
   - 变更是否对其他项目活动产生负面影响

3. **验证报告**：
   - 形成书面验证报告
   - 明确验证结论

### 5.6 变更记录

1. **更新变更单**：
   - 记录变更的完整信息
   - 归档变更单

2. **更新版本变更台帐**：
   - 使用[041_通用版本变更台帐模板](04_监控和控制/01_变更管理/04_变更记录/041_通用版本变更台帐模板_CHG.md)
   - 记录变更的详细信息

3. **更新项目状态**：
   - 在项目状态报告中反映变更情况
   - 确保项目计划与变更保持一致

4. **生成变更报告**：
   - 使用[044_通用变更报告模板](04_监控和控制/01_变更管理/02_变更报告/044_通用变更报告模板_CHG.md)
   - 总结变更实施情况和验证结果

## 6. 模板使用指南

### 6.1 变更单模板使用

1. **填写基本信息**：
   - 变更编号：使用统一的编号格式，如 CHG-YYYY-XXX
   - 项目名称和编号：填写变更所属的项目信息
   - 变更类型：选择变更的类型（需求变更、技术变更等）
   - 变更申请人：填写变更申请人的姓名
   - 申请日期：填写变更申请的日期
   - 预计实施日期：填写预计的变更实施日期

2. **填写变更原因**：
   - 详细描述变更的背景和原因
   - 说明变更的必要性和合理性

3. **填写变更内容**：
   - 变更前：描述变更前的状态或功能
   - 变更后：描述变更后的状态或功能

4. **填写变更影响分析**：
   - 分析变更对项目范围、进度、成本、质量等方面的影响
   - 制定相应的应对措施

5. **填写变更实施计划**：
   - 列出变更实施的具体任务
   - 明确任务负责人和时间安排

6. **填写变更审批**：
   - 审批人填写审批意见和日期

7. **填写变更实施记录**：
   - 记录变更实施的日期、实施人和实施内容
   - 记录实施结果和备注

8. **填写变更验证**：
   - 列出验证项和验证标准
   - 记录验证结果、验证人和验证日期

### 6.2 变更报告模板使用

1. **填写基本信息**：
   - 报告标题：填写变更名称和报告类型
   - 文档版本：填写报告的版本号
   - 编制日期：填写报告的编制日期
   - 编制人和审核人：填写相关人员的姓名

2. **填写变更基本信息**：
   - 变更单号：填写变更的编号
   - 变更名称：填写变更的名称
   - 变更类型：选择变更的类型
   - 变更申请日期和实施日期：填写相应的日期
   - 变更状态：填写变更的当前状态

3. **填写变更内容摘要**：
   - 变更原因：简述变更的背景和原因
   - 变更范围：描述变更涉及的模块、功能或系统
   - 变更目标：明确变更的预期目标和成果

4. **填写变更实施情况**：
   - 实施步骤：列出变更实施的具体步骤
   - 资源投入：填写人力、时间和成本投入
   - 实施风险：分析变更实施过程中的风险
   - 实施偏差：比较计划值和实际值，分析偏差原因

5. **填写变更验证结果**：
   - 测试情况：填写测试类型、覆盖和用例数量
   - 验证标准：描述变更验证的标准和依据
   - 验证结果：列出验证项、预期结果和实际结果
   - 问题发现：记录变更实施过程中发现的问题

6. **填写变更影响评估**：
   - 对项目进度、成本、质量和其他功能的影响

7. **填写变更经验总结**：
   - 成功经验：总结变更实施过程中的成功经验
   - 教训与改进：总结变更过程中的教训和改进建议
   - 最佳实践：提出可推广的变更管理最佳实践

8. **填写附件**：
   - 列出变更相关的附件，如变更单、测试报告等

## 7. 流程执行最佳实践

1. **及时沟通**：变更过程中应及时沟通变更信息，确保所有相关方了解变更情况
2. **严格执行**：严格按照变更管理流程执行，确保变更过程规范
3. **详细记录**：详细记录变更过程的每一步，便于追溯和分析
4. **持续改进**：总结变更经验教训，持续改进变更管理流程
5. **模板使用**：统一使用标准化的模板，确保文档格式一致

## 8. 常见问题及解决方案

| 问题 | 解决方案 | 示例 |
|------|---------|------|
| 变更评估不充分 | 建立评估 checklist，确保评估内容全面 | 使用标准化的评估表格 |
| 变更审批延迟 | 设定审批时限，建立催办机制 | 对超过3个工作日未审批的变更进行催办 |
| 变更实施偏差 | 严格按照变更单执行，定期检查实施进度 | 每日更新变更实施状态 |
| 变更验证不严格 | 建立验证标准，确保验证内容完整 | 使用标准化的验证表格 |
| 变更记录不完整 | 建立记录模板，确保记录内容全面 | 使用标准化的变更记录模板 |

## 7. 典型工程变更场景示例（V1.1.0新增）

> **以下3个场景展示了自动化工程项目中典型的跨领域变更链路,帮助理解V2.0规范的二维分类和传播链概念。**

### 场景A: 传感器位置调整（典型的跨领域变更链）

```
变更背景:
  现场安装时发现光电传感器位置偏差10mm,无法可靠检测1300×700mm玻璃到位
变更性质: DEF (缺陷修复 - 现场安装问题)
影响范围: CROSS (跨系统 - 涉及4个领域)

变更链路图:
  ┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐
  │ MECH    │ →  │ ELEC    │ →  │ PLC     │ →  │ DOCU    │
  │ 支架孔位 │    │ 预配线长 │    │ IO地址+  │    │ 文档同步 │
  │ 调整10mm│    │ 度调整   │    │ 参数适配 │    │ 修订     │
  └─────────┘    └─────────┘    └─────────┘    └─────────┘

步骤详解:
  Step 1: 发起 CHG-MECH-001 (主变更单)
          技术领域=MECH, 性质=DEF, 范围=CROSS
          内容: 机械支架安装孔位需从原位置偏移10mm

  Step 2: 影响评估(§6.2)发现电气受影响 → 关联 CHG-ELEC-002
          技术领域=ELEC, 性质=CFG (配置调整)
          内容: 传感器预配线长度需增加15cm,可能需要更换线号

  Step 3: CHG-ELEC-002评估发现IO点位可能变化 → 关联 CHG-PLC-003
          技术领域=PLC, 性质=CFG
          内容: 若传感器型号/接线方式变化,需更新GVL中的AT地址映射;
                可能需要微调i_SlowDelayTime参数以适应新检测位置

  Step 4: CHG-PLC-003评估发现HMI可能受影响 → 关联 CHG-HMI-004
          技术领域=HMI, 性质=CFG
          内容: HMI画面上的传感器位置示意图需更新;
                若有传感器状态显示页,变量映射需确认

  Step 5: 全部关联变更完成后 → 关联 CHG-DOCU-005
          技术领域=DOCU, 性质=OPT (文档同步)
          内容: 更新IO分配表/联锁逻辑文档/操作手册中的传感器位置说明

  Step 6: 全链路验证(§6.3)
          [MECH完成]→[ELEC验证通过]→[PLC验证通过]→[HMI验证通过]→[DOCU验证通过]
          现场带料测试: 送入玻璃板,确认新位置传感器可靠触发

关键经验:
  - 机械小改动可能引发4个领域的连锁变更
  - 每个环节都应有独立的变更单和验证
  - 最终必须做端到端的现场验证
```

### 场景B: 变频器型号替换（硬件驱动软件变更）

```
变更背景:
  原定汇川变频器缺货,需替换为台达品牌同功率型号
变更性质: CFG (配置调整 - 供应商变更)
影响范围: SYSTEM (系统级 - 涉及PLC+电气协调)

差异对比:
  | 项目 | 原变频器(汇川) | 新变频器(台达) |
  |------|--------------|--------------|
  | 功率规格 | 1.5kW | 1.5kW (相同) |
  | 控制方式 | 端子启停 + 0-10V模拟量调速 | 相同 ✅ |
  | 故障输出 | 1NO+1NC继电器 | 1NO+1NC继电器 ✅ |
  | 通信协议 | Modbus RTU (可选) | Modbus RTU (可选) ✅ |
  | 参数设置 | Acc系列菜单 | VFD-E系列菜单 ❌ |

变更链路:
  ┌─────────────┐         ┌─────────────┐
  │ ELEC        │ ←─────── │ PLC         │
  │ 变频器参数   │  参数对齐 │ 通信地址    │
  │ 配置不同    │         │ 映射可能变  │
  └─────────────┘         └─────────────┘

步骤:
  Step 1: CHG-ELEC-010 (主变更)
          技术领域=ELEC, 性质=CFG, 范围=SYSTEM
          内容: 变频器型号从汇川AC300替换为台达VFD-E,
                需重新配置加速时间/减速时间/转矩补偿等参数

  Step 2: 评估是否需要CHG-PLC-011
          如果使用了变频器通讯功能(读取频率/故障码):
            → 需要检查Modbus寄存器地址映射是否兼容
            → 如不兼容,发起CHG-PLC-011修改通信程序
          如果仅使用端子+模拟量(本项目DJ-2026-014的情况):
            → 无需PLC变更,在CHG-ELEC-010的§6.2标注"PLC不受影响"

  Step 3: 验证
          空载测试: 启停控制正常,速度给定0-100Hz线性对应
          带载测试: 输送玻璃板运行平稳,无异常振动

关键经验:
      不是所有硬件替换都会引发软件变更,需要具体分析
      "影响评估"环节的核心价值在于判断是否真的需要关联变更
```

### 场景C: 急停回路增加安全继电器（安全相关变更 - 特殊流程）

```
变更背景:
  客户第三方安全审核要求,急停回路必须增加安全继电器(如PILZ PNOZ),
  以符合ISO 13849-1 PLd / IEC 61508 SIL2等级
变更性质: EMRG (紧急/安全相关)
影响范围: SAFE (安全相关 - 最高审批级别)

⚠️ 此类变更走特殊流程:
  - 必须由安全负责人专项审批(不可用普通PM审批替代)
  - 需要单独的安全功能风险评估(SRA)
  - 验证必须包含安全功能测试(SFT)

变更链路:
  ┌──────────┐    ┌──────────┐    ┌──────────┐
  │ ELEC     │ →  │ PLC      │ →  │ DOCU     │
  │ 安全继电器│   │ 安全输入  │   │ 安全矩阵 │
  │ 回路改造 │   │ 点增加   │   │ 更新     │
  └──────────┘    └──────────┘    └──────────┘

步骤:
  Step 1: CHG-SAFE-020 (主变更 - EMRG性质)
          技术领域=ELEC(主)+SAFE, 性质=EMRG, 范围=SAFE
          审批人: 安全负责人 + 项目经理联合签字
          内容: 急停回路增加PNOZ安全继电器,重新布线,
                硬件成本增加约¥800,工期延长2天

  Step 2: 安全风险评估(SRA)
          识别新增风险点: 安全继电器自身故障模式
          缓解措施: 选用带诊断功能型号(PNOZ safety relay),
                      增加安全继电器状态反馈到PLC(DI点)

  Step 3: 关联 CHG-PLC-021 (如需安全反馈)
          技术领域=PLC+SAFE, 性质=DEF
          内容: GVL新增X_SafetyRelay_OK输入点,
                PRG_Main中增加安全回路状态监视逻辑,
                q_StatusWord新增"安全回路故障"编码

  Step 4: 关联 CHG-DOCU-022
          技术领域=DOCU+SAFE, 性质=REQ
          内容: 更新安全矩阵文档(§10安全设计章节),
                更新电气原理图(急停回路部分),
                更新验收标准(增加SIL2合规性测试项)

  Step 5: 安全功能测试(SFT) - 特殊验证要求
          测试1: 急停按下 → 安全继电器立即动作(<50ms) → PLC检测到信号丢失
          测试2: 安全继电器故障模拟 → 系统进入安全状态(不可复位启动)
          测试3: 复位序列验证 → 解除急停 → 安全继电器复位 → PLC检测到恢复 → 允许启动

关键经验:
      安全相关变更(EMRG+SAFE组合)是最高优先级
      必须有安全负责人参与全流程
      验证不能只看"功能正常",必须证明"失效时也安全"(Fail-Safe)
```

## 8. 工程变更快速参考卡（V1.1.0新增）

| 变更场景 | 典型领域 | 典型性质 | 典型范围 | 是否常涉及传播 | 审批层级建议 |
|---------|----------|----------|----------|:------------:|-------------|
| 传感器更换/移位 | MECH/ELEC | DEF/CFG | MODULE~CROSS | ✅ 常见(2-4领域) | PM |
| 变频器/电机更换 | ELEC | CFG | MODULE~SYSTEM | ⚠️ 有时(看是否用通讯) | Tech Lead |
| IO地址调整 | PLC/ELEC/HMI | CFG | MODULE | ✅ 常见(PLC→HMI联动) | PM |
| 联锁逻辑修改 | PLC | DEF/OPT | SYSTEM | ⚠️ 有时(若HMI有报警页) | Tech Lead |
| HMI画面新增 | HMI/PLC | REQ | LOCAL~MODULE | ⚠️ 有时(需PLC提供变量) | PM |
| 急停/安全回路 | ELEC/PLC/SAFE | **EMRG** | **SAFE** | ✅ 总是(至少ELEC+PLC+DOCU) | **Safety+高层** |
