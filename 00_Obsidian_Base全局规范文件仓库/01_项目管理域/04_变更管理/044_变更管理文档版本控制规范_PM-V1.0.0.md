## 3. 适用范围

本规范适用于所有变更管理相关文档的版本控制，包括变更管理流程规范、变更单模板、变更报告模板等。

## 4. 术语定义

| 术语 | 定义 |
|------|------|
| 版本号 | 用于标识文档版本的字符串，采用语义化版本格式 |
| 主版本 | 版本号的第一个数字，用于标识重大变更 |
| 次版本 | 版本号的第二个数字，用于标识功能变更 |
| 修订版本 | 版本号的第三个数字，用于标识 bug 修复和小改动 |
| 变更记录 | 记录文档变更内容的表格 |

## 5. 版本号格式

### 5.1 基本格式

采用语义化版本号格式：`V[主版本].[次版本].[修订版本]`

### 5.2 版本号规则

1. **主版本**：当文档结构发生重大变化，或功能发生根本性改变时，主版本号递增
2. **次版本**：当文档添加新功能，或对现有功能进行较大改进时，次版本号递增
3. **修订版本**：当文档进行 bug 修复、错误修正或小的改进时，修订版本号递增

## 6. 版本变更记录要求

### 6.1 变更记录格式

所有变更管理文档应包含版本变更记录，格式如下：

| 版本号 | 变更内容 | 变更人 | 变更日期 | 详细说明 |
|--------|----------|--------|----------|----------|
| [版本号] | [变更内容] | [变更人] | [变更日期] | [详细说明] |

### 6.2 变更记录要求

1. 每次文档变更都应在版本变更记录中添加一条记录
2. 变更内容应简明扼要地描述变更的主要内容
3. 详细说明应提供变更的具体细节，包括变更的原因、影响范围等
4. 变更记录应按时间顺序排列，最新的变更记录应位于最上方

## 7. 版本升级流程

### 7.1 修订版本升级流程

1. 识别需要修改的内容
2. 进行修改
3. 更新版本变更记录，修订版本号递增
4. 更新文档末尾的版本信息
5. 保存文档

### 7.2 次版本升级流程

1. 识别需要添加或改进的功能
2. 进行修改
3. 更新版本变更记录，次版本号递增，修订版本号重置为 0
4. 更新文档末尾的版本信息
5. 保存文档

### 7.3 主版本升级流程

1. 识别需要进行重大变更的内容
2. 进行修改
3. 更新版本变更记录，主版本号递增，次版本号和修订版本号重置为 0
4. 更新文档末尾的版本信息
5. 保存文档

## 8. 文档命名规范

### 8.1 文件名格式

变更管理文档的文件名应遵循以下格式：

`[序号]_[文档名称]_[前缀]-[版本号].md`

### 8.2 命名规则

1. **序号**：用于文件排序，建议按功能模块或创建时间顺序编号
2. **文档名称**：简洁明了地描述文档内容
3. **前缀**：表示文档类型，如：
   - CHG：变更相关
   - PM：项目管理相关
4. **版本号**：采用语义化版本号格式

## 9. 文档版本控制最佳实践

1. **及时更新**：每次文档变更后应及时更新版本号和变更记录
2. **保持一致**：所有变更管理文档应使用相同的版本控制机制
3. **详细记录**：变更记录应详细记录变更的内容和原因
4. **定期检查**：定期检查文档版本控制情况，确保所有文档都有正确的版本信息
5. **备份保存**：重要文档的不同版本应进行备份保存

## 10. 实施指南

1. **培训**：向团队成员培训版本控制规范，确保所有成员都了解并遵循规范
2. **检查**：定期检查文档版本控制情况，发现问题及时纠正
3. **改进**：根据实际使用情况，持续改进版本控制规范
