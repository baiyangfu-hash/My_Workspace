## 3. 范围

本规范适用于所有Python项目的命名，旨在确保项目名称的一致性、可读性和可维护性。

## 4. 术语定义

| 术语 | 定义 |
|------|------|
| 项目名称 | 项目的唯一标识符，用于区分不同的项目 |
| 模块名称 | 项目中功能模块的名称 |
| 变量名称 | 代码中变量的名称 |
| 函数名称 | 代码中函数的名称 |
| 类名称 | 代码中类的名称 |

## 5. 项目名称命名规范

### 5.1 基本原则

- **简洁性**：项目名称应简洁明了，避免过长
- **描述性**：项目名称应能准确描述项目的功能和用途
- **一致性**：项目名称应遵循统一的命名规则
- **可读性**：项目名称应易于理解和记忆

### 5.2 命名格式

项目名称应使用小写字母，单词之间用下划线分隔（snake_case）。

**格式**：`project_name`

**示例**：
- `python_web_api`
- `data_analysis_tool`
- `machine_learning_model`

### 5.3 命名规则

1. **使用英文**：项目名称应使用英文，避免使用中文或其他语言
2. **避免缩写**：除非是广泛认可的缩写（如API、GUI等），否则应使用完整单词
3. **避免特殊字符**：项目名称应只包含字母、数字和下划线，避免使用其他特殊字符
4. **避免使用保留字**：项目名称应避免使用Python的保留字和内置函数名
5. **唯一性**：项目名称应在组织内部保持唯一，避免与其他项目重名

## 6. PLC及自动化项目编号规则 (DEV-V1.0.2 新增)

### 6.1 编号格式

```
[前缀]-[年份]-[序号]_[项目简称]
```

### 6.2 前缀定义

| 前缀 | 项目类型 | 适用场景 | 示例 |
|------|---------|---------|------|
| **DJ-** | 设备类(Device/Job) | PLC控制的机械设备、生产线单元 | DJ-2026-005_边框缓存机 |
| **SW-** | 软件工具类(Software) | Python工具链、桌面应用、Web服务 | SW-2026-004_Python项目管理工具 |
| **TPL-** | 模板类(Template) | 可复用的项目模板、整线方案模板 | TPL-FULLLINE-AUTO-001_自动化整线项目 |
| **ROB-** | 机器人应用类(Robot) | 含机器人集成的应用项目 | ROB-2026-001_焊接工作站 |
| **SYS-** | 系统集成类(System) | 多设备系统级项目 | SYS-2026-001_整厂控制系统 |

### 6.3 序号分配规则

- **001~099**: 通用标准项目
- **100~499**: 定制化项目
- **500~899**: 内部研发/实验项目
- **900~999**: 紧急/临时项目

### 6.4 项目简称命名规范

- 示例: `BufferFraming`(边框缓存), `ProjectManagerTool`(项目管理工具)

### 6.5 规范与项目文档基准文件名禁带版本号后缀硬约束 (基于008实践)

为了维护 Obsidian 知识图谱中 `[[双向链接]]` 的引用稳定性，以及保障 Git 文件提交历史追溯：
1. **禁用文件名版本后缀**：所有 Markdown 规范文件、PRD、REQ、DES、TECH 等项目文档的文件名（Basename）**严禁包含版本号后缀**（例如：严禁命名为 `001_产品需求文档_PRD_V2.0.md` 或 `LSP-905_v1.md`）。
2. **正确示例**：
   - 推荐: `001_产品需求文档模板_PRD.md`
   - 禁用: `001_产品需求文档模板_PRD_V1.0.0.md`
3. **版本号管理**：文件自身的版本演进信息必须且只能在 Markdown 头部的 YAML Frontmatter 属性 `version: V1.0.0` 中进行标识。

## 8. 变量名称命名规范

### 8.1 基本原则

- **简洁性**：变量名称应简洁明了，避免过长
- **描述性**：变量名称应能准确描述变量的用途和含义
- **一致性**：变量名称应遵循统一的命名规则
- **可读性**：变量名称应易于理解和记忆

### 8.2 命名格式

#### 8.2.1 局部变量

局部变量应使用小写字母，单词之间用下划线分隔（snake_case）。

**格式**：`variable_name`

**示例**：
- `user_id`
- `data_list`
- `result_count`

#### 8.2.2 全局变量

全局变量应使用大写字母，单词之间用下划线分隔（SNAKE_CASE）。

**格式**：`GLOBAL_VARIABLE`

**示例**：
- `MAX_RETRY_COUNT`
- `DEFAULT_TIMEOUT`
- `API_BASE_URL`

#### 8.2.3 常量

常量应使用大写字母，单词之间用下划线分隔（SNAKE_CASE）。

**格式**：`CONSTANT_NAME`

**示例**：
- `PI`
- `DEFAULT_ENCODING`
- `MAX_CONNECTIONS`

### 8.3 命名规则

1. **使用英文**：变量名称应使用英文，避免使用中文或其他语言
2. **避免缩写**：除非是广泛认可的缩写（如ID、URL等），否则应使用完整单词
3. **避免特殊字符**：变量名称应只包含字母、数字和下划线，避免使用其他特殊字符
4. **避免使用保留字**：变量名称应避免使用Python的保留字和内置函数名
5. **唯一性**：变量名称应在作用域内保持唯一，避免与其他变量重名

- **描述性**：函数名称应能准确描述函数的功能和用途

### 9.3 命名规则

2. **避免缩写**：除非是广泛认可的缩写（如API、GUI等），否则应使用完整单词

## 10. 类名称命名规范

### 10.1 基本原则

- **简洁性**：类名称应简洁明了，避免过长
- **描述性**：类名称应能准确描述类的功能和用途
- **一致性**：类名称应遵循统一的命名规则
- **可读性**：类名称应易于理解和记忆

### 10.2 命名格式

类名称应使用驼峰命名法（CamelCase）。

**格式**：`ClassName`

**示例**：
- `UserManager`
- `DataProcessor`
- `ApiClient`

### 10.3 命名规则

1. **使用英文**：类名称应使用英文，避免使用中文或其他语言
2. **避免缩写**：除非是广泛认可的缩写（如API、GUI等），否则应使用完整单词
3. **避免特殊字符**：类名称应只包含字母和数字，避免使用其他特殊字符
4. **避免使用保留字**：类名称应避免使用Python的保留字和内置函数名
5. **唯一性**：类名称应在作用域内保持唯一，避免与其他类重名
6. **使用名词**：类名称应使用名词或名词短语，以明确类的用途

## 11. 其他命名规范

### 11.1 文件名命名规范

文件名应使用小写字母，单词之间用下划线分隔（snake_case）。

**格式**：`file_name.py`

**示例**：
- `user_model.py`
- `data_analysis.py`
- `api_routes.py`

### 11.2 目录名命名规范

目录名应使用小写字母，单词之间用下划线分隔（snake_case）。

**格式**：`directory_name`

**示例**：
- `src`
- `tests`
- `docs`
- `utils`

### 11.3 数据库表名命名规范

数据库表名应使用小写字母，单词之间用下划线分隔（snake_case），并使用复数形式。

**格式**：`table_name`

**示例**：
- `users`
- `orders`
- `products`

### 11.4 数据库字段名命名规范

数据库字段名应使用小写字母，单词之间用下划线分隔（snake_case）。

**格式**：`field_name`

**示例**：
- `user_id`
- `order_date`
- `product_name`
