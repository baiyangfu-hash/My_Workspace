# 通用项目管理规范

## 1. 文档目的

本文档为项目管理提供通用规范，确保项目管理过程的标准化和一致性，提高项目管理效率和质量。

## 2. 适用范围

适用于所有Python和PLC电气工程项目的管理过程。

## 3. 项目管理流程

### 3.1 启动过程
- 项目立项与 PM_SESSION 初始化 (`auto-pm project create / retrofit`)
- 产品需求文档编写 (PRD)
- 项目章程与路线图制定

### 3.2 规划过程
- 需求分析 (REQ) 与详细设计 (DES)
- 迭代计划与任务拆解
- 技术方案设计 (TECH)

### 3.3 执行过程
- 代码开发与 PLC SCL 建模
- CLI / GUI 双重测试验证
- 部署交付与纯净度治理 (`auto-pm clean / doctor`)

### 3.4 监控和控制
- 变更管理 (CHG 9步流转 / Retrofit 快捷补单)
- 自动对账 (`auto-pm ledger reconcile`)
- 门禁实测与质量控制

### 3.5 收尾过程
- 项目验收 (CHK)
- 自动历史归档与总结 (SUM)

## 4. 项目管理核心载体：PM_SESSION 双层结构规约 (基于008实践)

为了解决项目长期迭代中管理文件无限膨胀导致 AI 读写卡顿的问题，所有项目必须采用 **快照主文件 + 历史档案** 的双层结构：

- **主文件 (快照型)**：`PM_SESSION_<项目编号>.md`
  - **行数卡点硬约束**：主文件总行数必须保持 **≤ 150 行**。
  - **只保留活跃状态**：仅记录当前焦点、未决风险、最近 3 条完成摘要与当前构建指令。
- **历史目录 (档案型)**：`00_项目管理/06_PM_SESSION历史/`
  - **自动版本归档**：在项目版本号（如 `pyproject.toml`）升级时，自动将上轮迭代的完整日志归档至 `YYYY-MM-DD_Vx.x.x.md`。
  - **免建 CHG 流程**：版本归档属于基础设施运维，不创建变更单。

## 5. 工具链依赖

- 统一使用 `auto-pm` (SW-2026-008) 工具链进行项目初始化、合规检查、变更单流转与台账对账。
- 严禁在工作区根目录丢弃临时脚本 (`.tmp_*.py`) 或测试日志 (`mypy*.txt`)，必须定向输出至 `.auto-pm/logs/` 或 `.auto-pm/scratch/`。

## 5. 版本管理

- 遵循语义化版本规范
- 使用变更管理模板记录版本变更

## 6. 质量保证

- 定期进行项目质量检查
- 使用AI输出质量检查清单进行质量控制

## 7. 风险管理

- 识别项目风险
- 制定风险应对措施
- 定期更新风险状态

## 8. 沟通管理

- 建立有效的沟通机制
- 定期召开项目会议
- 及时沟通项目状态

## 9. 文档管理

- 遵循文档管理规范
- 确保文档的完整性和准确性
- 及时更新文档版本

## 10. 附录

- 术语定义
