## 3. 使用规则

1. **定位**：URT 单表贯通"需求 → 验收判据 → 功能 → 失败行为 → FB 载体 → scltest TC → 追溯状态"，一个信号级需求一行，取代 URS（A1）/FS（A2）/RTM（A4）三表分立——需求即追溯矩阵，不存在"两张表对不上"的问题。
2. **信号级粒度**：每行必须落到信号/物理地址级（如 X76 允许送料），禁止停留在"支持通信""可编程"等系统级空话；物理地址在 io_points.csv 定稿前允许占位，定稿后必须回填真址。
3. **交互时序**：涉跨设备信号的需求行必须在"交互时序"列写明先后依赖（谁先谁后、超时归属），与 815 §4.2 接口登记册一致。
4. **失败行为必填**：每行必须回答"信号断了/超时会怎样"——失败行为直接对接 B6 报警表（报警号）与 fail_safe 列。
5. **追溯状态枚举**：`draft（草稿）→ confirmed（已确认）→ implemented（已实现）→ tested（scltest 通过）→ accepted（验收通过）→ changed（变更待复审）`；状态由 PM 工具/评审推进，禁止跳级。
6. **非功能与验收区**：性能/环境/安全等非功能需求（§5）与验收标准（§6）不进主表，但每条验收标准必须能回指主表 Req-ID。
7. 与 020/028 的关系：020 通用需求分析（系统级叙述）仍可用于对甲方沟通；URT 是工程实施与追溯的唯一真源，两者冲突时以 URT 为准。
