## 3. 概述

本文档提供了自动化项目的标准项目结构模板，旨在规范项目的目录组织，提高代码的可维护性和可读性，适用于Python项目。

## 4. 项目结构模板

### 4.1 顶层目录结构（5大过程组）

```
项目名称/
├── 01_启动/                    # 启动过程组：立项表、项目章程等
├── 02_规划/                    # 规划过程组：需求文档、设计方案、技术方案
├── 03_执行/                    # 执行过程组：迭代计划、执行记录
├── 04_监控/                    # 监控过程组：变更管理、整改项跟踪
│   └── 01_变更管理/            # 变更管理（详细目录结构见043规范）
│       ├── 01_变更单/          # 按领域分子目录: CHG-{DOMAIN}/
│       └── 02_变更记录/        # 变更索引和统计
├── 05_收尾/                    # 收尾过程组：发布说明、PM_SESSION归档
├── src/                        # 源代码（代码目录保持根目录，不入过程组）
├── tests/                      # 测试代码（代码目录保持根目录，不入过程组）
├── scripts/                    # 脚本文件（代码目录保持根目录，不入过程组）
├── docs/                       # 代码相关文档
├── PM_SESSION_<项目编号>.md     # 项目入口真源（保持在根目录）
└── pyproject.toml              # 项目配置
```

> **变更管理目录说明**：变更管理目录统一为 `04_监控/01_变更管理/`，与 auto-pm 实际实现和 [043_通用变更管理目录结构说明](../04_变更管理/043_通用变更管理目录结构说明_PM.md) 保持一致。
>
> | 项目类型 | 变更管理目录 | 变更单子目录 | 说明 |
> |---------|-------------|-------------|------|
> | **PLC项目** | `04_监控/01_变更管理/` | `01_变更单/CHG-{DOMAIN}/` | 按技术领域分子目录（ELEC/MECH/PLC/HMI/SCPT/DOCU/SAFE） |
> | **Python项目** | `04_监控/01_变更管理/` | `01_变更单/CHG-{DOMAIN}/` | 统一路径，代码目录保持根目录 |
>
> 详细的变更管理目录结构请参考 [043_通用变更管理目录结构说明](../04_变更管理/043_通用变更管理目录结构说明_PM.md)。

> **关键原则**：5大过程组目录只重组管理文档，代码目录（src/tests/scripts/auto_pm/等）保持项目根目录，避免破坏 import 路径和打包配置。PM_SESSION_*.md 保持在项目根目录，作为项目入口真源。

### 4.2 目录说明

| 目录名称 | 描述 | 包含内容 | 适用项目类型 |
|---------|------|----------|-------------|
| **01_启动** | 启动过程组 | 项目立项表、项目章程等 | 通用 |

| **05_收尾** | 收尾过程组 | 发布说明、PM_SESSION归档、验收报告等 | 通用 |

| **docs/** | 代码相关文档 | API文档、开发指南 | 通用 |

## 7. 构建与部署

### 7.1 Python项目构建

**build.py**:
```python
# -*- coding: utf-8 -*-
"""
打包脚本

使用方法:
    python build.py [--clean] [--debug] [--onedir]
    
参数:
    --clean: 清理构建目录后重新打包
    --debug: 打包调试版本（带控制台窗口）
    --onedir: 打包为目录模式（默认单文件）
"""
import os
import sys
import shutil
import subprocess
from pathlib import Path

def clean_build():
    """清理构建目录"""
    dirs_to_clean = ['build', 'dist', '__pycache__']
    for dir_name in dirs_to_clean:
        if os.path.exists(dir_name):
            print(f"清理目录: {dir_name}")
            shutil.rmtree(dir_name)
    
    spec_file = 'build.spec'
    if os.path.exists(spec_file):
        os.remove(spec_file)

def build_exe(debug=False, onedir=False):
    """打包可执行文件"""
    print("="*50)
    print("项目管理工具 - 打包脚本")
    print("="*50)
    
    cmd = [
        sys.executable, '-m', 'PyInstaller',
        '--onedir' if onedir else '--onefile',
        '--windowed' if not debug else '--console',
        '--name', '项目管理工具',
        '--add-data', 'config;config',
        'main.py'
    ]
    
    print(f"执行命令: {' '.join(cmd)}")
    result = subprocess.run(cmd, cwd=os.getcwd())
    
    if result.returncode == 0:
        print("打包成功!")
    else:
        print("打包失败!")
        sys.exit(1)

def main():
    """主函数"""
    debug = '--debug' in sys.argv
    clean = '--clean' in sys.argv
    onedir = '--onedir' in sys.argv
    
    if clean:
        clean_build()
    
    build_exe(debug=debug, onedir=onedir)

if __name__ == '__main__':
    main()
```

## 8. 文档规范

### 8.1 文档命名规范

| 文档类型 | 命名格式 | 示例 |
|---------|----------|------|
| 需求文档 | `[序号]-需求规格说明书_REQ.md` | `1-需求规格说明书_REQ.md` |
| 技术方案 | `[序号]-[技术方案名称]_DEV.md` | `2-总库管理技术方案_DEV.md` |
| 架构设计 | `[序号]-架构设计文档_ARCH.md` | `3-架构设计文档_ARCH.md` |
| 用户手册 | `[序号]-用户操作手册_MAN.md` | `4-用户操作手册_MAN.md` |
| API文档 | `[序号]-API文档_INT.md` | `5-API文档_INT.md` |

### 8.2 代码文件命名规范

**Python项目**:
- 使用小写字母和下划线（snake_case）
- 模块名：`module_name.py`
- 类名：`ClassName`（驼峰命名）
- 函数名：`function_name()`
- 变量名：`variable_name`

## 9. 版本控制

### 9.1 版本号格式

遵循语义化版本规范：
```
MAJOR.MINOR.PATCH
```

- **MAJOR**：不兼容的API变更
- **MINOR**：向后兼容的功能添加
- **PATCH**：向后兼容的bug修复

### 9.2 版本管理流程

1. 在配置文件中定义版本号
2. 在文档中更新版本信息
3. 提交代码时包含版本变更信息
4. 发布时创建版本标签
