## 3. 测试流程总览

### 3.1 测试阶段划分

```
Phase 1: 基础功能验证 (5-10分钟)
    ↓  通过后进入下一阶段
Phase 2: 核心功能深度测试 (20-30分钟)
    ↓  通过后进入下一阶段
Phase 3: 边界情况和异常测试 (10-15分钟)
    ↓  通过后进入下一阶段
Phase 4: 数据一致性验证 (10分钟)
    ↓  通过后进入下一阶段
Phase 5: 回归测试 (15-20分钟)
    ↓
测试完成，输出报告
```

### 3.2 各阶段时间分配建议

| 阶段 | 预计时间 | 核心目标 | 关键产出 |
|------|----------|----------|----------|
| Phase 1 | 5-10分钟 | 验证程序可正常运行 | 启动截图、版本确认 |
| Phase 2 | 20-30分钟 | 验证核心业务功能 | 功能操作截图、问题记录 |
| Phase 3 | 10-15分钟 | 发现边界和异常情况 | 异常场景记录 |
| Phase 4 | 10分钟 | 数据准确性验证 | 数据库查询结果 |
| Phase 5 | 15-20分钟 | 确认历史 bug 未复现 | 回归测试报告 |

**总预计时间**: 60-85 分钟（可根据实际情况调整）

### 3.3 每个阶段的通过标准

#### Phase 1-3 通过标准:

- ✅ 所有关键检查点必须通过
- ⚠️ 允许存在非关键性的 UI 小问题（如字体大小、间距等）
- ❌ 任何导致功能不可用的问题都应阻断测试

#### Phase 4 通过标准:

- ✅ 数据库记录与 UI 显示 100% 一致
- ✅ 无孤立数据（数据库有但 UI 不显示）
- ✅ 无脏数据（UI 显示但数据库不存在）

#### Phase 5 通过标准:

- ✅ 之前修复的所有 P0/P1 级 bug 均未复现
- ✅ 新增功能未引入回归问题

#### TC-001: 程序启动测试

**优先级**: P0 | **耗时**: 2分钟 | **类型**: 冒烟测试

**前置条件**: 无

**测试步骤**:
1. 打开命令行终端，切换到主程序目录：
   ```bash
   cd "<主程序目录路径>"
   ```
2. 运行启动命令：
   ```bash
   python main.py
   ```
   或者双击 `main.py` 文件
3. 等待窗口完全加载（观察时间，不应超过 5 秒）
4. 观察控制台输出信息

**检查点**:
- [ ] **窗口显示**: 程序主窗口正常显示，无白屏或黑屏
- [ ] **标题栏**: 显示正确版本号（格式: "Python项目管理工具 V{x.x.x}"）
- [ ] **控制台日志**: 无 ERROR 或 CRITICAL 级别日志输出
- [ ] **主界面布局**: 选项卡可见且可点击（仪表盘、模板管理、项目管理等）
- [ ] **响应速度**: 从执行命令到窗口完全显示 <= 5秒

**预期结果**:
✅ 程序在 5 秒内成功启动，显示完整的主界面，标题栏包含正确的版本号

**失败处理流程**:
1. **第一步 - 检查环境**:
   ```bash
   python --version  # 确认 Python 版本 >= 3.8
   pip list | grep PyQt5  # 确认 PyQt5 已安装
   ```

2. **第二步 - 查看错误日志**:
   ```bash
   # Windows PowerShell
   Get-Content logs/app.log -Tail 50
   ```

3. **第三步 - 常见问题排查**:
   - ImportError → 缺少依赖包，运行 `pip install -r requirements.txt`
   - DatabaseError → 数据库文件损坏或权限不足
   - ModuleNotFoundError → Python 路径配置问题

- 📷 **截图1**: 启动后的完整主界面（包含所有选项卡）
- 📷 **截图2**: 控制台/终端的输出日志（如有任何警告或错误）

**通过/失败判定**:

#### TC-002: 版本号显示一致性测试

**优先级**: P0 | **耗时**: 1分钟 | **类型**: 配置验证

**背景说明**:
某些版本发现版本号存在多层缓存问题（version.py → config.py → app_config.json），此测试确保版本号在所有位置保持一致。

**测试步骤**:
1. 观察主窗口标题栏显示的版本号
2. 点击菜单栏中的"帮助" → "关于"（如果存在该菜单）
3. 记录关于对话框中显示的版本号
4. （可选）使用代码直接读取配置文件验证：

```python
# 验证脚本
import json
from pathlib import Path

# 读取 version.py
version_file = Path("config/version.py")
if version_file.exists():
    exec(version_file.read_text(encoding='utf-8'))
    print(f"version.py: {__version__}")

# 读取 app_config.json
config_file = Path("config/app_config.json")
if config_file.exists():
    config = json.loads(config_file.read_text(encoding='utf-8'))
    print(f"app_config.json: {config.get('app_version', 'N/A')}")
```

**检查点**:
- [ ] **标题栏版本号**: 格式正确（如 "V{x.x.x}"），无硬编码的旧版本号
- [ ] **关于对话框版本号**: 与标题栏完全一致（如有该对话框）
- [ ] **配置文件一致性**: version.py 和 app_config.json 中的版本号相同
- [ ] **无残留旧版本**: 不存在上一版本的版本号显示

**预期结果**:
✅ 所有位置显示的版本号均为当前迭代版本（例如 V{x.x.x}），完全一致

**已知问题参考** (从实际测试经验):
⚠️ **BUG-003**: 如果发现版本号不一致，可能原因：
- 修改了 version.py 但未同步更新 config.py
- 修改了 config.py 但未更新 app_config.json
- 程序缓存了旧版本号

**解决方案**: 直接修改最终的配置源文件（通常是 app_config.json 或 version.py），确保所有引用点统一。

- 📷 **截图3**: 主窗口标题栏特写（清晰显示版本号）
- 📷 **截图4**: 关于对话框（如有）

#### TC-011: 模板管理 - 刷新功能测试 ⭐核心测试

**优先级**: P0 | **耗时**: 5分钟 | **重要性**: 🔴 极高 | **类型**: 回归测试

**背景说明**:
这是 **某版本修复的核心 Bug**。在之前的版本中，存在严重的刷新缺陷：

❌ **问题描述**: 用户点击"刷新"按钮后，模板列表从正常的 N 个骤减至仅显示少量模板，严重影响使用。

✅ **修复方案**: 使用 `blockSignals()` 方法在刷新时重置所有筛选器状态，避免旧筛选条件干扰数据加载。

**因此，这个测试用例是本次 GUI 测试方案中最关键的测试点！**

**测试步骤**:

**主测试流程** (必须严格执行):
1. 在模板管理页面，记录当前显示的模板数量（预期: N 个）
2. 点击"刷新"按钮
3. 等待表格重新加载（不超过 2 秒）
4. 再次统计模板数量，并与步骤 1 对比
5. **重复步骤 2-4，共进行 5 次完整的刷新循环**
6. 记录每次刷新后的模板数量和列表内容

**详细记录表** (测试时填写):

| 刷新次数 | 刷新前数量 | 刷新后数量 | 是否一致 | 备注 |
|----------|------------|------------|----------|------|
| 第 1 次 | N | N | ✅ | 正常 |
| 第 2 次 | N | N | ✅ | 正常 |
| 第 3 次 | N | N | ✅ | 正常 |
| 第 4 次 | N | N | ✅ | 正常 |
| 第 5 次 | N | N | ✅ | 正常 |

**每次刷新后的检查点** (每刷新一次都要勾选):
- [ ] **数量稳定性**: 刷新后模板数量保持不变（始终为 N 个）
- [ ] **内容一致性**: 刷新前后模板列表完全一致（顺序、ID、名称都相同）
- [ ] **UI 平滑性**: 刷新过程中无闪烁、白屏或卡顿现象
- [ ] **筛选器重置**: 刷新后所有筛选器自动恢复到"全部"/默认状态
- [ ] **搜索框清空**: 刷新后搜索框内的文字被清除（如有）
- [ ] **统计信息更新**: 底部统计信息实时更新且数值正确

**边界测试** (可选但推荐):

**测试 A: 快速连续刷新**
- 快速连续点击"刷新"按钮（间隔 < 0.5秒，连续 5-10 次）
- 预期: 程序稳定，最终显示正确的 N 个模板

**测试 B: 切换选项卡后刷新**
1. 设置某些筛选条件
2. 切换到其他选项卡（如"项目管理"）
3. 再切回"模板管理"
4. 点击"刷新"
- 预期: 显示全部 N 个模板，筛选条件被重置

**测试 C: 带搜索关键词刷新**
1. 在搜索框输入 "PLC"
2. 观察列表过滤结果
3. 点击"刷新"
- 预期: 搜索框被清空，显示全部 N 个模板

**预期结果**:
✅ **理想情况**: 无论刷新多少次（1次、5次、50次），始终显示完整的 N 个模板，无任何数据丢失

❌ **失败情况**: 如果任意一次刷新后数量减少，则 **测试失败**，说明 BUG 复现！

**失败诊断流程** (如果测试失败):

**第一步: 收集证据**

**第四步: 数据库验证**

**方法二: 使用 Python 脚本** (推荐)

创建临时验证脚本 `verify_data.py`:

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
数据一致性验证脚本
用于对比 UI 显示与数据库实际数据
"""

import sqlite3
from pathlib import Path
from datetime import datetime

def verify_template_data():
    """验证模板数据一致性"""

    db_path = Path("data/project_manager.db")
    if not db_path.exists():
        print(f"❌ 数据库文件不存在: {db_path}")
        return False

    try:
        conn = sqlite3.connect(str(db_path))
        cursor = conn.cursor()

        # 1. 统计总数
        cursor.execute("SELECT COUNT(*) FROM templates")
        total_count = cursor.fetchone()[0]
        print(f"\n{'='*60}")
        print(f"模板数据一致性验证报告")
        print(f"验证时间: {datetime.now().strftime('%Y-%m-%d %H:%M:%S')}")
        print(f"{'='*60}")

        print(f"\n[1] 模板总数: {total_count}")
        if total_count == N:  # N 为预期的内置模板数量
            print("    ✅ 总数正确 (预期: N)")
        else:
            print(f"    ❌ 总数错误 (预期: N, 实际: {total_count})")

        # 2. 查询所有模板详情
        print(f"\n[2] 模板详细信息:")
        print("-" * 80)
        print(f"{'Template ID':<25} {'名称':<20} {'版本':<8} {'内置':<4}")
        print("-" * 80)

        cursor.execute("""
            SELECT template_id, name, version, is_builtin
            FROM templates
            ORDER BY template_id
        """)

        rows = cursor.fetchall()
        for i, row in enumerate(rows, 1):
            tpl_id, name, version, is_builtin = row
            builtin_mark = "✅" if is_builtin else "⚪"
            print(f"{tpl_id:<25} {name:<20} {version:<8} {builtin_mark:<4}")

        # 3. 验证内置模板数量
        cursor.execute("SELECT COUNT(*) FROM templates WHERE is_builtin = 1")
        builtin_count = cursor.fetchone()[0]
        print(f"\n[3] 内置模板数量: {builtin_count}")

        # 4. 检查是否有重复
        cursor.execute("""
            SELECT template_id, COUNT(*) as cnt
            FROM templates
            GROUP BY template_id
            HAVING cnt > 1
        """)
        duplicates = cursor.fetchall()
        if duplicates:
            print(f"\n❌ 发现重复模板 ID:")
            for dup in duplicates:
                print(f"    - {dup[0]} (出现 {dup[1]} 次)")
        else:
            print(f"\n[4] 重复检查: ✅ 无重复模板 ID")

        # 5. 检查是否有孤立的旧数据
        expected_ids = [
            'TPL-FULLLINE-AUTO-001',
            'TPL-SINGLE-PLC-S001',
            'TPL-SINGLE-PLC-M001',
            'TPL-SINGLE-ROBOT-001',
            'TPL-UPGRADE-STD-001',
            'TPL-UPPER-STD-001'
        ]

        cursor.execute("SELECT template_id FROM templates WHERE is_builtin = 1")
        actual_ids = [row[0] for row in cursor.fetchall()]

        missing_ids = set(expected_ids) - set(actual_ids)
        extra_ids = set(actual_ids) - set(expected_ids)

        if missing_ids:
            print(f"\n⚠️ 缺失的内置模板 ID:")
            for mid in sorted(missing_ids):
                print(f"    - {mid}")

        if extra_ids:
            print(f"\n⚠️ 多余的内置模板 ID (可能是旧版本残留):")
            for eid in sorted(extra_ids):
                print(f"    - {eid}")

        if not missing_ids and not extra_ids:
            print(f"\n[5] 模板 ID 完整性: ✅ 完全匹配")

        print(f"\n{'='*60}")
        print("验证完成")
        print(f"{'='*60}\n")

        conn.close()

        # 返回验证结果
        return (
            total_count == N and
            not duplicates and
            not missing_ids and
            not extra_ids
        )

    except Exception as e:
        print(f"❌ 验证过程出错: {e}")
        import traceback
        traceback.print_exc()
        return False


if __name__ == "__main__":
    success = verify_template_data()
    exit(0 if success else 1)
```

## 9. 文档使用指南

### 9.1 如何使用这份文档

**适用场景**:
1. **每次迭代发布前**: 作为 GUI 测试的标准作业指导书
2. **新测试人员入职**: 快速了解测试流程和方法
3. **测试过程追溯**: 记录测试执行的完整证据链
4. **质量改进依据**: 基于历史数据持续优化测试策略

**使用流程**:
```
1. 测试前 (准备阶段)
   ├─ 阅读"测试环境要求"(第2节)，确认环境就绪
   ├─ 打印"快速检查清单"(附录 7.4)
   └─ 准备截图保存目录

2. 测试中 (执行阶段)
   ├─ 按照 Phase 1-5 的顺序执行
   ├─ 每个测试用例严格按步骤操作
   ├─ 及时记录问题和截图
   └─ 遇到失败立即停止并诊断

3. 测试后 (报告阶段)
   ├─ 整理所有截图和日志
   ├─ 填写问题记录表 (第5节)
   ├─ 完成"签署确认表" (第6.2节)
   └─ 生成正式测试报告 (附录 7.3)
```

### 9.2 定期更新机制

**触发更新的时机**:
- ✅ 每次迭代发布后，根据实际测试经验补充新的用例
- ✅ 发现新的 Bug 类型，增加对应的回归测试
- ✅ 功能模块重大变更，调整测试范围和重点
- ✅ 测试工具或环境变化，更新环境要求和命令

**更新流程**:
1. 在"版本历史"(第8节)添加新条目
2. 标注变更内容和原因
3. 通知团队成员文档已更新
4. （如需要）召开简短的评审会议

### 9.3 反馈与改进

如果您在使用这份文档时有任何建议或发现需要改进的地方，请：
