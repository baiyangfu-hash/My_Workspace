# 项目交付管理规范 (V2.3.0)

## 1. 规范定位与核心双轨制原则

本规范适用于工作空间内所有 Python 软件、QML 桌面驾驶舱与 Siemens PLC 工业自动化项目的全流程交付与跨角色分发管理。

## 2. AI 工程师主动担当与零负担交付铁律 (Zero-Burden Law)

所有参与本工作空间的 AI 必须恪守以下四项工程师职业担当铁律：

```
                              零负担交付四大原则
  ┌─────────────────────────────────────────────────────────────────────────────┐
  │ 1. 【严禁半成品外溢】                                                       │
  │    呈报给用户的内容必须 100% 经过严格走查、无死链、无运行时报错、全量门禁全绿│
  │    严禁像“挤牙膏”一样等待用户发现低级破绽。                                 │
  ├─────────────────────────────────────────────────────────────────────────────┤
  │ 2. 【交卷前极限自我施压】                                                   │
  │    在向用户报告“已完成”前，AI 必须先扮演最挑剔的测试专家，主动完成：        │
  │    • SCL 代码：通过 Linter 语法白名单与全参数调用检查；                     │
  │    • HMI 原型：通过导航死链静态扫描（所有按钮有目标容器，所有函数有定义）； │
  │    • Python 上位机：通过 pytest 全量测试（100% 绿门禁）与类型检查。         │
  ├─────────────────────────────────────────────────────────────────────────────┤
  │ 3. 【绝不就事论事，根治源头产线】                                           │
  │    发现缺陷必须溯源脚手架模板（templates/）、生成器（Service）与 Linter 门禁 │
  │    从源头彻底消缺，并补充自动化防御单测，确保未来生成的项目 100% 不复发。   │
  ├─────────────────────────────────────────────────────────────────────────────┤
  │ 4. 【只报成果与决策，彻底消化琐事】                                         │
  │    彻底消化技术实现细节，只向用户呈报经过充分验证的清晰结论与宏观决策点。   │
  └─────────────────────────────────────────────────────────────────────────────┘
```

## 3. 外部人员交付资产标准（按受众精准分流）

为解决“不同外部人员电脑环境不同、权限不同”的痛点，对外分发采用清晰的三大交付通道：

```
                               对外交付三大标准通道
  ┌──────────────────────────────┬──────────────────────────────┬──────────────────────────────┐
  │ 通道 1：Release 免安装运行包 │ 通道 2：Source 离线源码包    │ 通道 3：线上 Git 仓库协作    │
  ├──────────────────────────────┼──────────────────────────────┼──────────────────────────────┤
  │ • 交付对象：现场客户/使用方/ │ • 交付对象：离线开发人员/    │ • 交付对象：核心研发团队/    │
  │   黑盒 QA 验收测试人员       │   外部第三方外包开发         │   具备仓库权限的协作开发者   │
  │ • 交付形态：免安装独立压缩包 │ • 交付形态：纯净源码压缩包   │ • 交付形态：Git Clone 权限   │
  │ • 命名规范：                 │ • 命名规范：                 │ • 协作方式：                 │
  │   {项目}_V{版本}_Release_    │   {项目}_V{版本}_Source_     │   git clone <repo-url>       │
  │   {日期}.zip                 │   {日期}.zip                 │   pip install -e .           │
  │ • 内部构成：                 │ • 内部构成：                 │ • 核心文档：                 │
  │   1. {项目}.exe 绿色程序包   │   1. auto_pm/ 完整源码       │   02_规划/003_详细设计_DSN.md│
  │   2. USER_GUIDE 操作手册     │   2. tests/ 1585 单测套件    │   02_规划/002_接口文档_INT.md│
  │   3. TEST_PLAN 验收清单      │   3. DSN 详细设计说明书      │                              │
  │   4. 启动程序.bat            │   4. pyproject.toml 依赖     │                              │
  │ • 特性：电脑无 Python 也可跑 │ • 特性：开箱即支持二次开发   │ • 特性：实时代码拉取与合并   │
  └──────────────────────────────┴──────────────────────────────┴──────────────────────────────┘
```

## 3. 工作空间内部目录拓扑（对内单一真源）

工作空间内部文档一律保持**无版本号后缀的标准文件名**，版本号由 Frontmatter 与 pyproject.toml 单一真源控制：

```
工程根目录/
├── 02_规划/
│   ├── 001_产品需求文档_PRD.md
│   ├── 002_接口文档_INT.md
│   └── 003_详细设计说明书_DSN.md              # 【开发真源】Clean Architecture 5层分层与代码地图
│
├── 05_收尾/                                   # 【对内验收】
│   ├── 001_项目总结报告_SUM.md
│   ├── 002_验收核验报告_PM.md
│   ├── 003_测试策略与验收规程_TEST_PLAN.md    # 【测试真源】20维验收 Checklist 与测试脚本指引
│   └── 02_PM_SESSION归档/
│
└── 06_交付物/                                 # 【对外分发集散地】
    ├── README.md                              # 交付包全局指引
    ├── 001_用户操作指南与排障手册_USER_GUIDE.md# 【用户真源】图文 SOP 与排障 FAQ
    ├── 002_版本发布说明_RELEASE_NOTES.md      # 版本更新记录
    ├── {项目}_V{版本}_Release_{日期}.zip      # 【对外分发】免安装独立绿色运行包
    └── {项目}_V{版本}_Source_{日期}.zip       # 【对外分发】离线源码开发包
```

## 4. 交付质量放行 5 步硬门禁

在执行发布打包与关闭交付变更单前，必须按序完成以下门禁：
1. **工作空间治理**：`python -m auto_pm clean` 清除缓存与临时文件；`auto-pm doctor` 健康自检合格；
2. **静态门禁检查**：`ruff check` 0 error；`mypy` 0 error；
3. **自动化测试回归**：后端单测 100% 通过（如 1585 passed）；GUI 全景交互测试 20/20 满分通过；
4. **三方交接文档对齐**：DSN 架构路径最新、TEST_PLAN 用例齐全、USER_GUIDE 说明完整；
5. **构建对外分发双包**：生成 `Release.zip`（含 exe）与 `Source.zip`（含源码）。
