## 1. 总则

### 1.1 目的
为了统一PLC编程标准，提高代码质量、可读性和可维护性，特制定本规范。

### 1.2 适用范围
本规范适用于所有PLC编程系统，包括Autoshop、Work3等，确保跨系统的编程一致性。

### 1.3 核心原则
1. **标准化**：严格遵循IEC 61131-3标准
2. **结构化**：采用分层架构，实现高内聚低耦合
3. **可读性**：代码清晰易懂，便于维护和调试
4. **可靠性**：确保程序稳定运行，避免逻辑错误
5. **可扩展性**：便于后续功能扩展和系统升级

## 2. IEC 61131-3编程标准

### 2.1 编程语言
- **推荐使用**：结构化文本（ST）、梯形图（LD）、功能块图（FBD）
- **禁止使用**：指令表（IL）、顺序功能图（SFC）（除非项目特殊要求）

### 2.2 程序组织单元（POU）
- **功能块（FB）**：用于实现特定功能的可重用模块
- **函数（FC）**：用于实现特定计算的可重用模块
- **程序（PRG）**：主程序或子程序

### 2.3 数据类型
- **基本数据类型**：BOOL、INT、DINT、REAL、STRING等
- **复合数据类型**：ARRAY、STRUCT、UNION等
- **用户自定义数据类型**：根据项目需要创建

### 2.4 编程结构
- **顺序结构**：按顺序执行的代码
- **选择结构**：IF-THEN-ELSE、CASE等
- **循环结构**：FOR、WHILE、REPEAT等

## 3. 程序结构规范

### 3.1 分层架构
1. **IO采集层**：负责硬件IO的采集和输出
2. **功能块层**：实现具体的控制功能
3. **工艺逻辑层**：实现工艺流程控制
4. **监控与报警层**：实现系统状态监控和报警处理

### 3.2 程序组织
- **主程序**：负责调用各个功能块和子程序
- **功能块**：实现特定功能的模块化单元
- **子程序**：实现特定任务的程序片段
- **数据块**：存储程序数据

### 3.3 任务配置
- **循环任务**：定期执行的任务
- **事件任务**：由事件触发的任务
- **任务优先级**：根据任务重要性设置优先级

## 4. 功能块设计规范

### 4.1 功能块命名
- **命名格式**：`FB_编号_英文功能描述_设备对象`
- **示例**：`FB_1001_ConveyorControl_BeltConveyor`（皮带输送机启停控制）

### 4.2 功能块结构
1. **头部注释**：包含功能块描述、版本、输入输出变量等信息
2. **变量声明**：清晰声明输入、输出、输入输出和内部变量
3. **初始化逻辑**：确保变量正确初始化
4. **主逻辑**：实现核心控制功能
5. **错误处理**：处理异常情况
6. **输出更新**：更新输出变量

### 4.3 功能块设计原则
- **高内聚**：功能块内部功能紧密相关
- **低耦合**：功能块之间依赖关系最小化
- **可重用**：设计通用功能块，便于在不同项目中重用
- **可测试**：便于单独测试和调试

### 4.4 功能块示例
```ST
// 输送线控制FB块 - 高内聚低耦合版本
// 版本：v4.9.0 [2026-01-24_15:47]
// 功能：控制输送线电机的启动、停止、速度调节和故障检测
// 输入变量：
//   i_Start - 启动信号
//   i_Stop - 停止信号
//   i_Position1Sensor - 位置1传感器信号
//   i_MainControlMode - 主控运行模式(0-停止,1-手动,2-自动)
//   i_MotorDirection - 电机运行方向(0-正转,1-反转)
//   i_SlowDelayTime - 慢速延时时间设定(毫秒)
//   i_SpeedFrequency - 速度频率设定(HZ)
//   i_Reset - 复位按钮信号
//   i_DriveAlarm - 驱动报警信号
// 输出变量：
//   q_MotorRunning - 电机运行状态
//   q_MotorFault - 电机异常状态
//   q_MotorDirection - 电机运行方向状态(0-正转,1-反转)
//   q_ProductInPlaceDone - 产品到位完成标志
//   q_SpeedOutput - 速度输出频率(HZ)
//   q_StatusWord - 状态字(位0:模式错误,位1:驱动报警状态,位2:方向输入错误)
```

## 5. 变量命名规范

### 5.1 变量命名规则
- **输入变量**：`i_变量类型_变量描述`，示例：`i_bStartButton`
- **输出变量**：`q_变量类型_变量描述`，示例：`q_bMotorRun`
- **输入输出变量**：`iq_变量类型_变量描述`，示例：`iq_bMotorRun`
- **内部变量**：`变量类型_变量描述`，示例：`bRunning`
- **全局变量**：`变量类型_变量描述`，示例：`bSysAutoMode`
- **上升沿/下降沿检测变量**：`LDP_变量类型_变量描述`或`LDF_变量类型_变量描述`
- **硬件IO变量**：`In_变量类型_变量描述`或`Out_变量类型_变量描述`

### 5.2 变量类型前缀

| 变量类型 | 前缀 | 示例 |
|----------|------|------|
| 布尔型 | b | `bStart`, `bStop`, `bAlarm` |
| 整数型 | i | `iSpeed`, `iCount`, `iTemperature` |
| 长整数型 | li | `liSpeed`, `liCount`, `liTemperature` |
| 实数型 | r | `rPressure`, `rFlow`, `rLevel` |
| 字符串型 | s | `sProductName`, `sRecipeID` |
| 浮点数型 | f | `fPressure`, `fFlow`, `fLevel` |
| 数组 | a | `aMotorSpeed[3]`, `aSensorData[10]` |

### 5.3 常量命名
- 常量名应使用全大写字母，单词之间用下划线分隔
- 示例：`MAX_SPEED`, `MIN_TEMPERATURE`, `DEFAULT_PRESSURE`

## 6. 注释规范

### 6.1 变量注释
- 所有变量都应添加注释，说明其用途和含义
- 注释应简洁明了，避免冗余
- 对于复杂变量，应详细说明其使用方法和注意事项

### 6.2 功能块注释
- 功能块应包含头部注释，说明功能、版本、输入输出变量等信息
- 注释应包含变更记录，便于追踪历史修改

### 6.3 代码注释
- 复杂逻辑应添加注释，说明实现思路
- 关键算法应添加注释，说明算法原理
- 特殊处理应添加注释，说明处理原因

## 7. 错误处理规范

### 7.1 错误检测
- 实现输入参数验证
- 实现运行状态监控
- 实现硬件故障检测

### 7.2 错误处理
- 错误状态应及时反馈
- 错误处理应安全可靠
- 错误应可复位和恢复

### 7.3 报警管理
- 报警信息应清晰明确
- 报警级别应合理划分
- 报警应可记录和查询

## 8. 性能优化规范

### 8.1 程序执行效率
- 减少不必要的计算
- 优化循环结构
- 合理使用计时器和计数器

### 8.2 内存使用
- 合理分配内存空间
- 避免内存泄漏
- 优化数据结构

### 8.3 响应时间
- 确保关键任务的响应时间
- 合理设置任务周期
- 优化通信协议

## 9. 安全规范

### 9.1 程序安全
- 实现互锁逻辑
- 避免死循环
- 防止误操作

### 9.2 数据安全
- 保护关键数据
- 实现数据备份
- 防止数据篡改

### 9.3 系统安全
- 实现权限管理
- 防止未授权访问
- 确保系统稳定运行

## 10. 测试规范

### 10.1 单元测试
- 对功能块进行单独测试

- 测试边界条件

### 10.2 集成测试
