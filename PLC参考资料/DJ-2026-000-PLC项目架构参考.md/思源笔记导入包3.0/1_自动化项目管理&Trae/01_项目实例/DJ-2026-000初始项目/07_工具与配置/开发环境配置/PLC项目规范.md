## 1. 项目命名规范

### 1.1 项目文件夹命名

- **格式**：`Project_XXX_项目名称`
- **说明**：
  - `XXX`：三位数字项目编号，从001开始递增
  - `项目名称`：清晰描述项目内容的中文名称
- **示例**：`Project_001_气缸控制系统`

### 1.2 文档命名

- **格式**：`文档名称_版本号.扩展名`
- **说明**：
  - `文档名称`：简洁描述文档内容
  - `版本号`：`V主版本.次版本`
  - `扩展名`：根据文档类型选择（.md、.pdf、.docx等）
- **示例**：`IO点表&变量清单_V1.0.md`

### 1.3 程序文件命名

- **格式**：`类型_功能描述.扩展名`
- **说明**：
  - `类型`：FB（功能块）、FC（功能）、DB（数据块）等
  - `功能描述`：简洁描述功能
  - `扩展名`：根据PLC类型选择（.st、.awl等）
- **示例**：`FB_CylinderControl.st`

## 2. 变量命名规范

### 2.1 全局变量

- **格式**：`g_变量类型_功能描述`
- **说明**：
  - `g_`：全局变量前缀
  - `变量类型`：BOOL、INT、REAL等
  - `功能描述`：驼峰命名法，首字母小写
- **示例**：`g_BOOL_CylinderExtended`

### 2.2 局部变量

- **格式**：`变量类型_功能描述`
- **说明**：
  - 无全局前缀
  - 其他规则同全局变量
- **示例**：`INT_Counter`

### 2.3 IO变量

- **格式**：`IO_方向_类型_位置_功能`
- **说明**：
  - `IO_`：IO变量前缀
  - `方向`：I（输入）、Q（输出）
  - `类型`：BOOL、INT等
  - `位置`：模块位置或地址
  - `功能`：简洁描述功能
- **示例**：`IO_I_BOOL_0_StartButton`

### 2.4 常量命名

- **格式**：`CONST_功能描述`
- **说明**：
  - `CONST_`：常量前缀
  - `功能描述`：大写字母，下划线分隔
- **示例**：`CONST_MAX_SPEED`

## 3. PLC程序结构规范

### 3.1 程序层次结构

1. **主程序**：MainProgram
2. **功能块（FB）**   ：按功能模块化
3. **功能（FC）**   ：通用功能
4. **数据块（DB）**   ：数据存储

### 3.2 功能块设计

- **输入参数**：`i_参数名`
- **输出参数**：`o_参数名`
- **输入/输出参数**：`io_参数名`
- **静态变量**：`s_变量名`
- **临时变量**：`t_变量名`

### 3.3 程序注释规范

- **头部注释**：包含功能描述、版本信息、作者、修改日期
- **变量注释**：描述变量用途
- **代码注释**：关键逻辑添加注释
- **示例**：
  ```st
  // 功能块：气缸控制
  // 版本：V1.0
  // 作者：张三
  // 修改日期：2026-03-04
  FUNCTION_BLOCK FB_CylinderControl
  VAR_INPUT
      i_Start : BOOL; // 启动信号
      i_Stop : BOOL;  // 停止信号
  END_VAR
  ```

### 3.4 程序结构示例

```
PLC程序/
├── 主程序/
│   └── MainProgram.st
├── 功能块/
│   ├── FB_CylinderControl.st
│   ├── FB_MotorControl.st
│   └── FB_SafetyLogic.st
├── 变量表/
│   ├── GlobalVariables.st
│   └── LocalVariables.st
├── 模块配置/
│   └── HardwareConfig.xml
└── 程序文档/
    └── PLC程序说明.md
```

## 4. 版本管理规范

### 4.1 版本号格式

- **格式**：`V主版本.次版本.修订版本`
- **说明**：
  - `主版本`：重大功能变更
  - `次版本`：新增功能
  - `修订版本`：bug修复
- **示例**：`V1.2.1`

### 4.2 版本变更记录

- 每次版本变更必须在《版本变更记录》中记录
- 记录内容：版本号、变更内容、关联任务、完成时间、责任人

## 5. 代码风格规范

### 5.1 缩进

- 使用4个空格进行缩进
- 保持代码层次清晰

### 5.2 命名规范

- 变量和函数名使用驼峰命名法
- 常量使用大写字母加下划线
- 功能块和函数名使用 Pascal 命名法（首字母大写）

### 5.3 代码长度

- 每行代码不超过80个字符
- 复杂逻辑拆分为多个函数或功能块

## 6. 安全规范

### 6.1 安全逻辑

- 安全相关逻辑必须独立编写
- 安全功能必须有冗余设计
- 安全逻辑必须经过验证

### 6.2 错误处理

- 所有输入必须进行范围检查
- 异常情况必须有错误处理
- 关键操作必须有确认机制

## 7. 测试规范

### 7.1 测试流程

1. 单元测试：测试单个功能块
2. 集成测试：测试模块间交互
3. 系统测试：测试整个系统

### 7.2 测试文档

- 测试计划
- 测试用例
- 测试报告
- 验证记录

## 8. 文档规范

### 8.1 文档结构

- 项目总方案
- 需求规格说明书
- 详细设计说明书
- IO点表&变量清单
- PLC程序说明
- HMI设计规范+操作手册
- 版本变更记录
- 验收交付清单

### 8.2 文档格式

- 使用Markdown格式编写
- 保持文档结构清晰
- 定期更新文档

## 9. 最佳实践

### 9.1 模块化设计

- 功能块尽量独立，减少耦合
- 通用功能抽象为独立功能块
- 保持功能块接口简洁

### 9.2 代码复用

- 相同功能使用相同功能块
- 避免重复代码
- 建立代码库

### 9.3 性能优化

- 避免不必要的计算
- 合理使用数据类型
- 优化循环和条件判断

### 9.4 可维护性

- 代码结构清晰
- 注释充分
- 命名规范
